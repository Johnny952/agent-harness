# T-198 — per-role fallback in the Settings `role_model` hint

Decision: `docs/decisions.md` ADR 513.

## What

- `front/src/routes/models.tsx`: `ROLE_MODEL_FALLBACK` (`arquitecto-draft` -> `arquitecto`,
  `integrador` -> `implementador`) and `roleModelHint(roles)`, which `SettingControl` uses
  for the `role_model` hint. With neither role in the served list the sentence is the old one;
  otherwise it appends `; except <role> runs on <fallback>'s model` for each listed one.
- `front/src/routes/-models.test.tsx`: two tests, one per case, asserting role names rather
  than the whole sentence.

## Why this way

The console cannot read `Config.model_for` (`dispatcher/config.py`), so the map is a hand
copy, as ADR 513 Consequences accepts. The hint lists only roles the served map names, so it
never mentions a role the operator cannot edit.

## Ruled out

- Serving the fallbacks from the config writer: a new contract for a hint.
- Changing the `role_effort` hint or the `(default)` placeholder: not wrong.
