# T-086 — Debt as backlog items, the import, and `impact` (board-service step 5d)

Decisions: `docs/decisions.md` ADR 131. It covers:
- `impact`, a debt index column the auditor writes, and its priority;
- `debt_id`, the link from a backlog item to its entry;
- the idempotent writer, the dispatcher's filing after the auditor, and
  `dispatch import-debt`.

## What was built

- `dispatcher/debt.py`:
  - `COLUMNS` ends with `impact`. `IMPACTS` (`risk`, `cost`, `cosmetic`),
    `NO_IMPACT`, `IMPACT_PRIORITY`, `DEFAULT_IMPACT_PRIORITY`, `impact_of`
    and `priority_for`.
  - `index_rows` returns `impact`, read by header name only, so old and
    short rows read as `none`.
  - `open_rows`, `backlog_item` (title, description, priority) and
    `declared_row` (a filed entry the index does not show).
  - `filing_note` asks for the impact.
- `dispatcher/context_transfer.py`: `TaskFile.debt_id`, written only when
  set.
- `dispatcher/tasks.py`:
  - `DEBT_TAG` and `is_debt_id`; `field_problems` reports a bad `debt_id`.
  - `find_debt_item`, `propose_debt` (under `CREATE_LOCK`, idempotent on
    `debt_id` at any status) and `file_debt` (rows, skips resolved ones, has
    a dry run).
- `dispatcher/dispatcher.py`: `_mirror_filed_debt`, called after the

## Why this way

- The auditor writes the impact because it has just read the code; the
  board only maps it.
- `debt_id` lives in the hive, which the board owns, so filing never
  commits to the project's branch.
- One idempotent writer under `CREATE_LOCK` serves both the mirroring and
  the import, so their order does not matter and neither files twice.
- Filing after the auditor, not at numbering, so the row and its impact
  exist. A failure only warns: the index is still the record, and the import
  catches up.
