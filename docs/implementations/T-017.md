# T-017 — a filter that matched nothing is not an empty harness

One vocabulary entry and three screens. The decision is `docs/decisions.md`
**ADR 43**, appended by this task's arquitecto to answer the closing paragraph
of **ADR 42** — which declared this gap rather than fixing it — and the build
order was `/data/.hive/tasks/T-017/plan.md`, which is outside the repo and goes
with the task. This file is what was actually built, why that way, and what was
ruled out. It closes `docs/debt/T-016-D1.md`.

Before: `front/src/routes/learnings.tsx` and `front/src/routes/debt.tsx` both
tested the **filtered** list with `rows.length === 0` and rendered the
`EmptyState` written for an empty collection. An operator who typed
`obserability` into the Learnings filter was told that no phase has ever written
a learning entry; one who mistyped a slug in the Debt filter was told the project
has filed no debt. Both sentences are about the harness, and the true statement
was about the characters just typed. `front/src/routes/index.tsx` had already
split the branch, so the console held two answers to one question and the one
with no written entry behind it was the one two screens used.

## The entry first, because the screens are a transcription of it

`docs/ui.md` *Absent, empty and broken are three different things* gained **No
match**, as a bullet inside the existing entry rather than a new heading: a
filter that matched nothing is a successful query over a collection that is not
empty, which is Empty's own sentence with a different subject, so the heading's
own count of three stays true. The bullet says what the state may claim — the
query verbatim, and the control that brings the rows back — and what it may not:
anything about the harness.

The paragraph after the bullets is the load-bearing half, and it is the half a
later refactor is most likely to undo without noticing. **Empty and No match are
two tests over two lists, in that order**: the collection as the read served it,
and only then the filter's result. A collection that really is empty keeps
Empty's sentence with a query still in the box, because the filter is not why
there is nothing there. The same paragraph fixes two more things the screens
needed: a screen with more than one filter names every control it would take to
bring the rows back rather than quoting one query, and the pair binds a filter
over a **wired** read only.

Writing this first was the card's own instruction and it was worth following.
Each screen below is a transcription, and no screen reworded the entry.

## The three screens

Each route exports the component holding its own branch, taking the two numbers
the branch turns on rather than a query result. That is ADR 43's third bullet and
it is what makes the branch testable with a plain `render` and no router and no
query client — the shape `front/src/routes/-index.test.tsx` already uses for
`TaskCard`. Exporting a component beside `Route` draws no lint warning;
`index.tsx` already does it and the lint's nine are all in `components/`.

`front/src/routes/learnings.tsx` — `LearningsEmpty({ served, query })`, called
with `served.length`, which the route already computed for its over-cap banner.
The collection sentence is byte-identical to what shipped. The no-match arm
quotes the query, says `Clear the filter box`, counts what clearing it brings
back, and names which fields the filter reads. The singular arm — *the one
entry* — is the file's own idiom, beside the banner's existing
`overCap.length === 1 ? "entry is" : "entries are"`.

`front/src/routes/debt.tsx` — `DebtEmpty({ served, query })`, the same shape. The
route had no `served`, so it gained one line: `debt.data?.data ?? []`, plain and
unmemoised, as `learnings.tsx` has it. Unmemoised is safe here and not an
oversight — it feeds no hook dependency, which is the condition in
`docs/learnings/a-query-default-feeding-a-usememo-dep-depends-on-the-data-object.md`.
Its count says *open and resolved*, because a resolved row stays in the index and
clearing the box brings both partitions back.

`front/src/routes/tail.tsx` — the third screen with a filter box over a wired
read, and the one the debt card does not name. Its two existing branches test
the unfiltered `events`, so neither was wrong and neither moved; what the screen
had no sentence for at all was a buffer holding events with every one of them
filtered out, which rendered as a blank virtual scroller. It gained a third arm
after the other two, `TailNoMatch({ buffered })`. Three filters, so it names its
three controls — the payload box and the two `Picker`s — rather than quoting one
query, which is the Board's form and what the `docs/ui.md` paragraph asks for.
Taking it in this task is the task's own "any other screen with a filter box over
a wired read": a known divergence on the day an entry lands is how the console
ends up with two answers again, which is the condition ADR 43 exists to end.

`front/src/routes/index.tsx` already conformed and was not touched.
`front/src/routes/sessions.tsx` has the conflation in one sentence — *Either no
session is running or your filters hide everything* — and stays out. Its
`listSessions` is a fixture, a fixture is never empty, so the state is
unreachable there. Both `docs/ui.md` and ADR 43 name the file, so the task that
wires it inherits the split rather than discovering it. This is not debt: there
is nothing an operator can reach.

## The tests

Three new files under `front/src/routes/`, written before the components and run
red first — thirteen failures, all `Element type is invalid … got: undefined`,
which is the only failure that proves the test is reaching for the component and
not for something that happens to exist.

- `-learnings.test.tsx`, five: an empty collection with no query, an empty
  collection **with** a query still in the box, a collection of 41 with a query
  that matched none, that the no-match arm says nothing about the harness, and
  the singular arm.
- `-debt.test.tsx`, six: the same five plus the *open and resolved* clause.
- `-tail.test.tsx`, two: the three controls and the buffered count, and that it
  says nothing about the collector being quiet.

Thirteen in all, which is the 60-to-73 the runner printed.

The case pinned hardest is the empty collection with a query in the box. That is
the one a later refactor inverts, and it is the order ADR 43 fixes. Each
no-match case also asserts the *absence* of the collection sentence, because what
this state may not say is half the entry.

The `-` prefix on each filename is load-bearing: `@tanstack/router-plugin` reads
every other file under `src/routes/` as a route and `routeFileIgnorePrefix`
defaults to `-`, so without it these files arrive in `routeTree.gen.ts` as routes
no phase here can regenerate. `afterEach(cleanup)` is explicit in all three
because `vitest.config.ts` sets `globals: false`.

`bun run test` went from **60 passed in 5 files** to **73 passed in 8**, both
numbers quoted off the runner rather than counted off `it(` blocks
(`docs/learnings/counting-it-blocks-undercounts-the-front-suite.md`).

## What ships unexecuted, and why

All of it, in the sense that matters. The subject of this change is a sentence an
operator reads, and no phase can open a browser. `docs/ROADMAP.md` **V0.6f** is
the walk — a new id beside V0.6e rather than a step added to it, because V0.6c,
V0.6d and V0.6e all assert the *collection*-empty sentences and every one of
those is still correct — and its Results row is NOT RUN for V0.6e's reason. The
suite pins which branch is chosen and never the words in it. No api image is
involved, so a stale `compose-api-1` is not this check's trap.

## The call sites are the half the tests do not reach

Extracting each branch into an exported component is what made it testable, and
it moved the defect up one level. Every arm of `LearningsEmpty`, `DebtEmpty` and
`TailNoMatch` is pinned; the *argument the route passes* is not —
`served={served.length}` rather than `rows.length`, `buffered={events.length}`
rather than `filtered.length`. That argument is the whole of what T-016-D1 was.
Pass `rows.length` and all 73 tests stay green while the screen is wrong again,
with only the comment above each call site standing in the way.

Pinning it needs a route render, which needs a router and a `QueryClient` seeded
with a fixed `/api/learnings` and `/api/debt` body — a harness this suite does
not have, and building one is wider than the single surface this task was told to
keep to. What would resolve it: that helper under `front/src/`, plus one test per
screen asserting that a served collection of N with a query matching none renders
the no-match title and not the collection's. The helper is worth having well
beyond these three screens, which is why it is a task of its own rather than a
corner of this one. Declared as introduced debt in this task's handoff.

Two smaller edges, recorded rather than fixed: `TailNoMatch`'s `buffered` is
`events.length` after `.slice(-2000)`, so on a busy harness it is the buffer and
not a total — which is what the sentence says — and the tail's new arm is
reachable with an error banner above it, which is the partial form `docs/ui.md`
asks for and which no test pins.

## What was not done, and is not debt

**No clear button.** The entry asks for the sentence that names the box, not an
affordance. No filtered screen in the console ships a clear control, and adding
one is a change to all of them at once and to *A region with no route says which
route, and when*'s rule about controls — ADR 43's second bullet decides this, so
a later task finds a decision rather than a gap.

**No shared primitive.** `EmptyState` is the shared one already and it takes two
strings. The subject noun differs per screen — a learning entry, a debt row, an
event — so a `NoMatchState` would be parameterised down to the wording it was
meant to hold. What binds the wording is the `docs/ui.md` entry, which is the
point of filing it there.

**No api change and no new route.** Nothing about a filter is served: the query
is `useState` in the component. An entry that could only be honoured by changing
a route would have been filed in the wrong file
(`docs/plans/front.md` *What `docs/ui.md` may decide, and what it may not*).

**No other wording on any of the three screens**, and nothing on `sessions.tsx`.
