# T-175 — `escalated_model` (ADR 432)

## What was built

- `dispatcher/config.py`: `Config.escalated_model` (None by default), loaded by
  `_load_escalated_model` (null or a non-empty string, like `role_model`'s
  entries), a read-only `CONFIG_KEYS` row. The two checks that were inline in
  `effort_for` are now `Config._escalates`, and `model_for(role, round_num,
  repeated_finding)` returns `escalated_model` for the implementador when it
  is set and `_escalates` holds. `DRAFT_ROLE` / `INTEGRADOR_ROLE` call
  `model_for` without a round, so the integrador never escalates.
- `dispatcher/dispatcher.py`: `run_phase` computes `chosen_model` once and
  passes it to `dispatch_phase` (whose `model` argument is what the usage line
  records) and to `save_handoff`. `_cycle_rounds` takes `repeated_finding` as a
  seed; the ADR 73 log line adds "on model X" when the key is set.
- `dispatcher/context_transfer.py`: the envelope (the "phase record") gains
  `model` and, when true, `repeated_finding`, each only when given.
- `dispatcher/command_run.py`: both resume paths read `repeated_finding` from
  the filing envelope and pass it to the resumed `run_phase` and to
  `_cycle_rounds`, so a resumed round decides effort and model as it did.
- Docs: `config.example.yaml`, README `--round`, `cli.py` `--round` help,
  `docs/plans/backlog.md` item 4.

## Why this way

One rule (`_escalates`) feeds both effort and model, so they cannot drift. The
signal is stored in the envelope because the cycle's memory is gone by the time
a verdict resumes the round. Resumed rounds that ran on the signal now also
resume at `escalated_effort` (before, the signal was lost on resume); ADR 432
records that as a fix.
