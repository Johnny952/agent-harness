# T-069 — the CLI's permission denials on the usage line, in the handoff envelope and on the task page (command-requests step 1)

Decisions: `docs/decisions.md` ADR 116 (the usage line's `permission_denials`
and its caps, no other redaction, the envelope's fifth key, recording never
fails a phase, `task_usage` unchanged, the page's four states).

## What was built

- `dispatcher/dispatcher.py`: `_reduce_permission_denials(raw)` reads the
  result's `permission_denials`: `null` unless it is a list; the first 50
  entries (`_MAX_PERMISSION_DENIALS`) each reduced by `_reduce_denial` to
  `tool_name`, `tool_use_id`, `tool_input`, or `{"malformed": <type name>}`
  when the entry is not an object or its `tool_name` is not a string;
  `permission_denials_dropped` when more were reported. `_cut_strings` cuts
  every string value over 500 characters (`_MAX_DENIAL_STRING`) to
  `"…[cut N chars]"`, keys left whole, the raw result not mutated.
  `_permission_denial_fields` wraps it: an exception is a warning and `null`.
  `_usage_record` spreads it onto every line. `DispatchResult` gains
  `permission_denials` (default `PERMISSION_DENIALS_ABSENT`); both returns of
  `dispatch_phase` after a call set it from the final result
  (`_handoff_denials`), and `run_phase` passes it to `save_handoff`.
- `dispatcher/context_transfer.py`: `PERMISSION_DENIALS_ABSENT` and
  `save_handoff(..., permission_denials=PERMISSION_DENIALS_ABSENT)`, which
  writes the fifth key only when given one.
- `observability/api/app.py`: only the `MAX_USAGE_CALLS` comment.
- `front/src/lib/api/types.ts`: `UsageLine.permission_denials`,
  `UsageLine.permission_denials_dropped` and `PermissionDenial`.
- `front/src/routes/tasks.$taskId.tsx`: `DeniedFields` on each call line (the
  four states, the dropped count, Malformed for a wrong type), `DenialEntry`
  (the tool's name, the input on one line cut to 80 characters, the whole in
  `title`), and the "N denied" badge on an attempt's header (`deniedCount`).
- Tests: in `tests/dispatcher/test_dispatcher.py` the reduction (kept,
  `[]` apart from absent, not-a-list, extra keys, missing id or input,
  malformed entries, 53 and 50 entries, long and nested strings, no
  mutation), a raising reduction leaving the line and the phase intact, the
  last retry's list handed back, no account handing back the sentinel, and
  `run_single_phase` writing a list and `null` into the envelope; the full
  key-set test gains the key. In `tests/dispatcher/test_context_transfer.py`
  the four-key envelope without denials, the fifth key for a list, `[]` and
  `null`, and an old envelope still reading. In
  `front/src/routes/-tasks.test.tsx` "the usage region's denials": the four
  states, the shortened input and its title, malformed entries, a non-list,
  the dropped count, the badge and its absence.
- Docs: ADR 116; the *Built* note under decision 1 of
  `docs/plans/command-requests.md`.

## Why this way

- Every call's line gets the key, retries and gate calls included, because
  each is its own CLI call with its own refusals.
- The envelope takes only the final result's list: it is the phase's record,
  and the per-call history, the dropped counts included, is on the usage log.
- A sentinel default, not `None`, keeps "this phase made no call" (four keys)
  apart from "the CLI reported nothing usable" (`null`).
- The *denied* row is on each call line, not repeated on the first-call
  summary, so a call's denials are drawn once.
- A malformed entry's Python type name is mapped to a stand-in value so
  `Malformed` names it in the page's usual words ("a string", "a list").

## Pending

- No backfill: older lines and envelopes show "written before denials were
  logged" or nothing.
- `read_handoff_envelope` is unchanged and does not look at the fifth key;
  its docstring now names it (fixed at review).
- The plan's next steps (command requests, verdicts, an Approvals card,
  widening the allowlist) are not started.

## Ruled out

- Redacting tool inputs beyond the length cut: the transcript already holds
  them, readable by the same users.
- Failing or retrying a phase over a denial it could not record.
- Changing `task_usage` or `MAX_USAGE_CALLS`.
