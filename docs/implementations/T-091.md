# T-091 — The console forwards the backlog reads and the board-service writes

Decisions: `docs/decisions.md` ADR 136. It covers:
- the board-service as the forward's third upstream, for four exact
  method and path pairs;
- `BOARD_SERVICE_URL`, default `http://board-service:8792`, and no token;
- the CSRF check: JSON content type, `Sec-Fetch-Site` and `Origin`;
- `/api/ready` and `GET /api/tasks/<id>/comments` forwarded to the api,
  with `POST` on the comments path going to the board-service.

## What was built

- `front/src/lib/api/server-env.ts`: `BOARD_SERVICE_URL`, trailing slashes
  trimmed, and `BOARD_SERVICE_TIMEOUT_MS` (5000).
- `front/src/lib/api/forward.ts`:
  - `/api/ready` in `FORWARDED`, with no parameter and no project.
  - `GET /api/tasks/<id>/comments` to the api, shaped like the usage
    route: one segment, re-encoded, `%zz` a 404, no query.
  - `boardTarget` matches `POST /api/backlog`, `PATCH /api/tasks/<id>`,
    `POST /api/tasks/<id>/comments` and `POST /api/tasks/<id>/accept`,
    after the settings branch and before the 405.
  - `forwardBoard`: 415 for a non-JSON content type, 403 for a
    `Sec-Fetch-Site` other than `same-origin`, 403 for a foreign `Origin`,
    413 over 64 KiB (`readBounded`, by the declared length or while
    reading). Then it sends only `Content-Type: application/json` and the
    body. The answer passes back unchanged. Unreachable is a 502 and a
    timeout a 504, both naming "the board-service"; the address is logged.
  - The header comment and the 404's count: twelve api routes.
- `front/src/lib/api/types.ts`:
  - `Task` gains `phase`, `priority`, `source`, `tags`, `rank` and
    `debt_id`, the fourteen keys `_task` serves. `TaskStatus` adds the
    backlog statuses and `epic`.
  - `DebtEntry` gains `impact`.
  - New: `ReadyOrder`, `TaskComment`, `TaskComments`, and the body and
    result types of the four writes.
- `front/src/lib/api/client.ts`: `getReady` and `listComments` through
  `readEnvelope`; `proposeBacklog`, `editTask`, `commentTask` and
  `acceptTask` through `readBare`, which keeps the JSON and `{error}`
  checks and returns the board-service's bare result. No mock.
- `front/src/lib/api/queries.ts`: `readyQuery`, `commentsQuery(id)`, and a
  `mutationOptions` factory per write. Each takes the `QueryClient` and,
  when the write settles, invalidates `tasks`, `ready`, and for one task its
  `task` and `comments` queries.
- `front/src/lib/api/mock/fixtures.ts`, `front/src/routes/-index.test.tsx`
  and `front/src/routes/-tasks.test.tsx`: the new required fields on their
  literals, with the defaults of a task filed before them.
- Tests, `front/src/lib/api/forward.test.ts`: `/api/ready` with no
  parameter; the comments read to the api; each of the four pairs to the
  board-service with one header and the exact body; other methods on those
  paths unchanged; status and 201 passed back; 415; 403 for `cross-site`,
  `same-site` and `none`; 403 for a foreign `Origin`, and the console's own
  not forwarded; 413 by length and by stream; 502 and 504 naming the
  service and not its address.
- `bun run typecheck`, `bun run test` (228 passed) and `bun run lint` pass.

## Why this way

- An exact list of pairs, like the rest of the forward: a new
  board-service route does not reach the browser until it is added here.
- The CSRF check sits in the forward because the board-service cannot tell
  the console from anyone on `console_net`, and refuses `Origin` outright.
- No mock, as with the settings writes: a mock would only rehearse a
  board-service the console cannot see.
