# T-107 — The Queue screen reads the real action queue

Decisions: `docs/decisions.md` ADR 163. This note records how it was built.

## What was built

- `getActionQueue(limit = 1)` in `front/src/lib/api/client.ts` takes the finished-list
  limit; the Board's call passes nothing and still asks `?limit=1`.
  `cancelAction(id)` is `POST /api/actions/<id>/cancel` with body `{}` through
  `readBare`.
- `queries.ts`: `QUEUE_DONE_LIMIT = 20`, `actionQueueListQuery` (key
  `["action-queue", "list"]`, so a start's invalidation refetches it) and
  `cancelActionMutation` (invalidates `["action-queue"]` and `["tasks"]` on settle).
- `routes/queue.tsx` rewritten: three groups, worker line, Cancel behind a `Dialog`.
  Meta description updated.

## What was removed

The verb bar, the enqueue dialog and `VERBS` from the page; `listActions`,
`enqueueAction` and `commandLine` from `client.ts`; `actionsQuery`; `QueuedAction`
and `ActionVerb` from `types.ts`; `mockActions` from `mock/fixtures.ts`. The
`client.ts` header no longer lists `listActions`/`enqueueAction` as mocks, and the
`actionBackendDown` comment counts three helpers (two writes and
`pingActionBackend`). `actionBackendQuery` and `pingActionBackend` stay: app-shell,
approvals and tokens use them. `front/AGENTS.md` and the `docs/README.md` `front/`
row were updated to match.

## States chosen

- **Groups:** Pending (served order, each with `waiting`), Running (`claimed`),
  Finished (`n`, or `n of done_total` when more exist). Each empty group says so.
- **Row:** kind, task id, project, actor, note and a ticking age (queued / claimed /
  finished); a null field is `Absent`. A `cancel` row prints `params.target`.
  A done row has a status pill and its `error` on its own line.
- **Page:** loading line; `ErrorState` on a failed read; one `EmptyState` when all
  three lists are empty and `done_total` is 0; a group that is not a list is
  `Malformed` while the others render; `warnings` in `WarningBanner`.
- **Worker line:** warning banner when `heartbeat` is null, or when it is present and
  `stale` (with `stale_after_seconds` and the age of `beat_at`). Staleness is the
  api's, never recomputed.
- **Cancel:** only on a `start` in Pending or Running. Confirm is disabled while the
  write is in flight; success is `toast.success` and a refusal `toast.error` with the
  served message; the dialog closes either way.

## Ruled out

A second reader function (the two would differ by a number); keying the screen
`["actions"]` (a start's invalidation would miss it); `alert-dialog` (its action
closes before the write settles).

## Verified

`bun run typecheck`, `bun run lint` clean; `bun run test` 383 passed in 21 files
before the final lint-only reformat. `front/src/routes/-queue.test.tsx` has 13
cases covering every state in the task's *Done when*. A grep of `front/src` for the removed names
finds only a comment in `fixtures.ts`.
