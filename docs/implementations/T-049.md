# T-049 — the usage region prints `model` and `models_used`

Decision: `docs/decisions.md` ADR 69.

## What

- `front/src/lib/api/types.ts` `UsageLine`: optional `model` and `models_used`,
  commented with ADR 68.
- `front/src/routes/tasks.$taskId.tsx`: `ModelFields`, two slots (`model`,
  `models used`), rendered in `FirstCall` (from `phase_call`) and in `CallLine`,
  unconditionally, so an unmeasured line still shows its model.
- `front/src/routes/-tasks.test.tsx`: `describe("the usage region's models")`:
  explicit values, `null`, `[]`, missing keys, malformed, a list holding a
  non-string, an unmeasured line.
- `docs/plans/front.md` *The usage task*: the "separate front task" sentence
  now says the region shows them.

## Why this way

- A missing key is tested as `undefined` and has its own muted string, so it
  cannot read as `Absent` or as the CLI default.
- Nothing is compared, sorted or derived across lines.

## Ruled out

- Fixtures: `front/src/lib/api/mock/` holds no usage line (`listUsage` reads
  the api only), so there is nothing to extend.
