# T-097 — The action queue and the worker that drains it

Decisions: `docs/decisions.md` ADR 142. It covers, one per decision:
1. the worker is a `worker` compose service from the dispatcher's image, the
   only long-running service with the docker socket;
2. the queue is JSON files under `<state_dir>/actions/` (`pending/`,
   `claimed/`, `done/`), written by the board service, moved only by the
   worker, read by the api; `dispatcher/actions.py`, separate from
   `dispatcher/queue.py`;
3. the action record and its kinds: `start`, `cancel`, `command_verdict`,
   `turn` now; the account and project kinds named for later, each added
   under its own ADR;
4. one worker under a `flock`, an atomic claim by rename, recovery of a
   claimed action by kind, and cancel of a pending versus a running start;
5. the rules: one cycle per project, a start's note becomes an `operator`
   comment, verdicts go through the T-074 function under C-12;
6. the spending limit is step 9's, only reserved here;
7. the refusals at create;
8. the board service's action routes sit behind `BOARD_ACTIONS_TOKEN`.

## The split

Ten tasks, in build order; ADR 142 *The split* has the tests of each:
1. `dispatcher/actions.py`, the contract.
2. The worker loop, with `start` and `cancel`.
3. The board service's start and cancel routes, with the token.
4. `GET /api/actions` in the read api.
5. Compose: the `worker` service and the `actions` mount (needs approval).
6. The console's forward and *Start development*.
7. The `/queue` screen.
8. The worker's `command_verdict` handler.
9. The board service's verdict route.
10. The worker's `turn` handler, after the composer's charter ruling.

## Consequences that bite later

- Task cards carry no `project`, so a cycle started by hand with `run-task`
  or `run-queue` is invisible to the worker's one-cycle-per-project rule.
- The board service gains a bearer on its action routes. ADR 136 had ruled
  one out for backlog writes; ADR 142 says why actions differ (agents reach
  the service on `ia_harness_net`, and an action spends quota).
- Until sign-in exists, the actor is `operator`, and C-12's owner-only rule
  rests on Caddy's Basic auth.
- The compose task changes `docker/compose/` and needs the user's approval.
- ADR numbers 143 and 144 are unused; they stay gaps.

## Why this way

- Under `state_dir`, not the hive: every agent container mounts the hive
  read-write and none mounts the state dir, so an agent cannot enqueue a
  run that spends quota (C-4).

## Ruled out

See ADR 142 *Ruled out*: the hive as the queue, a database, reusing
`queues/<id>.json`, the socket in the board service, several workers with
leases, re-running a spent action after a crash.
