# T-024 — what every `claude` call cost, written down

The dispatcher parsed the CLI's result object on every phase, read three keys
off it and dropped the rest with the local. `usage`, `num_turns`,
`duration_ms` and `total_cost_usd` were measured by the service, handed to the
harness, and never persisted — so the only numbers this project had about what
a phase costs were the operator's one-off transcript read of T-016
(`docs/plans/token-economy.md`, *What the transcripts show*). This task gives
the harness a series instead: one appended JSON line per `claude` call, in the
task's own usage log, recorded as `docs/decisions.md` ADR 53. Scope:
`dispatcher/context_transfer.py`, `dispatcher/dispatcher.py`, their tests,
`docs/decisions.md`, P5 in `docs/plans/token-economy.md`, this file.

## Verified first-hand, not taken from the card

| Claim | Where | Verdict |
|---|---|---|
| `ClaudeResult.raw` is the parsed `--output-format json` object | `dispatcher/docker_exec.py:exec_claude` | true |
| `raw` is `{}` on a failed parse | same | true, and in four ways: the host-backstop timeout, empty stdout, stdout that is not JSON, and JSON that is not an object |

| `save_handoff` writes one JSON envelope per phase | `dispatcher/context_transfer.py:save_handoff` | true: four keys, one file per role, overwritten each round |
| `/api/phases` lists those envelopes, one row per role and task | `observability/api/app.py`, the `/api/phases` route and `_phase` | true, six keys per row |
| The dispatcher posts nothing to the collector | `hooks/emit_event.py` is the only poster | true, and stronger: `dispatcher/` has no HTTP client and no `requests` import |
| Which keys a real `raw` holds | — | **could not be checked**; see below |

Two facts the card does not mention, and the record's shape turns on both:

- **A phase is not one `claude` call.** `dispatch_phase` loops over accounts
  when one answers 429, and inside one attempt `_run_gates`,
  `_refuse_review_writes` and `_shrink_over_budget` may each spend one
  `--resume` — and each *replaces* `result` with the retry's. Anything derived
  from a phase's final return therefore describes its last retry.
- **A failed phase leaves no envelope.** `run_phase` returns before
  `save_handoff` whenever a fatal phase did not succeed.

## What no stored `raw` could tell us, and what was assumed

Nothing on this harness persists a CLI result object. The task scratch
directories of T-011 … T-020 hold the roles' notes and
`handoffs/<role>.json`, which is ADR 27's four-key envelope and carries no CLI
object; ADR 49's probe record holds parsed percentages; `.data/verify/`, where
`docs/ROADMAP.md` keeps its probe evidence, is outside the directories a phase
may read. `docs/ROADMAP.md` V1.1 — the check whose *Record* step would have
written the key set down — has no Results row: it was never run. And this task
was forbidden a live probe.

So the measured keys are spelled from `docs/ROADMAP.md` V1.1's *Record* step,
its 2026-09-24 V5.1 Results row (CLI 2.1.273: `num_turns`, `total_cost_usd`,
`api_error_status`, `stop_reason`) and the root `README.md` item 2 (`usage`
with input, output, cache read and cache creation). **That is the assumption,
and the code is written so that it costs nothing if it is wrong:** every field
is read with `.get`, a value that is not a number is recorded `null` rather
than coerced, and each line carries `raw_keys` — the sorted top-level key
names, values excluded. The first real dispatched phase therefore says on its
own which keys the CLI printed, and a renamed key shows up as a column that
went all-null instead of as a number quietly meaning something else.

## The change

### `dispatcher/context_transfer.py`

`usage_log_path` and `append_usage`, beside the handoff functions and
namespaced the same way:
`<hive_tasks_dir>/<task_id>/usage/calls.jsonl`, a *sibling* of `handoffs/`
rather than a file inside it, because
`list_handoff_roles` reads every `.json` in that directory as a role.

`append_usage` is the one writer in that module that does not go through
`_write_atomic`, and the docstring says why: that helper exists for a JSON
document another process may read mid-replace, while this is a log whose every
line is final once written and whose only writer is the dispatcher holding the
task lock. Re-serialising the file per `claude` call would buy nothing and
would get worse as the series grows. The reader's half of the contract — skip
a line that will not parse, do not assume the last line is complete — is in
the docstring too. It raises `OSError` to its caller; the swallow belongs at
the call site, which knows this is bookkeeping.

### `dispatcher/dispatcher.py`

- `_usage_record(task_id, role, round_num, account, call, result, now)` —
  pure, builds ADR 53's seventeen keys. `measured = bool(result.raw)`,
  `raw_keys = sorted(result.raw)`, `recorded_at = now.isoformat()`. `now` is a
  parameter and the caller reads the module's one clock seam, `_utc_now`,
  which is `_probe_record`'s shape and what
  `docs/learnings/one-clock-seam-per-module-and-a-now-parameter-is-the-other-half.md`
  allows.
- `_number_or_none` — the guard that keeps a guessed number out. `bool` is
  excluded explicitly, because it is an `int` in Python and a `num_turns` that
  came back `true` is a drift, not one turn.
- `_UsageRecorder` — a frozen dataclass holding the five things that are fixed
  for one attempt (`cfg`, task, role, round, account), with one method
  `record(call, result)`. It exists so the three retry helpers take one new
  parameter instead of five. Everything it does is wrapped in
  `try/except Exception` and logged, on `_record_probe`'s contract and for
  `_record_probe`'s reason: this is bookkeeping on a path that may already be
  failing, and a full disk must not be what fails a phase.
- The four call sites. `dispatch_phase` builds the recorder once the account
  is picked, records `"phase"` on the line after `exec_claude` returns —
  before the retries, since each replaces `result`, and before the gates, so a
  crash in one cannot cost the phase's own numbers — and passes the recorder
  to the three helpers. Each helper records `"gate-retry"`, `"review-retry"`
  or `"shrink-retry"` immediately after its own `exec_claude`, *before* the
  branch that decides whether to keep the retry: a retry discarded as a result
  still cost the account a turn.

Two paths come along for free. A 429 attempt's `continue` runs after its
record is written, so a failover leaves one line per account, in order. And
the optional mapper is recorded like any other role, because it goes through
`dispatch_phase`.

Untouched on purpose: the `/usage` probes in `check_quota_ok` and
`_recheck_cooling_accounts`, and `dispatcher/operator.py`. A probe is not a
phase, it is a local command that reports `num_turns` 0, and ADR 49 already
persists what one found. No config key either — the record costs no quota and
no model call, so a switch for it would only be a way to lose the series.

## Why its own file, and not the two alternatives

Both arguments are ADR 53's, in full, and are not re-made here. In short: a
`usage` key on the handoff envelope would be overwritten every round, which
destroys exactly the series P5 asks for; it would be absent for the phases
that failed, since those never reach `save_handoff`; one record per role and
round cannot hold the four calls an attempt can make; and keyed off the final
`result` it would report a shrink retry's two turns as the phase's whole cost,
which is worse than absent. The collector is out because `dispatcher/` has no
HTTP client at all, and a POST would add a network failure mode to a cycle
that has none.

`/api/phases` is unchanged and serves nothing new. The route lists
`handoffs/`; this log is a sibling directory, and the console screen that
would read it is `docs/plans/front.md`'s own card, outside this task. A task
that serves this is choosing a row shape for a *series*, which is that
screen's decision and not one to guess at from here. The guard is a test:
after `append_usage` has run, `list_handoff_roles` is still empty and
`list_task_ids` has not grown a task.

## What was left standing, and why

P4's "The proxy until P5 exists" and P8's "until P5 gives a measured phase
cost" are **not** edited. Both are about a measured *budget* — "the median
ia-harness implementador costs X% of a window" — and that is not what landed:
one task's records are not a median, and nothing converts a token count into
the window percentage `/usage` reports, whose weighting is unpublished. The P5
section says so in its own words, which is where
`docs/learnings/a-plans-status-line-is-yours-and-its-older-counts-are-not.md`
puts a pre-existing sentence a diff did not write.

## Tests

`tests/dispatcher/test_context_transfer.py` — `append_usage` writes one
parseable line in the right place; a second call appends rather than
replacing; and the file shows up as neither a handoff nor a task.

`tests/dispatcher/test_dispatcher.py`, under *what every `claude` call cost* —
the three the card requires, on `_usage_record` and pure: a full `raw` where
every field lands, a `raw` with no `usage` block where the four counts are
`None` and explicitly not `0`, and an empty `raw` that records
`measured: false` with the dispatcher's own nine fields still right. Plus a
parametrized case for the values a drifting CLI could print — a count as a
string, `usage` as a list, `usage` as `null`, a count as `true` — all of which
record `null`. Then through `dispatch_phase` on the fakes already in that
file: a successful phase leaves one line with its account and round; a phase
that timed out still leaves its line, `measured: false`; a failover leaves one
line per account in order; each of the three retries is recorded as its own
call; a discarded retry is recorded anyway; and an `append_usage` that raises
`OSError` does not fail the phase.

## One trap for the next task

Never spell the log file bare in a doc under `docs/`.
`dispatcher/gates.py:pointer_token` accepts any backticked token with a slash
and an extension, resolves it from the repo root and from beside the citing
doc, and a path under the hive directory resolves to neither — it lives
outside every worktree. `git check-ignore` does not excuse it either, since
`_ignored` asks about the token as written. Use the placeholder spelling ADR
53 and the P5 section use, `<hive_tasks_dir>/<task_id>/usage/calls.jsonl`: an
angle bracket makes `pointer_token` reject the token outright. Filed as a
learnings entry under the T-024 slug
`a-hive-path-cited-bare-is-a-broken-pointer`.
