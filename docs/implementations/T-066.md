# T-066 — the settings forward and the read-only Settings screen (console-config task 3, first half)

Decisions: `docs/decisions.md` ADR 112 (the forward: paths, methods, headers,
failures, CSRF) and ADR 113 (the split, the screen's states and rendering).

## What was built

**The split was taken.** Task 3 allows its arquitecto to split the screen into
a read-only half and the controls; ADR 113 part 1 does, and this task is the
read-only half. *Save*, *Reset* (including the broken-config banner's), the 409
banner, the 422 message under a row and the refetch after a write are the
follow-up's.

- `front/src/lib/api/server-env.ts`: `CONFIG_WRITER_URL` (default
  `http://127.0.0.1:8791`, trailing slash trimmed), `CONFIG_WRITER_TOKEN`
  (trimmed; empty is unset; never throws at import), `CONFIG_WRITER_TIMEOUT_MS`.
- `front/src/lib/api/forward.ts`: `forwardSettings`, dispatched before the api
  whitelist's GET-only 405 so `FORWARDED` and `src/server.ts` are unchanged.
  `GET /api/settings` → `/settings`; `PUT`/`DELETE /api/settings/<key>` →
  `/settings/<key>`, one segment, decoded then re-encoded. Shape and method are
  checked before the token. Sends `Authorization: Bearer`, `X-Actor: operator`,
  `Accept`, and for a write the body bytes with its own `Content-Type`; the
  writer's status, body and content type come back unchanged.
- `front/src/lib/api/client.ts`, `queries.ts`, `types.ts`: `getSettings` through
  `readEnvelope`, `settingsQuery` with no poll, `Settings`/`SettingRow`/
  `SettingChange`. The Role models mock (`listModelOptions`, `listRoleModels`,
  `setRoleModel` and their queries) is gone.
- `front/src/routes/models.tsx`: the Settings screen, no control of any kind.
  `front/src/components/console/app-shell.tsx`: nav label *Settings*; route,
  file and `m` chord kept. `front/src/lib/format.ts`: `formatDateClock`.
- `front/src/test/render-route.tsx`: `Served` also takes `{status, error}`.
- Tests: `forward.test.ts` (the settings forward and the token-unset module),
  new `front/src/routes/-models.test.tsx` (17 cases).
- Docs: `front/AGENTS.md` and `front/README.md` name the two variables;
  `docs/ui.md` chord line says `m` settings (ADR 113 *Consequences*); *Built*
  note on task 3 of `docs/plans/console-config.md`.

## Why this way

- The dispatch sits ahead of the GET-only 405 rather than inside `FORWARDED`,
  because the settings prefix answers PUT and DELETE and goes to another host
  with another token; the whitelist stays a closed GET list.
- A failed fetch logs the writer URL to `console.error` and answers a body that
  names "the config-writer service" only: the cause text of a refused
  connection carries the address, so it is not echoed.
- Every failed read is one *Unreachable* state that quotes the served message,
  because the forward's 503 already says which variable or failure it was.
- `formatDateClock` lives in `lib/format.ts` beside `formatClock`, not in the
  route, so the route module exports only its component and the note constant
  (`react-refresh/only-export-components`).

## Pending for the follow-up

The controls by `kind` on editable rows, *Save* with `revision`, *Reset* on
overridden rows and on the broken-config banner, 422 under its row with the
value kept, 409 banner and refetch, refetch after every write, and the plan's
tests "*Reset* present", "a save sending the revision" and "a 422 under its
row". The forward already serves PUT and DELETE.

## Ruled out

- Disabled controls in this half: a control that looks wired and is not breaks
  tier 3's floor (ADR 113).
- Failing the console's boot on a missing `CONFIG_WRITER_TOKEN`: one screen's
  credential should not take the other screens down (ADR 112).
