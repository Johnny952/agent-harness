# T-010 — the read-only board, Phase 2 of the board plan

What this task built, why it is shaped this way, and what it did not build. The
spec is `docs/plans/board.md` "Phase 2 — a read-only board"; only that file's
Status paragraph was edited, and why is below. The toolchain is not this task's
to choose: `docs/charter.md` C-7 rules the board Flask and Jinja. The decisions
a later task could undo without knowing they were decisions are
`docs/decisions.md` ADR 6–10, and this file does not restate them.

## What was built

One new service, one new credential, one new field, one parser fix, and one
service deleted.

- `observability/board/`: `app.py` with
  `create_app(api_base_url, token, username, password_hash, project)` — the
  api's shape — four `GET` routes, `templates/` (`layout`, `index`, `task`,
  `debt`, `events`, plus `_region.html`), and a `Dockerfile` on the api's model
  **without** `COPY dispatcher/`, `EXPOSE 8790`, entrypoint
  `python -m observability.board.app`. `__init__.py` is empty like its
  neighbours'.
- `observability/auth.py`: `check_token(presented, token)` and
  `requires_auth(..., token=None)`, beside the untouched `check_auth`. The
  bearer branch reads the raw `Authorization` header and runs before the Basic
  one; a falsy configured token rejects every bearer.
- `observability/api/app.py`: `lock_expired` on the task row, from
  `_lock_expired(task, ttl_seconds)` over the unchanged
  `dispatcher/context_transfer.py:is_lock_expired`; `_task` takes the ttl as an
  argument and both call sites pass `cfg.heartbeat_ttl_seconds`. `create_app`
  grows a trailing `token=None`, read from `API_TOKEN` with `os.environ.get`.
- `dispatcher/debt.py`: `_unwrap_code`, a matched-pair unwrap replacing
  `cell.strip("`")` inside `_rows`. That is `T-009-D3`, resolved.
- `docker/compose/docker-compose.yml` and `docker-compose.coolify.yml`: the
  `board` service with no `volumes:` key at all, `API_TOKEN` added to `api`, and
  the `dashboard` service deleted from both.
- `scripts/configure.sh`: `gen_token()`, `API_TOKEN` written into
  `docker/compose/.env` beside the two `DASHBOARD_` variables, and the
  credentials block no longer calling itself the dashboard's.
- `pyproject.toml`: `"observability.board" = ["templates/*.html"]` under
  `package-data`. No dependency added — that is C-7's saving.
- Deleted: `observability/dashboard/` and `tests/observability/test_dashboard.py`.
- Tests: `tests/observability/test_board.py` (77), `tests/observability/test_auth.py`
  (the seven rehomed auth tests plus the token path), `lock_expired` and bearer
  cases in `tests/observability/test_api.py`, the backtick cases and a
  fingerprints-did-not-move test in `tests/dispatcher/test_debt.py`, and three
  compose invariants (the board mounts nothing, both services carry `API_TOKEN`,
  the dashboard service is gone from both files).

`dispatcher/context_transfer.py`, the collector, the events schema and
`config.example.yaml` are untouched, as "Out of scope for Phase 2" requires.

## Why this way

**The region is the unit, and one function is the boundary.** Every api call in
`observability/board/app.py` goes through `_fetch`, which returns a `Region`
(endpoint, rows, warnings, error) and cannot raise into a template. It requires
a 200, requires `application/json` before `.json()`, and validates the envelope
shallowly — `data` and `warnings` present, `warnings` a list of strings, each row
a mapping carrying the keys that screen reads. Anything else is that region's
Error state naming the endpoint and the status. `/` therefore renders its tasks
table while `/api/accounts` answers 503, which is the property the spec asks for
and the thing a page-level `try` would lose. The content-type guard is not
defensiveness: ADR 5 pins that Flask's own 404 and 405 are HTML, so a client
assuming JSON crashes on a mistyped path instead of showing its Error state.

**`lock_expired` is three-valued on the api side, and the dispatcher's function
is unchanged.** `is_lock_expired` answers `False` for a task with no heartbeat,
because for the dispatcher "no lock to release" and "the lock is fine" take the
same branch. For a reader they are opposite news, so `_lock_expired` maps a null
heartbeat to `null` and leaves the dispatcher's callers the boolean they want.
The board renders the field and computes no ages against it (ADR 8): a
`timedelta` is allowed in that package, a comparison against the expiry window
is not, and `test_the_board_never_compares_a_timestamp_against_an_expiry_window`
is the grep that says so.

**The bearer path is closed by default and shares the Basic realm.** The api
checks a *hash*, so a service authenticating with Basic would need the plaintext
in `.env` beside the hash and make the hash decorative. `check_token` returns
`False` when either side is falsy, which is what keeps `compare_digest("", "")`
from turning a host whose `.env` predates `API_TOKEN` into a service that accepts
an empty bearer from anyone. The 401 still names `Basic realm="…"` whichever
credential failed: the human is the only caller who can act on a challenge.
The board's own `requires_auth` is passed no token, so the api's credential is
not a second door into the board.

**Nothing on the page writes, and nothing on the page fetches.** The only form
is `/events`' `source_app` filter and its method is `get`, which is a navigation.
There is no `<script>` anywhere; a test asserts both, because the spec makes a
browser-side fetch of the api a review finding rather than a style preference.

**The templates' strings are the spec's strings.** The empty states, the lock
labels, the two different null-card sentences and the events-half heading are
constants in `app.py` or literals in the templates, worded as
`docs/plans/board.md` and `/data/.hive/tasks/T-010/plan.md` write them. They
render as plain text rather than being reformatted into `<code>`: the point of
those sentences is that an operator can read the command out of them. The spec's
own illustrative sentence puts backticks around `dispatch run-task`; the
constants drop them, because an autoescaped backtick reads as noise in a
sentence a human is meant to read straight through.

**The dashboard's auth tests were rehomed by hand.** `docs/plans/board.md` says
they "moved to the shared `observability/auth.py` in Phase 1". They did not:
`tests/observability/test_dashboard.py` still held all nine, seven of which were
auth tests driving the dashboard app because that was the app that had auth, and
no `tests/observability/test_auth.py` existed. Deleting the file on the strength
of that sentence would have deleted `observability/auth.py`'s only coverage. The
seven now live in `tests/observability/test_auth.py` against a two-line Flask app
the test builds itself, renamed off `test_index_*` to say what they check, with
the token path's tests beside them. The two that were about the dashboard — the
events table and the cold-start `init_db` — went with it.

**The Status paragraph of the plan was updated; the Phase 2 spec was not.** A
plan whose Status denies a built phase is the defect `docs/debt/T-008-D3.md`
records, so that paragraph now says Phase 2 is built and names the two sentences
in the section below that are records of what was true when they were written —
the Loading row (ADR 6) and the auth-tests claim. Rewriting the section itself to
match the code would delete the reasoning a reversal of C-7 would need.

## What was ruled out

- **A per-task events list.** `/tasks/<id>` maps the task's `owner` to a
  container through `/api/accounts` and labels the list for what it is. No field
  joins an event to a task, and inventing one out of `source_app` is what the
  screen spec exists to prevent. When `/api/accounts` fails there is no map, so
  the events half carries that call's own error and the task's fields above it
  still render.
- **Re-deriving anything.** No frontmatter parser, no markdown-table parser, no
  status vocabulary restated in a template, no `dispatcher` import, no
  `config.yaml`. `test_nothing_in_the_board_imports_the_dispatcher` and the
  Dockerfile's missing `COPY dispatcher/` are the two halves of that.
- **A Loading state and a skeleton.** ADR 6: a Jinja template renders after every
  call has returned or failed, so no region can be in it.
- **Renaming `DASHBOARD_USERNAME`/`DASHBOARD_PASSWORD_HASH`.** Settled before this
  phase started: a rename means editing a `.env` that exists on a running host,
  plus the api, the coolify file and every doc, to buy a spelling.
- **Fixing `debt.resolved()`'s identical unwrap.** Declared as this task's debt
  instead: it feeds no screen, and moving two unwraps at once would have made the
  fingerprint argument harder to check.
- **`T-008-D1` and `T-009-D2`.** Out of scope by name. `/events` and
  `/tasks/<id>` both send an explicit `limit` so the board does not lean on
  `DEFAULT_EVENT_LIMIT`, but the api is still unclamped for a hand-typed one.
- **Mounting anything on the board.** Including the events volume, which would
  have made `/events` one SQLite read instead of one HTTP call and a second
  reader of the collector's schema.

## Verified

- `python3 -m pytest`: **1041 passed, 10 skipped** (baseline at the arquitecto's
  handoff: 927 passed, 10 skipped).
- `tests/dispatcher/test_debt.py` alone, read for the thing that mattered rather
  than for green: `test_the_fingerprints_of_the_projects_own_index_did_not_move`
  parses `docs/debt/README.md` under the new unwrap and under the old strip
  (monkeypatched back in) and asserts the fingerprint sets and the ids are
  identical. They are, and for a reason worth knowing: `fingerprint` replaces
  punctuation with spaces and then strips, so a backtick at either end of a
  **what** cell never reached the comparison. The defect was always in the
  rendered cell.
- `tests/integration/test_compose_invariants.py`: 17 passed, with the board
  present in both files and asserted to have no `volumes` key at all.
- The `dashboard` grep, case-insensitive over the tree: every remaining hit is
  the two `DASHBOARD_` variable names, a dated ROADMAP row, a debt entry or an
  implementation note recording what was true when written, `docs/plans/board.md`
  describing the deletion, `docs/superpowers/**` (vendored upstream), or a
  comment in this phase's own code and tests explaining what was deleted.

## Not done

- **The image build and the by-hand browser check.** `docker build` and
  `docker info` are both refused in a phase (see
  `/data/.hive/learnings/inbox/T-010-docker-is-refused-in-a-phase.md`), so
  "the image builds from a clean checkout and serves `/`" is unverified here, and
  the spec's own by-hand check — open 8790, stop the api, reload — touches the
  containers running this task and is a human's to run. `docs/ROADMAP.md`'s
  **V0.6b** recipe covers the board on 8790 with those steps, including the
  api-stopped reload, and carries a `NOT RUN` row until a human runs it. It is a
  new id on purpose: `V0.6` was the deleted dashboard's, and its `2026-09-16`
  PASS row stays a record of that check rather than answering for this one.
  What is verified instead: every route, every state and every error shape
  through Flask's test client, and
  `test_the_wheel_the_image_installs_ships_the_templates`, which asserts the
  `package-data` entry the image depends on — a wheel without it renders nothing,
  and running from a checkout would never show it.
- **`scripts/configure.sh` was not executed.** No test covers `scripts/`, and a
  phase may not run a shell script or syntax-check one
  (`/data/.hive/learnings/inbox/T-008-bash-n-is-refused-like-python3-c.md`). The
  edits were read line by line against the surrounding style: `gen_token` is
  shaped like `hash_password`, `command -v openssl` with a `/dev/urandom`
  fallback, and `API_TOKEN` is written in the same block and nowhere else.
