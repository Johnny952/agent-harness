# T-181 — the credentials snapshot module

Builds ADR 456 *Consequences* 2 to the contract of ADR 462 (`docs/decisions.md`).

## What was built
- `dispatcher/credentials.py`: `snapshot` (pure, no write), `read`, `write`
  (module lock, atomic temp + `os.replace`), `SnapshotError`. The git token and
  deploy keys are told apart by `os.stat` / `os.scandir` only; the deploy key's
  fingerprint is `project_keys.fingerprint` on the `.pub`. Accounts take one
  `docker exec sh -c 'if [ -f "$1" ]; then stat -c "%s %Y" "$1"; else echo absent; fi'`
  each, so a missing file is exit 0 and a failed exec is `unreachable`.
- `dispatcher/worker.py`: `CREDENTIALS_SNAPSHOT_SECONDS = 300`; `_maybe_snapshot`
  runs in `run()` before `tick` and starts a daemon thread `credentials-snapshot`
  that calls `credentials.write(cfg)` and logs, never raises. The first pass is
  the snapshot at start. A failed pass waits the next 300 s, it does not retry.
- Tests: `tests/dispatcher/test_credentials.py`, and `test_worker.py` with an
  autouse stub of `credentials.write` so no `run()` test execs docker.

## Why this way
- The suite runs as root, which ignores mode `0000`, so the never-opened test
  chmods the secrets to `0000` and also patches `builtins.open`, `io.open` and
  `os.open` to raise on those paths.
- A thread, because an exec into a silent agent can take 15 s and the loop
  handles a `cancel` at once.

## Ruled out
- Reading the token or login file to check it is non-empty: size from `stat` says it.
- A config key for the interval: a constant, as `POLL_SECONDS` is.

## For task 3
Call `credentials.write(cfg, logins={account: logged_in_at})` after an
`account_login` ends `done`, and `credentials.write(cfg)` after a `git_token` or
`keygen`. This task adds no such call.

## Not observed
The `stat -c '%s %Y'` output inside the agent image is assumed coreutils; the
tests fake the exec.
