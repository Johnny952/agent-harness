# T-154-S2: a reopened `limit_reached` task restarts where it was held

Contract: `docs/decisions.md` ADR 357 (the description says 349; the reserved
block is 357-359). It amends ADR 336, decision 5, and uses ADR 354's
`start_at`/`start_round`/`on_held`.

## What was built

- `dispatcher/queue.py`: `Entry.held_at` (`{"role", "round"}` or None), saved
  by `asdict`; old files load with None through the dataclass default.
- Both runners keep the `(role, round)` that `on_held` reports in a list local
  to the task and hand it to `_settle`, which stores it only when the entry ends
  `limit_reached` and clears it otherwise. `reopen` is untouched: it only
  changes state and note, so `held_at` survives.
- `_start_kwargs(entry)` gives `start_at`/`start_round` for a held role, and
  nothing for the arquitecto or the mapper, which start there anyway.
- In `_run_parallel` the callback runs in the worker thread, and `_settle` reads
  the kept pair under `cond`, as it already does for the outcome.
- Fakes `FakeCycle` and `ScheduledCycle` accept the keywords; `FakeCycle` takes
  a `held_at` script key and records `start_at`/`start_round`.
- Docs: `docs/cli.md` run-queue paragraph, debt rows for `T-152-D1` and
  `T-154-S1-D1`.

## Ruled out

- Clearing `held_at` in `reopen`: the resume needs it.
- Storing it on every `HELD`: only `limit_reached` is resumed, and a held task
  after spend is not retried.
- Touching `dispatcher/dispatcher.py` or the confirmation's estimate (out of scope).

## Tests

(serial and parallel), arquitecto/mapper defaults, no report stores None, old
file loads, FINISHED/BLOCKED/SPLIT/HELD clear it. `python3 -m pytest` green.
