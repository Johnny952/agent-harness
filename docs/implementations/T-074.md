# T-074 — the command-request verdict from the CLI, the run and the resume (command-requests step 4)

Decisions: `docs/decisions.md` ADR 119 (step 4 built in the dispatcher first,
through `dispatch command-verdict`, by the user's ruling; one function,
`run_command_request`; one verdict per block, recorded before the run; the
re-check on the resuming account; the argv through `docker exec -w` with no
shell; the log's format; the resume of the phase's own session and the cycle
after it).

  n, verdict, comment=None, by="operator") -> CycleOutcome` and its refusals

## Why this way

- One function the CLI calls and the board service's worker will call, so
  moving the verdicts to Approvals changes who calls it, not what it does.
- The verdict is recorded before the command runs: a crash after that can
  leave a verdict with no resume, never a command run twice.
- The re-check is step 3's own `check`, so the rules at the verdict are the
  ones at filing, against what is running now.
- The argv is a list from the envelope to `docker exec`; nothing joins it
  into a string a shell could read.
- The resume reuses the cycle's own pieces, so the gates, the revisor rounds
  and a request filed again behave as in a fresh cycle.
- The log sits in the scratch dir, so a resumed phase told the path can read
  output past the cap.

## Pending

- A resume held after the verdict (its account not idle) leaves the verdict
  recorded, so a second verdict is refused; the phase has to be run again
  with `run-phase`, in a fresh session.
- The timeout kills the `docker exec` client, not the process inside the
  container.
- A service command runs in the service's own workdir; the `cwd` only lets
  compose find the project.
- The resume has no write window, as `run-phase` has none.
- A resume on another account than the phase's (left to the board service's
  worker), *Allow* and the allowlist (step 5), the Approvals card (step 6).
- `--permission-prompt-tool` is still deferred (ADR 118).

## Ruled out

- Running the argv through a shell, or joining it into one string.
- Running the command before recording the verdict.
- Numbering refused requests so a verdict could reach them.
- Starting a fresh session instead of resuming the phase's.
- A verdict per request rather than per block: the phase resumes once.
