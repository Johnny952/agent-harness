# T-177-S2 — `nullable_model` control on the Settings screen

Front half of debt T-175-D1; the decision is `docs/decisions.md` ADR 444, over
the server contract of ADR 441.

## What changed

- `front/src/routes/models.tsx`: `escalated_model` joins `MODEL_KEYS`, and
  `SettingControl` has a `nullable_model` branch next to the `string` one: a text
  `Input` on the `settings-models` datalist, with the hint "Empty saves null: no
  escalated model. Reset falls back to config.yaml." under it. Save sends the
  trimmed text, or `null` when that is empty.
- `initialDraft` and `SettingValue` are unchanged: a null value already starts as
  an empty field and renders as `not set`. Reset comes from `RowButtons` as for
  any overridden row.
- `front/src/routes/-models.test.tsx`: an `escalated_model` row in `ROWS`
  (source `override`, so Reset shows) and a `the nullable_model control` block:
  input shown not the fallback, null starts empty and reads `not set`, empty and
  blank save `null`, a padded model ID saves trimmed, Reset sends a DELETE.

## Why this way

Whitespace-only saves `null` rather than an error (ADR 444 decision 2): the
writer refuses `'  '`, so the front trims first instead of showing a 422 for
something the operator means as "off". No client-side model validation, as with
the `string` kind: the writer judges it.

## Ruled out

A separate "turn off" switch beside the field: more state, and an empty field
already means off.
