# T-105-S1: the action forward

Contract: `docs/decisions.md` ADR 157, on ADR 151 and ADR 136.

## What was built

- `front/src/lib/api/server-env.ts`: `BOARD_ACTIONS_TOKEN`, trimmed, `null` when
  unset, empty or whitespace. Never a boot refusal, never logged or answered.
- `front/src/lib/api/forward.ts`:
  - `POST /api/tasks/<id>/start` and `POST /api/actions/<id>/cancel` go to the
    same paths on `BOARD_SERVICE_URL` with `Authorization: Bearer
    BOARD_ACTIONS_TOKEN`. Matched in `boardTarget` by method and path, so other
    methods keep their old answers (GET 404, PUT/PATCH/DELETE 405).
  - Order in `forwardBoard`: the three CSRF checks, 503 for a missing token, 503
    for a start with no `CONSOLE_PROJECT`, 413, then the body rules.
  - `/api/actions` with `limit` joins `FORWARDED` (thirteen routes now); no
    `?project=`, the queue is the hive's.
- `front/README.md`: env table rows for `BOARD_SERVICE_URL` and
  `BOARD_ACTIONS_TOKEN`, count fixed.
- `forward.test.ts`: each pair to the exact path with the bearer, both 503s with
  nothing sent, the project, browser `project` refused, other methods, the token
  in no response, `/api/actions`.

## The project choice

A start's `project` is the console's `CONSOLE_PROJECT`, never the browser's. The
browser body may hold only `note` (string, null or absent); any other key,
`project` included, is a 400, not silently ignored, so a client that thinks it
picks the project finds out. The upstream body is rebuilt as
`{"project": CONSOLE_PROJECT, "note": note ?? null}`. A cancel sends `{}`
whatever the browser sent. `CONSOLE_PROJECT` unset is a 503 naming it, for start
only.

## Ruled out

- Passing the browser body through: it would let a browser name the project.
- Dropping a browser `project` silently: hides a client bug.
- Validating action or task ids in the console: the board-service does; the id is
  only decoded and re-encoded, as the other routes do.

## Not done

Nothing sets `BOARD_ACTIONS_TOKEN` for the console in compose yet (ADR 142
step 5), so both routes answer 503 until it does. The 401 pass-back drops
`WWW-Authenticate`, like every pass-back here.
