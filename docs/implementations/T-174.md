# T-174: the origin word at the end of a debt row's what

Decision: `docs/decisions.md` ADR 426.

## Cause

No code writes the word. `debt.declared_row` and `debt.filing_note` pass the
declaration's `what` unchanged; the auditor model writes the rows by hand and
copied the habit from earlier rows.

## What was done

- `dispatcher/debt.py` `filing_note`: one sentence tells the auditor to end the
  `what` cell at the what and put the origin on the entry file's `**Origin:**`
  line, never in the row. This is the source fix.
- `dispatcher/debt.py` `backlog_item`: `_ORIGIN_TAIL_RE` strips a trailing
  ` Introduced` or ` Found` (case-sensitive, last word only) from the what, so
  title and goal are clean for the rows already in the index.
- Tests in `tests/dispatcher/test_debt_backlog.py`: the note's sentence, a
  `declared_row` keeping its what verbatim, stripping for both words, and
  mid-text or lowercase uses left alone.
- `docs/debt/log.md`: a T-174 paragraph names the 25 ids.

## Ruled out

- Rewriting the 25 rows: the index is append-only (ADR 297), so the debt log
  stands in, as the task allowed.
- Changing `index_fingerprints`: left as is (ADR 426).
- Retitling backlog items already filed: out of scope, for the operator.
