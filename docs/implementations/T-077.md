# T-077 — *allow* and the per-project, per-role allowlist (command-requests step 5)

Decisions: `docs/decisions.md` ADR 121 (*allow* runs once and writes a
standing entry; the exact command by default and `--prefix N` as the
operator's choice; what a pattern and a prefix may hold; the list under
`state_dir`, out of every agent's reach; the merge into a phase's flags and
the re-check of each entry; `dispatch allowlist` to list and revoke).

## What was built

- `dispatcher/allowlist.py`: `pattern_for(argv, prefix=None)` and its
  refusals as `AllowRefused`; `pattern_problems`, `prefix_problems`,
  `stored_pattern_problems`; the file at `<state_dir>/allowlists/<slug>.json`
  with `entries`, `add` (deduplicating) and `revoke`, under an `flock` and an
  atomic replace; `merged_allowed_tools(state_dir, slug, role, base)`, which
  puts the global list first, adds the role's entries with no repeat, and
  skips and logs any entry that no longer passes.
- `dispatcher/command_run.py`: the `allow` verdict. `run_command_request`
  takes `prefix`, refuses it with any other verdict, refuses *allow* for a
  request not resolved to kind `agent` or whose argv or prefix cannot stand
  as a pattern, all before the verdict is recorded; then writes the entry,
  records `allowed` on the verdict, runs once and resumes. `run_prompt` adds
  a line naming the pattern; `resume_command_verdict` treats a held *allow*
  as a held *run*.
- `dispatcher/dispatcher.py`: `_phase_permission_flags(cfg, role, slug)`
  merges the project's list; `dispatch_phase` passes the slug to it and to
  each retry (`_resume_missing_handoff`, `_shrink_over_budget`, `_run_gates`,
  `_refuse_review_writes`), so a resume gets the same list.
- `dispatcher/cli.py`: `command-verdict ... allow [--prefix N]`; the
  `allowlist --project <slug> [--role R] [--revoke PATTERN]` subcommand.
- Tests: `tests/dispatcher/test_allowlist.py`, with the fake
  `dispatch_phase`, the fake `docker exec` and a fake `exec_claude` — *allow*
  exact and with a prefix (entry written with its source, one run, the
  prompt's line, `allowed` on the verdict); the same pattern twice kept
  once; every refusal end to end (an argv with a space, dangerous prefixes,
  a prefix too long, a `dind` command, a prefix with *run*) leaving no file,
  no run, no verdict and no phase; `pattern_for` on the denylisted, the
  dangerous heads, launchers, quotes, parentheses, `:*`, metacharacters and
  empty tokens; the merge (global first, no repeat, only the matching
  project and role, a bad entry skipped and logged, a corrupt file adding
  nothing); `_phase_permission_flags` with and without a slug; a phase and a
  resume given the merged list; a held *allow* resumed with no second run or
  entry; the CLI's `--prefix`, its parser errors, the listing and revoke.
  In `tests/dispatcher/test_command_run.py` the unknown verdict is now
  `approve`, since `allow` is one.
- Docs: ADR 121; in `docs/plans/command-requests.md`, *Built 2026-10-18*
  notes under decision 6 and step 5, and an *Answered* note under the open
  question on prefixes.

## Why this way

- The list is in the dispatcher's own state volume because every place a
  phase can write (its worktree, the hive) would let it grant itself.
- Exact is the default because a prefix lets the phase append anything; the
  prefix is a count of the argv's own tokens so it cannot name more than the
  operator saw.
- The merge is in `_phase_permission_flags`, the one place every call that
  runs a role's own work already gets its flags, so no path misses it.
- Each entry is checked again when read, so a hand edit or a rule tightened
  later cannot carry an entry past decision 7.

## Pending

- The Approvals card (step 6) offering *allow* and the prefix choice.
- A prefix on a project's own runner (`npm test:*`, `uv run pytest:*`) runs
  scripts and test files the phase can edit; that is inherent in a prefix and
  left to the operator's choice (ADR 121, *Consequences*).
- The never-head and launcher lists are hand-kept; a launcher not on them is
  judged as an ordinary command.
- Exact entries follow the filing rules only, so `Bash(git)` or an exact
  interpreter call can be allowed when filing accepts it.
- A resume on another account than the phase's is still not built.

## Ruled out

- A free-form pattern on the CLI.
- Keeping the list in the hive or the project's repo.
- Writing an entry into the global `allowed_tools`.
- Allowing a `dind` or `service` command.
