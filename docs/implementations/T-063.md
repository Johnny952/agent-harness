# T-063: Basic auth on the console through Caddy

The rule is `docs/decisions.md` ADR 103; this is the plan, and the implementador
records what was built under *What was built* below.

## Plan

1. `docker/caddy/Caddyfile`. In the header comment add the two variables
   (`CONSOLE_AUTH_USER`, fallback `console`; `CONSOLE_AUTH_HASH`, bcrypt from
   `caddy hash-password`, no fallback, ADR 103). In the site block, right
   above `reverse_proxy console:8790`, with tabs:
   ```
   	# ADR 103: every proxied request asks for this. No hash, and the account
   	# line is the user alone, which basic_auth refuses: Caddy will not load.
   	basic_auth {
   		{$CONSOLE_AUTH_USER:console} {$CONSOLE_AUTH_HASH}
   	}
   ```
   No matcher on `basic_auth`, no realm argument, no second site block, no
   `handle` or `route`. Keep the comment free of the grepped tokens the test
   counts (`basic_auth`, `reverse_proxy`) except where they are the directive:
   say "the directive below" in comments.
2. `docker/compose/docker-compose.yml`, the `caddy` service only: two
   environment entries after `ACME_EMAIL`:
   ```yaml
       - CONSOLE_AUTH_USER=${CONSOLE_AUTH_USER:-console}
       - CONSOLE_AUTH_HASH=${CONSOLE_AUTH_HASH}
   ```
   and one sentence in its comment block: the console's Basic auth, ADR 103;
   with no hash Caddy refuses its config and the rest of the stack still
   starts. Touch no other service and no other compose file.
3. `scripts/configure.sh`, the .env writer only: after the two TLS comment
   lines, append commented lines (all `echo "# ..."`, so `_env` in
   `tests/scripts/test_configure.py` still skips them):
   - `# The console's Basic auth through Caddy (docs/decisions.md ADR 103).`
   - `# Required: with no hash Caddy refuses to start. Make one with`
   - `#   docker run --rm -it caddy:2.10.2 caddy hash-password`
   - `# and paste it in single quotes: compose expands a $ in anything else.`
   - `# CONSOLE_AUTH_USER=console`
   - `# CONSOLE_AUTH_HASH='$2a$14$...'`
   Inside bash double quotes the `$` must be escaped (`\$2a\$14\$...`) so the
   file gets the literal text. No prompt. The image tag in the command is the
   one the `caddy` service pins.
4. `tests/integration/test_compose_invariants.py`:
   - `test_caddy_gets_no_socket_and_no_state`: the exact environment dict
     gains `CONSOLE_AUTH_USER: ${CONSOLE_AUTH_USER:-console}` and
     `CONSOLE_AUTH_HASH: ${CONSOLE_AUTH_HASH}`.
   - New `test_the_caddyfile_asks_for_basic_auth_before_the_proxy`: the text
     has exactly one `basic_auth` and one `reverse_proxy`; it matches
     `basic_auth\s*\{\s*\{\$CONSOLE_AUTH_USER:([^}]*)\}\s+\{\$CONSOLE_AUTH_HASH\}\s*\}`
     (no matcher, no hash default); the user fallback equals compose's `:-`
     default, parsed the way the HARNESS_DOMAIN test does, and is `console`;
     the directive sits after the `{$HARNESS_DOMAIN:` site line and before the
     `reverse_proxy` line; and the site address appears once.
   - New `test_only_caddy_reads_the_console_credential`: across the three
     compose files, `_variables_read_by` finds `CONSOLE_AUTH_USER` and
     `CONSOLE_AUTH_HASH` on the plain file's `caddy` and on no other service;
     the hash's suffixes are `{""}` (bare: compose warns, does not refuse);
     `DASHBOARD_PASSWORD_HASH` is not read by `caddy`.
   - New `test_configure_writes_the_console_credential_commented`: read
     `scripts/configure.sh` as text; it holds `# CONSOLE_AUTH_USER=`, a
     `# CONSOLE_AUTH_HASH='` line (single quote right after `=`), and
     `caddy hash-password` preceded by the exact `image` of the plain file's
     `caddy` service; it never writes an uncommented `CONSOLE_AUTH_` line.
   - New `test_compose_passes_a_quoted_bcrypt_hash_through_intact(tmp_path)`:
     skip unless `shutil.which("docker")` and `docker compose version` exits
     0. Write an env file under `tmp_path` holding
     `CONSOLE_AUTH_HASH='$2a$14$Zkx19XLiW6VYouLHR5NmfOFU0z2GTNmpkT/5qqR7hx4IjWJPDhjvG'`
     (Caddy's documented example hash; a letter follows the last `$`, so an
     unquoted value would be mangled). Run
     `docker compose -f <COMPOSE_DIR>/docker-compose.yml --env-file <that> config --format json`
     with an `env=` copy of `os.environ` minus every `CONSOLE_AUTH_*` key;
     assert exit 0 and `services.caddy.environment.CONSOLE_AUTH_HASH` equals
     the hash byte for byte and `CONSOLE_AUTH_USER` is `console`. Second case
     in the same test, an env file with no `CONSOLE_AUTH_*`: exit 0 and
     `api` and `console` both in `services` (compose does not refuse). Not
     parametrized; none of these is called from `test_configure.py`.
   Every existing invariant stays as it is.
