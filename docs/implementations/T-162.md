# T-162: a signed-in person on accept/drop and on actions

Decision: `docs/decisions.md` ADR 387. Resolves debt `T-150-D1`.

## What

All in `board_service/app.py`:

- `_http`: `backlog_accept` takes `_person()` as its role, so a drop's
  `dropped_by` (and an accept's `by`) names the signed-in person; no session
  stays `operator`.
- Every `actions.create` / `check_new` in `create_app` passes
  `actor=_person()` instead of the literal `"operator"`.
- `epic_start` / `epic_stop` take an `actor` keyword (default `OPERATOR`);
  their routes pass `_person()`.
- `task_start` admitted only a turn whose actor was `operator`; now it refuses
  a turn whose actor is not a string or is `thread`, so a signed-in person's
  turn still starts a task. Same error text.

A proposal's `source` is untouched: it is a closed enum (ADR 387), so the
console proposal still records `operator`.

## Tests

`tests/board_service/test_person_actor.py`: signed-in drop, start, approve
and turn; no-cookie stays `operator`; a `thread` turn is still refused.

## Ruled out

Putting a name in `source`: its readers filter on the enum. A `proposed_by`
field is a separate change (proposed as debt).
