# T-125-S2 — `POST /api/tasks/<id>/approve`

Design: `docs/decisions.md` ADR 258 decision 1, narrowed by ADR 267.

## What was built

- `dispatcher/tasks.py`: `VERDICT_KINDS_BUILT` is `("comment", "approve")`.
  `record_verdict` refuses an approve on `conflict` (the words name *resolve
  conflict*); a comment is still taken there. A merged task refuses both.
- `dispatcher/actions.py`: `check_new`, a public wrapper of `_new_record` that
  validates and writes nothing.
- `board_service/app.py`: `http_approve`, and `review_verdict` refusing
  `approve` with a 400 naming `POST /api/tasks/<id>/approve`.
- Tests: `tests/board_service/test_approve_route.py` (new), plus cases in
  `test_writes.py`, `tests/dispatcher/test_board_writes.py`,
  `tests/dispatcher/test_actions.py`.
- Docs: `docs/plans/review.md` step 4 and its Status intro, `docs/README.md`.

## Why this way

The route runs ADR 151's guards, then the unknown-field check, then
`actions.check_new`, then `record_verdict`, then `actions.create`. Checking the
action record before the line means a malformed body never leaves a line
behind; only a duplicate approve (409) or an unwritable queue (503) can.
Those answers carry `verdict`, so the console can say the verdict was recorded
and nothing queued. A 201 carries `{verdict, action}`.

## Ruled out

- Reusing `_action`: its refused answer is `{"error"}` alone.
- Going through `review_verdict` for the line: it now refuses approve, and
  the operator-as-author is the route's own.
- Making `create` write the line too: the action queue holds no hive.
- Rolling the line back on a refused action: ADR 258 keeps it.
