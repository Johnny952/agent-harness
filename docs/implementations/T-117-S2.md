# T-117-S2: the write-check push probe on git 2.39

## What was done

The probe's commands were run in the agent container (git 2.39.5): a writable
bare remote exits 0 (`[new branch]`, `Done`); a refusing transport exits 128; a
remote that is not there exits 128. The output and the decision are in
`docs/decisions.md` ADR 217. `_probe_push` reads the exit status only, and that
holds on 2.39.5, so its parsing did not change; only its docstring now says it
was measured on 2.39.5 too.

New test: `test_check_reads_a_refusal_real_git_meets_at_receive_pack` in
`tests/dispatcher/test_project_setup.py`. It runs real git against a stand-in
`GIT_SSH_COMMAND` that writes GitHub's read-only message and exits non-zero, so
git exits 128 and `check_remote` reports `writable is False`. The existing
writable test already runs real git, so the suite covers both cases on whatever
git runs it.

## Ruled out

- A pre-receive hook as the refuser: a dry-run push never runs the remote's
  hooks (exit 0), so it cannot stand for a refusal.
- Parsing the porcelain output: the exit status already separates the cases.

## Not covered

git 2.43 was not available here; its side rests on ADR 214's measurement.
