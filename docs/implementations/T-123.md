# T-123: run-queue --parallel up to the pool's phase slots

Decision: `docs/decisions.md` ADR 252 (amends ADR 83 decision 1).

## What

- `dispatcher/cli.py` `_run_queue`: the cap is now
  `sum(a.max_concurrent_phases for a in cfg.accounts)`; the error names the
  slot count. `--parallel` help text updated to match.
- `docs/plans/projects.md` *Parallel work*, Decisions 5: a *Widened* line.
- `tests/dispatcher/test_parallel_queue.py`: a parametrized cap test (3 / 4
  on one account, 3 / 4 on 2+1, default 2 / 3) and a queue test where one
  account with two slots runs two cycles at once.

## Why this way

`dispatcher/queue.py` needed no change: `wait_for_account` goes through
`core.pick_idle_account`, which already lists busy accounts with a free slot,
and `dispatch_phase` claims with `capacity=_capacity_for(cfg, account)`.

The multi-slot test restores the real `pick_idle_account` (`_REAL_PICK`,
captured at import) and has each fake cycle claim the account with its real
capacity, so a capacity-1 regression makes the second cycle wait and the
barrier / `_no_sleep` fail the test.

## Ruled out

- Editing `queue.py`: nothing there assumes one cycle per account.
- Touching `docs/plans/autonomy.md`: outside the Surface (declared as debt).
