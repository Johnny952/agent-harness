# T-125-S1: the `approve` action kind and its worker handler

Spec: `docs/decisions.md` ADR 258 (decisions 2, 4, 5, 6, 7), narrowed by ADR 264.

## What was built

- `dispatcher/actions.py`: `Kind("approve")` with `_validate_approve` (task and
  project required, `params` is exactly `{commit}`, a hex hash by `tasks._COMMIT_RE`),
  serial key `base:<project>`, `spends_quota` false, recovery `interrupt` with
  ADR 258's text word for word; `approve` joins `_ONE_PER_TASK`.
- `dispatcher/dispatcher.py`, beside `record_merge`: `ApprovalOutcome` and
  `approve_reviewed(cfg, task_id, slug, commit)`, which never raises. In one
  `_base_lock(..., "approve")` window and one read_owner/restore_owner window:
  `_stale_reason`, `pre_merge_check`, `docker_exec.merge_task_branch`,
  `head_commit`, `push_base`. After the window, `record_merge` and
  `learnings.drop_promoted`. It writes no comment; it returns the text.
- `dispatcher/worker.py`: `_approve` writes the one `dispatcher` comment
  (a refused write is logged) and finishes the action: `done` for `merged` and
  `merged_not_pushed`, `failed` otherwise with the comment's first line as
  `error`; `result` is `{outcome, commit, merge_commit, push}`. Registered in
  `HANDLERS`.

## Why this way

- `_consider` needed no change: it takes a `ProjectLock` only for `project:`
  keys and checks the account only when `spends_quota`, so `base:<p>` waits on
  neither; a busy key waits as `project` already.
- The stale check calls `docker_exec._rev_parse` (private) because
  `docker_exec.py` is outside the Surface; tests fake it, since `fake_git` does
  not.
- `conflict` vs `not_run` for a failed pre-merge is read from the task status
  after `pre_merge_check` (it writes `conflict` itself), as ADR 264 says.
- A stale comment names the branch's tip only when it was read; for the task-file
  reasons (no file, merged, wrong status) the branch is not read at all.

## Ruled out

- Reusing `_auto_approve_and_merge`: its merge is gated by `auto_approve.decide`
  and it writes its note into the task body; an approve needs neither.
- Taking the project `flock` (ADR 258, 3).
- A new `waiting` value for a busy base key.
