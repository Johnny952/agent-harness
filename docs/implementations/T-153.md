# T-153 — A backup before every approve merge

Builds `docs/decisions.md` ADR 342; resolves `docs/debt/T-147-D1.md`.

## Plan (arquitecto)

1. **`dispatcher/backup.py`**: add `before_merge(hive_root, state_dir,
   environ, *, now) -> str`. It calls `settings_from_env(environ)` then
   `backup(...)` and returns `backup before the merge: <name>`; it catches
   `BackupError`, `ProjectBusy` and `OSError` and returns
   `no backup before the merge: <the exception's text>`. Never raises.
2. **`dispatcher/dispatcher.py` `approve_reviewed`**: new keyword
   `before_merge: Callable[[], str] | None = None`. Call it once under the
   base lock, after `pre_merge_check` passed and before
   `docker_exec.merge_task_branch`; log the line at info; keep it in a local
   that the `out` closure appends as the last line (`\n<line>`) of every
   comment built after the call. Do not import `backup` here.
3. **`dispatcher/worker.py` `_approve`**: pass
   `before_merge=lambda: backup.before_merge(context_transfer.hive_root(cfg.hive_tasks_dir), cfg.state_dir, os.environ, now=_utc_now())`.
   `backup` imports `worker`; import `backup` inside `_approve` if a
   module-level import cycles.
4. **Compose, both files** (`docker-compose.yml`, `docker-compose.coolify.yml`),
   `worker` service only: volume `${BACKUP_DIR:-../../.data/backups}:/backups`
   and `environment:` `BACKUP_DIR: /backups`, `BACKUP_KEEP: ${BACKUP_KEEP:-}`.
   Update the comment above `worker` ("its mounts are the dispatcher's,
   copied") to say plus the backup mount, ADR 342.
5. **Tests.**
   - `tests/dispatcher/test_backup.py`: `before_merge` returns the copy's line;
     the unset-`BACKUP_DIR` line; a held project lock gives the busy line and
     writes nothing.
   - `approve_reviewed`'s existing tests (grep `approve_reviewed` under
     `tests/dispatcher/`): `before_merge` is called once on a merge, never on
     stale or failed pre-merge check, and its line ends the comment.
   - `tests/dispatcher/test_worker.py` *approve* section: the `Approve` fake's
     `__call__` gains `before_merge=None` and records that one was passed.
   - `tests/integration/test_compose_invariants.py`
     `test_the_worker_is_the_dispatchers_mounts_behind_its_own_profile`:
     worker volumes are the dispatcher's plus the backup mount, its
     environment the dispatcher's plus the two keys; add `BACKUP_KEEP` to
     `test_an_optional_variable_carries_an_empty_default`'s list.
6. **Docs.** Root `README.md` *Backups and restore*: replace the "documented
   follow-up" paragraph with what ADR 342 does (a copy before each approve
   merge, refused while a cycle runs, counted by `BACKUP_KEEP`); `docs/README.md`
   *Modules* rows for `dispatcher/backup.py` and `dispatcher/worker.py` gain
   "ADR 342".

## Implementation (implementador)

Built as planned, steps 1-6.

- `backup.before_merge` wraps `settings_from_env` and `backup`; it returns one
  line and catches `BackupError`, `ProjectBusy`, `OSError`.
- `approve_reviewed` takes keyword-only `before_merge`, called once under the
  base lock after `pre_merge_check` passed. Its line is kept in a list the
  `out` closure appends as the comment's last line, so every outcome after the
  copy (merged, not pushed, merge refused) carries it. A raising callback is
  turned into the same `no backup before the merge:` line; the merge never waits.
- `worker._approve` imports `backup` locally (backup imports worker) and builds
  the callback from `hive_root(cfg.hive_tasks_dir)`, `cfg.state_dir`, `os.environ`.
- Both compose files: `worker` gets `BACKUP_DIR=/backups`, `BACKUP_KEEP` and
  the `${BACKUP_DIR:-../../.data/backups}:/backups` mount, last in its volumes.
- Tests: three `before_merge` cases in `tests/dispatcher/test_backup.py`;
  three in `tests/dispatcher/test_dispatcher.py` (order and last line, raising
  callback, no call when stale or the check fails); one in `test_worker.py`
  (the callback is handed over and calls `backup.before_merge`); the compose
  invariant now expects the extra mount and env, and `BACKUP_KEEP` joined the
  empty-default list.
- Ruled out: waiting for locks (would deadlock on the worker's own held locks);
  importing `backup` into `dispatcher.py` (keeps the core free of the cycle).
- Not run: `docker compose config` (docker refused in phases); only the YAML
  invariant tests check the compose files.

## Out of scope

Nightly scheduling (stays a host crontab line, ADR 327); a copy before the
automatic approve or `dispatch merge-task` (ADR 342 *Consequences*).
