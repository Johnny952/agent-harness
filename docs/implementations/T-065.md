# T-065 — the config-writer service (console-config task 2)

Decisions: `docs/decisions.md` ADR 75 parts 3–4, ADR 106, ADR 109 (network,
port, token holders, Coolify) and ADR 110 (edges, root, `config.d`).

## What was built

- `config_writer/app.py`: `create_app(config_path, token)` and `main(environ)`
  (exit 2 naming `CONFIG_WRITER_TOKEN`). Routes `GET /settings`,
  `PUT`/`DELETE /settings/<key>`. Rows come from `CONFIG_KEYS`; roles come from
  `PHASE_ROLES`, `DRAFT_ROLE` and `MAPPER_ROLE`.
- `config_writer/Dockerfile` (root, no `USER`, ADR 110.8); `pyproject.toml`
  `include` gains `config_writer*`.
- Both compose files: `config-writer` service, `console_net`, console and
  caddy moved onto it, api on both, `config.d` `:ro` in dispatcher and api,
  console given `CONFIG_WRITER_URL` and `CONFIG_WRITER_TOKEN`.
- `scripts/configure.sh`: `CONFIG_WRITER_TOKEN=$(gen_token)`; `mkdir -p
  config.d` beside `--config-out`; `console_net:` in the Coolify render heredoc.
- Tests: `tests/config_writer/test_app.py` (40 cases), new invariants in
  `tests/integration/test_compose_invariants.py`, `tests/scripts/test_configure.py`.
- Docs: README steps 1 and 4 and the Coolify list, `config.example.yaml`
  comment, `docs/README.md` rows, *Built* note on task 2 of the plan.

## Why this way

- The write sequence is ADR 75 part 3 under `flock` on `overrides.lock`: read,
  revision check, parse check, candidate temp validated by `load_config`,
  `.prev` by temp and replace, `os.replace`, then `_append_change`. The append
  is its own function so a test makes it raise; on `OSError` the old bytes are
  put back (or the new file unlinked on a first save) and the answer is 500.
- `load_config` can raise `KeyError`, `TypeError` and `yaml.YAMLError` as well
  as `ValueError` (a `config.yaml` without `accounts`), so `LOAD_ERRORS` is the
  wider tuple; `GET` never answers 500 for a bad file.
- A DELETE of a key the file holds is accepted whatever its class (ADR 110.1);
  the check runs under the lock, after the revision and parse checks.
- No `fsync`, as in `docs/learnings/atomic-writes-copy-state-machine.md`.
- Flask's own 404/405 stay HTML (`docs/learnings/flask-answers-404-and-405-in-html.md`).

## Coolify

Read, not run (ADR 109 *Coolify*): the Coolify file has no proxy labels or
network; the domain is set on `console` in Coolify's UI and Coolify attaches
its own per-resource network, so moving `console` off `ia_harness_net` should
not break its proxy. If that network is attached to every service, agents share
it with the console on Coolify whatever `console_net` says. Settle it with
`docker network inspect` on a deploy. The render heredoc in `configure.sh` needed
`console_net:` too.
