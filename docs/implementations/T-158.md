# T-158 — `BACKUP_DIR` on the `dispatcher` service

Resolves T-157-D1. Decision: `docs/decisions.md` ADR 360.

## What
- `docker/compose/docker-compose.yml` and `docker-compose.coolify.yml`: the
  `dispatcher` service gets `BACKUP_DIR=/backups`, `BACKUP_KEEP=${BACKUP_KEEP:-}`
  and the `${BACKUP_DIR:-../../.data/backups}:/backups` mount, the same as the
  worker. The worker's mounts and environment are now equal to the dispatcher's.
- `scripts/backup.sh`: exports an absolute `BACKUP_DIR` (`realpath -m`) and
  runs `docker compose run --rm dispatcher ... backup` with no `-v`/`-e`;
  compose interpolates `BACKUP_DIR` and `BACKUP_KEEP` from the environment.
- `scripts/restore.sh`: its read-only mount moves to `/restore`, because a
  `run -v` onto `/backups` would collide with the service's own mount.
- Tests: the compose invariant now asserts worker == dispatcher; the script
  tests assert no `-v`/`-e`, the exported absolute path (also for a relative
  `BACKUP_DIR`) and the `/restore:ro` mount.
- `README.md` Backups and restore, `docs/README.md` `dispatcher/backup.py` row.

## Why this way
The mount belongs to the service so every verb that runs through it
(`run-task`, `run-queue`, `merge-task`) takes the pre-merge copy without each
caller remembering a run-line flag. `realpath -m` because compose resolves a
relative mount against the compose file, not the caller's directory.

## Ruled out
- Keeping `-v`/`-e` on the run line: duplicates the service mount on one path.
- Mounting restore at `/backups:ro`: same container path as the service mount.

## Not verified
`docker compose config` cannot run in a phase; the compose change is checked by
the yaml invariant tests only. `realpath -m` is GNU coreutils.
