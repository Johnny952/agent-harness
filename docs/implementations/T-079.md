# T-079 — The command-request card in Approvals (command-requests step 6)

Decisions: `docs/decisions.md` ADR 123. It covers a card that only reads,
the order of its parts, the argv as quoted text, the agent's reason marked as
the agent's, the CLI lines with no button, refused requests listed apart, and
the forward entry that makes the read reachable.

## What was built

- `front/src/components/console/command-requests.tsx` (new):
  `CommandRequestsSection` holds the state filter, the read, `WarningBanner`,
  and the error, loading and empty states. `CommandRequestCard` shows, in
  order: argv, target, then state, role, task link, `#n`, project and
  `filed_at`, then the verdict, the CLI lines and the agent's reason.
  `RefusedRow` shows a refused request apart.
- `front/src/routes/approvals.tsx`: renders the section under the page
  header, above the mock approvals, which are not changed.
- `front/src/lib/api/types.ts`: `COMMAND_REQUEST_STATES` and the
  `CommandRequest*` / `RefusedCommandRequest` / `CommandRequests` types, as
  T-078 serves them.
- `front/src/lib/api/client.ts`: `getCommandRequests({project, state})`
  through `readEnvelope`. The docstring now counts ten real reads.
- `front/src/lib/api/queries.ts`: `commandRequestsQuery(state)`, keyed by the
  state, polled at `POLL_MS`.
- `front/src/lib/api/forward.ts`: `/api/command-requests` in `FORWARDED`
  (`project`, `state`), not in `PROJECT_SCOPED`. The count in its comments
  and in its rejection message goes from nine to ten.
- `front/src/lib/format.ts`: `argvLine`, which quotes each token the way
  `shlex.quote` does.
- Tests:
  - `front/src/routes/-approvals.test.tsx` (new) covers:
    - the order, and text instead of markup;
    - the reason marked;
    - CLI lines only when set, the `--prefix` hint, and no button on a card;
    - the verdict summary;
    - the api's order kept;
    - refused requests apart, with a dash for a missing argv;
    - the empty and error states, and warnings;
    - the filter sent as `?state=`, with only GETs to that read;

  - `front/src/lib/api/forward.test.ts` gains two tests: the forward copies

- Docs: ADR 123, and a *Built 2026-10-18* note under step 4's *Decisions*
  and under step 6 of `docs/plans/command-requests.md`.

## Why this way

- Read-only, because a verdict is a write and a docker exec, and the CLI
  already gives it with its own checks.
- The argv first and quoted, and the reason last and marked, so the operator
  judges the command before the agent's pitch, and token boundaries cannot
  hide.
- Only the lines the api set, so the card never offers a verdict the CLI
  would refuse.
- Not project-scoped in the forward, because the api is hive-wide like
  `/api/roadmap`.
