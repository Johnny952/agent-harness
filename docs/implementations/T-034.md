# T-034 — the console says when a task has no description

This task resolves `docs/debt/T-033-D1.md`: `Task.description` in
`front/src/lib/api/types.ts` becomes `string | null`, which is what
`/api/tasks` and `/api/tasks/<task_id>` serve, and the three places the
console reads it each say what a task with no description shows. Nothing
under `observability/` or `dispatcher/` changes, and no ADR is written:
`docs/decisions.md` is outside this card, so the choices a later task could
undo are recorded here, under *Decisions*.

The sections down to *Verification the implementador owes* are the
arquitecto's design. The implementador corrects them where the tree turns
out different and lists those corrections under *Where the build differs
from the design*.

Nothing was different. Three things the card does not say:

1. **`description` is a `str` or `None` and nothing else.** It is not a
   frontmatter field served unvalidated: `read_description` returns
   `fh.read()` of a file opened as text, or `None`. So
   `docs/learnings/a-console-type-over-a-served-value-is-an-annotation.md`
   applies for the `null`, and there is no wrong-typed value to name with
   `Malformed`.
2. **`PageHeader`'s `subtitle` cannot take a node.** It is
   `string | undefined`, so the header cannot render `Absent` without one
   edit to `primitives.tsx`. See *Decisions*, 2.
3. **No test file exists for the task page.** `front/src/routes/` holds
   `-debt`, `-index`, `-learnings`, `-pool` and `-tail` tests and none for
   `tasks.$taskId.tsx`. The card says not to create a harness for it, so
   the header's `null` arm ships with no test. Declared as debt in the
   handoff.

## Decisions

1. **The absent form is `<Absent label="no description" />`, on both
   screens.** `docs/ui.md` *Absent, empty and broken are three different
   things* names `Absent`, and every call site in the console passes its
   own label where the default *not recorded* would not say which field
   (`no owner`, `no card`, `no rule`). The tile has no label beside the
   slot, so the label has to name the field.
2. **`PageHeader`'s `subtitle` is widened from `string` to `ReactNode`.**
   One line of `primitives.tsx`, the smallest edit that lets the header
   use the same component as the tile. Every other caller passes a string
   and is unaffected. The truthiness test on `subtitle` stays, so a string
   caller that passes `""` still draws no paragraph.
3. **The header says a description is absent only for a task that was
   read.** While the read is in flight, and for a card the api could not
   parse (`data: null`), `t` is `null` and the header has no subtitle, as
   today: "no description" there would be a claim about a task nothing has
   read.
4. **The search matches what the harness wrote, never the console's own
   words.** A `null` description contributes the empty string to the
   filter's haystack. So `null` does not match it, and neither does
   `no description`: the label is the console's sentence, not the task's.
   The task still matches by its id.
5. **The guard is `??`, so it covers `undefined` too.** A row with no
   `description` key at all is not something `_task` can serve, but the
   type is an annotation and the guard costs nothing extra.
6. **An empty `description.md` is left alone.** `read_description` returns
   `""` for an empty file, and the tile and the header draw nothing for
   it, as before. That is a recorded value and not `null`;
   `tasks.write_description` refuses a text with no `## Goal` and
   `## Done when`, so only a hand-made file reaches it. Not treated here:
   the card is about `null`.

## The edits

### `front/src/lib/api/types.ts`

In `Task`, replace `description: string;` with:

```ts
  /**
   * The text of the task's `description.md`, served verbatim. `null` when the
   * task has none: a render says so with `Absent`, never with an empty cell.
   */
  description: string | null;
```

Nothing else in the file moves. `TaskDetail` inherits it.

### `front/src/routes/index.tsx`

- Add `Absent` to the import from `@/components/console/primitives`,
  first in the list (it is alphabetical).
- The filter, in the `filtered` memo. A comment above the line, then the
  line with `?? ""` inside the literal:

  ```tsx
      // `description` is `null` for a task with no `description.md`, and a
      // template literal would spell that as the text `null` and match it.
      if (q && !`${t.task_id} ${t.description ?? ""}`.toLowerCase().includes(q.toLowerCase()))
        return false;
  ```

  The line is 94 columns, under prettier's 100.
- The tile, in `TaskCard`. The paragraph no longer fits one line, so it
  is written the way prettier breaks it:

  ```tsx
      {!dense && (
        <p className="mt-1 line-clamp-2 text-[11px] text-foreground/90">
          {task.description ?? <Absent label="no description" />}
        </p>
      )}
  ```

- `TaskCard`'s docblock says it is exported for the `depends_on` guard
  alone. Add one sentence: the description's absent arm is tested through
  the same export.

### `front/src/routes/tasks.$taskId.tsx`

`Absent` is already imported. Above the `return` of `TaskDetailPage`,
after `taskLearnings`:

```tsx
  // `null` is a task with no `description.md`, and the header says so. No
  // subtitle while `t` is `null`: nothing has read a task to say it of.
  const subtitle = t ? (t.description ?? <Absent label="no description" />) : undefined;
```

and the header takes `subtitle={subtitle}`. The parentheses around the
`??` are prettier's own form inside a conditional, as `lockedTask=` in
`front/src/routes/pool.tsx` has them.

### `front/src/components/console/primitives.tsx`

In `PageHeader`'s props, `subtitle?: string | undefined;` becomes
`subtitle?: ReactNode | undefined;`. `ReactNode` is already imported. The
body is not edited. Nothing else in the file is touched.

### `front/src/routes/-index.test.tsx`

`TASK` keeps its string; it still conforms. Two additions.

Imports: `fireEvent` and `screen` from `@testing-library/react`, `Route`
beside `TaskCard` from `./index`, and `renderRoute` from
`@/test/render-route`, as `front/src/routes/-debt.test.tsx` has them.

A describe block mounting the card, beside the existing ones:

```tsx
describe("a task the api served with no description", () => {
  it("says so on the tile instead of leaving it blank", () => {
    const { container } = render(
      <RouterContextProvider router={cardRouter()}>
        <TaskCard task={{ ...TASK, description: null }} now={NOW} dense={false} debtCount={0} />
      </RouterContextProvider>,
    );
    expect(container.textContent).toContain("no description");
    expect(container.textContent).not.toContain("null");
  });
});
```

A describe block mounting the screen, because the filter lives in
`BoardPage` and no component takes it as a prop:

```tsx
describe("the Board's search over a task with no description", () => {
  const task = (task_id: string, description: string | null): Task => ({
    ...TASK,
    task_id,
    description,
  });

  async function board() {
    await renderRoute(Route, "/", {
      "/api/tasks": { data: [task("T-101", null), task("T-102", "the pool screen")] },
      "/api/accounts": { data: [] },
      "/api/debt": { data: [] },
    });
    await screen.findByText("T-101");
  }

  it("does not match the text null", async () => {
    await board();
    fireEvent.change(screen.getByPlaceholderText(/^Filter tasks/), { target: { value: "null" } });
    expect(await screen.findByText("No task matches these filters")).toBeTruthy();
  });

  it("still finds the task by its id, and says it has no description", async () => {
    await board();
    fireEvent.change(screen.getByPlaceholderText(/^Filter tasks/), { target: { value: "T-101" } });
    expect(await screen.findByText("no description")).toBeTruthy();
    expect(screen.queryByText("T-102")).toBeNull();
  });
});
```

Without the `?? ""`, `T-101` matches `null` and the first test finds the
card and not the empty state. The file's header comment gains one
sentence saying the file also holds the description's absent arm and the
one route render that reaches the search.

Written blind: no phase runs `bun`, so the dispatcher's test gate is the
first run of these. The Board has not been mounted through `renderRoute`
before; the Debt, Learnings and Tail screens have, with the same shell.
If the gate is red on the route render and not on the assertion, read
`front/src/test/render-route.tsx` before changing the screen.
