# T-154-S1: `run_task_cycle` can enter at the implementador

Decision: `docs/decisions.md` ADR 354 (the task text says 348; the reserved
block was 354-356).

## What was built (`dispatcher/dispatcher.py`)

- `run_task_cycle` takes `start_at`, `start_round`, `on_held`. Validation
  (unknown role, `start_round < 1`, a later start with `changes_requested`)
  raises `ValueError` before `project_config` and `open_cycle`.
- `_LATER_STARTS` (implementador, revisor, auditor) all enter at the
  implementador of `start_round` (default 1) — revisor and auditor are narrowed
  to that, since the implementador's work is not resumable.
- The post-`open_cycle` body moved to `_run_cycle_body` so `run_task_cycle`
  has one outcome to read: a HELD outcome with `ctx.held_at` set calls
  `on_held(role, round)` once, inside the `try`, before `close_cycle`.
- A later start reads `context_transfer.read_handoff(..., "arquitecto")`; no
  envelope, or one that is blocked or a split, logs a warning naming the path
  and runs the normal path (mapping, arquitecto).
- `_cycle_from_arquitecto`'s tail is `_cycle_from_plan(ctx, ..., plan,
  start_round)`; the signature of `_cycle_from_arquitecto` is unchanged
  (`dispatcher/command_run.py` imports it).
- `_cycle_rounds(start_round=1)`: `first_round`, stale note on the first round
  run (both checks were `round_num == 1`).
- `CycleContext.held_at`, set in `run_phase` at both places `ctx.held` is set
  (the `may_start_phase` refusal and a fatal no-account) and by `_cycle_rounds`
  for the auditor with the last round run.

## Why this way

- `last_round = max(max_revision_rounds, first_round)` applies only when the
  rounds start past 1 (a resume or `start_round > 1`). Applying it always
  would turn `max_revision_rounds: 0` from zero rounds into one for the
  default call, which the task says must stay unchanged.
- The ValueErrors come before `open_cycle` so a bad call leaves no lock, no
  task file mark.

## Ruled out

- Resuming at the revisor or auditor: needs the implementador's result, which
  is not kept in a form a cycle can resume from.
- Passing the keywords from `dispatcher/queue.py`: out of scope; the next
  sub-task of T-154 records `on_held` and passes it back.

## Tests (`tests/dispatcher/test_dispatcher.py`, section start_at / on_held)

Default order unchanged; round-2 entry for each later role runs no arquitecto;
default `start_round`; stale note on the entered round (stubbed `BaseMove`);
fallback with a warning; three `ValueError`s with `open_cycle` forbidden;
`on_held` for each role, the caller's limit, and never on FINISHED.
