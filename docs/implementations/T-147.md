# T-147 — backup and restore (server-deployment step 8)

Contract: `docs/decisions.md` ADR 327 (backup) and ADR 328 (restore).

## What

- `dispatcher/backup.py`: `backup()`, `restore()`, `copies()`, `settings_from_env()`,
  `NEVER_COPIED`, `NOT_RECORDS`, `RESTORE_LINES`. `now` is a required parameter
  (no clock seam); the CLI passes `datetime.now(timezone.utc)`.
- `dispatcher/cli.py`: `backup` and `restore --from NAME|latest` via `_run_backup`;
  exit 2 on `BackupError`, 75 on `ProjectBusy` / `WorkerLocked`.
- `scripts/backup.sh`, `scripts/restore.sh`: run the verbs in the one-off
  `dispatcher` service with `BACKUP_DIR` mounted on the `run` line (no compose change).
- Tests: `tests/dispatcher/test_backup.py`, `tests/scripts/test_backup_scripts.py`.
- Docs: README *Backups and restore*, `docs/README.md` rows, plan step 8 *Built*.

## Why this way

- A copy is built under `.partial-<name>` and renamed, so a crash never leaves a
  counted copy. Locks are held across copy and rename.
- The credential guarantee is two layers: the only sources are the hive and state
  dir, and `fnmatch` over every path component drops credential shapes; symlinks
  are never followed. The test plants every shape at three depths in both roots.
- Restore syncs in place (temp file + `os.replace`) because both roots are mount
  points; extras are moved to `.pre-restore-<time>/`, nothing is deleted.
  `worker.acquire` plus all project locks refuse a restore mid-dispatch.
- Pruning excludes the copy just written even if older-named copies sort after it.

## Ruled out

Archives, an allowlist of subdirectories, a new pause flag, host Python, renaming
roots aside, deleting what the copy lacks (see ADR 327/328 *Ruled out*).

## Not done

- Nightly / before-merge scheduling: needs a `BACKUP_DIR` mount in the worker
  (compose change, flagged for approval). README documents a crontab line.
- The scripts were not marked executable (`chmod` was refused in the phase); the
  README invokes them with `bash`. Run `chmod +x scripts/backup.sh scripts/restore.sh`.
- The scripts were exercised only against a fake `docker`, never a real compose.
