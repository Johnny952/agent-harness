## Blocked: which return points mark, and why

`CycleContext` gains `took_lock: bool = False`. `run_phase` sets it when
`dispatch_phase` returned a result that is not `no_account`: that is the one
return that proves `tasks.acquire_lock` succeeded. A `LockHeldError` and a
`no_account` result leave it False.

A new `_mark_blocked(ctx)` in `dispatcher/dispatcher.py` is the one place
the rule lives. `run_task_cycle` calls it from a local `blocked()` beside
the existing `stopped()`, and `stopped()` returns `blocked()` when the run
is not held. It marks only when all of these hold:

- `ctx.took_lock` is set and `ctx.foreign_lock` is not.
- The task file exists (`FileNotFoundError` is the "no task file" case).
- The file's `owner` is None. Every phase of this run released the lock, so
  an owner there now is another run that took the task since, and
  `mark_blocked` would release that run's lock.

It never raises: any other failure is a warning, because the cycle already
ended and a traceback would hide the BLOCKED exit.

| Return in `run_task_cycle` | Marks | Why |
|---|---|---|
| `open_cycle` returned None | no | Refused before any lock; there is no context |
| The project's branch diverged | no | No phase ran, so `took_lock` is False; another run may own the task |
| The map bounced off another owner's lock | no | `foreign_lock` |
| A phase returned None, held | no | HELD is a wait, not a block |
| A phase returned None on a foreign lock | no | `foreign_lock`, even if an earlier phase of this run took the lock |
| A phase returned None because it failed | yes | It took the lock and the task cannot go on |
| The arquitecto's handoff is blocked | yes | The same, with its reasons in the body |
| The rounds ran out, or the revisor read a block | yes | The same |
| The auditor returned None, not held | yes | The same |

`run-phase` (`run_single_phase`) marks nothing. The card names
`run_task_cycle` only, and a single phase that failed is retried by the
operator who is driving the task by hand.

## Merge: one function both paths call

A new public `record_merge(cfg, task_id, outcome)` in
`dispatcher/dispatcher.py`, called by `_merge_task_branch` and by
`merge-task` whenever the outcome is not refused. A refused merge never
reaches it.

- It calls `tasks.mark_merged(hive, task_id, outcome.target)` when the
  outcome is `MERGED`, and on `UP_TO_DATE` only when the task file has no
  `merged` block yet. So a second `merge-task` keeps the first record's
  `at`, and one run after a merge whose record failed repairs it. That
  re-run is also how a task merged before this change gets its block.
- Then it calls the epic check, on both statuses, so a close that died is
  repaired the same way.
- It never raises. A task with no file, an unmigrated file or any other
  failure is reported and the merge stands: the cycle logs a warning, and
  `merge-task` prints the line to stderr and still exits 0, because the
  branch did land. The dependency gate then names the task as not merged,
  which is where the operator meets it.
- `merge-task` prints what was recorded, and the epic it closed if any.

## The epic check: `tasks.close_epic`

`close_epic(hive_dir, task_id) -> str | None` in `dispatcher/tasks.py`.
Returns the parent's id when it closed it, None otherwise. It closes only
when every one of these holds:

- the task's file has `epic`, and the parent's file exists and reads;
- the parent is `status: epic` (a `done` parent is left alone, unwritten);
- the task is in the parent's `split_into`;
- every id in `split_into` has a task file with a `merged` block.

Then it sets the parent's `status` to `done`, leaves its lock, body and
other fields, and ends in `_write_task_file`. A missing or unreadable file
answers None. An unmigrated parent raises `UnmigratedTaskError`, as from
every writer, and `record_merge` reports it.

## The gate in `open_cycle`

After the description has parsed and before a supplied one is written, so a
refused run writes no description. A task with no task file has nothing to
gate. A task file that will not parse raises as it does today from the
first phase's lock; only `FileNotFoundError` is caught.

The reasons are `tasks.unmet_dependencies(hive, task)` followed by a new
reader beside it, `tasks.epic_problems(hive, task)`. If there are any,
`open_cycle` logs one error line, `task <id> cannot start: <reasons joined
by "; ">`, and returns None. Nothing is marked: the card keeps a refused
task as it was, where section 4 of the split plan said "card blocked".

`epic_problems` returns `[]` for a task with no `epic`. Otherwise, one line
per problem:

- `epic` is not a task id; the parent has no task file; it cannot be read;
- the parent is not `status: epic`;
- the parent itself has `epic` (one level deep);
- the task is not in the parent's `split_into`, or that is not a list;
- `split_into` has fewer than two or more than four ids, or names one twice;
- an id in `split_into` has no task file, or its `epic` is not the parent;
- a child's `depends_on` names a task that is not one of its siblings.

The checks run on every `open_cycle`, not only the first: nothing records
that an epic was checked, and reading at most five files costs nothing.

## Tests

  not; a task with no `epic`, a parent that is `done`, a child not in

  target; a refused merge marks nothing; merging the last child closes the

closes an epic on its last child; a refused one marks nothing; a merged

## Ruled out

- **Marking a refused task blocked.** The card says those stay as they were.
- **Guarding `status: epic` or `done` in `_mark_blocked`.** A phase's own
  handoff already overwrites both, and refusing to run an epic is task 4's.
- **The `[epic …]` title of section 8, task 3.** There is no card
  (`docs/decisions.md` ADR 59).
- **A non-zero exit when the merge landed and its record did not.** Exit 1
  from `merge-task` means the branch did not land.
