# T-183 — board service routes for the GitHub token, sign-in and login code

ADR 456 Consequences task 4; the route decisions are ADR 468 in `docs/decisions.md`,
the queue contract ADR 459 (`dispatcher/actions.py`, unchanged).

## What was built

Three routes in `board_service/app.py` `create_app`, each through `_action` (the
ADR 151 guards: Origin 403, no token 503, bearer 401, query 400, non-object body 400):

- `POST /api/credentials/git-token` `{token, username?}` -> `actions.create("git_token", secret=token)`.
  The token's shape and the one-pending rule are `actions.py`'s 400/409.
- `POST /api/accounts/<name>/login` `{}` -> `account_login`; a name not in `cfg.accounts` is 404.
- `POST /api/actions/<id>/login-code` `{code}` -> `actions.put_login_code`, answering the
  record from `actions.find` (or `{"id"}` if the worker already ended it).

A small `_only_fields` helper gives the unknown-field 400. The routes are not in
`signin.REVIEWER_WRITES`, so a reviewer session is refused 403 by the sign-in hook:
owner only costs nothing.

## Tests

`tests/board_service/test_credentials_routes.py` (reuses the fixtures of
`test_actions_routes.py` and `test_signin.py`): guards per route, each 400 and 409,
the secret file's content and mode `0600`, the secret absent from every answer and
every queue record, a reviewer's 403, an owner's actor.

## Ruled out

- Editing `actions.py` or adding a second validation in the routes: it already holds every refusal.
- Reloading `accounts` per request: the 404 reads the config loaded at start (a new account needs a restart).
