## What changed

- **`dispatcher/context_transfer.py`:** `TaskFile` gains `epic`,
  `split_into` and `merged`. `read_task_file` reads them with no coercion;
  `write_task_file` writes each only when set, after `resolved_debt` and in
  that order, so a file without them keeps its bytes.
- **`dispatcher/tasks.py`:** `SplitError`, `file_split`, `_with_epic_line`,
  `mark_merged`, `unmet_dependencies`, `mark_blocked`. `acquire_lock` now
  moves `blocked` to `in_progress` as it moves `pending`. `SubTask` and
  `split_problems` are imported by name, because the module already defines
  a function called `handoff`. The import does not cycle.
- **Tests:** `tests/dispatcher/test_tasks.py` (the three new writers join
  `_WRITERS`, so both parametrized refusal tests cover them) and
  `tests/dispatcher/test_context_transfer.py`.
- **Docs:** both plans' *Status* paragraphs, a note on
  `docs/debt/T-028-D3.md` that its writer exists, and three rows of
  `docs/README.md`. The entry's row in `docs/debt/README.md` is not edited:
  the auditor is the one phase that writes that index.

## `file_split`, as built

It returns the sub-task ids in list order. It checks everything, raises one
`SplitError` whose `problems` lists every problem, and only then writes.

The checks, beyond the four the card names:

- **The parent must have a task file.** `file_split` never creates it: a
  split of a task nobody opened is a typo in the id.
- **A parent already split into other ids is refused.** Without this, a
  second and shorter split would orphan a sub-task and rewrite the record.
- **A sub-task file that exists with no description is refused.** There is
  nothing to compare, so it cannot be said to be the same split.
- A parent id that is not one path component raises plain `ValueError`, and
  an unmigrated parent or sub-task raises `UnmigratedTaskError`, as from
  every other writer. Neither is a `SplitError`.

The stored description is the entry's text with two lines inserted after the
last non-blank line of its *Goal* section: an empty one and
`Part of epic <parent>. Surface: <surface>.`. Every other line is kept. The
surface's whitespace is collapsed to single spaces so a newline in it cannot
open a section. The text ends in one newline. That composed text is what a
re-file compares against, to the byte.

The writes, in order: per entry, the description when none is stored, then
the task file when there is none; the parent last. So:

- A run that died part way is finished by running it again, as `migrate` is.
- An existing sub-task file is never rewritten. Its phases may have run.
- The parent is written only while its `split_into` is not already this
  split's. Task 3 closes an epic to `done`, and a re-file must not reopen
  it. Re-filing the same split therefore writes no file at all.

The parent keeps its owner, heartbeat, body, `depends_on` and
`resolved_debt`. Releasing its lock is the caller's, in task 3.

## The other writers

- `mark_merged` and `mark_blocked` raise `FileNotFoundError` for a task with
  no file, as `refresh_heartbeat` does, and create nothing. Task 3's merge
  paths have to handle that.
- A second `mark_merged` replaces the block. The module has no clock seam,
  so `at` is `datetime.now(timezone.utc)`, as the heartbeat is.
- `unmet_dependencies` takes a `TaskFile` and returns one line per unmet
  entry, in `depends_on`'s order: `<id> is not merged`, `<id> has no task
  file`, `<id>: its task file cannot be read`, `<value> is not a task id`,
  or, for a `depends_on` that is not a list, one line saying so. It tests
  only that `merged` is truthy; `done` without the block is unmet.

## Ruled out

- **Coercing `merged.at` on read.** A hand-written unquoted timestamp reads
  back as a `datetime`. Nothing compares it yet, and `depends_on` has no
  coercion either.
- **A `SplitError` for an unmigrated file.** It would take `file_split` out
  of the parametrized tests every writer shares.
- **Validating a hand-written epic** (a `split_into` naming files that do
  not exist). That is task 3's.
- **Serving the three fields from `observability/api/app.py`.** Out of
  scope by the card, so no screen shows an epic yet.
