# T-013 — `/api/phases`, and the console's phase timeline

What this task built, why it is shaped this way, and what it deliberately did not
reach. The spec is `docs/plans/front.md` tier 2 and its *Done when*; the two
decisions this task made are `docs/decisions.md` **ADR 27** (what a phase row is,
with all twenty-two of `Phase`'s fields sorted field by field) and **ADR 28** (why
the Board's five role lanes are not coming from this route). This file does not
restate them — read those for the *why* of any single field, and this file for the
*what* and the shape.

**This task does not reach parity and does not claim it.** Parity is the four
Jinja screens rendered with no fixture behind any query they make, and
`/api/learnings` does not exist, so the detail screen's learnings region is still
an empty state naming a route. `observability/board/` stays, with its compose
service and its tests; C-8 keeps it the tie-breaking reference and deleting it is
tier 1's *Done when*, not this task's.

## What a phase row is, in one paragraph

A phase row **is** a handoff file: `<hive_tasks_dir>/<task_id>/handoffs/<role>.json`,
written by `dispatcher/context_transfer.py:save_handoff` when a phase *ends*, one
file per role, overwritten each round. Six keys are served — `id`, `task_id`,
`role`, `round`, `saved_at`, `handoff` — and `id` is `<task_id>:<role>`, which is
the file itself rather than a surrogate. Thirteen of the fixture's seventeen
`Phase` fields and four of `HandoffEnvelope`'s five are gone, and ADR 27's table
says which bucket each one landed in. The one sentence worth repeating here is
ADR 17's closing rule, because it decided most of them: the api not serving
something is not by itself a reason for it to start.

## What was built — the reader in `dispatcher/`

`read_handoff` swallows `(OSError, ValueError)` and answers `None`, which is right
for its callers — `debt.declarations`, `debt.rulings` and `debt.resolved` are
repair paths that take `dict | None` — and useless to a route that has to tell an
operator *why* a file did not parse. Three names a file can fail under, one
answer, and a warning cannot say which.

So `dispatcher/context_transfer.py` grew two functions and `read_handoff` was
rewritten on one of them rather than copied:

- `list_handoff_roles(hive_dir, task_id)` — the roles with a file, sorted, `[]`
  when the directory does not exist, on `list_task_ids`' model including its
  `os.path.isdir` guard. Not ordered by the dispatcher's `ROLES`: the role list is
  not this function's business and a file named after a role this harness does not
  run is still a file a reader has to be told about.
- `read_handoff_envelope(hive_dir, task_id, role)` — the envelope whole, raising
  `OSError` for a file that will not open and `ValueError` for one that will not
  parse or is not a JSON object.

`read_handoff` is now a `try` around the second one, keeping its contract exactly.
That is the regression that mattered and it has its own test: the three shapes
that make the envelope raise still answer `None` there, and a good file still
answers its payload. The parser stays in `dispatcher/`, where this module's
docstring says a parser belongs, and there is one definition of where a handoff
lives.

## What was built — the route

`GET /api/phases` in `observability/api/app.py`, one optional parameter
`task_id`, on `/api/debt`'s shape and `/api/tasks`'s guard. `_phase` beside
`_task` builds the row; `MAX_PHASES = 100` caps the answer.

Four edges, all of them argued in ADR 27 and pinned by a test:

- **A `task_id` that is not a bare id is a 400**, and never reaches
  `handoff_path`. `_is_bare_task_id` is the lock the detail route already uses. A
  parameter is 400 territory; the 404 belongs to a route whose resource is the
  task.
- **A bare id with no task file is `[]` plus a warning naming it, never a 404.**
  The console reaches this route with an id it read off `/api/tasks`, and a 404
  would take a region to *Broken* on a screen whose own read succeeded.
- **A missing or unparseable handoff is not a 404 either.** A 404 says the phase
  does not exist, which is a lie about a file that does. One bad file costs a
  warning naming its path and every other row still comes back.
- **The sort key is built inside the per-row guard, as a `str`**, and the sort runs
  over strings outside it. This is
  `docs/learnings/a-never-500-read-wraps-the-use-not-the-parse.md`: the guard wraps
  the *use* of a parsed value, and a `saved_at` of the wrong type is a use, while a
  sort over the whole list cannot sit inside a per-row `try` without one bad file
  costing every row. A comment in the view says so, because narrowing that `try`
  to the reader reopens all of it.

A fifth edge is not in ADR 27 and was found while building: **the per-task
directory listing needs the same guard as the rows.** `list_handoff_roles` checks
`os.path.isdir` and then calls `os.listdir`, which still raises for a directory
that exists and cannot be read — and this route lists one directory per task, so
without a guard one unreadable directory costs every *other* task its rows. That
is the module's one rule inverted, so the call is wrapped and warns with the
scratch dir's path. It is a live shape and not a hypothetical: `.hive/` is written
by the dispatcher and read here over a `:ro` mount, which is the mixed-ownership
case `_write_atomic`'s `chmod` already exists for. `/api/tasks` has the same
exposure on the *one* top-level listing it does, which is a smaller blast radius
and was left as it was.

One thing the route does **not** do, and it is a decision rather than an omission:
a `saved_at` that is not a string is served **verbatim, with no warning**. Nothing
raises — `str()` of a mapping is a legal sort key — and ADR 10 already rules that
a timestamp this service cannot judge is the harness's news to report rather than
this service's to hide, which is how `/api/tasks` treats a hand-edited heartbeat.
Its test says that in its name.

`handoff` travels **whole and unpromoted**. Nothing is lifted onto the row and
nothing is projected: the payload's key set is the role's own schema in
`dispatcher/handoff.py:schema_for`, and a second copy of it maintained by hand on
this side is what this service's docstring refuses. A revisor's `verdict` and
`debt_rulings` arrive because nothing is filtering on a list of names, and that
has its own test too. `handoff: null` is a real answer — `save_handoff` writes the
envelope even when the return would not parse — and not a missing file.

No compose change, no new mount, no git read and no `dispatcher` behaviour change.
The api already mounts `.hive:ro`, `cfg.hive_tasks_dir` is `/data/.hive/tasks`
inside it, and the api having no docker socket is a property that
`tests/integration/test_compose_invariants.py` pins.

**Tests:** `/api/phases` joined `ROUTES` in `tests/observability/test_api.py`,
which buys the five parametrized cases plus `test_no_route_accepts_a_write`, and a
`_handoff` helper writes fixtures through `save_handoff` itself as that file's
docstring requires. Fourteen cases of its own cover the whole-row key set, the
payload travelling whole, the round, a null payload, newest-first ordering, the
filter, the unknown id, the two bad `task_id`s, a file that will not parse, an
envelope that is not an object, a `saved_at` of the wrong type, a directory that
will not list, a task with no `handoffs/` directory, and the clamp naming itself.
Ten more in `tests/dispatcher/test_context_transfer.py` cover the two new readers
and `read_handoff`'s unchanged contract. Baseline was 1173 passed and 10 skipped;
the suite is now 1202 passed and 10 skipped.

## What was built — the console half

Six files, and the seam each one sits on:

- `front/src/lib/api/forward.ts` — `"/api/phases": ["task_id"]` joins the closed
  GET-only whitelist. Without this line a wired `listPhases` 404s with the
  forward's own JSON. The module docstring and the reject message both said
  *five* and now say *six*, because a message that lies about its own list is the
  next reader's wrong turn.
- `front/src/lib/api/types.ts` — `HandoffEnvelope` is replaced by
  `HandoffPayload`, every field optional because the key set belongs to the role;
  `Phase` is the six served keys. `GateFinding` stays and its comment now says it
  describes the approvals surface alone.
- `front/src/lib/api/client.ts` — `listPhases` moved into the wired block and
  resolves to `ApiResult<Phase[]>` through the same `readEnvelope` boundary as the
  other five. No reverse, no mapping, no sort: the order a timeline shows is the
  screen's.
- `front/src/routes/tasks.$taskId.tsx` — the timeline, below.
- `front/src/routes/index.tsx` — the Board's banner, rewritten under ADR 28.
- `front/src/components/console/chat-panel.tsx` — two lines of comment that said
  the running role waits on `/api/phases`, which is now false in the one way that
  matters: the route exists and still does not answer it.

`queries.ts` did not change — `phasesQuery(taskId)` was already there with key
`["phases", taskId ?? "all"]`, which is what ADR 16 required of it.

### The timeline

`PhaseRow` was **reinstated, not rewritten**: it had been kept callerless at the
foot of that file for exactly this task, and only the fields ADR 27 retired came
out — the account and model `Mono`s, the `started …` line, the gate chips, the
`write_rejected` paragraph, the byte-budget bar and the commit/worktree block. The
`<li>`, the panel classes, the round indent and the `RoleBadge` are the generated
screen's. What it gained is the payload: the status and the verdict as pills, then
`changed`, `verified`, `pending`, `risks`, `paths` and `learnings` as labelled
lists, every one guarded with `?? []`.

Three region states, in the order `docs/ui.md` *Absent, empty and broken* asks
for. Broken takes the **region** and not the screen, because this is a secondary
read on a discrete block and the task card above it answered — the debt region
three lines down is the same shape. Empty names what would have been here, and it
is an empty state about the **harness**, not about the console: the route exists,
so naming one would send an operator looking for a bug in an api that answered
correctly.

Three smaller decisions that are this screen's and not the vocabulary's:

- **Order is by the cycle, not by the clock.** The route answers newest first,
  which is right for a feed; a timeline of one task reads arquitecto →
  implementador → revisor → auditor, and that order survives a `saved_at` the api
  could not judge. A role outside `ROLES` sorts last, with `saved_at` as the
  tie-break.
- **A role outside `ROLES` renders as its own string**, not through `RoleBadge`:
  there is no hue for it, and the api validates neither the filename nor the
  envelope's `role`.
- **`phaseTone` is local to the screen.** A phase's status is a second vocabulary
  and one screen shows it today; the second screen that does promotes it into
  `primitives.tsx` beside `StatusPill`, and the comment says so.

The learnings region **did not change in substance** and still names
`/api/learnings`, per ADR 19. One clause was corrected: it said the join waits on
two routes, and now one of them exists.

### Two files the plan did not name, and why they had to move

`front/src/lib/api/mock/fixtures.ts` — narrowing `Phase` to six keys would have
left `mockPhases()` returning seventeen-field objects typed `Phase[]`, which is a
type error in a tree with no typecheck in the loop: a landmine for the next task
rather than dead code. ADR 25's rule for the five fixtures T-012 retired decides
it — kept rather than deleted, and kept **conforming to the served shape**, so a
typecheck still catches a type that drifts from the route. It is four rows now,
including a `handoff: null`, and the module docstring moved it from the paragraph
about fixtures that back a read to the one about fixtures that back nothing.

`front/src/lib/format.ts` — `formatBytes` and `formatDuration` lost their only
caller when the byte bar and the `started … · duration` line came out. Kept with a
comment saying why, which is `splitStatus`' treatment under ADR 25: `formatDuration`
comes back unchanged for the first duration the harness persists, and `formatBytes`
for the first measured size it keeps.

## What ships unexecuted, and why

The console half again. `front/` has no `node_modules`, no test script and no
typecheck in the loop, and `bun install` is out of scope for a phase — so every
TypeScript edit above is unexecuted, and `python3 -m pytest` being green says
nothing about it. The condition is declared as found debt in this task's handoff
with `/data/.hive/tasks/T-012/console-plan.md` section 11 as the fix.

The task text cited `docs/debt/T-012-D1` as the row already carrying this, and it
is a different row — that entry is `merge-task` dropping promoted inbox entries.
T-012's arquitecto declared this condition and T-012's auditor never ran, so it is
in no index, which is why it is declared here once rather than cited. The trap is
written up in `/data/.hive/learnings/inbox/T-013-a-task-text-can-cite-a-debt-id-that-is-a-different-row.md`.

## What was not done, and is not debt

- **No `/api/learnings`**, and no half of it on this route. `handoff.learnings`
  travels as the role wrote it — inbox filenames inside prose, not ids — and the
  join needs that route. ADR 27's last paragraph.
- **No lanes on the Board.** ADR 28 is the argument: no file records which phase
  is *running*, and a lane fed from the newest handoff would be one phase behind
  while looking live. The fix is one line of dispatcher state, not a route, and it
  would serve `duration_s`, `account`, `model`, `shrink_retry` and `started_at`
  with it — four of ADR 27's seven *present nowhere* rows and one out of the
  bucket above them, but not `commit_sha` and not `envelope.to_role`.
- **No git read for `commit_sha`.** The phase commit exists on
  `agent/task/<task-id>` with the role and the account in its message, and
  `.data/projects` is mounted `:ro` — but a message is not a record, this image
  carries no git, this service spawns nothing, and a merged-and-cleaned branch is
  gone. Arguing for it is a later task's, with the image it costs.
- **No `bytes_budget`.** `budget_for(role)` is one line away and is not served:
  its only consumer was a bar whose numerator the harness does not persist, and a
  denominator with no numerator is a figure nobody can read.
- **No byte cap on `/api/phases`.** `MAX_PHASES` bounds a count, not bytes. The
  unfiltered call is the only one that can grow, nothing polls it, and the console
  always sends `?task_id=`. A byte cap is the fix if a screen ever polls the
  unfiltered form.
- **No history of rounds.** One file per role is the record. A timeline showing
  round 1 beside round 3 would be inventing the one.
- **No deletion of `observability/board/`**, its compose service or its tests.
  C-8's condition is unmet.
