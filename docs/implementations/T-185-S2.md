# T-185-S2: the worker mounts the git token

Decision: `docs/decisions.md` ADR 486 (builds ADR 456 Consequences 6).

## What

- `docker/compose/docker-compose.yml`: `worker` gets
  `../../.data/credentials/git-credentials:/run/secrets/git-credentials`
  (no `:ro`) as its last volume, commented; the comment above `worker` now says
  its mounts are the dispatcher's plus this one. `dispatcher`, the Coolify file
  and the agents file are untouched.
- `scripts/configure.sh`, after the `config.d` mkdir: a directory is reported
  (Docker made it, remove it), an existing file or symlink is kept, otherwise
  the file is created empty under a `umask 077` subshell. The create sits in an
  `if` condition because the script runs `set -euo pipefail`; a failure prints
  a line and the wizard goes on.
- `README.md`: step 1 paragraph, the `worker` bullet, the Coolify passage
  (`not_mounted`).
- Tests: two new invariants (no parameter, so `test_configure.py` calls them on
  the rendered pool), the worker==dispatcher test branched by file, and three
  configure tests (created 0600 empty, existing kept, directory reported).

## Ruled out

- Mounting it in the dispatcher too: only the worker renews the token.
- A test for the failed-create branch: the suite runs as root, which ignores
  file modes, so it cannot be provoked.
