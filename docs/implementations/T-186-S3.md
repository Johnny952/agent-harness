# T-186-S3 — the Tokens screen's controls

Contract: `docs/decisions.md` ADR 492 (on ADR 456 decision 7, ADR 489, ADR 483,
ADR 212, ADR 216).

## What was done

- `front/src/routes/tokens.tsx`: the controls inside ADR 489's rows.
  - GitHub token: `RenewToken` (password field, username, Renew).
  - Deploy key rows: `KeyControls` (Replace key with an inline confirmation,
    Check; public half, fingerprint and the four check sentences).
  - Claude login rows: `LoginControls` (Sign in again, the URL as a link, code
    field, Send code, outcome, Cancel).
  - Shared: `useFollowed` (an `actionQuery` by id; invalidates `["credentials"]`
    once the record ends), `Progress`, `Ending`, `Refusal`, `useSettle`.
  - `TokensPage` also reads `actionQueueQuery`; a login row adopts the open
    `account_login` for its account, so a reload resumes the sign-in.
- `front/src/lib/api/queries.ts`: `FINISHED` gains `"cancelled"`.
- `-tokens.test.tsx`: each request's path and body, cleared fields, quoted
  400/409/503 refusals with no leak of the token (page HTML, console spies, URL),
  the login stages, Cancel, adoption, no controls without a snapshot.
- `docs/README.md` *Modules* `front/` row: the T-186-S3 clause.

## Why this way

- The token and the code go through plain async handlers, not `useMutation`: its
  cache keeps `variables`. Keygen, check, sign-in and cancel carry no secret and
  use `useMutation`.
- The followed id is row state, not the URL (ADR 492 decision 2); only a sign-in
  is resumed after a reload.
- The `Check` result drops `projects.new.tsx`'s push-task-branch clauses: this
  screen reads no project record.
- A running sign-in with an `awaiting: "code"` but no https `url` draws `Malformed`
  and no code form: a code with nowhere to sign in is useless.

## Ruled out

- `useMutation` for secrets; ids in the URL; an `AlertDialog` for the confirmation
  (ADR 492 *Ruled out*).
