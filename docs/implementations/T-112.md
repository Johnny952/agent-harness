# T-112 — `POST /api/threads/<id>/turns`

The decision is `docs/decisions.md` ADR 181.

## What was built

- `board_service/app.py`: `MAX_TURN_TEXT_CHARS = 20_000` and `http_turn`,
  copied from `http_start`. It runs through `_action` (ADR 151's guards:
  origin, token, bearer, query, JSON object), then refuses an unknown field,
  a `text` that is not a non-empty string, a `text` over the limit (all 400),
  an unknown thread (404) and an unreadable or archived one (409), and calls
  `actions.create(state_dir, "turn", params={"thread", "text"},
  actor="operator")`. The answer is the created record, 201.
- `tests/board_service/test_turns_route.py`: 18 cases on a state dir and
  hive under `tmp_path`: the record and its claim, the bearer guards, each
  refusal, the limit at 20000 and 20001, unknown and archived threads, two
  posts on one serial key `thread:<id>`, and the cancel route accepting the
  turn's id.
- Docs: `docs/plans/main-thread.md` Status and step 5; `docs/README.md` row.

## Why this way

- The limit is 20,000 characters because the text is one argv element of
  `docker exec` (ADR 181, 3).
- Text is stored as sent, never stripped; only an all-whitespace text is
  refused.
- `actions._validate_turn` is left alone: the limit is a route rule, so a
  later creator (the MCP tool, step 6) must reuse `MAX_TURN_TEXT_CHARS`.
- Nothing interrupts a running turn: a message queues behind it on the serial
  key. Stop is the existing cancel route; the kill of a running turn by it is
  covered by `tests/dispatcher/test_worker.py::test_a_cancel_kills_a_running_turn`
  and was not duplicated.

## Ruled out

- Checking the thread inside `actions.create`'s lock: an archive racing a post
  is refused later by the worker (ADR 173, 2).
