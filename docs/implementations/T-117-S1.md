# T-117-S1 — format front/src/routes/README.md

Only the Conventions table in `front/src/routes/README.md` was off prettier's
style (cells unpadded, short `---` delimiters). `.prettierrc` sets no
`proseWrap`, so prose stays as written.

## What I did

Padded every cell of the table to its column's widest cell and widened the
delimiter row to match. No words, links or dashes changed.

## Why by hand

`bunx prettier --write` was refused in this phase, so I aligned the table by
hand (column widths 24 and 116 characters; an em dash counts as width 1). I
checked the rows line up with `cut -c121-`, allowing for the two extra bytes an
em dash takes.

## Not verified here

`bunx prettier --check src`, `bun run lint` and `bun run test` were not run:
`bunx` was refused, and the change is a Markdown table only, which neither
eslint nor vitest reads. The reviewer or dispatcher should run
`cd front && bunx prettier --check src` as the arbiter.

Since settled: the operator ran `bunx prettier --check src` in `front` (exit 0,
"All matched files use Prettier code style!"), and the auditor ran
`bun run lint` (clean) and `bun run test` (30 files, 678 tests passed).
