# T-163: `proposed_by` on a console proposal

Decision: `docs/decisions.md` ADR 390. Resolves debt `T-162-D1`.

## What

- `dispatcher/context_transfer.py` `TaskFile.proposed_by`: read from and
  written to the frontmatter only when set.
- `dispatcher/tasks.py`: `field_problems` checks it with `dropped_by`;
  `propose(proposed_by=)` checks it is a non-blank string and puts it on the
  task, or on the epic and each child; `_propose_again` gives a late-written
  child the epic's value and never compares it.
- `board_service/app.py`: `_call` takes `trusted`, merged after `_check`, so
  the schema never admits it; `_http` passes `{"proposed_by": _person()}` for
  `backlog_propose` only. `backlog_propose` forwards it to `propose`.
  `board_list` rows carry it; `board_get` already serves the frontmatter.
- `observability/api/app.py` `_task` row carries it.

`source` stays `operator`. `TOOLS["backlog_propose"]` is unchanged, so an
HTTP body or an MCP call naming `proposed_by` is refused as unknown.

## Tests

`tests/board_service/test_person_actor.py` (signed-in, epic, no cookie, body
refused, phase proposal has none, list and get), `tests/dispatcher/test_board_writes.py`,
`tests/observability/test_api.py`; whole-row literals gained `proposed_by: None`.

## Ruled out

- A `proposed_by` tool argument: a phase could pass for a person.
- Setting it on phase proposals: it would repeat `source`.
- `front/` changes: the console does not show it yet (proposed as debt).
