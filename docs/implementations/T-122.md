# T-122: `close-task`

Decision: `docs/decisions.md` ADR 255.

## What was built

- `dispatcher/tasks.py`: `NotMergedError` and `mark_closed(hive_dir, task_id)`,
  right after `mark_merged`. `@_locked`; refuses an unmigrated file first, then
  a missing file (`FileNotFoundError`), then a task with no `merged` block.
  Returns the status it moved from, `None` when already `done`. Only `status`
  changes; no notification.
- `dispatcher/cli.py`: `close-task --task-id --project`, via `_run_close_task`.
  Exit 1 with `task <id>: not closed: <reason>` on stderr for an unmerged,
  unmigrated or missing task, or a card whose `project` is another slug. No
  docker, no git, no base lock.
- Tests: `tests/dispatcher/test_tasks.py` (`mark_closed` section) and
  `tests/dispatcher/test_cli.py` (`close-task` section), on `tmp_path` hives.
- Docs: `docs/README.md` verbs row, root `README.md` paragraph after the
  merge-task passage.

## Why this way

- `mark_closed` is not in `test_tasks.py`'s `_WRITERS`: that table's
  neighbour test runs every writer on a file with no `merged` block, which
  `mark_closed` refuses. It has its own tests.
- The unmigrated refusal comes before the writer's own errors, so a legacy
  file reports "run migrate" rather than "not merged".
- The `--project` check reads the card first and ignores a read failure, so
  `mark_closed` is the one that words the file's problem.

## Ruled out

- Notifying on close: the merge was already announced by `mark_merged`.
- Clearing `blocked_reason` or touching the lock: the spec changes status only.
- Refusing a task with a live lock: the spec says any non-done status moves
  (ADR 255 Consequences).
