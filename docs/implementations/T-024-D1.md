## The change

### `dispatcher/context_transfer.py`

`read_usage(hive_dir, task_id) -> UsageLog(lines, skipped)`, after
`append_usage`. It reads the file's bytes once and splits on `\n`, so an
unterminated last line — an append cut short — is never parsed; if it is not
blank it is counted as skipped. Each other line is decoded and parsed with a
`parse_constant` hook that refuses `NaN` and `Infinity`, so a line that would
not survive `jsonify` never enters `lines`. Bad UTF-8, a JSON error, a
`RecursionError` from absurd nesting, or any value that is not an object is
skipped and counted; a blank line is skipped and not counted. A missing hive
directory, scratch directory, usage directory or file is an empty log. Every
other `OSError` propagates — a `PermissionError` above all, because "no calls"
and "may not look" must stay two answers. An id that is not exactly one path
component (`""`, `.`, `..`, a slash, a NUL) raises `ValueError` before the
filesystem is touched.

### `observability/api/app.py`

`GET /api/tasks/<task_id>/usage`, `task_usage`, placed before `/api/learnings`,
behind `requires_auth`, with `_reject_unknown_parameters` and no parameters.
In order: a non-bare id is a 404, a missing task file is a 404 even when a log
exists, a reader `ValueError` is a 404, a `PermissionError` is `data: null`
with a warning naming the 0700-directory cause and ADR 54, any other `OSError`
is `data: null` with `unreadable usage log`. Skipped lines become a warning
with their count. Past `MAX_USAGE_CALLS` (1000) lines the newest are kept and a
warning says so and that the first group may lack its `phase` line. Grouping
and a dry serialisation run inside `_UNREADABLE`, so a hand-edited line costs a
warning and never a 500.

`_usage_groups` builds the groups: a new one at each `call: "phase"` line or
where `(role, round, account)` changes, compared with `==`. Each group is
`task_id`, `role`, `round`, `account`, `calls` (the lines verbatim),
`call_count`, `call_kinds`, `measured_calls`, `unmeasured_calls` and
`phase_call`. The module docstring now counts `read_usage` as a sixth
dispatcher reader the api goes through.

## Why this shape

A line is a call, an attempt is up to four calls on one account, a phase is as
many attempts as failover tries, a task is many phases. Per phase and per task
are sums, and a sum over a resumed session is wrong by up to the number of
retries if `usage` is cumulative — the open half of `docs/debt/T-024-D2.md`.
Per attempt is the finest grouping the log marks on its own, and it can be
served correctly today if it carries only counts and the first call's line.
ADR 54 lays out the alternatives and what a total becomes once D2 is answered:
the sum of the lines if per call, the last line if cumulative, either way a
**new** key under a **new** ADR.

The route is a path segment because the id is required and names one task;
it answers 404 rather than ADR 27's 200 because the screen it serves opens
`/api/tasks/<task_id>` first, and that already 404s for the same id.

## What was left standing, and why

- **The write side.** The 0700 usage directory is recorded in ADR 54 and named
  by the route's warning, not fixed: `handoffs/` and the scratch directory share
  it, and a fix belongs to the writer for all three at once
  (`docs/learnings/a-0644-file-under-hive-still-sits-in-a-umask-directory.md`).
- **D2.** Answering it needs one live phase with a retry; this change ran no
  container. It is now the only thing between the route and a total.
- **The screen.** No card owns a cost view and `front/` was out of bounds, so
  it is filed as `docs/debt/T-024-D3.md`.

## Tests

`tests/dispatcher/test_context_transfer.py` — `read_usage` round-trips what
`append_usage` wrote; a task with no scratch directory, no usage directory or
no hive at all reads as empty; blank lines are skipped and not counted; a
parametrized set of bad lines (garbage, cut short, non-UTF-8, a list, a string,
a number, `null`, `NaN`, `Infinity`, deep nesting) is skipped and counted
between two good ones; an unterminated last line is never trusted, even when it
would parse; six bad ids raise `ValueError` with a log planted where they would
lead; a `PermissionError` propagates.

`tests/observability/test_api.py` — the route joins the auth matrix, and under
*usage*: grouping with the full expected group; failover and re-dispatch open
groups with `phase_call` `null` where no `phase` line exists; no measured
field is summed anywhere in the answer; a drifted `measured` or `call` is in
neither count; an empty task is `[]` with no warning; no task file and a
non-bare id are 404 even with a log present; a reader `ValueError` is 404; a
`PermissionError` and another `OSError` are `null` with two distinguishable
warnings; skipped lines are counted in a warning; the clamp keeps the newest
lines and says so; the route writes nothing.
