# T-096 — The Debt screen's backlog items

Decisions: `docs/decisions.md` ADR 141. It covers:
- pairing an entry with its item on `debt_id`, as the dispatcher does;
- the states: not imported, not accepted, accepted (with the status);
- two items with one `debt_id`;
- a failed tasks read.

## What was built

- `front/src/lib/debt.ts`:
  - `itemsByDebtId` groups the tasks by `debt_id`, in id number order;
  - `pairEntry` gives an entry's items and whether there is more than one;
  - `itemState` and `stateLabel` give an item's state and its words;
  - `duplicateWarning` names the tasks that share a `debt_id`.
- `front/src/routes/debt.tsx`:
  - reads `tasksQuery` once, beside `debtQuery`;
  - the Open partition gets an *item* column: a link to `/tasks/$taskId`
    and the state, or "not imported";
  - a shared `debt_id` shows every item under a warning;
  - a failed tasks read shows a broken-read line, and each item cell says
    "pairing unavailable";
  - the tasks read's warnings join the debt read's in the banner;
  - the Resolved partition is unchanged.
- Tests:
  - `front/src/lib/debt.test.ts` (16).
  - `front/src/routes/-debt.test.tsx` (18, of which 11 are new). They cover
    - not imported, with no link;
    - proposed, deferred and dropped, each linked;
    - pending, in progress and merged, each linked;
    - the duplicate warning, with both items;
    - a failed tasks read;
    - resolved entries with no item column;
    - no writes.
- `bun run typecheck`, `bun run test` (338 passed, 20 files) and
  `bun run lint` pass.

## Why this way

- The pairing copies `find_debt_item`, so the screen never pairs an entry
  the dispatcher would file again, or the other way round.
- The tasks read is a join, not the screen's own read. Its failure is shown
  as broken, not as every entry being unfiled.
- The pairing is pure functions, so every state is tested without a render.
