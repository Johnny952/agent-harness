# T-167: file_debt — one lookup per row, and flag a blocker it cannot read

Follows T-164-S2 (ADR 396). No new ADR: filing a row whose task-id blocker
the board cannot read, with no `depends_on`, is ADR 396's decision; this
task only makes the result and the outputs say so.

## Plan

### 1. `dispatcher/tasks.py` `file_debt`

- Call `find_debt_item` only in the `gated` and `dry_run` branches. A real
  row goes straight to `propose_debt`, which already looks the entry up
  under `CREATE_LOCK`; so a real row calls `find_debt_item` exactly once.
- Add `unknown_blocker` to every result:
  `unknown_blocker = kind == "task" and not deps` (a task-id blocker that
  `_depends_problems` refused). False for no blocker, a readable task id and
  a plan step (`gated`). Computed the same way under `dry_run`.
- Docstring: add `"unknown_blocker"` to the listed result keys and say it
  is true only for a task-id blocker the board cannot read.

### 2. `dispatcher/dispatcher.py` `_mirror_filed_debt`

In the results loop, before the existing `logger.info` for a non-gated
result, when `result["unknown_blocker"]`:

```
logger.warning(
    "task %s: debt entry %s is blocked by %s, which the board cannot read; "
    "filed with no dependency", task_id, result["debt_id"], result["blocked_by"],
)
```

The info line still follows.

### 3. `dispatcher/cli.py` `_run_import_debt`

After the `depends_on` suffix, for a non-gated result:

```
if result["unknown_blocker"]:
    verb += f", blocked by {result['blocked_by']}, which the board cannot read"
```

so the line reads e.g.
`T-1-D4: filed as T-053, blocked by T-999, which the board cannot read (priority normal): <title>`
(`would file, blocked by …` under `--dry-run`, `already T-053, blocked by …`
for a row filed before). The summary line is unchanged.

`docs/cli.md` `import-debt`: add one sentence after the ADR 396 paragraph:
a row blocked by a task id the board cannot read is filed with no
dependency and its line adds `, blocked by <id>, which the board cannot read`.
