# T-057 — an account holds up to N phases

Decision: `docs/decisions.md` ADR 85.

## What was built

`dispatcher/state_machine.py` keeps `holders` (task_id, busy_since each) in the
state file. `get_state` is derived: a parked state (`PARKED_STATES`) wins, else
BUSY while any holder remains, else IDLE. New: `Holder`, `get_holders`,
`claim(..., capacity=1)`, `release`, `park`, `unpark`. Every writer goes through
`_locked` and one internal `_write_account`, which carries `rate_limited_at` and
`last_probe`.

The top-level `current_task_id` / `busy_since` are still written (mirroring the
first holder) and win over `holders[0]` on read, because `test_dispatcher`'s
`_age_busy_since` edits that key. An old-shape file reads as one holder.

`set_state` keeps its whole-account meaning, so a park through it drops the
holders (ADR 85 point 6); `park` is the one that keeps them.

## Ruled out

- Changing `set_state` to keep holders on a park: it would change what the
  callers outside this surface mean at capacity 1.
- Editing the callers: left to T-058.

## For T-058

Every `set_state` call in `dispatcher/dispatcher.py` and `dispatcher/operator.py`
drops the other holders at capacity above 1; T-058 must replace them with
`release` / `park` / `unpark` (ADR 85 *Consequences*). `list_idle_accounts` still
lists only accounts with no holders.
