# T-193-S1 — the first-user command

Decision: `docs/decisions.md` ADR 519.

## What

- `board_service/signin.py`: `UserExists(ValueError)` and a keyword-only
  `create_user(..., first=False)`. With `first=True` it raises `UserExists`
  under `_locked`, after `_read`, when any user exists.
- `board_service/first_user.py`: `main(argv, *, environ, read_password, out, err)`.
  Exit 0 created, 1 a user exists, 2 bad input or `BOARD_AUTH_DIR` unset or
  empty. Reads the password twice with `getpass`, creates an `owner` (name from
  `--name`, default `owner`), writes a `user_created` audit line without the
  secret, prints the TOTP secret and the otpauth URI once.
- `tests/board_service/test_first_user.py`: creation, `--name`, refusal with a
  user, unset and empty variable, mismatched and short passwords, modes
  (`0700` dir, `0600` file), the `first` flag, and a subprocess smoke test.
  An autouse fixture lowers `SCRYPT_N` and `SCRYPT_P`.
- `README.md` Future work bullet on the password digest.

## Why this way

- The "already a user" check lives in `create_user` under the lock, so two
  racing runs cannot both create an owner. `main` also checks before prompting
  so the operator is not asked for a password that will be refused.
- `main` takes its environment and I/O as arguments, so tests need no TTY.
- A printed secret instead of the plan's one-time setup link: a link needs a
  served route and a store for the token, and this command runs before the
  service is reachable (ADR 519).

## Ruled out

- A flag on `create_user` that defaults to refusing: breaks existing callers.
- Creating the directory before the existence check: a refusal writes nothing.

## Not run

`getpass` on a real TTY: tests inject `read_password`.
