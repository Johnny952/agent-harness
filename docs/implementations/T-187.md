# T-187 — `update_project_before_task` becomes editable

ADR 456 decision 8 (Consequences 8), built as written; no new ADR.

## What

- `dispatcher/config.py` `CONFIG_KEYS`: the `update_project_before_task` row
  is `_editable("bool", ...)` with the reason "Fetches before each task; the
  Tokens screen shows whether a credential exists." `config_writer` is
  untouched: `_check_override_value` already knows `bool`, and the writer
  checks no credential.
- `tests/dispatcher/test_config.py`: class counts 24/21/3 to 25/20/3; three
  new tests (class, kind and reason; a `true` override loads; `'yes'` is
  refused naming the file).
- Counts in `docs/learnings/a-new-config-field-needs-a-config-keys-row.md`,
  its row in `docs/learnings/README.md`, and `docs/plans/console-config.md`
  section 4.

## Why this way

The front renders `/api/settings` rows generically (a bool gets a switch), so
no front change. The row stays where it was; moving it would only add diff.

## Ruled out

- A credential check in the writer: out of scope, and ADR 456 keeps the
  writer free of credentials.
- Editing the dated "Built 2026-10-17 ... 22 editable" line in
  `docs/plans/console-config.md`: a record, not a current count.
