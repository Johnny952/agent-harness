# T-048 — a scoped commit with nothing in scope does not crash the cycle

## What

`_nothing_to_commit` in `dispatcher/docker_exec.py` now also recognises git's
"no changes added to commit", which is what `git commit` prints (exit 1) when
the only changes are unstaged because they sit outside the phase's scope.
`commit_worktree` then returns `False` and the phase's handoff is saved.

## Why this way

Same substring-marker mechanism as the two existing markers; one more entry,
no new control flow. The out-of-scope warning (`_warn_changes_outside`) is
untouched. Any other failed commit still raises `RuntimeError`.

## Ruled out

- Checking the scope before committing instead of reading git's message:
  a second source of truth for the same fact.
- An ADR: no contract changed.

## Tests

`tests/dispatcher/test_docker_exec.py`: the T-047 output with
`paths=["docs"]` returns `False`; a scoped commit failing with exit 1 and an
unrelated message still raises "git commit failed".
