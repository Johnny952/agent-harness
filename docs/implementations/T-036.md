# T-036 — the pointers gate checks a task's own citations first

The decision is `docs/decisions.md` ADR 61. This note is the build: what
changed in `dispatcher/gates.py`, the tests that pin it, what was measured
and what was ruled out.

## What was wrong

`_broken_pointers` built one list, the present docs' citations first and the
task's own last, and stopped at `_POINTER_LIMIT = 400` unique (doc, token)
pairs. On this tree the present docs give exactly 400. So the loop broke on
the last present-doc pair, and the gate checked none of a task's own
citations: not a fresh implementation note, not a line added to
`docs/decisions.md`. A clean pointers gate on a recent task said nothing
about that task's own docs.

## Verified first-hand, not taken from the card

| Card's claim | Where | Verdict |
|---|---|---|
| `_POINTER_LIMIT = 400`, `_POINTER_CHUNK = 100` | `dispatcher/gates.py` | true at the base |
| `_broken_pointers` lists present docs, then `fresh`, then added record lines, and breaks at the limit with a log line | `_broken_pointers` | true: one `_cited` call over `PRESENT_DOCS` then `fresh`, the added lines appended, `break` inside the loop |
| `_cited`, `_added_lines`, `_missing` exist; `_missing` asks `ls` in chunks of `_POINTER_CHUNK` | `dispatcher/gates.py` | true |
| `PRESENT_DOCS`, `RECORD_DOCS`, `is_record` | `dispatcher/project_docs.py` | true |
| `test_a_pointer_whose_target_is_gone_is_reported_with_the_doc_that_cites_it` | `tests/dispatcher/test_gates.py` | true |
| The present docs give "roughly twice" ADR 35's 151 pairs | this tree | **different: exactly 400**, see *The count* |

One more difference, which the card does not state either way: the old log
line fired when the list reached the limit (`>=`), not when something was
skipped. On this tree it said "the rest went unchecked" on a run where no
present-doc pair had been skipped (only the task's own had).

## The count

400 unique (doc, token) pairs, over 337 candidate paths, from 3820 raw
spans. Both phases ran it and got the same numbers.

Method: the gate's own steps, run on the host from the worktree root in a
throwaway test kept outside the repo (`test_count.py` in the task's hive
directory). It runs `grep -r -H -o -E` with `_POINTER_PATTERN` over
`PRESENT_DOCS` under `LC_ALL=C`, splits each line the way `_cited` does,
passes each span through `pointer_token`, and counts unique (doc, token)
keys; the candidate paths come from `_candidates`.

Per doc: `docs/README.md` 52, `docs/charter.md` 19, `docs/business.md` 18,
`docs/learnings/README.md` 36, and 275 over the 33 files of the debt
directory (`docs/debt/README.md` alone 62). The architecture doc that
`PRESENT_DOCS` names does not exist in this project, which grep reports and
the gate ignores.

Five of the 400 name a path that is not on disk: `.lovable/project.json`
twice and a verification file under `.data/` three times. Both are excused
today: `front/.lovable/project.json` is tracked (`git ls-files`), so
`_in_a_subproject` takes it, and `.data/` is a line in the root
`.gitignore`. So the wider check turned up no stale citation to declare.

## The change

`dispatcher/gates.py`, the pointers gate only:

- `_POINTER_LIMIT` is 1000, with a comment saying what it now bounds.
- `_broken_pointers` still makes one `_cited` call with the same argument
  list. It then sorts the pairs by `project_docs.is_record`: a fresh record
  is a record, no present doc is. The added record lines join the task's own
  pairs as before.
- The task's own pairs fill `cited` first, with no limit.
- The present-doc pairs follow, each added while `cited` holds fewer than
  `_POINTER_LIMIT` keys. One past that goes into an `unchecked` set and is
  not asked about. There is no `break`: the loop goes on to count.
- If `unchecked` is not empty, one line is logged:
  `gates: N present-doc citations went unchecked: the limit is L and this
  task's own took K`.

Everything from the `candidates` line down is untouched. `cited` keeps
insertion order, so a finding lists the task's own breaks first, ahead of
the eight-entry report limit.

The budget is shared, as the card's Goal says and ADR 61 decides: the
present docs get the limit minus what the task's own took, floor zero. A
task with more than 1000 citations of its own is checked in full and the
present docs are all counted as unchecked for that run.

### Round trips

`_missing` asks `ls` once per `_POINTER_CHUNK` (100) candidate paths, and a
pair has at most two candidates. 400 pairs was at most 8 calls; 1000 is at
most 20. Measured, this tree's 400 pairs are 337 paths, 4 calls, the same
before and after. The task's own pairs are outside the limit and add to
that: one call per 50 to 100 own pairs.

## Tests

Four in `tests/dispatcher/test_gates.py`, at the end of the Gate 4 section,
with two helpers: `_crowd(count)` builds that many present-doc citations
that all resolve, and `_asked(worktree)` is every path handed to `ls`.

- `test_a_broken_pointer_on_an_added_record_line_survives_a_full_limit`
- `test_a_broken_pointer_in_a_fresh_record_survives_a_full_limit`
- `test_the_log_names_how_many_present_citations_went_unchecked`: limit + 5
  present pairs and two own, so 7 unchecked. It also checks that those
  seven paths never reached `ls` and the one before them did.
- `test_a_limit_exactly_filled_logs_nothing`

Each crowd is sized off `gates._POINTER_LIMIT`, not against a patched
value.

### How "each fails on today's code" was checked

The four tests were written first and run with `dispatcher/gates.py`
untouched: `python3 -m pytest tests/dispatcher/test_gates.py -q` printed
`4 failed, 100 passed in 0.21s`, and the four failures were these four.

- The two broken-pointer tests: `ValueError: not enough values to unpack
  (expected 1, got 0)`. No finding at all.
- The count test: the one line was `gates: stopped after 400 citations,
  the rest went unchecked`, which names no count.
- The exact-fill test: that same line was logged with nothing skipped.

After the change the same command printed `104 passed in 0.13s`, and
`python3 -m pytest` printed `1597 passed, 10 skipped in 9.85s` (the base was
1593 passed, 10 skipped).

## Ruled out

- **Removing the limit.** The gate runs on every project between two
  phases, and an unmeasured docs tree should not buy an unbounded number of
  `docker exec` calls.
- **A limit for the present docs apart from the task's own pairs.** The
  card says the present docs "share whatever budget is left". It also keeps
  the worst case for one run near one number.
- **A second grep for the fresh records.** One more container call per
  run, and `_scope` in the tests asserts one grep. `is_record` already
  tells the two kinds apart.
- **Patching `_POINTER_LIMIT` down in the tests.** A test against a patched
  5 would have passed or failed without regard to the real number. Sized
  off the constant, the tests cost a 1005-entry list and run in
  milliseconds.
- **Changing ADR 61's decision.** The build matches it, wording of the log
  line included. One phrase of it was reworded, see below.

## The gate's first catch was its own ADR

ADR 61 as the arquitecto appended it named the architecture doc in
backticks, as a path, while saying the file does not exist here. That is a
line this task added to a record, citing a path that is not there, nothing
tracks and nothing ignores: exactly what the gate now reports and, at 400,
never reached. The ADR is this cycle's own and unmerged, so the phrase was
reworded in place to name the doc without the path. This note avoids the
same spelling for the same reason.
