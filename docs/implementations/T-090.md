# T-090 — The read api serves a task's comment thread

Decisions: `docs/decisions.md` ADR 135. It covers:
- `GET /api/tasks/<task_id>/comments`, in the usual envelope;
- 404 as on the detail route, and an empty thread for no file;
- a bad line skipped and named by its line number;
- only the six known keys, and a count and a byte bound.

## What was built

- `observability/api/app.py`:
  - `GET /api/tasks/<task_id>/comments`: no parameters, bearer or Basic
    auth like every route. `data` is `{"task_id", "comments"}`, the
    comments oldest first, each `{at, author, text}` plus
    `{file, line, commit}` when the line has a whole diff anchor.
  - 404 for an id that is not bare, one with no task file, or one
    `comments_path` refuses. No `comments.jsonl` is `[]` with no warning.
    A file that will not open is `data: null` with a warning.
  - `_comment` parses one line. A line that is not JSON, not an object, or
    without a string `at`, `author` and `text` is skipped with
    `"<path>: line <n>: …, skipped"`. A broken anchor is dropped with a
    warning, and the comment is still served. Unknown keys are dropped.
  - `_comments_tail` reads at most `MAX_COMMENTS_BYTES` (1 MiB) from the
    file's end, from a whole line, and counts the prefix's newlines so
    line numbers are the file's. `MAX_COMMENTS` (500) keeps the newest.
    Both cuts are warnings.
- `docs/README.md`: the route in the api row.
- Tests, `tests/observability/test_api.py`:
  - The route in `ROUTES`, so it is covered by the 401, 400, envelope and
    bearer checks.
  - Comments written by `add_comment`, with and without an anchor, served
    as written, oldest first.
  - No file; no task file (404, with a planted file); ids that are not
    bare.
  - Bad lines (not JSON, an array, a missing or non-string key, non-UTF-8)
    skipped with their line numbers; a blank line skipped silently.
  - Unknown keys dropped; five broken anchors dropped with a warning.
  - The count cap and the byte cap, cut on a line boundary and mid-line.
  - An unreadable file; the route writes nothing.

## Why this way

- The envelope and not a top-level `comments`: every 200 of this api is
  `{data, warnings}`, and the console's client rejects any other 200.
- The 404 of `/api/tasks/<task_id>/usage`, since the page opens the task
  first.
- A byte bound besides the count, because one comment may be 20 000
  characters.
