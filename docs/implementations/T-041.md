# T-041 — whether a resumed call's `usage` is per call or per session

`T-024-D2` asked whether the figures on a `--resume` call's result count that
call or the whole session. Two real retries were already in the usage logs
ADR 53 writes, so this task reads them and records the answer.

Written by the arquitecto on 2026-10-14 against base commit `ffd252a`.

## Decisions

1. **The answer is `docs/decisions.md` ADR 64**, appended by the arquitecto.
   Token fields and `num_turns` are per call; `total_cost_usd` is cumulative
   over the session. For ADR 54's per-attempt total: tokens may be summed over
   an attempt's calls, and cost is the last call's figure. ADR 53 and ADR 54
   are not edited.
2. **T-030 decides the cost reading on its own and T-031 does not.** T-030's
   retry is below its phase on every token column and still has a larger
   `total_cost_usd`, which no per-call price allows. T-031's retry read more
   cache than its phase, so its rising cost fits either reading. ADR 64 says
   which pair proves what.
3. **The table was checked against the logs, not just copied.** Both
   `<hive_tasks_dir>/T-030/usage/calls.jsonl` and
   `<hive_tasks_dir>/T-031/usage/calls.jsonl` were read in this phase. The
   four lines match the card's table field for field, each pair shares one
   `session_id`, all four are `measured: true`, and every `raw_keys` lists
   `usage`, `num_turns`, `total_cost_usd` and `modelUsage`.
4. **No CLI version is on the line**, so ADR 64 calls "one CLI version" an
   inference from the date and account the two attempts share, not a
   recorded fact.
