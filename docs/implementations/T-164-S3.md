# T-164-S3 — role prompts and debt rules

Builds S3 of `docs/plans/debt-triage.md` (R1–R4); the decisions are ADR 393,
394 and 396, so no new ADR.

## What

- `dispatcher/project_docs.py`
  - `_ARQUITECTO`: never narrow a goal that spans surfaces and leave the rest
    as debt; the rest is the next sub-task. A mechanical fix is not a second
    surface (R1).
  - `_IMPLEMENTADOR`: `blocked_by` (a task id waits, a plan step is not filed),
    the next slice of the goal declared with its `fix` as the task, and a
    mechanical fix applied to every copy in the repo (R2, R3).
  - `_REVISOR`: `accepted` reserved for a deliberate shortcut or a found defect;
    `rejected` includes debt that only defers the mechanical fix; `follow_up`
    for the next slice, not a finding (R1, R4).
  - `_AUDITOR`: a `follow_up` entry is never filed.
- `docs/debt/README.md`: a "What is debt and what is not" block above the
  table (still the last block, ADR 297), and the `impact` paragraph no longer
  says every open entry is filed.
- `tests/dispatcher/test_project_docs.py`: four tests pinning those phrases.
- `docs/plans/debt-triage.md`: Status says S3 is built.

## Why this way

The prompts are pinned by substring, so each rule is one phrase a test checks.
The word "split" stays out of the implementador, revisor and auditor
(`test_no_other_role_is_told_about_a_split`); "next slice" and "next task"
carry it there. `_IMPLEMENTADOR` is `str.format`ed, so no braces were added.
In the auditor the `f` prefix stays on the line holding `{DEBT_DIR}`, and the
debt paragraph has no "card" (existing test).

## Ruled out

- A new ADR: ADR 393 already decides all of it.
- Telling the auditor about the `Blocked by <value>;` where-lead: the filing
  note already says it (ADR 396).
