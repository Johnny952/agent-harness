# T-100 — the action worker (ADR 142 split step 2)

## What was built

- `dispatcher/worker.py`: `acquire` (non-blocking `flock` on
  `actions/worker.lock`; `WorkerLocked` on a second holder), `Worker`
  (`beat`, `recover`, `tick`, `stop`, `join`, `run`), `run_worker` (the verb's
  body: lock, SIGTERM/SIGINT call `stop`, exit 2 when locked), and
  `HANDLERS = {"start": _start, "cancel": _cancel}` (ADR 148, 1).
- `dispatcher/cli.py`: the `worker` verb, no arguments.
- `dispatcher/queue.py`: `_account_open` is now `account_open`; its one
  caller, `wait_for_account`, was updated. No old name is kept.
- `dispatcher/actions.py`, the step 6 fix only: `recover` moves a final-status
  record from `pending/` as well as `claimed/` to `done/`; `claim` moves a
  record that is already final to `done/` unchanged and returns `None`, before
  `validate`. Tests: `test_recover_moves_a_final_record_left_in_pending` and
  `test_claim_refuses_a_final_record_left_in_pending` in
  `tests/dispatcher/test_actions.py`.
- `tests/dispatcher/test_worker.py`, with `run_task_cycle` faked.

## The loop

`run`: `recover`, then until `stop`: `beat`, `tick`, wait `POLL_SECONDS` (2s,
injectable), and at the end `join` every handler thread. `tick` runs the
pending `cancel`s first on the loop thread (ADR 148, 2), then the rest in name
order. An unknown kind goes to `done/` failed. A kind with no handler is left
as it is. A `start` whose project key is running waits `project`; with no
account open it waits `account`. `waiting` is rewritten only when it changes,
and `claim` clears it. The claimed start gets a non-daemon thread, registered
in `running` before the thread starts, so a second start for the same project
in the same pass waits.

`account_open` is paced (ADR 148, 5): a false answer closes the check for
`account_poll` (`queue.WAIT_POLL_SECONDS`), because it can probe every parked
account. The one clock read is `worker._utc_now`.

## Choices where ADR 142 left room

- ADR 148's five: handlers in `worker.HANDLERS`, `Kind.handler` untouched;
  cancels first; a cancel is idempotent (a rerun on a target it already
  cancelled ends done); shutdown ends a held start `interrupted`; paced
  account check.
- Result shape of a `start`: `outcome`, `blocked_reason` (only for BLOCKED),
  `noted_at`, and `last_phase` when cancelled. A HELD cycle with nobody
  cancelling or stopping is `done` with outcome `held`; the person starts it
  again.
- A comment the board refuses (`tasks.BoardWriteError`, which includes
  `NoTaskError`) ends the start `failed` before `started_at`: nothing ran.
  A blank note is not commented.
- `noted_at` is written after the comment and before `started_at`. A crash
  between the comment and that rewrite comments twice on the rerun; the
  window is one write, accepted.
- A cancel on a running `start` sets a flag the start reads in
  `may_start_phase`; the cancel ends `done` at once and the start ends
  `cancelled` at its next phase boundary. A cancel on a claimed
  `command_verdict`/`turn`, or one not in `running`, ends `failed`.
- A handler exception ends the action `failed` with one line
  `Type: message`, and always frees the serial key.
- `command_verdict` and `turn` are left pending, untouched (split items 8 and
  10). The heartbeat stays on disk at exit; staleness is split item 4's.
- The worker uses `actions._scan` and `actions._load`; renaming them breaks it.
- Shutdown waits for the phase in flight with no timeout; compose's stop grace
  decides whether it is killed, and then `recover` interrupts the claimed
  start.

Nothing in compose or the board service runs the verb yet.
