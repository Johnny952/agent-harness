# T-103: `GET /api/actions` (ADR 142 split step 4)

## What was built

- `observability/api/app.py`: the `GET /api/actions` route (`action_queue`),
  with the helpers `_action_records` and `_worker_heartbeat`, and the
  constants `DEFAULT_ACTIONS_DONE = 50`, `MAX_ACTIONS_DONE = 500` and
  `WORKER_STALE_SECONDS = 15 * worker.POLL_SECONDS` (30s). The module
  docstring's read-only list now names the actions read.
- `tests/observability/test_actions.py`, against `test_api.py`'s `_harness`
  in a tmp dir.

## The answer

`{data, warnings}`. `data` is:

- `pending`: every record in `actions/pending/`, in name order (the order the
  worker takes them), each with its `waiting`.
- `claimed`: every record in `actions/claimed/`, in name order.
- `done`: the newest `limit` records of `actions/done/` by name, newest first.
- `done_total`: how many files `done/` holds.
- `worker`: `{heartbeat, stale, stale_after_seconds}`. `heartbeat` is
  `worker.json` as written (`{pid, started_at, beat_at}`), or null.

`?limit=` is a positive int, 50 by default. Above 500 it is clamped, with a
warning, on the `MAX_EVENT_LIMIT` model. Any other parameter, or a bad
`limit`, is a 400.

The route never makes a directory or writes a file. It does not call
`actions.read_all`, because that calls `ensure_dirs`. It lists each directory
itself and parses each file with `actions._load`, so a record it serves is
one the worker would take. A file that does not load is a warning naming its
path, never a 500.

## Choices where ADR 142 left room

- `done` is ordered by name, which is creation order, not by `finished_at`.
  That way only the last `limit` names are opened, and the read stays bounded
  while `done/` grows unpruned. A bad file in that window still uses one
  slot, so `done` can hold fewer than `limit` records, and the warning says
  why.
- `done_total` is served so a reader can tell that history was cut off.
- A missing `actions/` directory, or a missing subdirectory, is an empty list
  with no warning. A host that never ran the queue has none. Any other
  listing error is a warning.
- The stale threshold is 15 beats of the worker's 2s poll, 30s. A pass that
  blocks on an account's `/usage` probe (up to 120s) reads stale until the
  pass ends. `beat_at` is served next to the flag, so a reader can tell a long
  pass from a dead worker.
- No `worker.json` means heartbeat null and stale true, with no warning: a
  stack can run without the worker. An unreadable file, or one that is not
  an object, is a warning and the same answer. A `beat_at` that is not an ISO
  time with a zone serves the heartbeat as written, with stale true and a
  warning.
- The pid is served but not checked. It belongs to the worker container's pid
  namespace, not the api's.
- The route imports the private `actions._load`, as the worker already does.
  It reads `worker.HEARTBEAT` and `worker.POLL_SECONDS` but calls nothing in
  the worker. No public helper was added to `dispatcher/actions.py`.
- `/api/actions` is not yet in `test_api.py`'s `ROUTES` list (the auth and
  envelope sweep). Adding it is a follow-up.

The front does not read the route yet.
