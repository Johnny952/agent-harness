# T-191 — integrador model/effort keys in the console config

The dispatcher already accepted and read `role_model.integrador` and
`role_effort.integrador` (`dispatcher/config.py` `_load_role_model`,
`_load_role_effort`; `resolve_conflict` passes `cfg.model_for/effort_for`).
Only `config_writer/app.py` `payload()` omitted it from the `roles` block it
serves, so the console (which renders that list) had no row and the writer
rejected the key.

## What changed
- `config_writer/app.py`: `role_model` and `role_effort` lists add
  `INTEGRADOR_ROLE`. `fallback_roles` unchanged (ADR 507, 2).
- `config.example.yaml`: `role_effort` comment names the integrador.
- Tests: writer serves and accepts the key, and `load_config` reads it back;
  `tests/dispatcher/test_integrador.py` covers its own key and the absent-key
  default.

## Ruled out
- Adding the integrador to `PHASE_ROLES`: it would also put it in
  `fallback_roles` and every other derived set (ADR 507).
- Front change: `front/src/routes/models.tsx` derives rows from the api.
