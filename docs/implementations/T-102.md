# T-102 — the board service's action routes

Step 3 of ADR 142's split. The contract is ADR 151 in `docs/decisions.md`,
which narrows ADR 142 where it left room; the worker side is ADR 148.

## What was built

- `board_service/app.py`: `POST /api/tasks/<task_id>/start` and
  `POST /api/actions/<action_id>/cancel`, both through one helper, `_action`,
  which runs the guards and turns `actions.create`'s result into 201 with the
  record. `create_app` reads `BOARD_ACTIONS_TOKEN` once and `cfg.state_dir`.
- `tests/board_service/test_actions_routes.py`: the cases of the card's Done
  when, plus the guard order, the case-insensitive scheme, an unwritable
  state dir, and that building the app writes nothing.

Nothing mounts the queue or sets the token yet (step 5, compose).

## Choices where ADR 142 left room (all ADR 151)

- The project is the start body's `project`; unknown body keys are 400.
- Ready is `task_id in ready_order(read_all_tasks(hive_dir))`; `project` is
  not read, since no task card carries one.
- A cancel's body is `{}`; the route does not look for the target on disk.
- Guards answer Origin 403, token 503/401, query 400, body 400, then
  `ActionRefused`'s own status.
- The queue directories are made by `actions.create` on the first create, so
  a service with no state mount still starts.
- Not in ADR 151, chosen here: an `OSError` writing the queue is 503
  `{"error"}` (the state dir is unavailable, not the caller's fault); a 401
  carries `WWW-Authenticate: Bearer`; an empty presented bearer is refused
  before the comparison.

## Ruled out

- Importing `observability/auth.py` (not in the board service's image).
- Reusing `test_app.py`'s `cfg` fixture: its `state_dir` is the real
  `/data/dispatcher_state`, so the tests build their own config with the state
  dir under `tmp_path`.
