# T-120 — the console's push settings

Decisions: `docs/decisions.md` ADR 246 (on ADR 237 and ADR 232).

## What was built

- `front/src/lib/api/forward.ts`: `GET /api/push/settings` is a read of the
  board service (`forwardPushKey` became `forwardBoardRead(path)`, used for the
  key and the settings); `PUT /api/push/settings` is a `boardTarget` write with
  `action: "push"`, so it gets the bearer, the CSRF checks, the 64 KiB cap and
  the body unchanged. Header and prose counts moved from twenty to twenty-one
  writes; `FORWARDED`'s "twenty-one routes" is the api's and was left alone.
- `front/src/lib/push.ts`: `PushSettings`, `QuietHours`, `PushSettingsChange`,
  `parseSettings`, `readSettings`, `writeSettings`, `browserZone`. A read says
  "cannot be reached" on a 502/504 or a failed fetch; a write sends only the
  fields present (`quiet_hours: null` counts) and throws "Nothing to save." for
  an empty change without fetching; a 400 is `The push settings were not saved:
  <server error>` through the existing `refusal`.
- `front/src/routes/notifications.tsx`: `PushSettingsSection` after
  `PushControl`. States `reading | unreadable | server-off | ready`, the key
  read alongside the settings; server-off disables every control. Kinds are
  ordered by `orderKinds` (the four needing the person, then the rest as
  served), because Flask serves them alphabetically. Quiet hours: a switch plus
  a draft (start, end, zone, default 22:00/07:00/browser zone) saved by a button;
  turning off a served window writes `{quiet_hours: null}`.
- Tests: `forward.test.ts` (settings read, PUT, 400 pass-through, CSRF,
  other methods, 503 without the token), `push.test.ts` (parse, read, write),
  `-notifications.test.tsx` (order, flip, window on/save/off, 400, 502,
  server-off). Two existing push-control tests no longer assert "no key read",
  since the settings section reads the key; they assert no subscription instead.

## Ruled out

- A UTC fallback when the browser zone is refused by a server without a tz
  database: the section shows the server's 400 instead.
- Types in `lib/api/types.ts` (out of scope, and the settings are not the api's).
- Saving the window on every field change: a half-typed window would be
  written; an explicit save button does it once.
