# T-118-S2 — the Board's Awaiting review column

Decision: `docs/decisions.md` ADR 243 (status itself: ADR 240).

## What was done

- `front/src/lib/api/types.ts` `TaskStatus` and `front/src/lib/board.ts`
  `KNOWN_STATUSES` gain `awaiting_review`, so the Board no longer warns about it.
- `columnOf`: the `merged` check stays first; then `awaiting_review` and `done`
  both return `review`. A `done` that reaches the switch is unmerged by the
  earlier check, so no second test is needed. Header comment rewritten; Other is
  now `drafted` and unknown words only.
- `front/src/routes/index.tsx` `Column`: the "not built" empty note and its
  ternary are gone; an empty column always says `empty`.
- `StatusPill`: `awaiting_review` is `warning` (waits on the person, neither
  terminal like `done` nor failed like `blocked`); `docs/ui.md` *The tone of a
  state* says so.
- `execution.ts` `inPlay` and `debt.ts` `ACCEPTED_STATUSES` include it.
- `docs/plans/board-service.md` section 8: the not-built line now says what the
  column holds; the integrador lane and step 9 stay not built.

## Why this way

One column for both statuses (ADR 243): an older `done` unmerged task waits on
the same person for the same merge, so splitting would put one kind of task in
two places. `warning` over `success` because `done` is terminal.

## Ruled out

- A new column or a migration of old `done` files: the dispatcher does not
  rewrite them and the column rule covers both.
- Touching `/approvals` and `review.ts`: T-118-S3, so Board and Approvals
  disagree on `awaiting_review` tasks until then.

## Tests

`board.test.ts` (placement, merged first, Other without `done`),
`-index.test.tsx` (no "not built", both statuses in `review`, no unknown-status
warning), `primitives.test.tsx` (warning tone), `execution.test.ts` (in play,
merged not), `debt.test.ts` (accepted). Front typecheck, lint and test pass:
794 tests. `prettier --check src` was refused as a bare command; the lint
script runs prettier through eslint and passes.
