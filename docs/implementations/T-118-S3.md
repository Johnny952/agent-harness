# T-118-S3 — Approvals "Awaiting review" reads `awaiting_review`

Decision: `docs/decisions.md` ADR 249.

## What

- `front/src/lib/review.ts` `reviewLane`: `conflict` first and unchanged;
  then `awaiting_review` or `done` with `merged === false` is `review`;
  everything else (including `awaiting_review` with `merged: true`) is `null`.
- `front/src/routes/approvals.tsx`: header comment drops the "no status yet"
  note and names `awaiting_review` or an older `done` (ADR 240, ADR 249). No
  code change.
- `front/src/lib/review.test.ts` and `front/src/routes/-approvals.review.test.tsx`
  cover `awaiting_review` merged and unmerged; the route test now expects
  rows `T-1`, `T-5` and tab "Awaiting review · 2".

## Why this way

`done` stays in the list so tasks finished before the status existed still
show up; `merged` still gates both, matching the Board's `columnOf` (ADR 243).

## Verified

`bun install --frozen-lockfile`, `bun run typecheck`, `bun run lint`
(eslint runs prettier as a rule) and `bun run test` (815 passed) all pass.
`bunx prettier --check src` was refused in the phase, then run by the
operator: all files match Prettier style.

## Ruled out

Dropping `done` from the list (would hide pre-existing finished work);
changing the `TaskStatus` type (S2 already added `awaiting_review`).
