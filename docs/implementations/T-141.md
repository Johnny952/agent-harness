# T-141 — the `size` gate

Built to `docs/decisions.md` ADR 309.

## What

- `dispatcher/gates.py`: `SIZE = "size"`, `SIZE_NOTE_LINES = 800` (provisional),
  `_measured`, `_line_counts`, `_oversized`, called from `run` in the fork-point
  branch after `_contracts_without_docs`. One NOTE per touched, non-test Python
  file whose `wc -l` is past the constant; the detail names path and count.
- `tests/dispatcher/test_gates.py`: `_Worktree` answers `wc -l --` (with a
  `total` line, like wc) and takes `sizes`. Six tests: at the threshold, past it
  (NOTE, no block, no ask), untouched large file, deleted file, test/non-Python
  files (no `wc` call at all), untracked new file.
- README Future work item 1 bullet marked built; `docs/README.md` gates row.

## Why this way

Lines are counted in the container with one `wc` per 100 paths, like the
pointers gate's `ls`, so no file is read into the dispatcher. A path wc cannot
open (deleted) is simply absent from the answer, so deletion needs no separate
git query. The constant is not a config key (ADR 309).

## Ruled out

A hard cap or blocking level (out of scope); config key; other languages.

## Known edges

`wc -l` counts newlines, so a file without a trailing newline is one short;
git-quoted non-ASCII paths are not found and stay silent. At 800 the note fires
on most dispatcher/ edits (this task's gates.py included).
