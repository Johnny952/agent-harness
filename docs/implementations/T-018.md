# T-018 — the knob was `routeFileIgnorePrefix`, and the fix was a decision

One sentence of `front/README.md` was wrong, and correcting it was not an
edit. It named `routeFileIgnorePattern` as the reason a test may not live
under `front/src/routes/`, and said that knob is set in the
Lovable-generated `front/vite.config.ts` which `docs/charter.md` **C-9**
keeps off-limits. Both halves are false, and the bullet was the prose form
of `docs/decisions.md` **ADR 30**, whose *Context* says the same thing —
while **ADR 44**'s third bullet had already shipped three tests in the place
ADR 30 says none can go. Two accepted entries disagreed, so the first thing
this task owed was a ruling: `docs/decisions.md` **ADR 45**, appended by the
arquitecto. Everything below it is transcription. The build order was
`/data/.hive/tasks/T-018/plan.md`, outside the repo and gone with the task.

No source behaviour changed. `front/vite.config.ts`, every statement in
every `.ts`/`.tsx`, every test and `front/src/routeTree.gen.ts` are
untouched; the two `.tsx` files in the diff are docblock comments and
nothing else in them moved.

## The mechanism, read rather than repeated

The card asked for the generator's actual behaviour, not the card's account
of it. `cd front && bun install --frozen-lockfile` → `Checked 512 installs
across 549 packages`, and then, in `front/node_modules`:

So the four files already in the tree — `front/src/routes/-index.test.tsx`,
`-learnings.test.tsx`, `-debt.test.tsx`, `-tail.test.tsx` — rely on a
**default** and not on configuration. C-9's off-limits file is not in the way
at all, which is half of what ADR 45 establishes. `-index.test.tsx`'s own
header has said so since `bc93b1d`.

ADR 45 names which half of ADR 30 was wrong: its **premise**, that reaching
a one-screen renderer from a test costs either a `vite.config.ts` edit or a
move. Its **decision** stands — being unreachable from a test is a reason to
promote a component — because that decision was never about the generator.
The condition it fires on goes from "always, under `src/routes/`" to almost
never. ADR 30 and ADR 44 are append-only and were not touched: ADR 30 keeps
its number, its `**Status:**` line, its wrong *Context* and an unstruck
heading, per
`docs/learnings/a-stale-count-in-a-dated-paragraph-is-not-a-finding.md`.

## What was ruled out

- **Editing ADR 30 or ADR 44.** The card says append-only, and a narrowing
  entry is this project's own form for it. A strikethrough would also lose
  the record of how a plausible wrong knob survived from T-013 to T-018.
- **Adding `routeFileIgnorePattern` to `front/vite.config.ts`.**
  Unnecessary — the prefix default already does it — and C-9's to forbid.
  ADR 45 says both.
- **Moving `payload.tsx` or `console/learnings.tsx` back into their
  routes.** ADR 45's last bullet rules on it: the first is right under the
  third bullet anyway, the second was promoted under a trigger this entry
  retires, and re-deriving green tests to undo a move is churn.
- **A test to prove the mechanism.** The proof is four files already passing
  under `src/routes/` and no mention of any of them in
  `front/src/routeTree.gen.ts`; a new test would assert a dependency's
  behaviour, which is the dependency's business.
- **ADR 24's parenthetical** that `front/node_modules` "does not exist in
  this repository and installing it is not authorised" — false of a phase
  whose task grants `bun install`, which is how ADR 45's *Context* was read.
  It is an ADR on `main` and a different subject, so it is another task's
  narrowing, and ADR 45's *Consequences* says so rather than leaving it for
  a later round to re-raise.

## The `tests-in-diff` answer

The dispatcher's gate asked for a test beside
`front/src/components/console/payload.tsx` and
`front/src/components/console/learnings.tsx`, correctly: it pairs a changed
file with a test in the same language since `docs/decisions.md` **ADR 31**,
and the only `.tsx` files in this diff are those two. The one-line answer:

> **Both hunks lie entirely inside each file's leading docblock comment: no
> statement, import, export or identifier changed, so there is no behaviour
> for a test to pin.**

It is recorded here and not only in the handoff because the gate's question
gets asked again by the next reader of the diff
(`docs/learnings/a-referential-stability-fix-in-front-is-answered-not-tested.md`
*What to do*). This is a stronger case than the one that entry describes:
that shape is a code change with no DOM difference, where something did
execute differently and the argument is that nothing observable moved. Here
nothing executes differently at all. The evidence either way is the same
three numbers, unchanged from the baseline: 73 tests passing, `tsc --noEmit`
silent, nine lint warnings at nine unmoved positions.

Writing a test to clear this gate would mean pinning `PhasePill`,
`PhaseList` or the learnings cells — renderers this task did not touch and
which already pass — which the same entry says not to reach for.
