# T-119 — push settings and quiet hours, server half

Decisions are ADR 237 (`docs/decisions.md`); the build followed it unchanged.

## What was built

- `dispatcher/push.py`: `push-settings.json` store (`settings_path`,
  `read_settings`, `update_settings`, `default_settings`, `in_quiet_hours`,
  `SettingsRefused`). The file holds only what the person set; the effective
  settings are the table's defaults overlaid by it, so a kind added to
  `notifications.KINDS` later takes its default. Writes go through the
  existing `_lock` and `_write_json` (0600), and merge: the kinds a PUT names
  are set, the rest stay.
- `Notifier._tick` reads the settings each pass. In quiet hours it returns
  before `_new_records`, so the cursor stays and the file is the queue; the
  first pass after the end reads everything and the existing grouping makes
  one push per kind. `_pushes` filters on the settings' kinds instead of the
  table's default; a skipped record's cursor still moves. `wall_clock` is the
  new injectable seam (aware UTC), beside `clock` which stays the monotonic
  grouping clock.
- `board_service/app.py`: open `GET` and bearer-guarded `PUT`
  `/api/push/settings`; a refusal is 400 `{"error"}`. No POST alias.
- Tests: `tests/dispatcher/test_push.py` (defaults, bad file, validation,
  midnight window, kind off, held then sent, inbox byte-identical) and
  `tests/board_service/test_push_routes.py` (routes, and the PUT added to
  `CALLS` for the bearer/origin/no-token/non-object guards).
- `tests/board_service/test_push_routes.py` no longer imports `cryptography`
  at module level: the key fixture writes a placeholder when it is missing and
  the three tests that need a real key `importorskip` it. The full suite now
  collects in this container (3981 passed, 15 skipped).

## Ruled out

- Holding pushes in memory (a restart would lose them); storing every kind on
  each write; replacing the whole document on PUT (see ADR 237).
- Adding `tzdata`: only `UTC` is accepted on a host without a tz database.
