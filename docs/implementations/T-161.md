# T-161 — a colon in a frontmatter value no longer drops the learning

Spec: `docs/decisions.md` ADR 378.

## What

- `dispatcher/learnings.py`: `_split` now splits first, then calls
  `yaml.safe_load`; on `yaml.YAMLError` it uses the new
  `_fallback_frontmatter`. The fallback reads `key: value` lines (first `:`
  followed by a space or end of line), skips blanks and `#` lines, drops an
  inline ` # comment`, removes one pair of surrounding quotes, and answers a
  dict of strings only when `project`, `task` and `when` are all non-empty.
  Otherwise `None`, so `_read_entry` logs the same warning as before.
- `_WRITE` gained one sentence: keep `when:` on one line, quote it when it
  contains `: `.
- `tests/dispatcher/test_learnings.py`: colon-in-`when` tracked (with the
  `scope: project        # or harness` comment), quote removal, missing
  required keys and no frontmatter both untracked with the warning, valid
  YAML parsed as `yaml.safe_load` does, valid YAML without `when` still tracked.

## Round 2

`_split` now catches `(ValueError, yaml.YAMLError)` around `yaml.safe_load`.
An impossible date such as `when: 2026-02-30` makes SafeLoader raise a bare
`ValueError`, which escaped `_read_entry` and stopped `read_inbox` for every
entry. It now goes to the line-by-line fallback. Regression test:
`test_an_impossible_date_does_not_stop_the_read`.

## Why this way

The fallback runs only when YAML fails, so valid files parse exactly as
before and the required-key rule cannot reject anything that parsed.
The T-159 inbox file is picked up on the next read with no edit.

## Ruled out

- Making the required keys apply to YAML too: changes behaviour for files
  that already work.
- Repairing inbox files: out of scope.
