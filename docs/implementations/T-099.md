# T-099 — the action queue (`dispatcher/actions.py`)

Step 1 of ADR 142's split (`docs/decisions.md`, ADR 142). A file queue under
`<state_dir>/actions/` (`tmp/`, `pending/`, `claimed/`, `done/`, `write.lock`).
Nothing calls the module yet; the worker (step 2) and the board service
(step 3) are later tasks.

## What was built

- `dispatcher/actions.py`: `ensure_dirs`, `new_id`, the `KINDS` registry
  (`start`, `cancel`, `command_verdict`, `turn`; each a `Kind` with `validate`,
  `serial_key`, `spends_quota`, `recovery`, `interrupted_error` and an empty
  `handler` slot), `validate`, `serial_key`, `create`, `read_all`, `claim`,
  `rewrite`, `finish`, `recover`, and `ActionRefused(status, reason)`.
- `tests/dispatcher/test_actions.py`: create atomic and in pending, id order,
  claim once, every refusal, each kind's recovery rule, unknown kind, and
  `read_all` skipping bad files.
- Stdlib only. The temp-then-`os.replace` write follows
  `state_machine._write_state`; the `flock` follows `state_machine._locked`.
  `_utc_now` is the module's only clock read.

## Choices where ADR 142 left room

- **Ready check is an injected callable.** `create(..., ready=callable)` calls
  `ready(task_id)` for a `start`, inside `write.lock`, because decision 7 has
  the check and the create under one lock. This keeps the module free of the
  hive. `ready=None` skips it; the board-service route (split item 3) must
  pass it, or a non-Ready start is only caught by the worker or `open_cycle`.
- **Refusals** are `ActionRefused` with `.status` (400 or 409) and `.reason`.
  400: unknown kind, any validation problem. 409: a duplicate, a task not Ready.
- **Duplicate rule:** same kind and same `task_id` among `pending/` and
  `claimed/`, for `start` and `command_verdict` only. A start does not refuse
  a verdict on the same task.
- **`read_all` returns `(entries, warnings)`**; an `Entry` is `(state, record)`.
  A file that does not open or parse, is not an object, has another `version`,
  or whose `id` is not its name is skipped and named. Unknown kinds are
  returned, not skipped, so `recover` can fail them.
- **Validation also runs on `claim`**: a bad or unknown-kind record is
  finished `failed` with the problems as `error`, and `claim` returns `None`.
  A file that cannot be parsed stays in `claimed/`.
- **`finish` is rewrite, then rename** into `done/`. A crash between leaves a
  final-status record in its old directory; `recover` moves it to `done/`.
  `finish` takes the record from `claimed/`, then `pending/` (a cancelled
  target, an unknown pending kind).
- **Kind shapes beyond the table in the card:** `cancel` and `turn` need a
  null `task_id`, `cancel` a null `project`; `start` normalises `params`
  `None` or `{}` to `{"limit": None}`; `note` is for `start` only; `actor` is
  a non-empty string without whitespace. `command_verdict` mirrors
  `command_run.run_command_request` (`prefix` only with `allow`).
- **Slug rule** is copied from `project_keys._check_slug`, not imported (it is
  private).
- **Ids** are monotonic only as far as the clock is; the id is taken under
  `write.lock`, so two creates do not share a microsecond in practice.
- **No file mode** is set (as `_write_state`). If the board service runs as a
  different uid from the worker, temp files made by `tempfile.mkstemp`
  (mode 0600, used by `rewrite`/`finish`/`claim`) may be unreadable to others;
  split item 5 should check the uids.

## Ruled out

- A lock in the worker primitives: ADR 142 has one creator and one mover.
- `fsync`: not used by `_write_state` either.
- Importing the hive for the Ready check.
