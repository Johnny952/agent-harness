# T-045-S1: role_model refuses cartografo

## What
`_load_role_model` in `dispatcher/config.py` now refuses a `cartografo` key
with a ValueError naming `role_model` and `mapping_model`. Other unknown keys
still raise the unknown-roles error, now listing the four accepted roles
(`PHASE_ROLES` minus `project_docs.MAPPER_ROLE`). Decision: ADR 66 in
`docs/decisions.md`.

## Why this way
- `PHASE_ROLES` is untouched: `role_effort` still accepts `cartografo`.
- The cartografo check comes before the unknown-role check so its message is
  the specific one, not a generic "unknown role".
- The accepted set is computed inside the function, not a new module constant:
  one use, so no new name.

## Ruled out
- Narrowing `PHASE_ROLES`: would break `role_effort`.
- Silently dropping the key: a dead entry is the very bug being fixed.

## Tests
Three added to `tests/dispatcher/test_config.py`: cartografo refused (match
`mapping_model`), four roles load together, unknown-role message lists exactly
the four roles. `python3 -m pytest`: 1621 passed, 10 skipped.
