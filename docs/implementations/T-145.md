# T-145 — operator reads the refusal hold

Resolves debt T-143-D1 (ADR 312 point 6, ADR 318).

## What

`dispatcher/operator.py` no longer computes a refusal's hold itself.
`account_reports` and `release_account` call `dispatcher._refusal_hold_until`,
the one copy of the rule (recorded `retry_at`, else refusal time plus
`quota_cooldown_seconds`).

- `_cooldown_remaining(hold_until, now)` is `max(0, hold_until - now)`.
- `AccountReport.hold_until` carries the instant for `format_status`.
- Status says `refused, held until <UTC instant> (<d> left)`; `release-account`'s
  refusal says `is held until <instant> (<d> left)`. `_instant` formats it.

## Why this way

Importing the private rule, as `_threshold_for` already is, keeps a single
definition; reimplementing it in operator.py is how the two drifted. Showing an
instant, not only a duration, is accurate when `retry_at` is hours away.

## Ruled out

Calling `state_machine.get_retry_at` directly in operator.py: a second copy of
the fallback rule. Keeping the `quota_cooldown_seconds` wording: wrong once
`retry_at` is used.

## Tests

`held until`; new `test_a_recorded_retry_at_outranks_the_cooldown_in_status_and_release`.
