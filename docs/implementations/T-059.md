# T-059: the Coolify compose mounts the deploy keys

The rule is `docs/decisions.md` ADR 91; this is the plan, and the implementador
records what was built under *What was built* below.

## Plan

All edits are text; no code under `dispatcher/` changes.

1. `docker/compose/docker-compose.agents.yml`, the comment above the
   `git-credentials` mount on `agent-cuenta1`: replace "and needs no write
   scope." with words saying the token needs read access, and write
   (contents) access for a project the dispatcher pushes
   (`docs/decisions.md` ADR 78). Comment only; no mount line changes.
2. `docker/compose/docker-compose.coolify.yml`:
   - `dispatcher.volumes`: add
     `../../.data/credentials/projects:/run/secrets/projects` (no `:ro`),
     after `claude_shared`, as `docker-compose.yml`'s dispatcher has it, with
     a short comment: writable here so `project-keygen` can write a pair; see
     docker-compose.yml's dispatcher / docker-compose.agents.yml.
   - `agent-cuenta1.volumes`: add
     `../../.data/credentials/projects:/run/secrets/projects:ro` with a short
     comment pointing to docker-compose.agents.yml's agent-cuenta1 comment.
   - `agent-cuenta2.volumes`: the same line, under a comment in the file's
     existing style ("See agent-cuenta1 above.").
   - Header: the bullet "Cloned project repos still bind-mount
     `<repo-root>/.data/projects`" also names
     `<repo-root>/.data/credentials/projects`, the deploy keys; say the
     https:// `git-credentials` file is not mounted here (ADR 91).
3. `scripts/configure.sh`, `render_coolify_compose`: the agent pairs are
   rendered from two heredocs there (the first account's and every other's),
   and `tests/scripts/test_configure.py`
   `test_the_default_pool_renders_the_shipped_coolify_file` holds the
   cuenta1/cuenta2 render byte-equal to the shipped file. So both heredocs
   get the same comment and `/run/secrets/projects:ro` line as the shipped
   agents, character for character (`$name`/`$first` where the shipped file
   says cuenta1/cuenta2). The dispatcher and header are copied from the
   shipped file by the awk, so they need nothing here. Not in the card's
   *Surface*, but required by its own *Done when* (`pytest` green); the
   renderer is the Coolify file's other half, not another compose file.
   - `tests/scripts/test_configure.py`
     `test_a_rendered_coolify_pool_holds_the_agents_file_invariants`: its
     docstring says the shipped Coolify file mounts no
     `/run/secrets/projects`, which stops being true; drop that sentence and
     call the deploy-key check on the render there too.
4. `README.md`, *Deploying with Coolify*: one bullet or sentence saying a
   private project is reached through its deploy key from `project-keygen`
   (mounted from `.data/credentials/projects`), added to the repository with
   write access when the project pushes; no https:// token file on this path.
5. `docs/plans/projects.md`, *What exists today*, the SSH bullet: after the
   sentence "`docker-compose.coolify.yml` mounts neither credential." append
   an indented `*Narrowed 2026-10-17:*` note (the style of *Decisions*, 5):
   since T-059 it mounts the deploy keys, not the https:// file
   (`docs/decisions.md` ADR 91). Do not rewrite the sentence.
6. `tests/integration/test_compose_invariants.py`: parametrize
   `test_every_agent_mounts_the_deploy_keys_read_only` over
   `docker-compose.agents.yml` and `docker-compose.coolify.yml`, and
   `test_the_dispatcher_mounts_the_deploy_keys_writable_at_the_agents_path`
   over `docker-compose.yml` and `docker-compose.coolify.yml`, the way the
   other tests in the file are parametrized. Assertions unchanged. Give the
   agents test's `compose_file` parameter the default
   `"docker-compose.agents.yml"`: `test_configure.py`
   `test_a_rendered_pool_holds_the_compose_invariants` calls it with no
   argument, and also add a call there with `"docker-compose.coolify.yml"`.
7. Run `python3 -m pytest`.
