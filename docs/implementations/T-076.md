# T-076 — the held resume of a command-request verdict (command-requests step 4)

Decisions: `docs/decisions.md` ADR 120 (`dispatch command-resume`; the prompt
rebuilt from the verdict entry and the log, never by running the command
again; `ran` and `resumed_at` on the verdict entry, and why `resumed_at` is
set when the resumed phase takes the lock; how an entry without them is read;
the block put back after a held resume; a pinned phase that found its account
taken read as held).

## What was built

- `dispatcher/command_run.py`: `resume_command_verdict(cfg, task_id, slug) ->
  CycleOutcome` and its refusals as `VerdictRefused`; `awaits_resume`, which
  the CLI asks to name the next command; `_block_verdict`; `_logged_run`,
  which reads a *run* back from the entry's `ran` and `commands/<n>.log`, or
  from the log's header for an entry without `ran`; `_settle_resume`, which
  `_resume` calls right after `run_phase` (it now takes `filed_at`) to record
  `resumed_at` or put the block back. `run_command_request` keeps `ran` on
  the entry right after the run.
- `dispatcher/tasks.py`: `update_command_verdict`, which merges fields into
  the verdict on one block.
- `dispatcher/cli.py`: the `command-resume` subcommand, `<task> --project
  <slug>`; a refusal prints `resume refused: <reason>` and exits 1.
  `_exit_on_resumed_outcome`, shared with `command-verdict`: blocked 1, held
  75 (naming `command-resume` when the task awaits one), split 3.
- `dispatcher/dispatcher.py`: `run_phase` reads `no_account` on a call pinned
  to an account as held, so a held cartografo resume no longer hands the task
  on to the arquitecto.
- Tests: `tests/dispatcher/test_command_run.py`, with the fake
  `dispatch_phase` and the fake `docker exec` — a verdict that resumed
  records `ran` and `resumed_at`; a held run resumed with the same prompt and
  zero exec calls, on through revisor and auditor to finished; the same for a
  non-zero exit, a timeout and output over the cap; a held deny resumed with
  its comment; a resume held again staying resumable; every refusal (not
  blocked, no verdict yet, already resumed while still blocked, no session on
  record, a second resume after one that ran); a resume that took the lock
  and failed not resumed again; a rate limit inside the pinned call putting
  the block back; an entry without `ran` rebuilt from its log for each kind
  of run; a missing log and a log for another argv refused with no exec; a
  held cartografo resume staying blocked, then resumed on to the arquitecto;
  the CLI's held message naming `command-resume`, and `command-resume`'s
  held, finished and refused exits.
- Docs: ADR 120; in `docs/plans/command-requests.md`, *Amended 2026-10-18*
  notes under step 4 and decision 5.

## Why this way

- The verdict stays recorded before the run, and the resume never runs the
  command, so the command runs once whatever happens to the resume.
- `resumed_at` is set when the resumed phase took the task's lock: that is
  when the session may run. A held resume has not reached it and stays
  resumable; a crash after it leaves the task off its block, which the
  status check refuses, so no session is resumed twice.
- `ran` holds the run's facts and not its output, which is already in the
  log; the log's header covers entries written before `ran`.
- One exit helper for both commands, so a held verdict and a held resume say
  the same thing.

## Pending

- An exception inside `dispatch_phase` after it took the lock leaves the task
  `in_progress` with no owner and no `resumed_at`; `command-resume` refuses it
  on status, and it is moved on with `run-phase`. The session may have partly
  run, so this is left to the operator.
- A resume on another account than the phase's (left to the board service's
  worker), *Allow* and the allowlist (step 5), the Approvals card (step 6).

## Ruled out

- Running the command again to rebuild the prompt.
- Setting `resumed_at` before the resume (a held one would be stranded) or
  after the cycle (a crash mid-cycle would allow a second resume).
- Copying the output into the task file's frontmatter.
- Allowing a second verdict on the block instead of a resume of the first.
