# T-146 — sign-in in the board service

Contract: `docs/decisions.md` ADR 324. Step 1 of `docs/plans/server-deployment.md`
*How it would be built*.

## What was built

- `board_service/signin.py` (stdlib + flask): scrypt hashing, RFC 6238 TOTP,
  the users store (`users.json`), sessions (`sessions.json`, keyed by sha256 of
  the id), the append-only `audit.jsonl`, and `install(app, auth_dir)`, which
  registers `POST/GET/DELETE /api/session` and one `before_request` hook.
- `board_service/app.py` `create_app`: one `signin.install(...)` call, with
  `BOARD_AUTH_DIR` read once. Unset, sign-in is off (503) and a cookie is ignored.
- `tests/board_service/test_signin.py`: good sign-in, wrong password, unknown
  name, wrong and replayed code, lockout and release, idle and fixed expiry,
  unknown cookie, missing and wrong CSRF, reviewer vs owner, sign-out, the
  machine path unchanged, off switch, `create_user` refusals, file modes, and a
  sweep that no response body or audit byte holds a password, code, hash, TOTP
  secret or session id (and `sessions.json` no live id). Each asserts its audit line.

## Why this way

- The whole sign-in runs under the `flock`, scrypt included: it serializes
  sign-ins, which is fine for a handful of people and makes the failure count
  and the replay step race-free.
- Tests use `use_cookies=False` and send the `Cookie` header: the cookie is
  `Secure` and the test client speaks http, so a jar would drop it.
- Tests lower `SCRYPT_N`/`SCRYPT_P`; one test checks the defaults.
- The submitted name is logged only when it matches a stored user, so a
  password typed into the name field never reaches the log.

## Ruled out

argon2/bcrypt (new compiled dependency); a signed cookie (not revocable);
requiring a session on every route (would lock the console out before step 2);
per-address throttling (needs `X-Forwarded-For` from step 2).

## What step 2 must do

Forward the cookie, `X-CSRF-Token` and `X-Forwarded-For`; refuse requests with
no session; wire `BOARD_AUTH_DIR` to a volume in both compose files; build the
first-user command on `signin.create_user`. See ADR 324 *Consequences*.
