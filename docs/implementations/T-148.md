# T-148 — short "continue" prompt after a rate limit

Rule: `docs/decisions.md` ADR 330. Code: `dispatcher/dispatcher.py`.

## What was built

- `_CONTINUE_PROMPT`, `_served_a_turn`, `_resume_refused` beside
  `_with_resume_notes`.
- `dispatch_phase` keeps three loop locals: `handed_on_by_limit`,
  `session_briefed`, `prior_auth_handover` (the last only picks the log
  reason). A rate-limit handover sets the first two; an auth handover
  clears the first.
- The attempt's prompt is decided before the "goes to account" INFO line so
  the line carries the suffix (`with the short continue prompt` or
  `with the full prompt (<reason>)`). The old text stays as a prefix.
- A refused resume (`no conversation found`) after a rate-limit handover
  triggers one `exec_claude` with the full prompt, no resume, recorded as
  `phase-restart`. Both calls share one `exec_kwargs` dict.
- Tests: seven new functions (one parametrised over three no-turn shapes) in
  `tests/dispatcher/test_dispatcher.py`, using `_scripted_phase`.
- README: item 3 marked built; one sentence in the Core failover paragraph.

## Why this way

The short prompt needs proof the session holds a briefing: a served turn
(`num_turns` > 0) is that proof, and it sticks once seen. Everything else
keeps today's behaviour, so a wrong guess costs no more than before.

## Ruled out

- Probing the transcript before resuming (ADR 330, Ruled out).
- Short prompt on every resume (auth and verdict resumes are out of scope).

## Not verified

- The CLI's refused-resume wording `No conversation found` is as remembered,
  never observed here; and `num_turns` on a limit hit before any turn is
  unmeasured. Both fall back to today's behaviour if wrong.
- `python3 -m pytest tests/dispatcher/test_dispatcher.py`: 559 passed.
