# T-186-S1 — forward and client for the credentials read and writes

Contract: `docs/decisions.md` ADR 483 (on ADR 468 and ADR 471).

## What was built

- `front/src/lib/api/forward.ts`: `"/api/credentials": []` in `FORWARDED`
  (no parameter, not `PROJECT_SCOPED`); three `POST` pairs in `boardTarget`
  with a new `action: "credential"` — the exact `/api/credentials/git-token`
  and two entries of the `actionRoutes` table (`/api/accounts/<name>/login`,
  `/api/actions/<id>/login-code`). In `forwardBoard` the action only adds the
  bearer, the 503 ("credential routes") and the shared 64 KiB cap: the body is
  never parsed or rebuilt, so the console holds a token or code nowhere.
- Counts: api reads twenty-one -> twenty-two (header, `resolveTarget` comment
  and its pinned 404); board writes twenty-four -> twenty-seven (recounted:
  21 + 3 push + 3 credential).
- `types.ts`: `CredentialsSnapshot` and its row/state types, `LoginCodeResult`.
- `client.ts`: `getCredentials` (`readEnvelope`), `renewGitToken`,
  `startAccountLogin`, `sendLoginCode` (`readBare`, whose errors are built from
  path, status and the service's `error`, so none holds a secret).
- `queries.ts`: `credentialsQuery`, polled at `POLL_MS * 2`. No mutations.
- `front/AGENTS.md`: the whitelist bullet no longer carries a stale count.

## Tests

`forward.test.ts`: the read (bearer, no `?project=`, 405s), each write
(path, bearer, body byte-for-byte, re-encoding, `%zz` 404, other methods,
CSRF), the 503s without `BOARD_ACTIONS_TOKEN` and without `CONSOLE_PROJECT`,
and a secret-never-echoed test over the 415, 403, 413, 502 and 504 answers
and every `console.error` call.

## Ruled out

- Parsing the body to check the token or code (ADR 483 ruled-out list).
- Shape-checking the name or id in the forward: the board service answers 404/409.
- Mutation helpers in `queries.ts`: the screen sub-task decides invalidation.
