# T-094 — The task page's description, comments and epic view

Decisions: `docs/decisions.md` ADR 139. It covers:
- the description's sections, mirrored from `parse_description`, with the
  raw text as the fallback;
- the comment thread and form, `{text}` only, with the code-point limit;
- the title and epic link in the header, and the phase with its stale flag;
- the epic view from one `/api/tasks` read, and its progress rule.

## What was built

- `front/src/lib/description.ts`: `parseDescription`, the sections in the
  dataclass order or the dispatcher's reason.
- `front/src/lib/comments.ts`: `MAX_COMMENT_CHARS`, `commentLength` (code
  points), `commentProblem` and `commentAnchor`.
- `front/src/lib/epic.ts`: `epicChildren` (split order, `null` for a missing
  child), `epicProgress` (merged, total less dropped, dropped, missing,
  settled) and `childDependsOn`.
- `front/src/components/console/task-description.tsx`: the sections over
  `Markdown`, or the raw text with the reason; absent and empty states.
- `front/src/components/console/task-comments.tsx`: the thread (loading,
  error, unreadable, empty) and the form with its counter, its checks and
  its toasts, through `commentTaskMutation`.
- `front/src/components/console/task-epic.tsx`: the children with links,
  status, the merged chip and "after T-x"; the progress line.
- `front/src/routes/tasks.$taskId.tsx`: the title and epic link in the
  header, the phase field, and the description, epic and comments regions.
- Tests:
  - `front/src/routes/-tasks.test.tsx` (41): the header, the description
    region, the thread, the form's post, limit, blank check and error toast,
    the phase (live, stale, between phases), and the epic view (order,
    missing child, links, progress, one read, absent on a sub-task).
  - `front/src/lib/description.test.ts` (6), `front/src/lib/comments.test.ts`
    (5), `front/src/lib/epic.test.ts` (5).
- `bun run typecheck`, `bun run test` (283 passed, 18 files) and
  `bun run lint` pass.

## Why this way

- The parser is copied rule for rule so the page never shows sections the
  dispatcher would refuse, and a refused text is still readable.
- The limit counts code points so the form never passes a text the service
  refuses for length.
- One list read for the epic: every row a child needs is already in it.

## Pending

- `parseDescription` splits lines on `\r\n`, `\r` and `\n`; Python's
  `splitlines` also splits on `\v`, `\f`, ` ` and a few more, so a text
  holding those could parse differently.
- The comments' authors are whatever the service wrote; the page does not
  check them.

## Compose

No change.

## Ruled out

- A separate epic route, a read per child, and an author field in the form
  (ADR 139).
