# T-026 — the task module, the description in its own file, and `dispatch migrate`

This task builds the first half of step 1 of `docs/plans/board-service.md`,
*How it would be built*: `dispatcher/tasks.py`, the description moved out of
the task file into a `description.md` on the board, and the `migrate` verb.
The prompt change to *Goal* and *Done when*, and moving the dispatcher's
other task-file writes onto the module, are the next task. No ADR, per the
card.

Three things the card does not say:

1. `_open_kanban_issue` is a third read of the description in
   `dispatcher/dispatcher.py`: it titles the card from the description's
   first non-blank line, which with sections is `## Goal`.
2. The live descriptions come in four YAML scalar styles (plain, `|`, `|-`,
   double-quoted), so the key cannot be cut out of the frontmatter as text.
3. Every `context_transfer` writer is read, mutate, `write_task_file`. Once
   `read_task_file` stops carrying the key, each of those writes silently
   deletes an unmigrated description, and `reap_expired_locks` rewrites
   *other* tasks' files at the top of every cycle.

## What was built

- **`dispatcher/tasks.py`** (new).
  - `board_root` and `description_path`: the board is the directory `board`
    beside the hive tasks dir, derived from `context_transfer.hive_root`. No
    config key, for the reason `learnings.root_dir` gives.
  - `parse_description` returns a frozen `Description` (`goal`, `done_when`,
    `surface`, `steps`, `out_of_scope`) or raises `DescriptionError`.
  - `read_description` and `write_description`. The file holds the text
    verbatim; the write validates first, makes its directories 0755 with
    `_makedirs_readable` and writes through `_write_atomic`.
  - `is_unmigrated`, `unmigrated_ids`, and `UnmigratedTaskError`, whose
    message names the task file and `dispatch migrate`.
  - `migrate` returns a `MigrateReport` (`moved`, `emptied`, `refused`,
    `already`).
- **`dispatcher/context_transfer.py`**: `TaskFile.description`,
  `set_description` and `read_description` are gone, and `read_task_file`
  and `write_task_file` no longer touch the key.
- **`dispatcher/dispatcher.py`**: `open_cycle` refuses an unmigrated hive
  before `reap_expired_locks`, reads through the module, validates and only
  then stores. `_open_kanban_issue` titles the card from *Goal*.
  `_role_prompt` is untouched.
- **`dispatcher/cli.py`**: the `migrate` verb (`_run_migrate`);
  `_require_migrated` at the top of `run-task`, `run-phase` and
  `release-account`; the section check in `_resolve_description`.
- **`observability/api/app.py`**: `_task` takes the description as an
  argument; both task views read it with `read_description` inside their
  existing guard. The row's keys and their order are unchanged.

## Decisions

1. **The file holds the text verbatim.** Parsing is a separate pure
   function, so `_role_prompt` keeps embedding the stored text whole, and
   the api keeps serving one string under `description`.
2. **Grammar.** A section starts at a column-zero line that is exactly `## `
   plus one of the five names, case-sensitive, trailing spaces allowed. Any
   other line, other `##` headings included, is text of the section it is in.
   Order is free. The errors, each written to follow "the task description ":
   - ``is missing its `## Done when` section`` (both named when both are
     missing; a required section with only whitespace under it counts);
   - ``has two `## Steps` sections``;
   - ``has text before its first section; start with `## Goal` ``.
   Fenced code blocks are not special-cased.
3. **Unmigrated means the frontmatter is a mapping with a `description`
   key**, whatever its value. A task file that is missing or will not parse
   is not unmigrated: it is another reader's error to report.
4. **The refusal is hive-wide wherever a task file can be written**, not
   only per task. `read_description` refusing the one task would leave fact
   3 above open. Ruled out: raising inside `read_task_file`, which is
   structurally stronger but has `context_transfer` reading the key the card
   says it no longer reads. The later task that moves the writes onto this
   module makes the refusal structural.
5. **`migrate` rewrites the task file with
   `write_task_file(path, read_task_file(path))`.** That is "as
   `write_task_file` writes it" by construction, and byte-identical to the
   old file less the key for any file the dispatcher wrote.
6. **`migrate` never guesses.** Per file, in id order:
   - no `description` key: counted as already migrated, not rewritten;
   - `null` or whitespace: the key is dropped, no file is written;
   - not text, or text that already holds a column-zero section heading (the
     old text would not survive whole under `## Goal`): refused, untouched;
   - a `description.md` already there with other content: refused; with the
     same content (a run that died between its two writes): finished;
   - a task file that will not read: refused, untouched.
   `description.md` is written first and the task file second. Any refusal
   makes the verb exit 1 after it has done the rest.
7. **The api serves the raw text**, `null` when there is no file. An
   unmigrated task file costs that task its row and a warning naming
   `dispatch migrate`, through the existing `_UNREADABLE` tuple: both new
   errors are `ValueError`s, so the tuple is not widened.
8. **`tasks.py` imports four private names from `context_transfer`**
   (`_makedirs_readable`, `_write_atomic`, `_is_single_path_component`,
   `_FRONTMATTER_DELIM`). The two modules are one seam mid-move; making the
   helpers public would rename what a dozen docs cite.

## Tests

`python3 -m pytest` printed `1519 passed, 10 skipped`; the base printed
`1478 passed, 10 skipped`.

- `tests/dispatcher/test_tasks.py` (new): parse, the required sections,
  write and read, modes under a 077 umask, the refusal of an unmigrated

  `write_task_file` writes, each refusal untouched).

  was the stored description are replaced by one that a legacy file reads
  and is written back without the key; the others seed with `acquire_lock`.
- `tests/dispatcher/test_dispatcher.py`: `_DESCRIPTION` has sections,
  `_GOAL` is the old one-line text; new tests for an unmigrated hive and
  for a stored description that lost a section.
- `tests/dispatcher/test_cli.py`: section errors for both flags, the three
  verbs refusing an unmigrated hive, and `migrate` (prints, second run,
  exit 1 on a refusal).
- `tests/observability/test_api.py`: descriptions seeded through the
  module; a legacy file is a warning on both routes.

## Operator steps after the merge

1. Rebuild the dispatcher and api images.
2. Make sure no cycle is in flight: nothing enforces it.
3. Run `dispatch --config <config> migrate` once. Expect one "description
   moved" line per task file and a summary; exit 1 means a file was left for
   hand migration, and its line on stderr says why.
4. Until then `run-task`, `run-phase` and `release-account` exit 2 naming
   the command, and the api drops each unmigrated task's row with a warning.
5. From now on a `--description` needs `## Goal` and `## Done when`.
