# T-071 — a frontmatter on every plan, and a test that keeps it valid (roadmap-view, cheap form, piece 1)

No ADR: the shape is the one `docs/plans/roadmap-view.md` (*What it needs
underneath*, 1) already gives, with `dropped` added to the enum.

## What was built

- A block at the top of each of the 21 `docs/plans/*.md`, before the title:
  `status`, `approved`, `built`, `supersedes`. Nothing else in a plan changed,
  but two dated notes in `docs/plans/roadmap-view.md`. In
  `docs/plans/command-requests.md` only the block was added.
- `tests/test_plan_frontmatter.py`: `check(text, plan_names)` returns the
  problems with one plan's block: no block at the top, a block that does not
  close or parse, keys other than exactly the four, a status outside
  `idea | design | approved | building | built | superseded | dropped`,
  a date that is not ISO or null, `built` set without status `built` or the
  reverse, a `supersedes` entry that is not a plan file. It runs over every
  plan, and over strings that break each rule, one a plan with no block.

## The rules used

- `approved` is the date the user accepted the plan, in outline or in full.
  An acceptance by the operator counts (`browser.md`). No date found: null,
  never a guess, and a git date is not taken for an approval.
- `built` is set if and only if status is `built`, and only when the whole
  plan is built. A partly built plan is `building` with `built: null`; so is a
  superseded one.
- Where a prose *Status* line is stale against the plan's own later
  **Built** notes, the notes win. The prose stays as it is.

## Choices

- `board.md` is `superseded`, not `building`: its header says it is
  superseded in part, the phases left are re-planned in `board-service.md`,
  and nothing more is built from it. `board.md` and `front.md` are one row
  each (the dated note under *Which plans count*).
- `roadmap-view.md` is `building` rather than `idea`, since this task builds
  part of it (the dated note under *What it needs underneath*, 1).

## Stale prose, left as it is

- `console-config.md`: "nothing is built", though all four tasks are.
- `command-requests.md`: "not built", though step 1 is.
- `task-split.md`: "built in part", though its later lines say all four
  steps are built.

## Readers of a plan's first line

None. Nothing in `dispatcher/`, `observability/`, `scripts/` or `front/`
opens or parses a plan file; the matches are comments citing a plan.
`dispatcher/project_docs.py` `PLANS_DIR` only marks plans as record docs for
the pointer gate, which reads backticked or linked paths with a slash and an
extension, so a bare `board.md` in the block is not a pointer.
`draft-specs --plan` hands the path to a phase prompt and reads nothing.
