# T-058: more than one phase on an account

The rule is `docs/decisions.md` ADR 88; this records how it was built.

## What was built

- `dispatcher/config.py`: `AccountConfig.max_concurrent_phases` (default 1).
  `load_config` refuses 0, a negative, a bool and a non-integer, naming the
  account. `config.example.yaml` documents it commented out under `cuenta2`.
- `dispatcher/state_machine.py`: two new helpers, no existing function touched.
  `list_shared_accounts` lists unparked accounts with a holder and a free slot;
  `stamp_holder` starts the clock on a holder that has no `busy_since`.
- `pick_idle_account` still calls `list_idle_accounts` (the barrier tests in
  `test_account_claim.py` patch it by name), then adds the shared accounts and
  re-sorts by `is_primary`. The sort is stable, so free accounts come before
  second slots and the primary stays last. The `fallback_roles` and
  `_waitable_workers` gates are unchanged.
- `dispatch_phase`: `claim(..., capacity=_capacity_for(cfg, account))`. Every
  end of a phase and every error path calls `release(..., task_id)`. The two
  parks (`check_quota_ok`, 429, auth) call `park`, then release the phase's own
  slot, in that order, so no slot is claimable on a parking account.
  `check_quota_ok` keeps its signature (tests patch it with two arguments), so
  the caller releases after `if not quota_ok`. `_recheck_cooling_accounts` uses
  `unpark(forget_rate_limit=True)`.
- `reap_stale_busy_accounts` judges each holder on its own card and
  `busy_since` and releases only the dead one; the account is reported once.
- `dispatcher/operator.py`: `AccountReport.task_ids`, `on T-1, T-2` in status,
  `_held_task_ids` reads every holder. `release_account(..., task_id=)` frees one
  holder (refused if it does not hold it; the cooldown guard is skipped since
  the park stays). `cli.py`: `release-account --task`.

## The `set_state` that stays

`release_account` with no task id still calls `set_state(IDLE)`: the operator
means a whole-account write that frees every holder and lifts a park. No
`set_state` call is left in `dispatcher/dispatcher.py`.

## Ruled out

- Evicting holders above a lowered capacity: only new claims are refused.
- Changing `check_quota_ok` to release its claimant: its signature is fixed by
  test monkeypatches.
- Counting a busy account with a free slot inside `list_idle_accounts`: it
  would change an existing function and the barrier tests' meaning.

## A trap I hit

In `release_account` the new `task_id` parameter was shadowed by the
`for task_id in ...` loops already in the function, so a release with no task
id took the one-holder path. Loop variables there are now `held_id` and
`locked_id`.
