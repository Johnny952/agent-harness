# T-033 — the console stops declaring a task's card

This task resolves `docs/debt/T-028-D1.md`: `front/src/lib/api/types.ts`
loses `KanbanIssue` and `Task`'s `kanban_issue_id` and `card`, the fixtures
stop returning them, and the comments that call the debt index's `card`
cell a Kanban board card id say what it is now. No screen changes, no code
under `observability/` or `dispatcher/` changes, and no ADR is written: the
decision is `docs/decisions.md` ADR 59, and this is the console's types
catching up with it.

The sections down to *Verification the implementador owes* are the
arquitecto's design. The implementador corrects them where the tree turns
out different and lists those corrections under *Where the build differs
from the design*.

## Verified first-hand, not taken from the card

| Card's claim | Where | Verdict |
|---|---|---|
| `KanbanIssue` exists and its docblock names the deleted client module | `KanbanIssue` in `front/src/lib/api/types.ts` | true |
| `Task` has `kanban_issue_id: string \| null` and `card: KanbanIssue \| null` | `Task` in the same file | true |

| A docblock and a JSX comment describe the `card` column as a Kanban board card | `Partition`'s docblock and the comment in `DebtTable`, `front/src/routes/debt.tsx` | true |

What is served, read from the code:

- `_task` in `observability/api/app.py` returns eight keys: `task_id`,
  `status`, `owner`, `depends_on`, `heartbeat`, `description`,
  `resolved_debt`, `lock_expired`. The detail route adds `body`. That is
  ADR 59's list, and
  `test_a_task_file_that_still_has_kanban_issue_id_is_served_without_it` in
  `tests/observability/test_api.py` pins it.
- `debt_index` in the same file serves `index_rows` of `dispatcher/debt.py`:
  `id`, `what`, `where`, `fix`, `card`, `resolved`. `card` is still served,
  and `docs/debt/README.md` still has the column, so `DebtEntry.card` stays.

Things the card does not say, each of which shapes the edit:

1. **`front/src/routes/-index.test.tsx` declares both fields.** Its `TASK`
   constant is a `Task` literal with `kanban_issue_id: null` and
   `card: null`. The file is not in the card's keep list, but it has to be
   edited: an object literal with a property its type does not declare
   fails `bun run typecheck`, and the card's own grep over `front/src` for
   `kanban_issue_id` must return nothing.
2. **Two docblocks count the keys.** `Task`'s says "The ten keys
   `/api/tasks` answers" and `TaskDetail`'s "the list's ten keys". With two
   fields gone both say eight.
3. **`description` is typed `string` and served `null` when a task has no
   `description.md`** (`_task`'s docstring). This is a different mismatch
   from the one this task closes and it is not fixed here: see *Not done*.

## The edits

### `front/src/lib/api/types.ts`

- Delete `KanbanIssue` and its docblock.
- Delete `kanban_issue_id` and `card` from `Task`. The six other fields
  keep their order.
- `Task`'s docblock: "The eight keys `/api/tasks` answers", and add that
  there is no card on a task since `docs/decisions.md` ADR 59, the task
  file being the board's data. Keep its two existing sentences on `body`
  and the debt list.
- `TaskDetail`'s docblock: "the list's eight keys plus the running record".
- `DebtEntry.card`'s docblock becomes:

  ```ts
  /**
   * The index's `card` column (`docs/debt/README.md`), not a task id and not
   * a Kanban board card id. Written `none` since ADR 59: nothing mirrors a row.
   */
  ```

### `front/src/lib/api/mock/fixtures.ts`

- `mockTasks`: delete the `kanban_issue_id: null` and `card: null` lines
  from all nine rows. Nine rows stay, with eight keys each.
- `mockDebt`: the five `card: "none"` values stay, because that is what the
  api serves. The comment above the rows becomes: ids take the `T-0NN-Dn`
  shape because `task_id` is a split of the id and not a column (ADR 17),
  and `card` is the index's `card` column, written `none` since ADR 59
  because nothing mirrors a row.

`front/src/lib/api/mock/ops-fixtures.ts` is not edited (see *Left as they
are*).

### `front/src/routes/-index.test.tsx`

Delete the two lines from `TASK`. Nothing else in the file moves.

### `front/src/routes/debt.tsx`, comments only

- `Partition`'s docblock, last clause: "and the `card` column is the
  index's own `card` cell, not a task id."
- The JSX comment in `DebtTable` becomes, in substance: text, not a link.
  This is the index's `card` column, and since ADR 59 every row's is the
  literal `none`, because nothing mirrors a row. It was never a task id, so
  linking it to `/tasks/$taskId` was a guess.

The rendered expression, the `card` header, the filter and the empty-state
strings are not touched. What the screen shows is unchanged.

### `front/src/lib/format.ts`, one docblock

`splitStatus`'s docblock says `in_progress:<role>` "is the shape a *card's*
status has" and "a card's status is not a `TaskStatus`". Both describe a
board card as present. Reworded to the past: `in_progress:<role>` was the
shape a board card's status had until ADR 59 removed the board seam, and
nothing writes it now. The function stays, callerless, as ADR 25 keeps
`formatDuration` and `formatBytes`: a later record of the running role
(ADR 26, ADR 28) may use the same shape, and the first caller owes it the
guard `docs/learnings/a-console-type-over-a-served-value-is-an-annotation.md`
names. Its signature and body do not change.

## Where the build differs from the design

The implementador re-read `_task` and `debt_index` in
`observability/api/app.py` and `index_rows` in `dispatcher/debt.py` before
editing: eight task keys, six debt keys with `card` among them, as the
table above says. Every edit under *The edits* was made as designed. Three
wordings differ, none in substance:

- `Task`'s docblock gained one sentence rather than a paragraph: "Nor is a
  card: the task file is the board's data and nothing mirrors it (ADR 59)."
- The `DebtTable` comment and the `mockDebt` comment both say "not a Kanban
  board card id" in so many words, because the card's third *Done when*
  item asks each of the three `card` comments to say what the column is
  not. The design's substance for them left that clause out.
- `splitStatus`'s docblock does not cite ADR 28 or the learning by name.
  It says the shape was a board card's until ADR 59, that nothing writes it
  now, and that the parser is kept for a later record of the running role.
  The guard a first caller owes is this file's to record, above, not a
  docblock's.

The closing-prose paragraph in `docs/debt/README.md` says a debt was
declared and leaves whether it gets a row to the auditor, since only that
phase knows the id.

What was run, and what it printed, is in the implementador's handoff. No
phase ran `bun`: the card grants `python3 -m pytest` only, so the
dispatcher's typecheck, test and lint gates are the first proof that the
narrowed `Task` compiles everywhere.
