# T-084 — The board's write tools (board-service step 5b)

Decisions: `docs/decisions.md` ADR 129. It covers:
- `backlog_propose`, `task_edit`, `task_comment` and `backlog_accept`;
- the writers in `dispatcher/tasks.py`, under `task_lock`;
- the source and author taken from the role;
- the console's HTTP endpoints.

## What was built

- `dispatcher/context_transfer.py`: `TaskFile.title`. It is read from the
  frontmatter and written only when set.
- `dispatcher/tasks.py`, a new write section:
  - `BoardWriteError` (one error, every problem) and `NoTaskError`.
  - `comments_path`, and the constants `ACCEPT_FROM`, `ACCEPT_TO`,
    `CREATE_LOCK` (`_create`), `COMMENTS_FILE`, `MAX_TITLE_CHARS`,
    `MAX_COMMENT_CHARS` and `MAX_AUTHOR_CHARS`.
  - `propose`: a task, or an epic of 2 to 4 tasks (`T-<n>-S<k>`), as
    `proposed`. It runs under `CREATE_LOCK` and is idempotent on the title.
    A repeat finishes a run that died part way (`_propose_again`).
  - `edit_task`: title, description, `depends_on` and `priority`, refused
    once the task has started (`_started`). It refuses a cycle, an unknown
    dependency, and a dependency that crosses an epic.
  - `add_comment`: one JSON line appended to `board/<id>/comments.jsonl`,
    with an optional `file`, `line` and `commit` anchor (all three or none).
  - `accept`: `proposed`/`deferred` to `pending`, `deferred` or `dropped`,
    with an optional priority. An epic carries its tasks (`_accept_epic`).
  - `accept_drafts` now holds `CREATE_LOCK`, so it and `propose` never pick
    one id.
- `dispatcher/board_mcp.py`: `ROLE_TOOLS` gives the operator all six tools
  and the arquitecto the reads plus `backlog_propose` and `task_comment`.
- `board_service/app.py`:
  - The four tools' schemas, all with `additionalProperties: false` (an
    epic's entries too) and the write tools without `readOnlyHint`.
  - `_writing` maps the module's errors: `NoTaskError` is not found;
    `BoardWriteError`, an unmigrated task and an `OSError` (a read-only
    mount) are tool errors.
  - `source` and `author` are set from the role.
  - The HTTP routes, as the operator: `POST /api/backlog` (201, or 200 for
    a repeat), `PATCH /api/tasks/<id>`, `POST /api/tasks/<id>/comments`
    (201) and `POST /api/tasks/<id>/accept`. Any `Origin` is 403. A query
    parameter, a body that is not a JSON object, or a `task_id` in the body
    is 400, and so is a tool refusal. No such task is 404.
- Tests:
  - `tests/dispatcher/test_board_writes.py` (new, 103 tests), each writer:
    - `propose`: numbering past the `-S` ids, idempotency and refilling a
      lost description, every problem at once with nothing written, epics
      all or nothing, finishing a half-made epic, title clashes, the
      `CREATE_LOCK` wait, eight concurrent proposals with distinct ids, and
      `accept_drafts` waiting on the same lock.
    - `edit_task`: changed fields, nothing to change, started and
      not-started statuses, an epic whose task started, title uniqueness,
      `depends_on` cycles and unknowns, the epic sibling rule, and the lock
      wait.
    - `add_comment`: append and count, each bad comment, no task leaving no
      directory, the lock wait, and ten concurrent comments not
      interleaving.
    - `accept`: each transition, the no-op and its priority refusal, the
      board and `dropped` refusals, epics (accept keeping a deferred task,
      drop cascading, defer alone, a missing task), a task waiting for its
      epic, and the lock waits.
    - The unmigrated refusal for `edit_task`, `add_comment` and `accept`.
  - `tests/board_service/test_writes.py` (new, 61 tests):
    - `tools/list` per role, the arquitecto refused `task_edit` and
      `backlog_accept`, and every other phase refused all four with
      nothing written;
    - an unknown role and an `Origin` refused;
    - `source` and `author` from the role, and refused as arguments;
    - schema refusals;
    - each tool over MCP;
    - a read-only hive as a tool error;
    - every HTTP route, its status codes and its refusals;
    - the service holding no write of its own.
  - `tests/board_service/test_app.py` and `tests/dispatcher/test_board_mcp.py`:
    the role table and the tool lists with the writes.
- Docs: ADR 129, the plan's Status and step 5.

## Why this way

- Writers in the module, because section 5 says one module writes and
  ADR 127's lock lives there. The service only validates the shape and maps
  errors.
- The source and author from the role, because an argument would let a
  phase claim to be the operator.
- The title in the frontmatter, because idempotency must not depend on
  parsing a description's prose.
- One create lock, because picking the next id is a read of the whole hive.
- All checks before any write, so a refused epic leaves no half of itself.
- The task file before its description, so a retry after a crash finds the
  task and fills in what is missing.
- `task_edit` only before start, because a phase may already be reading the
  description it was given.

## Pending

- **The uid.** `board_service/Dockerfile` runs as root, so the files and
  directories it creates in the host's `.hive` (`board/<id>/`,
  `locks/<id>.lock`) are owned by root. A dispatcher on the host as the
  operator's user could not write into a `board/<id>/` the service made. If
  that matters, the service needs a `user:` in compose. That is for the
  user to decide.
- **The console** (step 8). Every request with an `Origin` is refused, as
  the reads already were, so the console's proxy must call the service
  server side and strip `Origin`. The service is already on `console_net`.
- **A deferred or dropped task of an accepted epic** never merges, so its
  epic never closes on its own. Closing it means accepting the task, or
  editing the epic by hand.
- **5c**: `tags` and `rank`. **5d**: debt as backlog items, with
  `source: debt` set by the dispatcher's own call to `propose`.
- The api does not serve `priority`, `source` or `title` yet.

## Compose

Applied with the user's approval on 2026-10-18, in both
`docker/compose/docker-compose.yml` and `docker-compose.coolify.yml`: the
`board-service` hive mount is `../../.hive:/data/.hive` (read-write, `locks/`
included), `config.yaml` and `config.d` stay `:ro`, and the service is on
`console_net` as well as `ia_harness_net`. `tests/integration/test_compose_invariants.py`
expects both: the board-service mount and network tests, and
`test_console_net_holds_the_console_side_and_no_agent_network`, which now
counts board-service with the api as on both networks.

## Ruled out

- A `source` or `author` argument.
- `task_edit` or `backlog_accept` for the arquitecto.
- The title only as the description's heading.
- A create lock per title.
- Undropping a dropped item, and editing a started task.
- The role from the HTTP request.
- Writes in `board_service` itself.
