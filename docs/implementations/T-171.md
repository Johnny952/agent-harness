# T-171 — waitress for the collector and the read API

Decision and numbers: `docs/decisions.md` ADR 417. This note is how it was built.

## What

- `pyproject.toml`: `waitress>=3.0`.
- `observability/collector/server.py`: `HOST`, `PORT`, `THREADS = 4` and
  `run(environ=None)`; `__main__` calls `run()`.
- `observability/api/app.py`: `HOST`, `THREADS = 8` beside `PORT`, and
  `run(environ=None, config_path=CONFIG_PATH)` holding what `__main__` used to
  build inline (same variables, same `.get` for `API_TOKEN`); `__main__` calls `run()`.
- Tests: `tests/observability/test_collector.py` (`run` serves with the pinned
  host/port/threads; a missing read token exits 2 with waitress installed and
  with it unimportable) and `tests/observability/test_api.py` (`run` serves with
  the env; no `API_TOKEN` keeps the bearer path shut; no `DASHBOARD_USERNAME`
  raises `KeyError` before the import).
- README *Future work*, `docs/plans/backlog.md` item 6 and `docs/README.md`
  *Stack* updated. Dockerfiles and compose untouched (`python -m` still runs
  `__main__`).

## Why this way

- `serve` is imported inside `run`, after the app is built: the agent venv has
  no waitress (`docker/agent/Dockerfile` lists its packages by hand), and a
  configuration refusal must not depend on it. Tests put a stand-in in
  `sys.modules` (`None` there makes the import raise, which pins the order).
- No real socket opens in any test.

## Ruled out

- gunicorn, and Werkzeug `threaded=True`: see ADR 417 *Ruled out*.
- An SSE test: the read API has no `/events/stream` (ADR 417 *Context*); the
  `/api/events?since=` tests are the tail's coverage and stay green.

## Not run

- The real `waitress.serve`: not installed here; kwargs (`host`, `port`,
  `threads`) taken from waitress 3.x. Operator rebuilds the images after merge.

## Debt

`board_service/app.py` and `config_writer/app.py` still call Werkzeug's `run`.
