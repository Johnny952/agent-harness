# T-061: the console as a compose service

The rule is `docs/decisions.md` ADR 97; this is the plan, and the implementador
records what was built under *What was built* below.

## Plan

1. `docker/console/Dockerfile` (new). Header comment in the style of
   `observability/api/Dockerfile`: path, "Build context: repo root", ADR 97.
   - Stage `bun`: the oven/bun image at the tag `docker/agent/Dockerfile`
     pins (1.3.12), used only to copy its binary, as that file does.
   - Stage `build`: the Node base the agent image uses (node 24,
     bookworm-slim). `COPY --from=bun /usr/local/bin/bun /usr/local/bin/bun`.
     `WORKDIR /app`. `COPY front/package.json front/bun.lock front/bunfig.toml
     ./`, then `RUN bun install --frozen-lockfile`. Then copy the sources by
     explicit path: `front/tsconfig.json`, `front/vite.config.ts`,
     `front/components.json`, `front/src/`, `front/public/` (never `COPY front/
     .`, so a host `node_modules` or `.lovable/` cannot ride in). Then `ENV
     NITRO_PRESET=node-server` with a comment saying why (ADR 97, 2: nitro reads
     it before the Lovable config's cloudflare `defaultPreset`; do not set
     `LOVABLE_SANDBOX` or `DEV_SERVER__PROJECT_PATH`, which make that config
     delete it), then `RUN bun run build`. If the build needs a file the list
     misses, add that one path, not the directory.
   - Stage runtime: the same Node base. `WORKDIR /app`, `ENV NODE_ENV=production
     HOST=0.0.0.0 PORT=8790`, `COPY --from=build --chown=node:node
     /app/.output ./.output`, `USER node`, `EXPOSE 8790`, `CMD ["node",
     ".output/server/index.mjs"]`. Nothing else from the build stage.
2. `docker/console/Dockerfile.dockerignore` (new): an allowlist. First `*`,
   then `!front/`, then these under `front/`, one line each: node_modules,
   .lovable, .output, dist, dist-ssr, .nitro, .tanstack, .vinxi, .wrangler,
   .dev.vars, every `.env*` and every `*.local` at any depth; and
   `**/__pycache__`. A comment saying BuildKit reads this file in place of the
   root `.dockerignore` for this Dockerfile only. (The names are left out of
   backticks here because the pointers gate would read the ones with a short
   extension as missing paths.)
3. `docker/compose/docker-compose.yml`: a `console` service directly after
   `api`, before `registry-mirror`, with a comment block like the api's:
   ```yaml
   console:
     build:
       context: ../..
       dockerfile: docker/console/Dockerfile
     restart: unless-stopped
     ports:
       - "127.0.0.1:8790:8790"
     environment:
       - API_BASE_URL=http://api:8789
       - API_TOKEN=${API_TOKEN}
       - CONSOLE_PROJECT=${CONSOLE_PROJECT:-}
     depends_on:
       - api
     networks:
       - ia_harness_net
   ```
   The comment says: no volumes and no socket, it reads only through the api
   (ADR 15); `API_TOKEN` bare because the console refuses to boot without it,
   so compose should say it is missing (ADR 97, 4); `CONSOLE_PROJECT` optional,
   `:-`. In the api service, change `API_TOKEN=${API_TOKEN:-}` to
   `API_TOKEN=${API_TOKEN}` and rewrite its comment: the holder is now the
   `console` service in this file; the api still runs without it (ADR 7), but
   the console does not, so it is spelt bare (ADR 97).
4. `docker/compose/docker-compose.coolify.yml`: the same `console` block,
   same place (after `api`, so above the first `agent-` line), same `ports`
   (this file publishes its other services on loopback too), a short comment
   pointing at `docker-compose.yml`'s. The api's `API_TOKEN` goes bare with
   its comment updated. In the header, the `API_TOKEN` bullet now says it is
   required (the console refuses to start without it), and the collector
   bullet's "Unlike API_TOKEN these are not optional" is reworded to match.
5. `scripts/configure.sh`: no heredoc changes (ADR 97, 5). Two comment edits
   only: `render_coolify_compose`'s list "header, collector, api,
   registry-mirror, dispatcher" gains `console`; and the comment above the
   collector tokens in the `.env` writer, "Required, unlike API_TOKEN", is
   reworded (API_TOKEN is required too now). Leave every `echo` line as is.
6. `tests/integration/test_compose_invariants.py`:
   - New, parametrized over both files,
     `test_the_console_reads_only_through_the_api(compose_file)`: the service
     exists; it has no `volumes` key (or an empty one) and the text of the
     service holds no `docker.sock`; `depends_on` includes `api`; `networks`
     includes `ia_harness_net`; `build` is `{context: ../.., dockerfile:
     docker/console/Dockerfile}`; `restart == "unless-stopped"`; `ports ==
     ["127.0.0.1:8790:8790"]`; `_environment` gives `API_BASE_URL ==
     "http://api:8789"` and `API_TOKEN == "${API_TOKEN}"`; and no variable it
     reads (`_variables_read_by`) and no key starts with `COLLECTOR_`.
   - `test_the_api_takes_the_token_a_service_authenticates_with`: docstring
     updated (the holder is the `console` service now), and assert the console
     takes `API_TOKEN` spelt exactly as the api does.
   - `test_an_optional_variable_carries_an_empty_default`: variable list
     `["CONSOLE_PROJECT"]`; docstring adjusted.
   - `test_a_required_credential_stays_bare_so_compose_says_it_is_missing`:
     add `"API_TOKEN"`; docstring names the console's refusal to boot.
7. `tests/integration/test_console_dockerfile.py` (new, static, like
   `test_agent_dockerfile.py`): the Dockerfile has `bun install
   --frozen-lockfile` and `NITRO_PRESET=node-server` before `bun run build`;
   after the last `FROM` there is a `USER` that is not root and a `CMD` naming
   the built server entry (index.mjs under .output/server); no `COPY front/ ` or `COPY front/.` line; the
   `.dockerignore` beside it lists `front/node_modules` and `front/.lovable`
   and an `.env` pattern; and nothing sets `LOVABLE_SANDBOX` or
   `DEV_SERVER__PROJECT_PATH`.
8. `tests/scripts/test_configure.py`: in
   `test_a_rendered_pool_holds_the_compose_invariants`, also call
   `invariants.test_the_console_reads_only_through_the_api("docker-compose.coolify.yml")`
   (file name passed explicitly: learning
   a-parametrized-invariant-called-directly-takes-no-default). The byte-for-byte
   test must pass with no other change.
9. Docs, each a minimal edit:
   - `front/README.md`, *The three environment variables*: after the "There is
     no compose service for this directory" paragraph, unchanged, one dated
     line: since 2026-10-17 it runs as the `console` service in both compose
     files, on `127.0.0.1:8790`, built for Node (ADR 97).
   - `README.md`: the layout line `front/ ... no service yet` names the
     `console` service; the *Setup* sentence "`front/` has no compose service
     yet" says it is now the `console` service; *4. Bring up the stack*: four
     persistent control-plane services, the console at
     `http://127.0.0.1:8790` (an SSH tunnel from elsewhere), an `.env`
     without `API_TOKEN` makes compose warn and the console exit at boot
     (rewrite the "An `.env` written before `API_TOKEN` existed" sentences), and
     the `CONSOLE_PROJECT` paragraph says the `console` service reads it from
     `.env` (drop "Neither compose file sets it"). *Deploying with Coolify*:
     one line that the resource now includes `console` and needs `API_TOKEN`.
     Per learning an-env-key-only-an-adr-names-is-invisible, step 4 is where
     the operator reads this.
   - `docs/README.md` *Modules*, the `front/` row: "run with `bun`, not a
     compose service" becomes run with `bun` on the host or as the `console`
     compose service (ADR 97). No other row.
   - Name image tags outside backticks in every doc (learning
     a-docker-image-tag-reads-as-a-path-to-the-pointers-gate).
10. Run `python3 -m pytest` and the three front gates. Try to build the image
    once (`docker compose -f docker/compose/docker-compose.yml build console`
    or `docker build`); a phase here could not run `docker` or set
    `NITRO_PRESET` on a `bun run build` (refused, 2026-10-17), so if refused,
    say so plainly under *What was built*.

Out of scope, from the card: Caddy, TLS, `HARNESS_DOMAIN`; anything under
`front/src/`, `front/vite.config.ts`, `front/package.json` or
`front/.lovable/`; sign-in, basic auth, the api's code.

## What was built

Plan steps 1-9 carried out as written (ADR 97 holds the reasoning).

- `docker/console/Dockerfile`: stages bun (binary only), build (node 24
  bookworm-slim, `bun install --frozen-lockfile`, explicit COPY list,
  `ENV NITRO_PRESET=node-server`, `bun run build`), runtime (copies only
  `.output`, `USER node`, `CMD node .output/server/index.mjs`, port 8790).
- `docker/console/Dockerfile.dockerignore`: allowlist (`*`, `!front/`, then the
  exclusions); BuildKit prefers it to the root ignore file for this Dockerfile.
- Both compose files: `console` after `api`, `API_TOKEN` bare in console and api,
  `CONSOLE_PROJECT` `:-`, loopback port 8790 in both (the Coolify file publishes
  its other services on loopback too). Header bullets in the Coolify file updated.
- `scripts/configure.sh`: two comments only; the render copies the head verbatim,
  so the byte-for-byte test needed no other change.
- Tests: `test_the_console_reads_only_through_the_api` (both files, also called
  from `test_configure.py`), the token tests adjusted, and a new static
  `tests/integration/test_console_dockerfile.py`.
- Docs: `front/README.md` dated note, `README.md` (layout, setup, step 4,
  Coolify), `docs/README.md` front row.

Ruled out: setting the preset in `vite.config.ts` or a nitro config (protected /
ADR 97); `${API_TOKEN:-}` for the console (it would hide the missing value and
loop the container).

Image build: **not attempted successfully.** `docker` and an env-prefixed
`bun run build` are refused in a phase (see the learning in the task inbox), so
the image was never built and whether `.output` runs on node alone is unverified.

## Audit

The auditor re-ran `python3 -m pytest` (2104 passed, 10 skipped) and the three
front gates (`bun run typecheck` clean, `bun run test` 121 passed, `bun run
lint` clean), and read the installed `@lovable.dev/vite-tanstack-config`: it
sets `defaultPreset: "cloudflare-module"` and drops `NITRO_PRESET` only when it
detects a sandbox, which agrees with ADR 97. The image was still not built;
`docker` is not available to a phase. Because the compose files changed,
charter C-4 means the owner must approve the merge. The first real
`docker compose build console` on a host is the check nothing here could run.
