# T-021 — the refusal stamp is epoch seconds, and the probe's staleness is ruled

The pool card never said a cooling account had been refused. The api serves
`rate_limited_at` as epoch seconds, `front/` typed it as an ISO string and read
it with `agoSeconds`, and `new Date(seconds)` reads a number as milliseconds,
so every refusal landed in January 1970 with its cooldown decades over. This
task fixes the unit, puts the fixture in the served shape so the mock shows
the bug class, rules on the probe-staleness conflict the card raised, and
fixes the fixtures' cuenta4/T-012 pairing. Scope: `front/src/`, `docs/ui.md`,
`docs/decisions.md`, this file.

## What was built

**The unit.** `front/src/lib/format.ts:agoEpochSeconds` takes epoch seconds
and answers whole seconds ago, or `null` for anything that is not a finite
number, for `agoSeconds`'s reason: the api does not type-check a hand-edited
state file. `Account.rate_limited_at` is `number | null`, and its comment
names the helper. `AccountCard` and `ProbeReadout` both read their stamps
through it.

**The test.** `front/src/routes/-pool.test.tsx`, *a refused account*. It
renders a cooling account refused 620 seconds before a fixed `now` and expects
"Refused by the provider. Back in 19m 40s (1800s cooldown).". It also checks
that a refusal 1900 seconds old is no longer shown. The first test was written
and run before the fix, and it failed on the old code (`1 failed | 11
passed`), because the card had no refusal line. The second passes either way.
It guards against the fix overshooting.

**The fixtures.** cuenta2 serves `rate_limited_at: epoch(620)`. T-012 is
locked by cuenta6, which is now `BUSY` on it. An account with no state no
longer holds a fresh lock.

**The staleness ruling: outcome (b), the rule does not apply.** A probe's age
is not a lock. Nothing in the harness expires a probe or acts on its age, so
no server window or config key exists for the console's thirty minutes to
drift from. That drift was ADR 18's harm. ADR 49 leaves the reading to the
consumer, and the mark never hides the numbers. Recorded as
`docs/decisions.md` ADR 51 and as a paragraph in `docs/ui.md` *Staleness is
served, never computed*. `PROBE_STALE_S`'s comment cites both.

## What was ruled out

- **Outcome (a), serving `probe_stale` from the api.** It would invent a server
  window that only the console reads, and it needs a change under
  `observability/` for a judgement the server never makes. ADR 51 says when it
  becomes right: when the dispatcher gives a probe an expiry of its own.
- **Keeping `agoSeconds` and multiplying by 1000 at each call site.** That is
  how the bug was made: the conversion lived with the caller, and the caller
  forgot it. A named helper whose argument type is a number makes the wrong
  call a type error.
