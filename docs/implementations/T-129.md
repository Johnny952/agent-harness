# T-129 — the console's *Request changes* button

Decision: `docs/decisions.md` ADR 276. Mirrors `docs/implementations/T-125-S3.md`.

## What was built

- `front/src/lib/api/forward.ts`: `TASK_REQUEST_CHANGES` and an `actionRoutes`
  entry (`action: "request_changes"`) beside approve's. `approveBody` became
  `reviewBody(bytes, who)`: one reader for both verbs, its 400s naming the verb
  (*An approve's*, *A request for changes'*), as does the CONSOLE_PROJECT 503.
  Prose counts moved: sixteen board pairs, twenty-three board writes. The api
  read count (twenty-one) is untouched.
- `types.ts`, `client.ts`, `queries.ts`: `RequestChangesBody/Result`,
  `requestChanges`, `requestChangesMutation` (same refetches as approve).
- `review.ts`: `requestChangesRefusal(task)`, null only on `awaiting_review`
  with `merged === false`; otherwise the sentence used as the button's title.
- `approvals.tsx`: the button beside *approve*. Typed words are required
  (`commentProblem`), no default text. The queued state is `{commit, kind}`,
  shared, so either review-ending button turns both off at that tip. The error
  branch became a local `refused(what, err)` used by both buttons.

## Why this way

The route refuses a blank `text`, so a default like `Changes requested.` would
send the arquitecto nothing to act on (ADR 276, ruled out). Pinned comments
travel server-side, so the screen sends only `text`.

## Tests

`forward.test.ts` (forward, bearer, rebuilt body, 400s, 503s, GET 404),
`review.test.ts` (each refusal branch), `-approvals.review.test.tsx` (body,
off states, 409 with verdict, plain refusal). The old assertion that the panel
says request changes is not in the console yet now asserts its absence.
