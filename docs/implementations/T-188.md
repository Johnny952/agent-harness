# T-188 — a split task's sub-tasks take its place in the queue

Decisions are `docs/decisions.md` ADR 495 (under charter C-4, *Amended*
2026-10-26); this note is how it was built.

## What changed

- `dispatcher/queue.py`
  - `Entry` gains `split_into` and `epic`; `SPLIT` leaves `FAILED`; public
    `failed(entry)` keeps a split with no `split_into` a failure, so an old
    queue file behaves as before and an unreadable split still skips its
    dependents. `_next` and `dispatcher/cli.py` `_run_queue`'s exit test use it.
  - `_absorb_split` runs right after `_settle` in `_run_serial` and in
    `_run_parallel`'s `work()` (under the condition). It inserts the sub-tasks
    after the split entry, re-points pending dependents (in the entry and, via
    `_comment(..., depends_on=)` and `tasks.handoff`, on the board) and logs.
  - `WriteScheduler.reorder` replaces the order after absorbing, so the
    sub-tasks hold the split task's place for write windows.
  - `confirmation` and `summary` tag `[split into ...]` / `[from T's split]`;
    the confirmation has the new rule sentence.
- `docs/cli.md` `### run-queue`: a paragraph on the behaviour.
- Tests: `FakeCycle` takes a `split` key (the `after` tuples) and calls
  `tasks.file_split`; `tests/dispatcher/test_queue.py` covers place, sibling
  wait, dependent wait, failed sub-task, resume, old file, unreadable
  sub-task, tags and CLI exit 0; `test_parallel_queue.py` covers the parallel
  order.

## Why this way

The sub-tasks are ordinary pending entries, so limit, parallelism, `_waits`
(sibling not merged) and the skip-on-failure all work unchanged, and `--resume`
needs no code. The dependent's `depends_on` is rewritten on the board because
`open_cycle` gates on `tasks.unmet_dependencies`, which never clears for an
epic parent.

## Ruled out

- Changing `tasks.unmet_dependencies` (outside the surface): debt, see handoff.
- A local named `failed` in `_next` shadowed the new function; renamed `broken`.
