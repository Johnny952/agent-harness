# T-160-S2 — a merge drops the debt cards it resolved

Contract: `docs/decisions.md` ADR 369 (amends ADR 131).

## What was built

- `dispatcher/tasks.py` `close_resolved_debt(hive_dir, task_id)`: returns
  `(closed, warnings)` and never raises. One `read_all_tasks` pass finds the
  cards by `debt_id`; each is re-read under its own `task_lock`;
  `proposed`/`deferred` go through `mark_dropped` as `dispatcher`; `dropped`
  or missing is silent; any other status is a warning. `close_epic` runs after
  the locks. The merging task's own card is skipped.
- `dispatcher/dispatcher.py` `record_merge` returns `(recorded, problem,
  warnings)` and calls it after the `mark_merged` block, written or not, so a
  re-run repairs a cut-off close. `_merge_task_branch` and `approve_reviewed`
  log the warnings; `approve_reviewed` appends them to the merged comment before
  the backup line; the auto-approve now records the merge before its note so
  the note can carry them.
- `dispatcher/cli.py` `merge-task` prints warnings to stderr; exit unchanged.

## Why this way

The trigger is the task file's `resolved_debt` (reviewed by revisor and
auditor), not the index's `resolved` cell that ADR 131 refused to trust.
Warnings are returned rather than raised so a merge that landed is never
reported as failed.

## Ruled out

Closing an accepted card (a person's decision); a separate command; reading
the debt index at merge (ADR 59).

## Tests

`tests/dispatcher/test_board_writes.py` (`close_resolved_debt`),
`test_cli.py` (merge-task), `test_dispatcher.py` (auto-approve,
`approve_reviewed`; existing `record_merge` unpacks now take three values).
`_aa_dispatch_phase` gained an `implementador` payload, since the cycle
rewrites `resolved_debt` from that handoff.
