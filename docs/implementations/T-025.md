## What was built

- **`_SPLIT_PROPERTY`**, section 1's code block key for key and word for
  word, after `_RESOLVED_DEBT_PROPERTY`. `_ROLE_EXTRAS` is unchanged, so no
  role's schema offers `split`.
- **`SubTask`**, a frozen dataclass: `title`, `surface`, `description`,
  `after`.
- **`split_of(payload)`**, after `pending`. `[]` for a falsy payload or a
  `split` that is not a list.
- **`split_problems(subtasks)`**, with the limits named `_SPLIT_MIN` and
  `_SPLIT_MAX`. The lines it returns:
  - `a split has 2 to 4 sub-tasks, this one has N`
  - `sub-task N: <field> is blank`
  - `sub-task N: after names X, which is not an integer`
  - `sub-task N: after names X, which is not an entry before it`
  - `sub-task N: after names X more than once`
- **`render`** prints `**Split**` through a helper `_split`, one line per
  entry: `1. <title> (<surface>) — after 1, 2`.

## Decisions the design leaves open

Step 4 reads these, since no ADR records them yet.

1. **`split_of` never raises and never repairs.** What it cannot read is
   dropped whole (an entry that is not an object, as section 7 says) or kept
   so `split_problems` refuses it. A silently lost `after` is a sub-task
   started before the work it reads.
2. **Positions are positions in the list `split_of` returns.** A skipped
   entry shifts the ones after it. `render` and `split_problems` both go
   through `split_of`, so they agree. Only the prose-fallback path can
   produce such an entry; the CLI validates the schema.
3. **Text fields.** A `title`, `surface` or `description` that is not a
   string becomes `""`, not `str(None)`, so it is reported blank. `title` and
   `surface` are stripped. `description` is kept verbatim, because section 2
   writes it verbatim and compares it on a re-file.
4. **`after`.** A list becomes a tuple with its items untouched. Missing or
   `None` becomes `()`. Any other value becomes a one-item tuple holding it,
   so it is refused instead of dropped.
5. **An integer is `type(x) is int`.** `True` is not position 1, and `1.0`
   is not either.
6. **`split_problems` reports every problem, in list order.** A bad split
   ends the task as a block, and the block's reasons are all the next
   arquitecto run gets. No line quotes a title or a description, so one
   problem is one line.
7. **`**Split**` goes right after the Status line,** before *Changed*. It is
   the phase's outcome, as the verdict is.
8. **`render` collapses whitespace in each split line.** A title holding a
   newline and then `## auditor` would otherwise write a column-zero heading,
   which `context_transfer.has_phase_section` reads as a phase
   (`docs/debt/T-014-D1.md`).

## What was ruled out

- **Adding `split` to `_ROLE_EXTRAS["arquitecto"]`.** That is the switch,
  and it belongs to step 4 with the dispatcher branch that files a split.
- **A `set()` over `after` to find duplicates.** An item from the prose
  fallback can be unhashable; `split_problems` keeps what it has seen in a
  list, which at four entries costs nothing.
- **Dropping a blank-titled entry from the render,** the way `_debt` drops a
  declaration with no `what`. The printed numbers would stop matching the
  positions `after` names.
- **Coercing `"1"` to `1`.** That is a repair; see decision 1.

## Tests

`tests/dispatcher/test_handoff.py`, all new, no existing test changed:

- Schema: *no role is offered a split yet* (every role); *the split property
  is closed like the other object lists*, because the existing closed-schema
  test cannot see the property until step 4.
- `split_of`: *is empty when there is no split*; *returns the entries in
  order*; *skips entries that are not objects*; *keeps what it cannot read
  for split_problems*; *a subtask cannot be changed once read*.
- `split_problems`: *is empty for a split that can be filed* (2, 3, 4);
  *refuses a split of the wrong size* (0, 1, 5); *a blank field* (each of
  three); *an after that is not an earlier entry* (itself, later, zero,
  negative); *a duplicate after once*; *an after that is not an integer*
  (`"1"`, `True`, `1.0`, `None`, `{}`); *reports every problem not the
  first*.
- `render`: *prints the split with positions and after*, and no description
  text; *prints no split section without a split*; *keeps a split title off
  column zero*; *tolerates a malformed split*.
