# T-144 — `/api/learnings?task=`

Resolves `docs/debt/T-142-D1.md`. Contract: `docs/decisions.md` ADR 321.

## What

- `observability/api/app.py` `learnings_index`: allowed parameters are now
  `{project, task}`. A non-bare `task` is a 400 after the project check.
  `reaching` is `handed(select(eligible(served, slug), context), harness)`;
  with no `task`, `context` is `learnings.NO_CONTEXT`, for which `select`
  returns its input, so the no-parameter answer is unchanged.
- New helper `_learnings_task_context` builds the context with the
  dispatcher's own `learnings.task_context` and the same card path and
  `task_store.read_description` that `_role_prompt` uses. Warnings: unknown task
  (200, unfiltered column), unreadable description, card project != slug.
- Tests in `tests/observability/test_api.py` after the learnings tests: the
  column differs with and without `?task=` in both directions (`MAX_ROWS`
  monkeypatched to 2), a non-matching task keeps the unfiltered column, 400,
  unknown task, unreadable description, project mismatch, writes nothing.
- `docs/README.md` Modules row for `observability/api/`.

## Why this way

The helper takes a `warnings` list and appends to it, as the route already
does inline; it keeps the route body short. The card is read twice (once in
`task_context`, once for `project`), as ADR 321 point 6 accepts, so
`dispatcher/learnings.py` stays untouched.

## Ruled out

- A 404 for an unknown task, a field saying whether the filter applied, taking
  the project from the card: ADR 321 "Ruled out".
- Unmigrated-description test through a real unmigrated card: the test
  monkeypatches `read_description` to raise `OSError`, which exercises the same
  `_UNREADABLE` guard.

Full suite: `python3 -m pytest -q` — 4395 passed, 15 skipped.
