# T-060: a draft run's arquitecto is a reader

The rule is `docs/decisions.md` ADR 94; this is the plan, and the implementador
records what was built under *What was built* below.

## Plan

1. `dispatcher/docker_exec.py`, `create_worktree`: add a keyword-only
   `at_base: bool = False`. When it is set, return
   `_add_review_worktree(container, project_dir, task_id, role, "HEAD")`
   before the `WRITER_ROLES` test, so even a writer role gets
   `git worktree add --detach worktrees/<task_id>/<role> HEAD`, run in the
   project clone. `ensure_worktrees_ignored` still runs first. Say in the
   docstring that `HEAD` here is the project clone's, the base, and that no
   branch is made (ADR 94). No new helper: the review path already drops the
   old checkout and adds a detached one at any ref.
2. `dispatcher/dispatcher.py`, `dispatch_phase`: add `at_base: bool = False`
   after `max_turns`. Pass it to `create_worktree` (as a keyword). Change the
   commit test to `if not at_base and _should_commit(role, result):`, with a
   one-line comment citing ADR 94. `_should_commit` and
   `_refuse_review_writes` do not change (ADR 94, 4: the retry does not fire
   for a draft).
3. `dispatcher/dispatcher.py`: a new `_drop_draft_worktree(cfg, draft_id,
   slug)`, beside `_drop_review_worktrees` and shaped like it. With
   `cleanup_container(cfg)` (return if None) and
   `project_dir = f"{cfg.projects_root}/{slug}"`: read the owner; then, inside
   one `try` that catches `Exception` and logs a WARNING (never raises):
   `docker_exec.dirty_paths(container, <task_worktrees_dir>/arquitecto)` and,
   if any, a WARNING naming them (first ten, as `_refuse_review_writes` does)
   saying the draft phase changed the repo and the changes are discarded;
   then `docker_exec.remove_task_worktrees(container, cfg.projects_root,
   slug, draft_id)`, and an INFO when it removed something. `restore_owner`
   in a `finally`. Put `read_owner` inside the guard too, so nothing in this
   function can be the run's error.
4. `dispatcher/dispatcher.py`, `run_draft_specs`: pass `at_base=True` to
   `dispatch_phase`. Wrap the call so the cleanup runs on every exit but the
   lock-held one: catch `LockHeldError` and return as now *without* cleanup
   (ADR 94, 5); on any other exception, clean up and re-raise; after a
   result (success or failure), clean up before the `tasks.handoff` /
   `logger.error` that follow. Update the docstring: the worktree is a
   detached checkout of the base, removed when the run ends, no branch.
5. Tests, all with no container:
   - `tests/dispatcher/test_docker_exec.py` (with `_fake_docker`):
     `create_worktree(..., "arquitecto", at_base=True)` issues
     `git worktree add --detach <root>/<slug>/worktrees/<id>/arquitecto HEAD`
     in the project dir, after removing that path, and never a `-b`, never
     `agent/task/<id>`, never `rev-parse --verify` of the branch. And the
     same call without `at_base` still issues the writer `-b agent/task/<id>`
     command at `.../work`.
   - `tests/dispatcher/test_dispatcher.py` (with `fake_git`, `_phase_exec`,
     a create_worktree fake that records kwargs): `dispatch_phase(cfg, id,
     slug, "arquitecto", ..., at_base=True)` with a successful result and
     `fake_git.dirty_paths` reporting a modified file commits nothing
     (`fake_git.commits == []`) and passed `at_base=True` to
     `create_worktree`; and a plain arquitecto `dispatch_phase` still gets
     the writer path (`.../work`) and one commit by `arquitecto (cuenta1)`.
   - `tests/dispatcher/test_drafts.py`: the faked `dispatch_phase` records
     its kwargs; assert `at_base=True` reaches it. Monkeypatch
     `docker_exec.remove_task_worktrees`, `read_owner`, `restore_owner` and
     `dirty_paths` (in `dispatcher.docker_exec`) to record calls, and assert
     the draft id's worktrees are removed and the owner restored after a
     success, after a failed phase, and after `dispatch_phase` raises (the
     exception still propagates); that it is *not* called on
     `LockHeldError`; that a `remove_task_worktrees` that raises leaves the
     run's result as it was, with a WARNING in `caplog`; and that a dirty
     path is named in a WARNING. The existing test fakes take `**kwargs`, so
     they keep working.
6. Docs: `docs/README.md` needs no row change (neither the
   `dispatcher/dispatcher.py` nor the `dispatcher/docker_exec.py` row
   describes the draft run's worktree). Append *What was built* here.

Out of scope, from the card: a reaper for old draft leftovers, the draft
prompt, `check_drafts`, `accept-drafts`, the draft id format, any other role.

## What was built

Plan steps 1-5 as written, with one deviation.

- `docker_exec.create_worktree(..., *, at_base=False)`: when set, returns
  `_add_review_worktree(..., "HEAD")`, so the arquitecto gets
  `worktrees/<id>/arquitecto`, detached at the project clone's HEAD, with no
  branch and no `show-ref`.
- `dispatch_phase(..., at_base=False)`: forwards it, and skips the commit
  (`if not at_base and _should_commit(...)`).
- `_drop_draft_worktree`: warns on dirty paths, calls `remove_task_worktrees`
  (rm -rf of the draft's dir plus `git worktree prune`), restores ownership;
  every failure is a WARNING.
- `run_draft_specs`: passes `at_base=True`; cleans up after a result and on
  any exception (re-raised), not on `LockHeldError` (ADR 94, 5).
- Deviation: `dispatch_phase` passes `at_base=True` to `create_worktree` only
  when set. Dozens of existing test fakes take the five-argument signature,
  and every non-draft phase now calls it exactly as before.
- Tests: `test_docker_exec.py` (detached at HEAD, no branch; writer path
  unchanged), `test_dispatcher.py` (no commit with a dirty tree; plain
  arquitecto still commits at `/work`), `test_drafts.py` (an autouse
  `cleanup` fixture fakes the container calls; removal after success, failure
  and exception, none on lock held, a failing cleanup is a WARNING, dirty
  paths named).
- The "a reviewer wrote something" retry does not fire for a draft: it is
  keyed on the reviewing roles and asks for `findings`, which the arquitecto
  schema lacks; the cleanup WARNING takes its place.
