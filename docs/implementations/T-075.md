# T-075 — the `/roadmap` screen, plans and tasks in three bands (roadmap-view, cheap form, piece 5)

No ADR: the screen, its bands, its filter and its read through the bearer
forward are the ones `docs/plans/roadmap-view.md` (*Decisions*; *What it needs
underneath*, 5) and the console's existing screens already give.

## What was built

- `front/src/routes/roadmap.tsx`: the `/roadmap` route. A *Full history* /
  *Current only* button pair (`aria-pressed`), the `WarningBanner`, then the
  error, loading or empty state, or the bands. Each band is a
  `<section aria-label>` with an `h2` heading and its plan count; each plan
  is a collapsed row (title or file, status, approved and built dates,
  supersedes and superseded by, task count) that opens to a task table: id
  linking to `/tasks/$taskId`, title, `StatusPill`, merged date.
  `RoadmapBands` is exported beside the route, as `DebtEmpty` is.
- `front/src/routes/-roadmap.test.tsx`, 8 tests: band order and counts, the
  no-plan groups at the end of their bands, a plan opening to linked tasks,
  the month grouping, *Current only* hiding the past band and merged tasks,
  the filter read from the URL, the warnings banner, the error state and the
  empty state.
- `front/src/lib/api/types.ts`: `RoadmapTask`, `RoadmapPlan`, `RoadmapMonth`,
  `Roadmap`, as `observability/api/app.py` serves them.
- `front/src/lib/api/client.ts`: `getRoadmap()`; `queries.ts`: `roadmapQuery`
  (`["roadmap"]`, polled at twice `POLL_MS`).
- `front/src/lib/api/forward.ts`: `/api/roadmap` in `FORWARDED` and in
  `PROJECT_SCOPED`; the count in its comments and rejection message goes from
  eight to nine. `forward.test.ts` gains a test that the roadmap route gets
  its own `?project=`.
- `front/src/components/console/app-shell.tsx`: a *Roadmap* nav entry, key
  `g r`, icon `Milestone`, after *Learnings*.
- `front/src/routeTree.gen.ts`: the `/roadmap` route, by hand (see below).

## Choices

- **The filter in the URL.** `?view=current` is *Current only*; *Full
  history* is the default and has no parameter, so the plain `/roadmap` link
  is the full view. Any other value reads as full.
- **What *Current only* hides.** The past band whole, and every task that is
  history: `merged_at` set or state `done`. Plans in future and now stay
  listed even when all their tasks are hidden; the row says how many were
  hidden ("k merged or done hidden"). `no_plan.now` is dropped when nothing in
  it is left.
- **The search read by the component.** The route declares `validateSearch`,
  but the page reads `useSearch({ strict: false })` and parses `view` itself,
  so it behaves the same under the test helper `renderRoute`, which builds its
  own route from the component only.
- **`routeTree.gen.ts` edited by hand.** The file is generated by the
  tanstackStart vite plugin during dev and build, and none of the granted
  scripts (typecheck, test, lint) runs it, as T-019 found. The entry was
  written in the generator's own format and order, so the next dev or build
  run regenerates the same file.
- **The forward.** `/api/roadmap` is project-scoped like `/api/debt` and
  `/api/learnings`: the console adds its own `?project=`, optional with one
  checkout and required with several.
