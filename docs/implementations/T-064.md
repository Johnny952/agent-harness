# T-064: the `load_config` merge

Task 1 of `docs/plans/console-config.md`. The rules are `docs/decisions.md`
ADR 75 and ADR 106, which narrows it. ADR 106 adds `auto_approve` and
`protected_paths` to the table as read-only and says when an error belongs to
the overrides. This is the plan. The implementador records what was built
under *What was built* below.

## Plan

1. **`dispatcher/config.py`, the key table.** Put it after `DRAFT_ROLE`.
   - Three class constants: `EDITABLE = "editable"`,
     `READ_ONLY = "read-only"`, `CREDENTIAL = "credential"`.
   - A frozen dataclass `ConfigKey` with `key_class: str`, `reason: str` and
     `kind: str | None`. `kind` is set only on an editable key and names the
     strict check in step 3. It is `None` on every other key.
   - `CONFIG_KEYS: dict[str, ConfigKey]`, one entry per top-level key, in
     ADR 75 part 5's order, then `auto_approve` and `protected_paths`. The
     three `REMOVED_BOARD_KEYS` each get their own entry with the board row's
     reason. Each `reason` is that row's text from ADR 75 part 5, or from
     ADR 106 part 1 for the two new keys. Give it a `#:` comment saying the
     writer of task 2 imports it, and citing ADR 75 part 5 and ADR 106.
   - Kinds for the 22 editable keys:
     - `bool`: `pace_primary_week`, `escalate_effort_on_repeated_finding`,
       `merge_on_done`, `gates_enabled`, `mapping_enabled`.
     - `positive_int`: `quota_threshold_pct`, `reserve_pct`,
       `quota_cooldown_seconds`, `max_revision_rounds`,
       `phase_timeout_seconds`, `gates_test_timeout_seconds`,
       `mapping_max_turns`.
     - `non_negative_int`: `escalate_effort_after_round`,
       `max_handoff_resumes`.
     - `string` (a non-empty string after `strip`): `primary_account`,
       `default_model`, `mapping_model`.
     - `effort` (one of `EFFORT_LEVELS`): `default_effort`, `escalated_effort`.
     - `list` (a YAML list, not a string): `fallback_roles`.
     - `mapping` (a dict, `{}` included): `role_model`, `role_effort`.
   - Counts: 22 editable, 15 read-only and 2 credential keys, 39 in all.
   - Add no `Config` field (ADR 75, *Consequences*).
2. **`load_config(path, *, overrides_path=None)`.** Move today's body after
   `yaml.safe_load` unchanged into `_build_config(raw: dict) -> Config`.
   Then `load_config` does this:
   - `overrides_path` defaults to
     `os.path.join(os.path.dirname(path), "config.d", "overrides.yaml")`.
     A bare `config.yaml` gives `config.d/overrides.yaml`.
   - Read the base as today. `overrides = _read_overrides(overrides_path)`.
   - If `overrides` is empty, `return _build_config(raw)`. That is exactly
     today's path, so every existing test and caller is unchanged.
   - Otherwise `merged = {**raw, **overrides}`, and
     `return _build_config(merged)`, catching `ValueError` as `err`. On a
     catch, call `_build_config(raw)`. If that raises, let its exception
     propagate unchanged (ADR 106 part 3). If it returns, raise
     `ValueError(<overrides message>) from err`. The message carries `err`'s
     text and the overridden keys, sorted.
   - Use one helper, `_overrides_error(overrides_path, keys, detail) -> ValueError`,
     for every message the overrides cause. The text is
     `f"{overrides_path}: {detail}. Reset {keys} from the console or delete
     {it|them} from {overrides_path}."`. For a whole-file failure, the keys
     are "the overrides" (the file holds no readable key). Every message
     contains the path, the word `console` and the word `delete`.
3. **`_read_overrides(overrides_path) -> dict`.**
   - Open the file. `FileNotFoundError` returns `{}`. Any other `OSError`
     propagates (ADR 106 part 4).
   - Run `yaml.safe_load`. A `yaml.YAMLError` becomes an overrides error
     ("does not parse: ..."), raised `from` the YAML error.
   - `None` (an empty or comment-only file) returns `{}`. A value that is
     not a `dict` is an overrides error ("must be a mapping of config key to
     value").
   - Check each item, in sorted order:
     - A key not in `CONFIG_KEYS`, including a non-string key, is refused:
       it is not a config key (ADR 106 part 2).
     - A key whose class is not editable is refused. The message names its
       class and reason.
     - A `None` value is refused: "null is not a value; a reset is deleting
       the key".
     - Then `_check_override_value(key, value, kind)` runs. Booleans must be
       `isinstance(v, bool)`, so the string `"true"` fails. Integers must be
       `int` and not `bool`, with `> 0` or `>= 0` as the kind says. For the
       other kinds see step 1.
   - Return the dict. The contents of `role_model`, `role_effort` and
     `fallback_roles`, the account `primary_account` names, and `reserve_pct`
     against the threshold are left to `_build_config` on the merged mapping.
     The merged-result path in step 2 attributes their errors.
4. **`tests/dispatcher/test_config.py`.** Leave every existing test as it is.
   Add a helper that writes `CONFIG_YAML` (plus extra text) to
   `tmp_path/config.yaml` and the overrides text to
   `tmp_path/config.d/overrides.yaml`. Then add these tests:
   - no `config.d` at all, an empty file, and a comment-only file: each loads
     the same `Config` as with no file (compare with `==`);
   - a scalar override (`merge_on_done: true`, `quota_threshold_pct: 95`)
     wins over the base;
   - with `role_model` in the base holding two roles, an override holding one
     replaces it whole, and `role_model: {}` empties it;
   - `fallback_roles` in the base replaced whole by a one-item list;
   - refusals, each `pytest.raises(ValueError)` with the overrides path,
     `console` and `delete` in the message: `accounts` (read-only),
     `project_keys_dir` (credential), `vibe_kanban` (a board key),
     `no_such_key` (unknown), `merge_on_done: null`, `merge_on_done: "true"`,
     `max_revision_rounds: true`, a file that is a YAML list, and a file
     that does not parse;
   - a merged-result refusal: the override sets `reserve_pct: 95` over
     `CONFIG_YAML`'s `quota_threshold_pct: 90`. The message names the
     overrides path and `reserve_pct`. Do not append a second
     `quota_threshold_pct` to `CONFIG_YAML`: PyYAML silently keeps the last
     duplicate;
   - a broken base and a valid override: the base sets `reserve_pct: 95`
     over the default threshold of 90, and the override sets
     `merge_on_done: true`. The base's own message is raised and does not
     name the overrides path (ADR 106 part 3);
   - an explicit `overrides_path` to `tmp_path/elsewhere.yaml` is read, and
     a `config.d/overrides.yaml` written beside the config is then ignored;
   - **the table test.** Write a config that sets every key in `CONFIG_KEYS`
     except the three `REMOVED_BOARD_KEYS`, with valid values (for example
     `auto_approve: {p: true}`, `protected_paths: {p: [docs/]}`,
     `primary_account: cuenta1`), and load it. Assert that
     `set(CONFIG_KEYS) == {f.name for f in dataclasses.fields(Config)} | set(REMOVED_BOARD_KEYS)`
     and that the YAML's own keys plus the board keys equal
     `set(CONFIG_KEYS)`. Also assert the class counts are 22, 15 and 2, that
     every editable key has a `kind` and no other key does, and that every
     `reason` is non-empty.
5. **`.gitignore`.** Add `/config.d/` right after `/config.yaml`.
6. **`config.example.yaml`.** Add a comment block after the header paragraph.
   It says that `config.d/overrides.yaml` beside this file overrides it. Each
   top-level key in that file replaces this file's value whole, maps and
   lists included. Only the keys `CONFIG_KEYS` in `dispatcher/config.py`
   marks editable may appear. A reset is deleting the key, and `null` is
   refused. A bad file stops every verb, and the dispatcher never falls back
   to this file alone. The directory is git-ignored. The console's
   `config-writer` will write it (`docs/plans/console-config.md` task 2, not
   built yet), and no container mounts it yet.
7. **`README.md`.** In *1. Clone and configure*, after the `cp
   config.example.yaml config.yaml` block, add one paragraph that says the
   same as step 6 in prose and cites `docs/decisions.md` ADR 75. Run `ls` on
   every path it cites.
8. **`docs/plans/console-config.md`.** After task 1's *Done when* list, add
   one paragraph: `**Built 2026-10-17** by T-064: ...`. It names
   `CONFIG_KEYS`, the `overrides_path` keyword, ADR 106 (the two read-only
   keys and the error attribution), and that nothing writes or mounts
   `config.d` yet. Change no other line, the *Status* line included.
   In `docs/README.md`, add a clause to the `docs/plans/console-config.md`
   row ("task 1 built by T-064") and to the `dispatcher/config.py` row

9. Run `python3 -m pytest`. It must be green.
