# T-126 — a public `docker_exec.resolve_commit`

Resolves debt `T-125-S1-D1` ([T-125-S1-D1](../debt/T-125-S1-D1.md)).

## What

- `dispatcher/docker_exec.py`: `_rev_parse` renamed `resolve_commit`. Same
  signature, same argv (`git rev-parse --verify --quiet <rev>^{commit}`), same
  `None` for a ref that names no commit. Its three in-module callers
  (`premerge_base`'s two reads and the merge's `merged_tip`) switched.
- `dispatcher/dispatcher.py` `_stale_reason`: both reads go through
  `docker_exec.resolve_commit`.
- `tests/dispatcher/test_dispatcher.py`: the approve fixture, the `boom`
  monkeypatch, the `spy(...)` name and the ordering assert use the new name.
- `tests/dispatcher/test_docker_exec.py`: two tests for `resolve_commit` (argv
  and stripped sha; `None` on a non-zero exit), using `_fake_docker`. Before this
  the approve tests faked the name and nothing exercised the real read.
- Debt row and file for `T-125-S1-D1` marked resolved in place.

## Why this way

Rename, no alias: a monkeypatch of the old name now fails loudly
(`monkeypatch.setattr` raises on a missing attribute), instead of silently
patching a name nothing calls. The debt entry's Fix is the recorded decision, so
no ADR.

## Ruled out

- A wrapper `resolve_commit` over `_rev_parse`: two names for one read.
- `_rev_parse_short`: a different read (`--short`, raises); untouched.
- Rewriting the historical mentions in `docs/implementations/T-125-S1.md` and
  `docs/decisions.md`: they describe what was true then.
