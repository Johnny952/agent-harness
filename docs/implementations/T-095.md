# T-095 — The board's live columns and epic swimlanes

Decisions: `docs/decisions.md` ADR 140. It covers:
- board items only, with epic rows heading swimlanes;
- the placement rule, including stale and between-phase `in_progress` rows;
- Ready in `/api/ready`'s order, and a failed ready read;
- Awaiting review with no status behind it, and no integrador lane.

## What was built

- `front/src/lib/board.ts`:
  - `columnOf(task, readySet)` places a card, or returns `null` for a row
    that is not a card;
  - `phaseNote` gives the chip on a No live phase card;
  - `boardColumns` lists the columns;
  - `laneOf` and `buildBoard` build the swimlanes, sort each column and
    apply the filter;
  - `KNOWN_STATUSES` holds the statuses the dispatcher writes.
- `front/src/routes/index.tsx`:
  - reads `tasksQuery` and `readyQuery`, plus the accounts and debt reads it
    already had;
  - has one swimlane per epic, whose header links to the epic and shows
    "n of m merged", and a no-epic lane;
  - adds a column filter beside the search and the account filter;
  - shows a broken-read line when there is no ready order;
  - the card shows the title, and on a No live phase card, the phase chip;
  - the ADR 28 banner is removed.
- Tests:
  - `front/src/lib/board.test.ts` (18).
  - `front/src/routes/-index.test.tsx` (23, of which 12 are new). They cover
    - the columns, and each one's placement;
    - the role lanes;
    - stale and between-phase rows;
    - backlog and epic rows excluded from cards;
    - lanes, their links and progress, and the no-epic lane;
    - the Ready order and the order elsewhere;
    - one read each of `/api/tasks` and `/api/ready`;
    - a ready read that errors, or answers with no ready order;
    - Other, and the warning for an unknown status;
    - the column filter;
    - the title on the card.
- `bun run typecheck`, `bun run test` (311 passed, 19 files) and
  `bun run lint` pass.

## Why this way

- The Ready order is the dispatcher's, served by the api, so the board shows
  the order the work will be taken in, and never a second copy of it.
- Each `in_progress` row lands in a column, so a reaped or stale task is
  still on the board.
- Placement is pure functions, so every branch is tested without a render.
