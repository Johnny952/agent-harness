# T-027 — the prompt carries Goal and Done when; the task-file writers move onto `dispatcher/tasks.py`

This task builds the second half of step 1 of `docs/plans/board-service.md`,
*How it would be built*. The phase prompt carries the description's *Goal*
and *Done when* sections and the path of `description.md`, not the whole
text, and every write the dispatcher makes to a task file goes through
`dispatcher/tasks.py`, whose writer refuses an unmigrated file itself. It
resolves `docs/debt/T-026-D1.md` and `docs/debt/T-026-D2.md`. No ADR, per
the card.

- **`dispatcher/operator.py`.** `release_account` calls

## Decisions

1. **The serializer stays in `context_transfer`; the refusing writer is
   `tasks._write_task_file`.** `write_task_file` belongs with `TaskFile`,
   `read_task_file` and `_write_atomic`, and nothing in `context_transfer`
   calls it any more. `migrate` is the one caller that must write over a
   legacy file, so it calls the raw one. There is no public
   `tasks.write_task_file`: nothing needs one. Ruled out: moving the
   serializer too, which would drag `TaskFile` and `_TaskDumper` across and
   touch every doc that cites them.
2. **The six writers move; they are not re-exported.** `tasks` imports
   `context_transfer`, so a re-export in `context_transfer` is an import
   cycle. A writer left there and re-exported from `tasks` would still call
   the raw `write_task_file` and fail the test that only `tasks.py` does.
   So every caller changed, `dispatcher/operator.py` included.
3. **None of the four checks is dropped.** The card says to drop them "only
   where the writer's refusal now covers them", and it covers none of them
   as a whole. The writer's refusal is per file. `open_cycle`'s check and
   `_require_migrated`'s are hive-wide, which is the rule
   `docs/business.md` *Task descriptions* confirms and names those
   functions for; that file is out of scope, so dropping a check it names
   would leave a confirmed row false. Concretely: without `open_cycle`'s
   check, a `pending` legacy file nobody locks would stop no cycle at all;
   without `_require_migrated`, `release-account` has no hive-wide check,
   and `run-task` on the unmigrated task itself is an
   `UnmigratedTaskError` traceback from `read_description`, not a usage
   error. What changed is their stated reason: they hold the whole-hive
   rule, and no longer guard the description.
4. **A lock is live for `migrate` when `status` is `in_progress`, a
   heartbeat is present, and `is_lock_expired` is false.** The "heartbeat
   present" clause is added to the card's formula, for difference 4 above.
   It matches `acquire_lock` and `operator._lock_is_live`, which both treat
   a missing heartbeat as takeable. The check is inside the `try` that
   reads the task file, so a heartbeat that will not parse is an
   "unreadable task file" refusal and not a traceback.
5. **`_role_prompt` parses, and a text that will not parse raises.** The
   refusal at dispatch is `open_cycle`'s, which parses before any phase,
   logs the missing section and blocks the task; that was already there.
   `_role_prompt` keeps taking the text and parses it again, so a caller
   that skipped `open_cycle` gets `DescriptionError` and never a prompt
   with half an ask. Ruled out: carrying the parsed `Description` on
   `CycleContext`, a wider change that saves one parse per phase.
6. **The path is always given to the arquitecto and the implementador**,
   with the names of the optional sections present, so a role does not open
   the file to find nothing. The revisor, the auditor and the mapper get no
   path: section 2 of the plan gives them *Done when* and no more.
