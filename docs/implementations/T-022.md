# T-022 — batch calls, read the Results log by its tail, check scope by stat

This task builds `docs/plans/token-economy.md` P1, P2 and P3, which are prompt
text and nothing else. Each one answers a cost that T-016's transcripts
measured: serial tool calls, reading the Results log's long rows to learn
their format, and the implementador re-reading the diff it had just written.
Scope: `dispatcher/project_docs.py`, its test, the plan and this file.

## What was built

**P1, every role.** `project_docs._BATCH` is the plan's line, word for word:
"Independent reads, greps and edits go in the same turn; every extra turn
re-reads your whole context." `duties` appends it after `_ANCHORS`, in the
same paragraph, on both of its return paths. So the arquitecto, implementador,
revisor, auditor and cartografo all carry it. A role with no duties block gets
nothing, as before.

**P2 and P3, the implementador only.** These are a new closing paragraph of
`_IMPLEMENTADOR`:

> Check your scope with `git diff --stat`, not the full diff — that is the
> revisor's read — and read only the region you need of a file with
> offset/limit. To append a row to `docs/ROADMAP.md`'s Results log, read only
> its last row, with `tail -n 1 docs/ROADMAP.md | cut -c1-400` run as written;
> never `sed` or `grep` whole rows.

Why only the implementador gets P2: it is the role T-016's transcript shows
appending a row. It also runs the checks that a row records. The revisor's
checkout is thrown away, and the auditor's duty is the indexes. The arquitecto
only plans.

Each rule lives in one place. Only P1 is shared, so only P1 is a constant.

## What was ruled out

- **The plan's "read its header and the last row".** The command does not
  return the header. The last row already shows the five columns, so the text
  claims only what the command does.
- **A pipe-free command for P2,** such as `awk 'END{...}'`. The plan names the
  `tail | cut` form. A pipe of two read-only commands ran in T-016
  (`grep "V0.6" | head -40`), and "run as written" is the exception wording
  that `_ONE_OPERATION_PER_CALL` already gives.
- **P2 in every role.** It would tell four roles how to do a duty none of them
  has, and every phase pays for its context.
