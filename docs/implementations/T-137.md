# T-137 — the debt index merges in parallel

Implements `docs/decisions.md` ADR 297.

## What

- `docs/debt/README.md`: intro rewritten for the rule; the `card` and `impact`
  paragraphs moved above the table verbatim; the table is the last block and
  every row is unchanged.
- `docs/debt/log.md` (new): the per-task paragraphs, verbatim and in order,
  under a short header. `dispatcher/project_docs.py` names it `DEBT_LOG`.
- `.gitattributes`: both files `merge=union`.
- `dispatcher/debt.py`: `index_rows` folds a resolution row (resolved, empty
  **where**) into the first row with its id; `duplicate_ids` names ids repeated
  by a row that is not a resolution; both go through a private `_raw_rows`.
  The filing note and the backlog fallback text say append / resolution row.
- `dispatcher/gates.py` `debt_index`, called beside `decisions_log` in
  `pre_merge_check` and `_gate_resolution` (`dispatcher/dispatcher.py`).
- Implementador and auditor prompts (`project_docs.py`): append, never edit.
- `docs/README.md` debt row. Tests: `tests/dispatcher/test_debt_index_merge.py`
  (fold, gate, the repo's own index, real-git merges with the no-attribute
  control and the in-place double edit), plus two assertions reworded.

## Why this way

The fold is in the one parser every reader uses, so the api, console,
`import-debt` and the backlog mirror needed no change. A folded row has the
shape an in-place-resolved row always had.

## Ruled out

Union on the README as it was (duplicates rows silently), a generated table,
a separate `resolved.md`, a custom merge driver: see ADR 297 *Ruled out*.
