# T-157 — A backup before the automatic approve and `dispatch merge-task`

Builds `docs/decisions.md` ADR 345; resolves `docs/debt/T-153-D1.md`.

## Plan (arquitecto)

1. **`dispatcher/backup.py`.** `_Locks.__init__` gains `shared: Iterable[str]
   = ()` and skips every slug in it. `backup(..., *, now, shared=())` passes
   it to `_Locks`; `before_merge(..., *, now, shared=())` passes it to
   `backup`. `restore` passes nothing. Update the module docstring's "taken
   with every project lock held" to say a caller may share its own.
2. **`dispatcher/dispatcher.py`.**
   - `CycleContext` gains `before_merge: Callable[[], str] | None = None`,
     commented like its neighbours (ADR 345).
   - `run_task_cycle` gains keyword `before_merge=None` and sets
     `ctx.before_merge` beside `ctx.may_start_phase`; docstring line.
   - `_cycle_rounds` passes `before_merge=ctx.before_merge` to
     `_auto_approve_and_merge`.
   - `_auto_approve_and_merge` gains keyword `before_merge=None`. Inside
     `if decision.approved:` and before `docker_exec.merge_task_branch`, call
     it with the same `try/except Exception` as `approve_reviewed`
     (`line = f"no backup before the merge: {exc}"`), log at info as
     `task %s: %s`, keep the line. Append `"\n" + line` to the note passed to
     `_record_auto_approve` for the `merge_failed_note` and `approval_note`
     outcomes only. Do not import `backup`.
3. **Callers that build the callable** (each imports `backup` the way it can:
   `cli.py` already has `backup_mod`; `queue.py` and `worker.py` import it
   inside the function, since `backup` imports `worker` which imports
   `queue`). The callable is
   `lambda: backup.before_merge(context_transfer.hive_root(cfg.hive_tasks_dir), cfg.state_dir, os.environ, now=<utc now>, shared=<below>)`.
   - `cli.py` *run-task*: `shared=(args.project,)`.
   - `queue._run_serial`: `shared=(queue.project,)`.
   - `queue._run_parallel`: `shared=()`.
   - `worker._start`: `shared=(record["project"],)` when
     `cfg.parallel_for(record["project"]) == 1`, else `()`.
   - Leave `_request_changes`, `command_run` resumes and `run-phase` alone.
4. **`cli.py` *merge-task*.** After `print(verdict.detail)` and before
   `docker_exec.merge_task_branch`: `line = backup_mod.before_merge(hive_root,
   cfg.state_dir, os.environ, now=datetime.now(timezone.utc))`; print it to
   stdout if it starts with `backup before the merge:`, else to stderr. Exit
   code unchanged.
5. **Tests.**
   - `tests/dispatcher/test_backup.py`: with this process holding project
     `p`'s `ProjectLock`, `backup(..., shared=("p",))` succeeds and
     `before_merge(..., shared=("p",))` returns `backup before the merge:`;
     with a second project's lock also held, `shared=("p",)` still refuses and
     writes nothing.
   - `_auto_approve_and_merge` tests (`tests/dispatcher/test_auto_approve.py`
     or `test_premerge.py`, wherever it is driven with fakes): the callable is
     called once before the merge and its line ends the approval note; a
     refusal never calls it; a raising callable still merges with the `no
     backup` line.
   - `run_task_cycle` hands `before_merge` to `_auto_approve_and_merge`
     (monkeypatch it in `tests/dispatcher/test_dispatcher.py`).
   - `tests/dispatcher/test_worker.py`: `_start` passes a `before_merge` and
     the `shared` rule follows `parallel_for` (1 → the slug, 2 → empty).
   - `tests/dispatcher/test_cli.py` *merge-task*: `before_merge` called after
     the check passed and before the merge, its line printed; not called when
     the check fails.
6. **Docs.** Root `README.md` *Backups and restore*: replace "The automatic
   approve and `dispatch merge-task` take none." with what ADR 345 does
   (and that the one-off `dispatcher` service needs `BACKUP_DIR` on its run
   line). `docs/cli.md` `merge-task`: one sentence on the backup line.
   `docs/README.md` *Modules* row for `dispatcher/backup.py`: ADR 345.
   Declare `T-153-D1` resolved in the handoff.

## Implementation (implementador)

Done as planned, with one addition: `backup.merge_hook(cfg, environ=None, *,
shared=())` builds the `before_merge` callable, so cli, queue and worker do
not each repeat the hive-root/now/env lambda. `queue._merge_hook` and
`worker._merge_hook` import `backup` locally (it imports `worker`, which
imports `queue` and `dispatcher`). `dispatcher.py` never imports `backup`: the
callable rides `CycleContext.before_merge`. `_auto_approve_and_merge` calls it
only after `decision.approved`, and appends its line (`_backup_suffix`) to the
merge-failed and approval notes only.

`worker._start` shares the project's slug only when `cfg.parallel_for` is 1;
`_run_serial` shares it, `_run_parallel` does not. `merge-task` shares nothing
(it holds no lock) and prints the line to stdout if the copy was taken, else
stderr. Ruled out: a waiting mode (would stall the merge behind a running
cycle; ADR 345) and a `before_merge` on `_request_changes`/resumes.

Tests: `test_backup.py` (shared lock, other project's busy lock still
refuses, `merge_hook`), `test_dispatcher.py` (once before merge and line in the
note, never on refusal, raising callable), `test_worker.py` (parallel rule),
`test_cli.py` (order, stderr, not called on failed check). Existing fakes of
`run_task_cycle` gained a `before_merge=None` parameter. Full suite: 4524
passed, 15 skipped.

## Out of scope

A waiting mode; the `BACKUP_DIR` mount on the compose `dispatcher` service
(ADR 345 *Consequences*); a copy before `merge_on_done`'s `_merge_task_branch`.
