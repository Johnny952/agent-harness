# T-072 — `GET /api/roadmap`, plans and tasks in three bands (roadmap-view, cheap form, piece 4)

No ADR: the route, its bands and its read-only, never-500 rules are the ones
`docs/plans/roadmap-view.md` (*Decisions*, 2, 3, 5; *What it needs
underneath*, 4) and the api's ADRs already give.

## What was built

- `observability/api/plans.py`: the strict frontmatter reader, moved out of
  `tests/test_plan_frontmatter.py` so the api and the test share one copy.
  `read(text, plan_names)` returns the block and its problems, the block only
  when there are none; `check` returns the problems (the test's old
  function); `title` returns the first `# ` heading after the block. The
  module is under `observability/` because the api image COPYs only
  `observability/` and `dispatcher/`.
- `tests/test_plan_frontmatter.py` imports `check` from it; its tests are
  unchanged.
- `observability/api/app.py`: `GET /api/roadmap?project=`, behind auth.
  `?project=` resolves through `_project`, as `/api/debt` does: no checkout is
  404, one is used when none is named, two or more without a name is 400, an
  unknown slug is 404. Any other parameter is 400. Plans come from
  `<projects_root>/<slug>/docs/plans/*.md`; tasks from `cfg.hive_tasks_dir`
  through `list_task_ids` and `read_task_file`, as `/api/tasks` reads them.
  `MAX_ROADMAP_PLANS = 500` and `MAX_ROADMAP_TASKS = 2000`, each with its
  comment; past one, the sorted names or ids are cut before any file is read
  and a warning gives the count dropped.
- `tests/observability/test_roadmap.py`, 20 tests; `/api/roadmap` added to
  `ROUTES` in `tests/observability/test_api.py`, so the shared auth, unknown
  parameter and envelope tests cover it.

## The response

Inside `_envelope`:

```json
{"project": "ia-harness",
 "bands": {"future": [<plan>], "now": [<plan>], "past": [<plan>]},
 "no_plan": {"now": [<task>], "past": [{"month": "2026-10", "tasks": [<task>]}]}}
```

- `<plan>`: `{"file", "title", "status", "approved", "built", "supersedes",
  "superseded_by", "tasks"}`. Dates are ISO strings or null.
  `superseded_by` is computed from the other plans' `supersedes`.
- Bands: `idea | design | approved` and `null` in `future`, `building` in
  `now`, `built | superseded | dropped` in `past`. Within a band: newest
  `built`, else `approved`, first; undated last; ties by file name.
- `<task>`: `{"id", "title", "state", "merged_at"}`. `title` is always null:
  no task file has one. `merged_at` is the `merged.at` that
  `tasks.mark_merged` writes, or null.
- `no_plan.now` holds the tasks with no `merged` block, in id order;
  `no_plan.past` the merged ones by `YYYY-MM` of `merged.at`, newest month
  first, a `"month": null` group last for a missing or unreadable date.

## Choices

- A plan with no frontmatter, an invalid one, or one that cannot be read is
  listed in `future` with `status`, `approved` and `built` null and
  `supersedes: []`, and a warning naming the file and the problems. A block
  that breaks one rule is not trusted for its other fields.
- Merged means the task file has the `merged` block, not a state.
- A task's `plan` places it under that plan only when it is a string naming
  a listed plan file. Anything else that is set (an unknown name, a list)
  sends it to `no_plan` with a warning.
- Tasks are per harness, not per project: no task file carries a project
  key. A task is filtered out only when its frontmatter has a `project` that
  is not the slug; the route's docstring says so.
- An unreadable task file (YAML that does not parse, no block, a block that
  is not a mapping) is a warning and is skipped.
- `superseded_by` links only the plans within the cap.

## Against the real checkout

Run once with the Flask test client, the worktree as the checkout (it has

`past` 6, `no_plan` 0 and 0, no warnings. Against

`future` 21, all `status: null`, with 21 warnings, one per plan.
