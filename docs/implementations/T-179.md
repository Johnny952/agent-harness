# T-179 — Tokens screen design (docs only)

**What.** `docs/decisions.md` ADR 456 and a pointer paragraph in
`docs/plans/console-config.md` section 4. No code, compose or front change.

**Why this way.** The ADR answers the four "Done when" items in its
*Decision* 1-6 (kinds and bodies, handlers), 4 (how the console sees a
credential) and 8 (`update_project_before_task`); *Consequences* lists eight
build tasks, one surface each. The central choice is that a secret never sits
in an action record (records are served by `/api/actions` and backed up), so it
travels in a `0600` file under `actions/secrets/` that the worker reads once
and unlinks. The console sees credentials through a `credentials.json`
snapshot the worker writes from `stat` and public halves only.

**Ruled out.** See the ADR's *Ruled out*: secrets in `params`, a `login_code`
kind, the board service writing the credential file, the config writer,
`docker exec -it`, `claude setup-token`, reading `expiresAt`, api-side exec.

**Revision round 1.** No review findings were handed on; I re-checked the ADR
and the section 4 paragraph against the task's Done when and found them
matching, so nothing changed.
