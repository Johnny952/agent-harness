# T-160-S3 — backlog drop reason and dropped-row display

Contract: `docs/decisions.md` ADR 372 (server rule: ADR 366).

## What was built

- `front/src/lib/api/types.ts`: `Task` gains `dropped_reason` and `dropped_by`
  (`string | null`, required); `AcceptTaskBody` gains optional `reason`.
  Every `Task` literal (fixtures and tests) carries the two nulls.
- `front/src/routes/backlog.tsx`:
  - `decide(taskId, to, opts)` takes `{priority?, reason?}`; the body is `{to}` plus
    `priority`/`reason` only when given, so accept and defer bodies are unchanged.
  - The drop confirm has a text input (`reason for dropping <id>`); *confirm drop* is
    disabled while the trimmed reason is blank and sends `{to: "dropped", reason}`
    trimmed. *cancel* clears the reason. A refusal reaches the existing error toast.
  - A dropped row shows a second line in the title cell, `DroppedWhy`:
    `dropped by <by>: <reason>`; a blank/null reason is `Absent` "no reason recorded";
    a blank `dropped_by` with a reason is `Absent` "not recorded".

## Why this way

- Trim on the client too: the server refuses a blank reason, so the button is the
  first gate and the toast the second.
- The reason stays in state after the confirm closes, so a refused drop needs only a
  second press of *drop* then *confirm drop*.
- A shared `OnDecide` type replaces the two copies of the callback signature.

## Ruled out

- Clearing the reason on confirm: loses the text on a refused drop.
- Touching the task detail screen: out of scope.

## Tests (`front/src/routes/-backlog.test.tsx`)

Gating (blank, whitespace, filled), body sent (trimmed reason), refusal toast, dropped
row shown, absent reason, absent author. Gates: `bun run typecheck`, `bun run test`
(867 pass), `bun run lint` all pass.
