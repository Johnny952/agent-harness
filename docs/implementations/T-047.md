# T-047 — model on every usage line

Decision: `docs/decisions.md` ADR 68 (narrows ADR 53).

## What

- `dispatcher/dispatcher.py`: `_usage_record` takes a required `model`
  (no default, so a forgotten caller fails loudly) and writes `model` and
  `models_used`. `_UsageRecorder` holds `model` beside `account`; `dispatch_phase`
  builds it with the same `model` it passes to `exec_claude`, so the phase line,
  every retry line and each failover account's line carry it with no change at
  the `recorder.record` call sites.
- `models_used` is `sorted(raw["modelUsage"])` only when that is a dict; the
  values are never read. `{}` gives `[]` (an object); absent, non-object or
  unmeasured gives `null`.
- Comments counting keys updated in `dispatcher.py`, `observability/api/app.py`
  and the `_call` fixture in `tests/observability/test_api.py`, which also
  gains the two keys. The api itself is untouched: lines travel verbatim.
- `docs/plans/front.md` usage card: one sentence, showing them is a separate
  front task.

## Ruled out

- Inferring `model` from the role or config default: ADR 53's rule is no
  guessed values.
- A default on the `model` parameter: would hide a call site that forgot it.
- Back-filling old lines: they stay without the keys.
