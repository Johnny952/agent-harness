# T-186-S2 — the Tokens screen reads the credentials snapshot

Contract: `docs/decisions.md` ADR 489 (on ADR 456 decision 7, ADR 471, ADR 483).

## What was done

- `front/src/routes/tokens.tsx` rewritten onto `credentialsQuery` and
  `accountsQuery`: loading line, `ErrorState`, no-snapshot banner, one
  `WarningBanner` for both reads, stale banner with a ticking age, a
  `BrokenBanner` line when `/api/accounts` fails, and the three regions
  (GitHub token, Deploy keys, Claude logins). No controls.
- Rows are read through guards in the components that render, so a row of the
  wrong shape is `Malformed` in its place and the others still draw.
- `accountStateTone` moved from `pool.tsx` `AccountCard` to `front/src/lib/format.ts`;
  both screens read it.
- Deleted: `listTokens`, `reauthContainer` and their state in `client.ts`;
  `tokensQuery`; `TokenState`, `ContainerToken`; `initialTokens` and the
  now-unused `inFuture` helper in `mock/ops-fixtures.ts`.
- `-tokens.test.tsx`: one test per state through `renderRoute`.
- Docs: `docs/README.md` *Modules* `front/` row and `front/README.md` now count
  three fixture screens.

## Why this way

- Row guards use a local all-optional-`unknown` interface (`Served`), because
  `noPropertyAccessFromIndexSignature` rejects `Record<string, unknown>` dot access.
- In the no-snapshot case the accounts read's warnings still go through
  `WarningBanner`: ADR 489 decision 3 only keeps the *credentials* warnings out of it.

## Ruled out

- Keeping `reauthContainer` for 7c: ADR 489 decision 1, 7c uses ADR 483's calls.
- Validating the snapshot up front: one bad row would cost the good ones.

## Verified

`bun run typecheck`, `bun run lint`, `bun run test` (full suite) in `front/`;
`grep` for the deleted names in `front/src` is empty.
