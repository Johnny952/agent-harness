# T-178-S3 — the Roadmap screen draws epics, walked headless

Contract: ADR 453 over ADR 447. Plan: step 2's screen half of
`docs/plans/roadmap-view.md`; step 4 of `docs/plans/browser.md`.

## What was built

- `front/src/lib/api/types.ts`: `RoadmapEpic`, the union `RoadmapRow`; the
  lists of a plan, a month and `no_plan.now` hold rows. `RoadmapTask` gained
  `kind?: undefined` so `kind === "epic"` narrows.
- `front/src/routes/roadmap.tsx` (drawn whole by `p.$slug.roadmap.tsx`, so the
  route file is untouched): `EpicRows` is a row whose title is an
  `aria-expanded` button, then the sub-tasks as indented rows of the same
  table, or one muted line, or `Malformed` when `tasks` is not a list. A
  `backlog` label sits beside the state when `place === "backlog"`.
  Plan rows are keyed `<band>:<file>`; an epic's key is `epic:<id>`.
  The plan head counts tasks and epics apart.
- `keep` (the Current-only filter) is one function over a list of rows, used
  for a plan's rows and for an epic's sub-tasks; an epic is history by the
  task rule. The merged count reads the api's `merged_tasks`, not the kept list.
- Tests: `describe("epics on the Roadmap screen")` in `-roadmap.test.tsx`:
  expand, backlog in future with the two-band key, no sub-tasks, current only.
