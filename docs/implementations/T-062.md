# T-062: TLS in front of the console

The rule is `docs/decisions.md` ADR 100; this is the plan, and the implementador
records what was built under *What was built* below.

## Plan

1. `docker/caddy/Caddyfile` (new). A header comment: path, what mounts it
   (the `caddy` service, read-only), ADR 100, and the two variables. Body:
   ```
   {
   	email "{$ACME_EMAIL}"
   }

   {$HARNESS_DOMAIN:http://localhost} {
   	header {
   		X-Content-Type-Options nosniff
   		X-Frame-Options DENY
   		Referrer-Policy strict-origin-when-cross-origin
   		-Server
   	}
   	@hsts {
   		protocol https
   		not host localhost
   	}
   	header @hsts Strict-Transport-Security "max-age=31536000"
   	reverse_proxy console:8790
   }
   ```
   Tabs, as `caddy fmt` writes them. A comment above the site address says why
   the fallback carries `http://` (that is what turns automatic HTTPS off for
   it, ADR 100 point 3) and above `email` why it is quoted (point 4). No
   `encode`: the live tail streams and nothing has measured it through one.
2. `docker/compose/docker-compose.yml`: a `caddy` service right after
   `console`, with a comment block in the file's style (plain file only and
   why, the only non-loopback publisher, no socket and no state, ADR 100):
   ```yaml
   caddy:
     image: caddy:2.10.2
     restart: unless-stopped
     ports:
       - "80:80"
       - "443:443"
       - "443:443/udp"
     volumes:
       - ../caddy/Caddyfile:/etc/caddy/Caddyfile:ro
       - caddy_data:/data
       - caddy_config:/config
     environment:
       - HARNESS_DOMAIN=${HARNESS_DOMAIN:-http://localhost}
       - ACME_EMAIL=${ACME_EMAIL:-}
     depends_on:
       - console
     networks:
       - ia_harness_net
   ```
   Add `caddy_data:` and `caddy_config:` under `volumes:`. In the console's
   comment, replace "the TLS proxy is a later task (docs/plans/server-deployment.md)"
   with: Caddy below proxies to it (ADR 100); the loopback publish stays for
   an SSH tunnel. Touch no other service. The Coolify and agents files are not
   edited (card *Out of scope*).
3. `scripts/configure.sh`, the `.env` writer: after the `COLLECTOR_WRITE_TOKENS`
   echo, append commented lines only, so `_env` in `tests/scripts/test_configure.py`
   (which skips `#` lines) is unaffected:
   `# TLS (docs/decisions.md ADR 100), plain compose only. Uncomment to serve`
   `# a domain over HTTPS; unset, Caddy serves http://localhost.`
   `# HARNESS_DOMAIN=console.example.com`
   `# ACME_EMAIL=you@example.com`
   No prompt (no default is right for every host, as ADR 9 argues for
   `CONSOLE_PROJECT`). `docker/compose/.env.example` does not exist; do not
   create it.

## What was built

- `docker/caddy/Caddyfile`: global `email "{$ACME_EMAIL}"`, site address
  `{$HARNESS_DOMAIN:http://localhost}`, four security headers plus `-Server`,
  HSTS behind a `@hsts` matcher (`protocol https`, `not host localhost`),
  `reverse_proxy console:8790`. No `auto_https` option, no `encode`.

  after `console`, volumes `caddy_data` and `caddy_config`, console comment
  updated. `scripts/configure.sh` writes four commented lines, no prompt.

  parametrized. `python3 -m pytest`: 2108 passed, 10 skipped.
- README *TLS* subsection, five services, Coolify paragraph. Plan step 3 got
  its *Built* note.
