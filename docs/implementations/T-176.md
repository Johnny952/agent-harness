# T-176 — socket proxy for the dispatcher and the worker

Binding decision: `docs/decisions.md` ADR 435 (inventory, allowlist, shape).

## What was done

- `docker/compose/docker-compose.yml` and `docker-compose.coolify.yml`: a
  `docker-proxy` service (wollomatic socket-proxy, pinned at 1.10.0) with the socket
  `:ro` as its only mount, no ports, on a new internal `docker_proxy_net`,
  profiles `dispatcher` and `worker`. Three allow flags (HEAD, GET, POST)
  hold the allowlist; `$` is written `$$` for compose.
- `dispatcher` and `worker` in both files: socket mount removed,
  `DOCKER_HOST=tcp://docker-proxy:2375`, joined `docker_proxy_net`, depend on
  `docker-proxy`. They stay equal to each other.
- `scripts/configure.sh` `render_coolify_compose`: the networks heredoc gets
  `docker_proxy_net`, so the byte-for-byte render of the Coolify file holds.
  The heredoc is unquoted: a backtick in its comment is executed, so the
  comment avoids backticks.
- `tests/integration/test_compose_invariants.py`: the old "worker and
  dispatcher mount the socket" test is replaced by four: only the proxy
  mounts it (`:ro`, agents file included); pinned/unpublished/internal with
  exactly three members; clients carry `DOCKER_HOST`; the allowlist admits the
  six exec-path calls and refuses create, start/stop/kill, other-container
  exec, image, volume, network, build and container listing.
- Docs: backlog item 6 marked done, README profiles list and Future work,
  `config.example.yaml` naming note.

## Why this way

The test reads the patterns out of the compose `command` and runs them with
Python `re`, so the file the proxy reads is the file under test. No Python
under `dispatcher/` changed: the `docker` CLI reads `DOCKER_HOST`.

## Ruled out

See ADR 435 *Ruled out* (tecnativa proxy, no name restriction, body
filtering, `DOCKER_HOST` in the Dockerfile, a published port).

## Not verified

No daemon here: the image tag, the CLI's exact call list and the proxy
passing the exec `101` upgrade are untested. A `403` in the proxy log on first
deploy names a missed call.
