# T-151: a CLI reference checked against the parser, and a --limit that refuses a count

Decisions: `docs/decisions.md` ADR 333 (the `--limit` floor) and ADR 334 (the
reference and its test).

## What was done

- `dispatcher/cli.py`: the parser construction moved out of `main()` into
  `build_parser()` unchanged (so a test can build it); `main()` calls it.
  `--limit` got `metavar="TOKENS"` and help that says measured tokens, not
  tasks. `MIN_QUEUE_LIMIT = 100_000` sits beside the exit codes; `_run_queue`
  refuses a smaller `--limit` with `parser.error` after the "needs" check and
  before `queue_mod.plan`, so nothing is planned, saved or started. The "needs"
  message now reads `--limit TOKENS` and `--resume QUEUE_ID`. `--resume` is not
  checked: the saved queue's own limit stands.
- `docs/cli.md`: all 21 subcommands, each with a table of arguments (unit,
  default), its exits, plus global options, the exit-code table, the project
  lock and `run-queue` in full. Linked from README *5. Run a task* and
  `docs/README.md`.
- `tests/dispatcher/test_cli_reference.py`: compares subcommands, options,
  positionals, global options and exit codes between the parser and the doc, in
  both directions, plus three self-tests that a doc with a row removed, a
  command renamed or an invented option is caught.
- `tests/dispatcher/test_queue.py`: refusal (`2`, `99999`) with no queue file
  and no phase started, the boundary `100000` accepted, missing `--limit` names
  `--limit TOKENS`.
- Existing CLI-driven tests raised their `--limit` (500 to 500000, 1000 and
  10000 to 1000000; the fake phase spend 600 to 600000) so they still fail or
  pass for the reason they name.

## Why this way

The parity test reads the doc's tables rather than generating the doc, so the
prose stays hand-written; only names and exit codes are enforced. The floor is
in the CLI only, so `queue.plan` and the console's start path (separate limit
check) are unchanged; ADR 79's measurement and enforcement are untouched.

## Ruled out

- Generating `docs/cli.md` from the parser: loses units and prose.
- Checking the floor in `queue.plan`: it would break the many tests that plan
  with small limits and widen the change beyond the CLI.
- Checking `--resume`: out of scope.

## Notes

The Done-when sentence "parallel cycles only run through `run-queue
--parallel`" is scoped in the doc to the CLI; the worker's `project_parallel`
(ADR 306) is named as the other path.
