# T-088 — The read api serves the backlog fields and the Ready order

Decisions: `docs/decisions.md` ADR 133. It covers:
- `priority`, `source`, `tags`, `rank` and `debt_id` on every task row,
  shaped as `board_list` shapes them;
- a bad value as a warning, with the row still served;
- `GET /api/ready`, the Ready column as ids in `ready_order`;
- `impact` on debt rows, as `index_rows` reads it.

## What was built

- `observability/api/app.py`:
  - `_task` gains `priority` (`tasks.effective_priority`), `source`,
    `tags` (`tasks.normal_tags`), `rank` and `debt_id`. Both task routes
    get them, and the detail route still adds only `body`.
  - `/api/tasks` and `/api/tasks/<task_id>` add `"<path>: <problem>"` to
    `warnings` for each of `tasks.field_problems`, computed inside the
    guard.
  - `GET /api/ready`: no parameters, `data` is a list of task ids in
    `tasks.ready_order` order. An unreadable task file and a bad field are
    warnings. `ready_order` itself is guarded, so it never 500s.
  - `/api/debt` is unchanged: it already served `impact` (T-086).
- `docs/README.md`: `/api/ready` in the api row.
- Tests, `tests/observability/test_api.py`:
  - `/api/ready` in `ROUTES`, so it is covered by the 401, 400 and envelope
    checks.
  - The two exact-row asserts gained the five keys, with the defaults of a
    task filed before them: `normal`, `null`, `[]`, `null`, `null`.
  - The fields on both routes, and a bad priority, tag, rank and `debt_id`,
    each warned once and served as written.
  - `/api/ready`: buckets, rank, id and dependencies; equal to
    `ready_order(read_all_tasks(...))`; an unreadable file and a bad field
    warned; empty with no tasks.
  - `impact` from a six-column index (`risk`, `cost`, `cosmetic`, `none`, a
    typo) and from an old five-column one.
- Full suite: 3032 passed, 10 skipped.

## Why this way

- The same helpers as `board_list`, so the two services answer one task the
  same way, and no second validator or order exists.
- `priority` and `source` come with `rank` and `debt_id`, since a rank only
  orders inside its bucket.
- `/api/ready` is its own route, so `/api/tasks` keeps its envelope and its
  "no parameters" rule, and it does not clash with `/api/tasks/<task_id>`.
