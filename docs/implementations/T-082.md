# T-082 — The backlog, `priority`, `source` and the per-task write lock (board-service step 5a)

Decisions: `docs/decisions.md` ADR 127. It covers:
- the backlog statuses;
- the two new fields, validated on read;
- `open_cycle` refusing the backlog;
- a `flock` write lock per task, separate from the ownership lock of ADR 126.

## What was built

- `dispatcher/context_transfer.py`: `TaskFile.priority` and `TaskFile.source`.
  They are read from the frontmatter and written only when set, so a file
  without them keeps its bytes.
- `dispatcher/tasks.py`:
  - Constants: `BACKLOG_STATUSES` (`proposed`, `deferred`, `dropped`),
    `ACCEPTED_STATUS` (`pending`), `PRIORITIES`, `DEFAULT_PRIORITY`
    (`normal`), `SOURCES`, `LOCKS_DIR_NAME`.
  - `field_problems`, `effective_priority`, `is_backlog`, `dispatch_problems`.
  - `BacklogTaskError`, which `acquire_lock` raises for a backlog status.
  - `locks_root`, `task_lock_path` and `task_lock`: an exclusive `flock` on
    `<hive root>/locks/<id>.lock`, re-entrant per thread. The file is created
    `0644` and never removed.
  - `@_locked` on every read-modify-write writer:
    - `set_resolved_debt`, `acquire_lock`, `refresh_heartbeat`;
    - `release_stale_lock`, `handoff`, `mark_blocked`, `mark_merged`;
    - `record_command_verdict`, `update_command_verdict`;
    - `file_split`, on the parent.
  - Explicit locks in `close_epic` (the parent), in `file_split` and
    `accept_drafts` (each child created), and in `migrate` (each task).
- `dispatcher/dispatcher.py`: `open_cycle` refuses on `dispatch_problems`,
  beside the dependency and epic refusals it already had.
- `dispatcher/queue.py`: `plan` refuses a task that cannot run for the same
  reasons. `_depends_on` became `_task_file`.
- `board_service/app.py`: `board_list` rows carry `priority` (the effective
  one) and `source`. A bad value comes back as a warning naming the file, and
  the backlog statuses come from `tasks.BACKLOG_STATUSES`.
- Tests:
  - `tests/dispatcher/test_tasks.py` covers:
    - the fields' round trip, and no keys written when unset;
    - a bad hand edit kept on write and named on read;
    - the backlog statuses not dispatchable, and the board statuses fine;
    - `acquire_lock` refusing the backlog and still taking a blocked task;
    - the lock's path, its `0644` mode under umask 077, and its absence from
      the hive's listing;
    - exclusivity against another descriptor, re-entrancy, a waiting thread,
      and two takers with one winner.
    - `_tree` leaves out `locks/`, since the tests that snapshot the hive
      assert that nothing was written to it.
  - `tests/dispatcher/test_dispatcher.py`: `open_cycle` refuses each backlog
    status and a bad priority, and still opens `pending`, `blocked` and
    `in_progress` with valid fields.
  - `tests/dispatcher/test_queue.py`: `plan` refuses a backlog task and a bad
    source.
  - `tests/board_service/test_app.py`: the rows carry `priority` and
    `source`; the backlog fields; the bad-field warnings; the service's
    backlog statuses match the dispatcher's.
- Docs: ADR 127, the plan's Status and step 5.

## Why this way

- Validation on read, because the writers that run every few seconds (the
  heartbeat) must not stop on a hand edit they did not make. The places that
  decide to dispatch are the places that refuse.
- The backlog refusal is narrower than "anything but `pending`": blocked
  retries, `in_progress` resumes and `run-phase` all go through `open_cycle`.
- A write lock separate from `owner`, because a read-modify-write is not
  ownership. The service will write comments and edits on a task a phase
  holds.
- `flock` on a kept file: released by the kernel on a crash, so no stale lock
  file, and it blocks other threads of the same process too.
- `locks/` outside `tasks/` and `board/`, because both are listed.

## Pending

- **5b**: the write tools (`backlog_propose`, `task_edit`, `task_comment`,
  `backlog_accept`, and defer and drop), over MCP and HTTP. They validate what
  they set and take `task_lock`. The service then needs the hive mounted
  read-write (see the compose note below).
- **5c**: `tags` and `rank`, and the *Ready* order with its dependency rule.
- **5d**: debt filed as backlog items with `source: debt`, the one-time import
  of the open entries in `docs/debt/`, and the auditor's `impact` column.
- A required `source` on a backlog item, once 5b's tools set one.
- The api and the read-only service take no lock. That is fine while
  `_write_atomic` replaces files whole.

## Compose (not changed here)

For 5b, the `board-service` service needs the hive mounted read-write instead
of `:ro`, `locks/` included, so it can take `task_lock` and write (ADR 124
point 4). Its process must be able to create files in `<hive root>/locks/`.
Until then nothing in the service writes.

## Ruled out

- Refusing a bad `priority` or `source` in the module's writer.
- `open_cycle` refusing every status but `pending`.
- The frontmatter's `owner` as the write lock.
- A lock file beside the task in `tasks/`.
- `fcntl.lockf`, or `O_EXCL` lock files removed after use.
