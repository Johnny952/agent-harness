# T-110 — the worker's `turn` handler

Contract: `docs/decisions.md` ADR 173. Main-thread step 2.

## What was built

- `dispatcher/threads.py`: `update(session_id=)` sets the last segment's
  session (opens no segment; the PATCH route does not accept it);
  `conversation_path` / `append_conversation` (append, flush per line).
- `dispatcher/docker_exec.py`: `run_docker_exec`'s argv factored into
  `_docker_exec_argv` and reused by `open_docker_exec` (Popen, stdout pipe,
  stderr to a temp file) — one path to the socket; `turn_command` (pid
  wrapper, `timeout`, flags per ADR 173, 3); `kill_in_container`.
- `dispatcher/worker.py`: `_turn` in `HANDLERS`; `Running.kill`; a cancel of a
  claimed `turn` sets `cancelled` and calls `kill`; `run()` kills running turns
  before joining; `recover()` writes `turn_end` for an interrupted turn;
  `_consider` skips the pool-wide account check for `turn` and writes
  `waiting: thread` for a busy `thread:` key.

## Why this way

- The handler looks its `Running` entry up by action id rather than changing
  the handler signature shared with `start`/`cancel`/`command_verdict`.
- A status of `interrupted` on stop applies only when no `result` arrived: a
  turn that finished before the kill landed is `done`.
- `Worker.recover()` closes the log only for results `actions.recover`
  reports as `interrupted`; the handler checks the record's kind and
  `started_at` itself.

## Ruled out

- A second Popen path, a handler-signature change, retrying a failed turn,
  parking an account on a rate-limit result (debt proposed).

## Tests

Fake `docker_exec.open_docker_exec` / `kill_in_container` (a `FakeProc` with
a blocking stream); no real `claude`. `tests/dispatcher/test_worker.py`
(turn section), `test_threads.py`, `test_docker_exec.py`. Not verified: the
Bash allowlist prefixes against a live CLI.

## Audit

- `_turn`'s no-result branch reads `proc.stderr`, but `open_docker_exec`
  passes a temporary file as `stderr`, and `subprocess.Popen` sets
  `.stderr` only for `stderr=PIPE`: on a real exec it is `None`. A turn that
  ends without a `result` event (no login, a refused flag) still ends
  `failed`, but its error reads `AttributeError: 'NoneType' object has no
  attribute 'seek'`, not claude's stderr. `FakeProc` sets `stderr` to a
  `StringIO`, so the test that checks for "no auth" passes. The
  `open_docker_exec` docstring makes the same wrong claim. Not fixed here
  because the auditor's commit covers `docs/` only, so it is handed on as
  debt. Learning: `docs/learnings/a-fake-popen-must-not-have-attributes-the-real-one-lacks.md`.
- On a `--resume` turn, `total_cost_usd` in the action's result is the
  session's running total, not this turn's
  (`docs/learnings/a-resumed-calls-cost-is-the-sessions-running-total.md`).
