# T-157-D1 — The compose `dispatcher` service has no `BACKUP_DIR` mount

**Origin:** introduced, by T-157; declared by its arquitecto and implementador.
**Status:** resolved 2026-10-23 by T-158 (`docs/decisions.md` ADR 360).
**Ruling:** accepted by T-157's revisor.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cost.

## What

Since T-157, `dispatch run-task`, `dispatch run-queue` and
`dispatch merge-task` take a copy before their merge (`docs/decisions.md`
ADR 345). Only the `worker` service mounts `BACKUP_DIR` (ADR 342, 1); the
one-off `dispatcher` service in the compose files does not.

## Where it bites

A task that changes the `dispatcher` service in `docker/compose/*.yml`, or
the `run` line in `scripts/backup.sh`.

## Why it stayed

`scripts/backup.sh` already adds the same `/backups` mount and variable on its
own `run` line; mounting it on the service duplicates that and is its own
change. The copy is best effort, so no merge is refused for its absence.

## Cost of leaving it

An operator running those commands through the `dispatcher` service gets
`no backup before the merge: BACKUP_DIR is not set` unless they pass the mount
and variable on the `run` line, and has only the nightly copy behind the merge.

## Fix

Mount `BACKUP_DIR` on the `dispatcher` service in both compose files and drop
the `-v`/`-e` from `scripts/backup.sh`'s `run` line; ADR 345 *Consequences*
names the gap.
