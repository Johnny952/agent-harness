# T-008-D3 — `docs/plans/board.md`'s Status paragraph still calls Phase 0 queued

**Origin:** introduced by T-008. **Status:** resolved 2026-09-26, out of cycle
— no task claimed Phase 1, and the paragraph was wrong in a second way the
declaration did not know about (see *Fix*). **Ruling:** accepted by the
revisor, rounds 1 and 2.

## What

`docs/plans/board.md`'s Status paragraph reads "Phase 0 is specified below and
queued as T-008, to be built by …". Phase 0 is built and on this branch, so the
plan's own front matter contradicts the code it planned.

## Where it bites

A task or an operator reading that paragraph to decide whether Phase 0 exists,
and concluding it is still queued. Phases 1–6 all start from that file.

## Why it stays

The task's "Out of scope" names `docs/plans/board.md` as the spec and forbids
touching it: editing the file a task is measured against, mid-task, moves the
target. Nobody in T-008 was allowed to close this.

## Cost of leaving it

The plan says Phase 0 is pending while `dispatcher/vibe_kanban_client.py` has
`LocalBoardClient` in it. A reader who trusts the plan either re-specifies work
that exists or waits for it.

## Fix

One line in that Status paragraph: Phase 0 landed in T-008, pointing at
`docs/decisions.md` ADR 1 and `docs/implementations/T-008.md`. It belonged to
whoever opened Phase 1 — the first task allowed to edit the plan.

Done 2026-09-26, without waiting for Phase 1, because by then the paragraph
had drifted a second time. The declaration above describes it as calling
Phase 0 "specified below and queued as T-008"; what it actually said when this
was fixed was that the run had been cut off by a host reboot and the
implementador's round 2 was green but uncommitted in the `work` worktree. That
was true when written and false by the time anyone read it: the run was
resumed with `run-phase`, round 2 committed as `1d4ca62`, the auditor closed
the task and the branch is merged. Both errors pointed the same way — a reader
would conclude Phase 0 does not exist — so the rewrite states the outcome and
cites the debt still open, rather than adding the one line asked for here.
Entries `T-008-D1` and `T-008-D2` remain the open Phase 0 items in the code.
