# T-193-S1-D1 — No command creates a second user (e.g. a reviewer)

**Origin:** introduced, by T-193-S1; declared by its arquitecto and implementador.
**Ruling:** accepted by T-193-S1's revisor.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cost.

## What

`python3 -m board_service.first_user` (`docs/decisions.md` ADR 519) creates
the first owner only: it refuses once `users.json` holds any user. Nothing
else adds a user, so a reviewer account (ADR 324 roles) has no command.

## Where it bites

A task, or an operator, needs a second account (a reviewer) on a live server
whose `BOARD_AUTH_DIR` already holds the owner.

## Why it stayed

Out of scope: T-193-S1's done-when names only the first owner.

## Cost of leaving it

The operator cannot add a reviewer without editing code or calling
`board_service/signin.py` `create_user` by hand.

## Fix

A sibling command, or a `--role` flag gated on an existing owner, recorded in
a new ADR next to ADR 519.
