# T-017-D1 — no test pins which number each route hands its empty-state component

**Origin:** introduced, declared by T-017's implementador in round 1 and again in
round 2 as one entry, in `front/src/routes/learnings.tsx`,
`front/src/routes/debt.tsx` and `front/src/routes/tail.tsx` — the three files
that task edited.
**Status:** resolved 2026-10-10 by the operator, out of cycle and together with
`T-017-D2`, in the order the *Fix* below asks (see *How it was resolved*).
**Ruling:** accepted by the revisor in round 1 and re-affirmed
in round 2, on the grounds that pinning it needs a router and a seeded
`QueryClient` this suite has no harness for, which is wider than the one surface
the task was held to.
**Card:** none — this harness has no board configured, the first reason given in
[`README.md`](README.md)'s closing paragraphs.

## What

Closing `T-016-D1` split each screen's bare-state branch into a component
exported beside its own `Route`, which is what made the branch renderable
without a router (`docs/decisions.md` **ADR 44**, third bullet). Thirteen tests
across `front/src/routes/-learnings.test.tsx`, `-debt.test.tsx` and
`-tail.test.tsx` pin every arm of `LearningsEmpty`, `DebtEmpty` and
`TailNoMatch`.

What no test pins is the **argument the route passes**, which is the whole of
what `T-016-D1` was:

```
front/src/routes/learnings.tsx   <LearningsEmpty served={served.length} query={q} />
front/src/routes/debt.tsx        <DebtEmpty served={served.length} query={q} />
front/src/routes/tail.tsx        <TailNoMatch buffered={events.length} />
```

Pass `rows.length` instead of `served.length`, or `filtered.length` instead of
`events.length`, and the component is handed `0` for a collection that holds
rows: the screen renders Empty's sentence over a filter that matched nothing,
exactly the defect `T-016-D1` described, with all 73 tests green. The only thing
standing in the way is the comment above each call site.

The extraction did not create the gap so much as move it. Before it, the whole
branch was untested; now the arms are pinned and the seam is one expression
wide and still unobserved.

## Where it bites

A task editing the empty-state call site in `front/src/routes/learnings.tsx`,
`front/src/routes/debt.tsx` or `front/src/routes/tail.tsx`, or changing how
either of the first two computes `served` or `rows` — the `served` line in
`debt.tsx` is one unmemoised `?? []` and reads like a duplicate of `rows`, which
is the shape a cleanup deletes.

Also any task that wants to assert *anything* about a `front/` screen as a
screen rather than about one of its components: the helper named in *Fix* is the
missing piece, and it is worth having well beyond these three.

Not a task editing only the component bodies — `LearningsEmpty`, `DebtEmpty` or
`TailNoMatch`'s copy and arms are covered.

## Why it stays

Pinning it needs a route render, and a route render needs a router plus a
`QueryClient` seeded with a fixed `/api/learnings` and `/api/debt` body. This
suite has no such harness: every one of its eight test files renders a component
directly, which is why `front/src/routes/-index.test.tsx` mounts `TaskCard` and
not the Board.

Building that harness is a task of its own. T-017's text held it to one surface
— *no api change, no new route, no other wording on either screen* — and the
tests it was asked for, both cases on both screens, are the ones that shipped.

## Cost of leaving it

A refactor reintroduces `T-016-D1` with a green suite. That is the specific
failure the fix was written against, so the cost is not a new defect class but
the absence of a guard on the one this project has already paid for once.

It is bounded in the same way the original was: the operator typed the filter,
their text is still in the box, and clearing it restores the table. Nothing is
lost and no decision rests on it. Nobody has reported it, and nobody has seen
any of these three states in a browser — `docs/ROADMAP.md` **V0.6f** is `NOT
RUN`.

## Fix

A route-render helper under `front/src/` — a `renderRoute`-style wrapper holding
a memory-history router and a `QueryClient` seeded per test — and then one test
per screen: a served collection of N, a query that matches none of it, asserting
the no-match title and the absence of the collection's. The helper is the
expensive half and the three tests are a few lines each.

Write the helper first and against one screen, not three: whether a seeded
`QueryClient` or an intercepted `fetch` is the right seam here is the decision
the task actually makes, and `front/src/lib/api/forward.ts` already has its own
test idiom to compare against.

## How it was resolved

The helper is `front/src/test/render-route.tsx`, and the seam it picks is an
intercepted `fetch`, not a seeded `QueryClient`. A seeded cache covers the two
screens that read through `useQuery` and misses the Live tail, which polls
`client.ts` from a `useEffect`; one `vi.spyOn(globalThis, "fetch")` — the idiom
`front/src/lib/api/forward.test.ts` already uses — covers all three, and the
served body still crosses `readEnvelope` and its adapters, so a test sees the
rows the screen does. A path a test did not serve answers 404, which the screen
draws as its error state. `renderRoute(Route, path, served)` takes only the
route's `component` and mounts it under its own root with a memory history, as
`-index.test.tsx` builds its own router, so the generated tree's document shell
never loads.

One test per screen, in `-learnings.test.tsx`, `-debt.test.tsx` and
`-tail.test.tsx`: three rows served, a filter that matches none of them, and
the assertion that the no-match title and *all 3* (*the 3 events* on the tail)
are on the page while the empty collection's title is not. Each was checked by
mutation: handing the component `rows.length`, or `filtered.length` on the
tail, fails its test, and the call sites were restored afterwards. The suite is
77 tests, all green; no call site and no component body changed for this entry.
