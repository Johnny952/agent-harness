# T-131-D1 — two more stale counts of the board-service's backlog writes

**Origin:** found, declared by T-131's arquitecto and implementador.
**Status:** resolved 2026-10-22 by T-132.
**Ruling:** accepted by the revisor in round 2.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cosmetic.

## What

Two places in `front/src/lib/api/` still count the board-service's backlog
writes as four, while `boardTarget` in `forward.ts` forwards five (`POST
/api/backlog`, and a task's `PATCH`, comment, accept and verdict):

- `server-env.ts`, module comment: ADR 136 adds `BOARD_SERVICE_URL` "for the
  board-service's four backlog writes" — the variable now serves every
  board-service write, not only the backlog ones.
- `forward.test.ts`, the test named *gives the four backlog writes no
  Authorization*.

## Where it bites

A task that edits `server-env.ts`'s comment on `BOARD_SERVICE_URL` or the
no-Authorization test in `forward.test.ts`, or that greps `front/` for a count
of board-service writes.

## Why it stayed

T-131's Goal named only `forwardBoard`'s doc comment.

## Cost of leaving it

A reader gets a stale count; the code is unaffected.

## Fix

Reword both to name the writes rather than count them, as T-131 did for
`forwardBoard`'s doc comment (`docs/implementations/T-131.md`). Check whether
the test's body covers the verdict write before renaming it to claim so. See
the learning
[the-forwarded-route-count-is-prose-and-derived-from-nothing](../learnings/the-forwarded-route-count-is-prose-and-derived-from-nothing.md).
