# T-014-D1 — the card gate reads a heading, and `handoff.py`'s prose fallback can write one

**Origin:** declared `introduced` by T-014's implementador in round 1, in
`dispatcher/learnings.py:drop_promoted` and `dispatcher/context_transfer.py:has_phase_section`
— the gate it had just built — and accepted by the revisor in round 1, then
re-verified against `dispatcher/handoff.py` in round 2.
**Status:** open. It is the limit of the proxy
[`T-012-D1`](T-012-D1.md)'s fix chose, and it is written up in
`docs/implementations/T-014.md` *The limit of the proxy, beyond the residual ADR
34 accepts* as the next thing to know if the gate is ever seen to pass on a
cycle whose auditor did not run.

## What

The gate added by [`docs/decisions.md`](../decisions.md) ADR 34 asks the task
card whether the promoting role's phase returned. Its evidence is a heading:
`context_transfer.has_phase_section` matches `^## auditor$`, or
`^## auditor (round N)$`, in the parsed body of `{hive_dir}/{task_id}.md`.

What makes that heading evidence is that the **dispatcher** writes it, not the
role it describes. `dispatcher/handoff.py:body` renders `## {label}` over the
label the phase loop builds, and `run_phase` returns `None` before building any
label when a fatal phase did not finish — so on the structured path a role can
neither forge a section nor forget to write one. Every line of the role's own
text lands behind a `- ` bullet or a `**Bold**` label, well inside the block.

The structured path is not the only path. When a phase comes back with no
parseable payload — it ignored the schema, or ran on an image whose CLI had none
— `body` falls back to `fallback_body(text)`, which returns the phase's raw
prose verbatim, unindented and unfenced, clamped only for length:

```python
rendered = render(payload) if payload else ""
if not rendered:
    rendered = fallback_body(text or "")
return f"## {label}\n\n{rendered}"
```

So a phase whose prose begins a line with `## auditor` at column zero puts that
heading into the card body, where the gate cannot tell it from a section the
dispatcher wrote. The role that forges it need not be the auditor: any phase's
fallback prose lands in the same body, and the gate searches the whole of it.

## Where it bites

You are changing what `dispatcher/handoff.py:body` or `fallback_body` renders
for a phase that returned no parseable payload — the fix lives there, and a
change that reflows or re-indents that text may close this entry by accident or
widen it. Or you are asking why the gate passed on a cycle whose auditor never
ran: the first thing to check is whether that card's `## auditor` section is a
real one, which is a section with the dispatcher's rendered fields under it
rather than prose continuing mid-sentence.

Not the structured path, which is every run so far. And not a `final=True`
phase that does not return at all: `run_phase` answers `None`, the loop builds
no label, and the card gets no section either way — so the case this entry
describes needs a phase that *returned* unparseable prose, and returned prose
that happens to open a line with the promoting role's own heading.

## Why it stays

The fix is in another function's contract. `fallback_body`'s docstring says what
it is for — "the phase that ignored the schema, or ran on an image whose CLI did
not have one" — and it keeps the head and the tail of the prose because
`revisor_approved` still reads a verdict line out of the tail. Changing what it
renders means re-deciding how a phase's unparseable return is preserved, which
is a question about handoffs, not about the drop, and T-014's twenty lines were
scoped to the drop.

No run has produced it. The structured path is what every phase in this harness
has taken, and it cannot reach column zero.

## Cost of leaving it

One silent drop, on exactly the cycle `T-012-D1` exists to protect: a
`merge-task` whose auditor never ran, where some other phase's prose forged the
section. The entries move to the `dropped/` sibling rather than away, so the
loss is recoverable — ADR 33 bought that independently of this gate — but it is
unannounced, and the kept line that would have told the operator which entries
stayed and why is never printed. The failure is quiet in the same way the
original was, which is what made `T-012-D1` expensive to notice.

## Fix

Fence or indent what `fallback_body` returns, so no role's prose can reach
column zero as a heading. Indenting is the smaller change and keeps the text
greppable; a fence has to survive prose that contains a fence of its own. The
gate then needs no change at all, because the only thing it trusts — a
column-zero `## <role>` heading in the body — becomes something only
`body`'s own f-string can write.

One test in `tests/dispatcher/test_handoff.py`: a prose body containing
`## auditor` renders no second-level heading. Pair it with the existing
`has_phase_section` cases in `tests/dispatcher/test_context_transfer.py`, which
already pin that the heading and not the role's name is the test.
