# T-009-D4 — `/api/events` cannot read the collector's WAL database through the `:ro` mount

**Origin:** introduced by T-009. **Status:** open. **Ruling:** accepted by the
revisor, rounds 1, 2 and 3.

## What

The `api` service mounts `observability_data:/events:ro`, as
`docs/plans/board.md`'s "Configuration" specifies, and reads with
`db.connect_read_only` (`file:<path>?mode=ro`, `uri=True`, never `init_db`). The
collector's database is in WAL mode, and a WAL reader creates `events.db-shm`
and `events.db-wal` when they are absent — measured. On a read-only mount it
cannot, so sqlite refuses the open and `/api/events` answers `[]` plus a warning
naming the path.

## Where it bites

Phase 3's tail, anyone comparing `/api/events` with the dashboard over the same
volume, or any later service handed `observability_data` `:ro`. It does not bite
the tests, which use a writable `tmp_path`, so the suite is green either way.

## Why it stays

The `:ro` mount is the plan's own Configuration, this task's non-negotiable, and
a compose invariant. The alternatives were ruled out rather than skipped:
`immutable=1` is undefined against a live writer, and changing the journal mode
is a schema change this task was forbidden. Failing with a warning that names
the file is the envelope behaving correctly; it is the mount that is wrong, and
only the running stack can confirm which.

## Cost of leaving it

The endpoint Phase 3 builds its tail on may be permanently empty in production,
for a reason whose sqlite message — `unable to open database file` — reads like a
missing database rather than a read-only one. `observability/api/app.py:_no_events_warning`
distinguishes a cold start from a database present but unopenable, which is the
only signal an operator gets.

## Fix

Mount `observability_data` read-write on the `api` service in both
`docker/compose/docker-compose.yml` and `docker-compose.coolify.yml` — `init_db`
still never called from the API — after confirming against the running stack
that the read-only open is what fails. The measurement and the ruled-out
alternatives are in `docs/implementations/T-009.md`, "The events volume is `:ro`
and the collector writes WAL"; the sidecar behaviour is
`docs/learnings/a-read-only-sqlite-open-still-writes.md`.
