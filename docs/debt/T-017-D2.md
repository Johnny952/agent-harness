# T-017-D2 — `TailNoMatch` has no singular arm, so one buffered event reads *the 1 events*

**Origin:** introduced, declared by T-017's implementador in round 2, in
`front/src/routes/tail.tsx` — a component that task added. Found by its revisor
in round 1 and called non-blocking there.
**Status:** open. **Ruling:** accepted by the revisor in round 2, as copy polish
`docs/ui.md` does not ask for, in a state reached only at `buffered === 1`.
**Card:** none — this harness has no board configured, the first reason given in
[`README.md`](README.md)'s closing paragraphs.

## What

`TailNoMatch` in `front/src/routes/tail.tsx` interpolates the buffered count
into one sentence with no singular form:

```
Clear the payload filter, or set source and type back to all, to see the
${buffered} events this tail has buffered again.
```

At `buffered === 1` that reads *to see the 1 events this tail has buffered
again*. Both siblings this task wrote carry the singular — `LearningsEmpty` has
`served === 1 ? "the one entry" : …` and `DebtEmpty` `"the one row"` — and
`-debt.test.tsx` *counts one served row in the singular* pins it. The tail's
arm is the one of the three that does not.

Reaching it takes exactly one event in the buffer and a filter excluding it: a
payload query matching nothing, or a `source`/`type` pair that no single event
carries. On a quiet harness, which is this project's normal state, that is not
an exotic combination.

## Where it bites

A task editing `TailNoMatch`'s body in `front/src/routes/tail.tsx`, or copying
the tail's form as the multi-filter precedent for a new no-match state —
`docs/ui.md` *Absent, empty and broken are three different things* points a
screen with more than one filter at this shape, so the wart is what the next
such screen would be copying.

Not a task editing the two single-filter screens: `LearningsEmpty` and
`DebtEmpty` both have the singular already.

## Why it stays

Round 2's findings were all in `docs/ROADMAP.md`, and the round whose job is the
check a human walks is the wrong place to add code a reviewer has not seen. The
`docs/ui.md` entry asks for the query or the controls and the count; it does not
ask for the singular, so this is polish inside a component that had already
passed review rather than a transcription error.

## Cost of leaving it

A grammatical wart in the one no-match state an operator reaches by accident
rather than by mistyping, on the screen whose silent-blank defect that arm
exists to end — and inconsistent with the two screens the original defect was
on, which is the kind of inconsistency `docs/ui.md` exists to prevent.

Nobody has seen it: `docs/ROADMAP.md` **V0.6f** is `NOT RUN`, and the copy is
reachable in a browser only.

## Fix

One ternary mirroring `LearningsEmpty`'s `served === 1 ? "the one entry" : …`,
plus a case in `front/src/routes/-tail.test.tsx` on `-debt.test.tsx`'s *counts
one served row in the singular* idiom. Both files are open in front of you and
the whole change is two lines.

Decide the noun while you are there: *the one event this tail has buffered* is
the form the siblings take, and *the 1 events* is the only thing this entry
objects to.
