# T-024-D3 — `/api/tasks/<task_id>/usage` has no screen, and no card says what one would show

**Origin:** found by the operator on 2026-10-10, out of cycle, while resolving
[`T-024-D1`](T-024-D1.md), whose *Fix* asked for a route and the screen that
consumes it. The route was built under `docs/decisions.md` **ADR 54**; the
screen was not.
**Ruling:** none — no revisor ruled on it, on the `T-012-D1` and `T-014-D2`
precedent in [`README.md`](README.md)'s closing paragraphs.
**Card:** none — this harness has no board configured, the first reason given
in [`README.md`](README.md)'s closing paragraphs.

## What

`GET /api/tasks/<task_id>/usage` serves a task's per-call usage log, one group
per attempt with the lines verbatim (ADR 54), and nothing in `front/` requests
it. The console has no view of what a phase cost, and no card in `docs/` says
what one would show, where it would sit or which of the group's keys it would
print.

## Where it bites

A task asked to show a phase's or a task's cost in the console, or to put the
usage route on a screen. Also a task building a screen around
`/api/tasks/<task_id>` — the task detail — since that is the screen this route
was shaped beside (ADR 54 answers 404 for the same ids that route does).

Not a task editing the console's Tokens screen or `docs/plans/front.md`'s Tokens
task: those are a container's provider login, a different object with the same
word ([the-tokens-screen-is-logins-not-spend](../learnings/the-tokens-screen-is-logins-not-spend.md)).
Not a task that only needs the numbers: the route serves them to anyone with
the api's credential.

## Why it stays

The resolution that built the route was out of cycle and kept away from
`front/`, and the screen needs a contract that does not exist yet — which page,
which columns, how a failover or a clamped first group reads — and that is a
card's job, not a debt fix's. A screen would also be tempted to show a total,
and none may be shown before [`T-024-D2`](T-024-D2.md) is answered.

## Cost of leaving it

The series is now readable over HTTP but still read by nobody, so the operator
reads a phase's cost with `curl` or `jq` rather than in the console. Bounded:
nothing is lost while this row is open, because the log is append-only and the
route serves it whole up to `MAX_USAGE_CALLS` lines.

## Fix

A card in `docs/plans/front.md` that names the screen — most likely a section
of the task detail — and what it prints from a group: the attempt's
`role`, `round`, `account`, `call_kinds` and `phase_call`'s measured fields,
with the per-call lines behind a disclosure. It must not print a sum across
`calls` until `T-024-D2` is answered and a new ADR adds the total as a key;
until then, a per-attempt figure is `phase_call`'s, labelled as the first call
and not as the attempt.
