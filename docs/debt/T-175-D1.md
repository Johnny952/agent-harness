# T-175-D1 — `escalated_model` is read-only in `CONFIG_KEYS`: the console cannot show or edit it

**Origin:** introduced, by T-175; declared by its arquitecto and implementador.
**Ruling:** accepted by T-175's revisor.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cost.

## What

T-175 added the opt-in `escalated_model` (`docs/decisions.md` ADR 432) with a
`_read_only` row in `dispatcher/config.py` `CONFIG_KEYS`. The override kinds
`_check_override_value` accepts have no nullable string, so the console's
config editor cannot set or clear it.

## Where it bites

A task that makes `escalated_model` editable in `CONFIG_KEYS`, adds an override
kind to `_check_override_value`, or changes the console config editor's rows.

## Why it stayed

T-175's scope was the `config.yaml` opt-in; its surface asked for the console
change to be filed as a follow-up.

## Cost of leaving it

The operator sets or clears `escalated_model` only by editing `config.yaml`.

## Fix

Add a nullable model-ID override kind to `_check_override_value` (null or a
non-empty string, as `_load_escalated_model` checks) and flip the `CONFIG_KEYS`
row to `_editable`; the console editor must render a `None` value.
