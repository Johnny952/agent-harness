# T-026-D2 — `dispatch migrate` does not check that no cycle is in flight

**Origin:** introduced, declared by T-026's implementador in round 1 and again
in round 2.
**Ruling:** accepted by the revisor in both rounds: a one-off operator command
documented to run with nothing in flight, and the per-task lock arrives with
the writes moving onto the module.
**Card:** none — this harness has no board configured, the first reason given
in [`README.md`](README.md)'s closing paragraphs.

## What

`dispatcher/tasks.py`'s `migrate` reads each task file, writes
`description.md`, then rewrites the task file with `write_task_file`. Nothing
between its read and its write holds a lock, and it does not look at the
task's `status` or heartbeat. A dispatcher that holds a live lock on the same
task has a heartbeat thread doing its own read-then-write
(`context_transfer.refresh_heartbeat`) on that file.

## Where it bites

An operator runs `dispatch migrate` while a dispatcher holds a live lock: the
heartbeat's read-then-write can interleave with migrate's rewrite of the same
task file.

Narrower than it looks. A dispatcher built from this branch refuses to open a
cycle on an unmigrated hive, so the racing process has to be one that started
before the images were rebuilt, or a cycle on a hive where only some other
file is legacy. Not a second `migrate` run: that is idempotent.

## Why it stays

There is no cross-process lock on task files yet; the plan's per-task lock
arrives with the second half of step 1 of `docs/plans/board-service.md`.
`migrate` runs once per hive, by hand, and
`docs/implementations/T-026.md` *Operator steps after the merge* says to stop
every cycle first.

## Cost of leaving it

A lost heartbeat write, or a `handoff` section written between migrate's read
and its write and then overwritten. An old-image dispatcher racing it could
also write the key back, which the next entry point refuses by name.

## Fix

Have `migrate` refuse a task file whose lock is live
(`status: in_progress` and `context_transfer.is_lock_expired` false),
reporting it under `refused` so the verb exits 1; or take the per-task lock
once step 1's second half adds it. A test in `tests/dispatcher/test_tasks.py`
beside the other refusals.
