# T-018-D1 — ADR 24 still says installing `front/node_modules` is not authorised

**Origin:** found, declared by T-018's implementador in round 1, in
`docs/decisions.md` **ADR 24** and in [`README.md`](README.md)'s closing
paragraph on `T-015-D1` — neither of them a file T-018's card named, both of
them read by this task's phases while establishing ADR 45's *Context*.
**Status:** open. **Ruling:** accepted by the revisor in round 1, which
verified both sentences exist and are false, and ruled that correcting an
append-only ADR about another subject is a second decision T-018's card did
not give.
**Card:** none — this harness has no board configured, the first reason given
in [`README.md`](README.md)'s closing paragraphs.

## What

Two sentences in `docs/` say a phase cannot have `front/node_modules`.

`docs/decisions.md` **ADR 24**, in the paragraph establishing the two facts
the bearer forward rests on, parenthesises that `front/node_modules` "does not
exist in this repository and installing it is not authorised".

[`README.md`](README.md)'s closing paragraph on `T-015-D1` says the same in
different words: that entry's *Fix* "cannot be verified by whoever takes it
from inside a phase, because no phase of this project can run `bun` and a
worktree has no `node_modules`", citing the shared inbox entry
`/data/.hive/learnings/inbox/T-015-bun-is-refused-in-a-phase.md`.

Both are false of a phase whose card grants the `front/` scripts. The agent
image has shipped `bun` 1.3.12 since 2026-10-08 (`docs/decisions.md` **ADR
39**), T-018's card granted `cd front && bun install --frozen-lockfile`, and
all four of its phases ran it — 486 packages on the cold install, `Checked 512
installs across 549 packages` warm. Reading `front/node_modules` is how
**ADR 45**'s whole *Context* was established: the two knobs' declarations in
`@tanstack/router-generator`'s `baseConfigSchema`, the `readdir` filter in
`getRouteNodes`, and the `no-route-export` branch that warns rather than
throwing.

The inbox entry ADR 24 and the row are consistent with is itself the stale
kind: `/data/.hive/learnings/inbox/T-016-a-phase-can-fill-node-modules-itself.md`
already says a phase whose card grants the install can run it.

What is false is the install clause, not everything ADR 24 concludes from it.
The sentence it supports — that a task here cannot run the route generator, so
a shape needing a new entry in `front/src/routeTree.gen.ts` cannot ship
complete — still holds: the scripts a card grants are `install`, `typecheck`,
`test` and `lint`, and none of them regenerates that file. A narrowing entry
has to say which half it is taking, which is why this is a decision and not a
word.

## Where it bites

Any task whose card grants a `front/` script and whose phase reads ADR 24, or
that `T-015-D1` paragraph, as a reason not to run it — the phase then reasons
a `front/` change through from in-file precedent instead of executing the
suite its own card gave it. That is the shape
`/data/.hive/learnings/inbox/T-016-a-phase-can-fill-node-modules-itself.md`
warns about, and the grant and the ADR now disagree in writing, so which one a
phase believes is luck.

Sharpest for a task taking `T-015-D1` itself, whose *Fix* needs the lint's own
nine file names and whose row says no phase can get them.

Not a task that never opens `front/`: nothing outside that directory depends
on either sentence.

## Why it stays

`docs/decisions.md` is append-only, and ADR 24 is an accepted entry on `main`
about a different subject — the bearer forward. Narrowing it is a second
decision with its own *Context* to establish: which phases may install what,
what makes it reproducible, and what the two index paragraphs then owe.
T-018's card scopes the task to the `routeFileIgnorePattern` claim, and fixing
this one in passing is exactly the move T-017's auditor correctly refused on
T-018's own bullet.

**ADR 45**'s *Consequences* names it as another task's narrowing rather than
leaving it silent, so a reader of the newest entry is told.

## Cost of leaving it

A phase plans around a wall that is not there and ships a `front/` edit
nobody executed — the eleven-defect class
[`T-013-D1`](T-013-D1.md) describes, which cost this project one revisor
finding, one debt row and nine defects found only when that row was closed by
hand.

Bounded by the card: a phase whose card grants the scripts and reads the grant
first loses nothing, and the test gate runs all three on every task regardless
(`docs/decisions.md` **ADR 39**), so a wrong `front/` edit is still caught at
the gate rather than on `main`.

## Fix

One narrowing ADR in **ADR 45**'s shape: `front/node_modules` is installable
by any phase whose card grants it, `cd front && bun install
--frozen-lockfile` is the form, and the lockfile plus `bun`'s install cache on
the projects mount are what make it reproducible and fast. ADR 24 keeps its
number, its `**Status:**` line, its parenthetical and an unstruck heading
(`docs/learnings/a-stale-count-in-a-dated-paragraph-is-not-a-finding.md`, *an
ADR on `main`*).

Then the one clause in [`README.md`](README.md)'s `T-015-D1` paragraph, which
is this index and so live prose, not a record.

A task taking this should take all four surfaces at once: the two above plus
the two the revisor found and did not file —
[`T-013-D1`](T-013-D1.md)'s row here, which contradicts itself in the same
cell ("the test gate installs `front/`'s dependencies … but no gate *runs*
any of the three scripts"), and the paragraph immediately above
`front/README.md` *Writing a test*, which states the same two false things
("no gate in `dispatcher/gates.py` *runs* any of the three", and the image
half "is blocked on an agent image with `bun` in it"). They are one stale
fact in four places, and `/data/.hive/tasks/T-018/review.md` *Findings carried
as `found` debt* holds the evidence for the two that are not this row's.
