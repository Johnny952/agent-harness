# T-014-D2 — thirty stale citations sit in the twelve docs the pointers gate stopped reading

**Origin:** filed by hand on `main`, out of cycle, 2026-10-07, against
`dispatcher/gates.py:_broken_pointers` — the gate narrowed the same day by
`docs/decisions.md` ADR 35. Like [`T-012-D1`](T-012-D1.md) it departs from
*Declare `found` debt only for files your task touched* in the README: the stale
sentences are in twelve docs this change never opened. It is filed anyway
because narrowing the scope is precisely what stops anyone from being told
about them again, and this row is now the only record that they are stale. The
id is hand-derived, on the `T-010` precedent that row used: ADR 35's gate landed
in `bc07f4e`, a hand commit from before the T-008 debt sequence existed, so it
has no sequence of its own, and `T-014-D1` was taken.
**Status:** open, partly paid. The first two fixes below landed by hand on
`main`, 2026-10-08: the gate's two excuses now compose, and the two foreign
paths are written from the root that owns them. That closes the
foreign-filesystem class whole and 2 of the build-output class's 4 pairs, and
*Landed* at the end of this row says why not all 4. What is left is
deliberately not resolvable by one pass: both remaining classes are edits to
*records*, which this project's own ruling says not to make.

## Where it bites

A reader following any of these citations, which is the ordinary cost. The
sharp case is `docs/learnings/a-plans-present-tense-claim-is-a-citation.md`: its
whole subject is that a document's present-tense claim must be checked with one
`ls` before you act on it, and its own *Symptom* section now names a test file
that T-010 moved. The learning fails at the thing it teaches.

Any task that proposes to widen `project_docs.PRESENT_DOCS` — the obvious
candidate is `docs/plans/`, since a plan's Status paragraph really is a claim
about the present — inherits these pairs the moment it does: 4 of them for
`docs/plans/`, and it has to fix them in the same change or the gate reports
them against work that did not cause them.

And any task touching `gates._in_a_subproject` or `gates._ignored` owns the
fourth class, because that is where the two excuses would compose.

Not the six entries `PRESENT_DOCS` names today. Those are clean: the gate
reports nothing on this tree, which is what makes this row the whole of what
was given up.

## Cost of leaving it

Bounded and already paid, for three of the four classes: a reader loses one
`ls` per citation and learns that a sentence in a record describes a tree that
has moved on — which is what a record is for, and what
`docs/learnings/a-plans-present-tense-claim-is-a-citation.md` exists to warn
about. What it really costs is that the warning is now the only line of defence,
since no gate will raise any of them again.

The fourth class is the one that grows. Every `front/` build writes new hashed
asset filenames, so any walk that pastes a build listing into
`docs/ROADMAP.md` adds citations that are stale as soon as the next build runs,
and ADR 35's excuses will not cover those either — the count only goes up, and
nothing reports it.

## Fix

Four, independent, and the first is the only one that is code.

**Compose the two excuses.** *(Landed.)* `_in_a_subproject` already asks
`git ls-files --cached` for a tracked path ending in `/<token>`; the same
listing reveals the subproject roots. Resolve each still-broken token against
those roots and hand `git check-ignore` the resolved paths as well as the bare
token. Two tests in `tests/dispatcher/test_gates.py`, beside the eight ADR 35
added: a token that only the composed form excuses, and one that neither rule
excuses, so the widening cannot swallow a real finding. It stays cheap because
both excuses are still asked only about tokens `ls` already failed on.

**Spell a foreign path absolutely.** *(Landed.)* A citation naming something
inside the agent image, or any filesystem that is not this repo, should be
written from its own root: `pointer_token` rejects a leading slash, so the
sentence keeps its meaning and stops pretending to be a pointer. Two lines in
`docs/ROADMAP.md`, and nothing is lost, because no reader could resolve the
relative form here either.

**Decide record-or-present once per doc, then edit only the present ones.**
This is the bulk of the 30 and it is a judgement, not a sweep. A walk's evidence
line, an implementation note and an ADR are records: ADR 35 and the learning
both say to leave the sentence and write the disagreement somewhere newer. A
sentence a reader would *act* on today — a plan's Status paragraph, the
architecture's description of what exists — is a claim about the present and is
worth fixing. The six retired-module tokens are one grep and one decision, not
eighteen.

**Decide whether `docs/plans/` belongs in `PRESENT_DOCS`.** ADR 35 left it out
because most of a plan is a prediction, and a prediction that reads as a fact is
the exact failure the learning describes. If a later task decides the Status
paragraph is enough to put the file in scope, that is an ADR of its own, and the
4 pairs above come with it.

## Landed

Two hand commits on `main`, 2026-10-08, in the order the Fix section lists
them.

`a2d74dc` composes the excuses. `_tracked` asks once for the cached listing
both excuses already needed; `_subproject_roots` reads the subproject roots off
it — the directory of every tracked gitignore below the root, the root's own
deliberately left out, since resolving a token against the root is just the
token; and `_ignored_by_a_subproject` hands `check-ignore` each token resolved
against each root, mapping the answers back to the bare tokens. It is asked
only about the tokens the other two excuses left standing. The two tests the
Fix asked for are in `tests/dispatcher/test_gates.py`.

It excuses 2 of the 4 build-output pairs, not 4. The two under a dotted
directory resolve. The two hashed assets do not, under any spelling, because
the citation leaves out the directory the build writes them into —
`front/dist/` — so they are mis-spellings of a path that never existed as
written, and they belong with the third class's judgement rather than with this
class's rule.

`93c4245` rewrites the two foreign paths in `docs/ROADMAP.md` from the root
that owns them: a checkout's own settings file under `/data/projects/<name>/`,
which is where this project's compose file bind-mounts project clones, and the
prune's destination under `/root/.claude/skills`, the shared skills tree
`docker/agent/entrypoint.sh` creates and links into each account's config home.
Both are rejected as tokens now, for the leading slash.

One thing this row had wrong: the relative settings path was not a sloppy
spelling of the absolute one the same doc cites. The sentence contrasts user
and managed settings with *a project's own* settings file, so the two are
different files, and the fix names the project's rather than collapsing them.
