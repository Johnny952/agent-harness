# T-019-D1 — `docs/ROADMAP.md` V0.6c and V0.6d still give the retired install clause as half their reason

**Origin:** found, declared by T-019's arquitecto and again by its implementador
in round 1, as one entry, in `docs/ROADMAP.md` **V0.6c** and **V0.6d** — a file
T-019's card did not name, read by every phase of it while checking that no
third surface rested on the clause `docs/decisions.md` **ADR 46** retires.
**Status:** resolved 2026-10-10 by the operator, by hand on `main` and out of
cycle, in the order the *Fix* below asks (see *How it was resolved*).
**Ruling:** accepted by the revisor in round 1, which verified
both bullets, noted that V0.6c's clause wraps across two lines so a grep for
the phrase finds only V0.6d's, and ruled that a guess in the doc that records
what was verified is worse than a dated reason.
**Card:** none — this harness has no board configured, the first reason given
in [`README.md`](README.md)'s closing paragraphs.

## What

Two bullets in `docs/ROADMAP.md` say why no phase can run a console check or
write its results row, and half of each reason is the clause ADR 46 retired.

**V0.6c**'s first bullet: the check has never been run "and no phase can run
it: a phase works in a fresh worktree, where `front/node_modules` is gitignored
and absent and `bun install` is not a role's call", and then, as the other
half, a T-010 inbox entry saying the container half is a human's row too.

**V0.6d**'s first bullet inherits it: "no phase can run it, because a phase's
worktree has no `front/node_modules` and `bun install` is not a role's call".

The install half is false of a phase whose card grants the `front/` scripts.
ADR 46 is the narrowing: `front/node_modules` is installable by any phase whose
card grants it, in the form `cd front && bun install --frozen-lockfile`, and
every phase of T-018 and T-019 ran it. "A fresh worktree" is wrong too, for a
smaller reason ADR 46's *Context* also records: the writer roles share one
persistent worktree per task, and only the revisor's is rebuilt.

The **conclusion** of both bullets may still be true. It now rests entirely on
the other half — a check that wants a browser driven against the console and
the compose stack brought up — and that half is undecided, not false:
`docs/decisions.md` **ADR 43** gives agent containers a headless Chromium for
QA screenshots, no card has granted a compose bring-up, and the inbox entry
V0.6c cites for the container half has not been re-ruled on since T-010.

## Where it bites

A task reading V0.6c or V0.6d to learn whether a phase may run a console
check; a task adding a check whose *Run* steps need `bun`, and copying the
nearest sibling's reason why no phase can write its row; a task ruling on
browser-driven QA (ADR 43) or on a compose bring-up inside a phase, which is
the decision that would settle the other half.

Not a task that only reads a *Results* row: the rows are dated records of an
operator's walk and say nothing about why a phase did not take it.

## Why it stays

Correcting the clause means naming the remaining blocker in its place, and
nobody has ruled on it. Striking the install half alone would leave each
bullet's conclusion standing on an inbox entry and an open question, which
reads as stronger than it is; writing "a phase needs a browser and the stack"
would be a ruling T-019's card did not give, put into the doc whose job is to
record what has been verified. T-019's card scoped it to four named surfaces
and the ADR, and its *What was ruled out* in
`docs/implementations/T-019.md` says so.

## Cost of leaving it

A phase reads the retired rule a third time — the shape `T-018-D1` was filed
for, now in the one doc ADR 46's *Consequences* lists as deliberately left.

Bounded: both checks are unrun by any phase either way, the card grant now
disagrees with the bullets loudly, and the `front/` scripts run at the test
gate on every task regardless (`docs/decisions.md` **ADR 39**), so nothing
ships unexecuted because of it.

## Fix

One clause per bullet, once browser-driven QA and a compose bring-up inside a
phase have been ruled on: drop the install half, cite ADR 46 for why it is
gone, and give whatever that ruling leaves as the reason — or, if the ruling
lets a phase run the check, say so and let the next task write the row.

Keep both ids and every *Run* and *Pass* step untouched
(`docs/learnings/retargeting-a-roadmap-check-keeps-its-id.md`). Grep for
`role's call` rather than the whole phrase: V0.6c's clause wraps after
"is not a", so a search for the sentence finds V0.6d's alone.

## How it was resolved

The ruling the *Fix* waited on was given by the operator on 2026-10-10: what
keeps a phase from running either check is that its setup brings the api up
with `docker compose`, and `docker` is not in `config.yaml`'s `allowed_tools`.
Browser-driven QA was not the blocker and was not ruled on.

One clause per bullet, nothing else moved. **V0.6c**'s first bullet now gives
that reason, dated, cites
`/data/.hive/learnings/harness/T-011-python3-heredoc-is-refused-like-python3-c.md`
for the refusal, and says the install half is gone because ADR 46 lets any
phase whose card grants it run `cd front && bun install --frozen-lockfile`.
**V0.6d**'s first bullet gives the same reason in one clause and cites ADR 46
for the retired half. Both ids, every *Run* and *Pass* step and the *Results
log* are untouched; `grep "role's call" docs/ROADMAP.md` finds nothing.
