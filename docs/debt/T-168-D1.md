# T-168-D1 — No in-container process probe: a dead orphan's account and task are held for the full window

**Origin:** introduced, by T-168; declared by its arquitecto and implementador.
**Ruling:** accepted by T-168's revisor.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cost.

## What

ADR 411 keeps an account `BUSY` with a task, and that task's expired lock,
while `_phase_may_be_running` says the phase can still be alive:
`phase_timeout_seconds` plus one heartbeat TTL from the later of the claim and
the card's last heartbeat. Nothing looks inside the account's container for the
`claude` process, so a phase that died with the host (a reboot, a container
restart) is held exactly as long as one that is still writing the worktree. The
Done-when's "or its process still seen" is met only through the time window.

## Where it bites

A task that changes `reap_stale_busy_accounts` or `orphan_holders` in
`dispatcher/dispatcher.py`, or adds a `docker exec` liveness check per account
holder.

## Why it stayed

A `pgrep` per holder on every account pick costs a container round trip, and
`claude`'s argv does not name its task; the in-container `timeout` bounds the
orphan anyway.

## Cost of leaving it

After a host or container restart the operator waits up to about two hours
before the task can be taken, or runs `dispatch release-account` by hand.

## Fix

`docs/decisions.md` ADR 411, *Ruled out*: probe for the `claude` process in the
account's container and release early when it is gone.
