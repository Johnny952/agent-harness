# T-034-D1 — No test covers the task page header's `null`-description arm

**Resolved 2026-10-13 by T-035.** See *How it was resolved*; the sections
before it describe the tree as it was.

**Origin:** introduced, declared by T-034's arquitecto and by the
implementador in round 1.
**Ruling:** accepted by the revisor in round 1: no test file exists for
`front/src/routes/tasks.$taskId.tsx` and T-034's card ruled out creating a
harness for it; the declaration names a checkable *where* and a concrete fix.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).

## What

`TaskDetailPage` in `front/src/routes/tasks.$taskId.tsx` builds a `subtitle`
for `PageHeader`: the task's description, `Absent` labelled *no description*
when the api served `null`, and nothing while no task has been read. T-034
wrote that expression to resolve [`T-033-D1`](T-033-D1.md), and widened
`PageHeader`'s `subtitle` prop in
`front/src/components/console/primitives.tsx` from a string to a node so the
header could take it.

No test renders either half. The Board's two reads of the same field are
tested in `front/src/routes/-index.test.tsx`; the task page has no test file
at all, and `front/src/components/console/primitives.test.tsx` has no
`PageHeader` case with a node.

## Where it bites

A task editing the `subtitle` expression in `TaskDetailPage`, or
`PageHeader`'s `subtitle` prop in `primitives.tsx`, or adding the first test
file for the task page. Not a task on the Board's tile or search, which are
covered.

## Why it stays

No test file exists for that route, and T-034's card said to report that
rather than create a new harness for it. Its files admitted only the route
test that already existed.

## Cost of leaving it

A later edit can drop the `Absent` arm, and nothing objects: `null` as a
prop compiles and `PageHeader` renders a falsy subtitle as nothing, so the
operator sees a header with no subtitle again, which is what `T-033-D1` was.
Narrowing the prop back to a string is the half the type checker does catch.

## Fix

Either of two, and the first covers more:

- a `-tasks` test file under `front/src/routes/` that mounts the route with
  `renderRoute` from `front/src/test/render-route.tsx`, serves a task whose
  `description` is `null` on `/api/tasks/<id>`, and asserts *no description*
  in the header. The page asks for more than one path; read its queries
  before listing what the test serves;
- one `PageHeader` case in `primitives.test.tsx` passing a node as
  `subtitle`. This pins the prop and not the page's expression.

## How it was resolved

**Resolved 2026-10-13 by T-035** (`docs/implementations/T-035.md`, *The
edits*).

Both fixes were taken, and no production file changed.

`front/src/routes/-tasks.test.tsx` is the task page's first test file. It
mounts the route with `renderRoute` at `/tasks/T-101` and reads the block
the level-1 heading sits in, one case per arm of the `subtitle` expression:

- a task served with `description: null`: the header says *no description*
  and not the text `null`;
- a task with a description: the header shows it, and *no description* is
  nowhere on the page;
- a card the api answered `data: null` for: the header is the task id alone.

The test serves the four paths the page asks for: `/api/tasks/T-101` with
the task under test, and `/api/debt`, `/api/phases` and `/api/learnings`
with `[]`, so no region draws its error state
(`docs/implementations/T-035.md`, *Every read the page makes*).

`front/src/components/console/primitives.test.tsx` has one `PageHeader`
case: `Absent` handed as `subtitle` is drawn under the title.

`renderRoute` in `front/src/test/render-route.tsx` gained an optional
fourth argument, `at`, the location the route is opened on. The task page's
path has a parameter, and the helper used one string as both the route's
path and the location. Left out, `at` is the path, so the five calls that
were there get what they got.

No phase of T-035 could run the front's tests: the dispatcher's gates were
their first run.
