# T-162-D1 — A console proposal records no person: `source` stays `operator` and there is no `proposed_by` field

**Origin:** introduced, by T-162; declared by its arquitecto and implementador.
**Status:** resolved 2026-10-23 by T-163.
**Ruling:** accepted by T-162's revisor.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cost.

## What

T-162 made a drop's `by` and every queued action's `actor` name the
signed-in person (`docs/decisions.md` ADR 387). A proposal filed from the
console still records only `source: operator`: `source` is a closed enum
(`dispatcher/tasks.py` `SOURCES`) and no field holds who proposed it.

## Where it bites

A task that adds who proposed a backlog item, or changes `backlog_propose`
over HTTP in `board_service/app.py` (`_http`).

## Why it stayed

`source` is a kind its readers filter on, so a name cannot go there (ADR 387,
*Decision* 4); a new field is outside the fix `T-150-D1` asked for.

## Cost of leaving it

Who proposed a task from the console is only in the sign-in audit log, joined
by time and path, not on the card.

## Fix

Add a separate `proposed_by` field, written from `_person()` in
`backlog_propose`'s HTTP path and read through by the api, as ADR 387,
*Decision* 4 leaves it.
