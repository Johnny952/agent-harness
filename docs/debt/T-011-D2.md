# T-011-D2 — front.md binds two items to "the first tier-1 task" and does not say T-011 was it

**Origin:** found by T-011's revisor, in `docs/plans/front.md` *Decisions this
tier's tasks make* — a file T-011 edited, which is what makes it eligible for a
`found` row.
**Status:** open. **Ruling:** accepted by the auditor, not by the revisor,
because the revisor is the one who raised it — the route a declaration takes to a
card (`dispatcher/debt.py:accepted`) reads the implementador's declarations
filtered by the revisor's rulings, so a revisor's own proposal reaches nobody
else. Recorded in `/data/.hive/learnings/inbox/T-010-no-debt-ids-after-a-hand-resume-again.md`.

## What

`docs/plans/front.md` *Decisions this tier's tasks make* opens "Bound to the
**first tier-1 task**, whichever screen it takes:" and hands it two items:

- **how `front/` enters the repo** — a ruling the arquitecto raises and stops on,
  because C-8 deliberately did not rule on whether `front/` keeps its Lovable
  round-trip, and the first commit touching those files is the last moment the
  question can be avoided;
- **the creation of `docs/ui.md`**, with the entries that task needs.

T-011 was a tier-1 task — the first one — and took no screen. It touched no file
under `front/` and wrote no screen vocabulary, so neither item fired. The section
still reads as though the first tier-1 task discharged both.

## Where it bites

A console task reading that section to decide whether those two items are already
discharged, or whether its own arquitecto has to raise the `front/` ruling and
stop. The trigger is any task in tier 1 of `docs/plans/front.md` that takes a
screen — which is every remaining one.

## Why it stays

Neither item was skipped by oversight; firing either would have been wrong.

Creating an empty `docs/ui.md` contradicts the plan's own rationale for the item
— "the first entry should come from a screen somebody is actually building" — and
C-6's counterpart, that a doc nobody will open is worse than no doc. The `front/`
ruling is unreachable for a task that touches no `front/` file: there is no
commit to decide the shape of.

And the fix is an edit to a section the plan binds to another task.
`docs/learnings/a-plans-status-paragraph-is-the-one-out-of-cycle-edit.md` is the
rule T-011 followed everywhere else in that file: the Status paragraph is the one
paragraph any task may fix out of cycle, and a section handing named items to
named future tasks is not it. Rewriting the binding here would be this task
taking a decision the plan gave to the console task.

The reasoning for each item is on the branch —
`docs/implementations/T-011.md` *What was not done, and is not debt* — and
front.md's new *The api's share* closing paragraph forwards a reader to that
heading.

## Cost of leaving it

A reader who jumps straight to *Decisions this tier's tasks make* — which is what
its heading invites — does not get that forward pointer, and cannot tell from the
section that the first tier-1 task has run and discharged neither item. The two
ways that goes wrong are opposite and both bad: skipping a ruling C-8 leaves open
because the section looks spent, or going looking for a `docs/ui.md` the plan says
exists.

## Fix

One clause in that section naming T-011 as the tier-1 task that took no screen
and passing both items to the first that does. It belongs to the console task,
which owns that section's work anyway and will be reading it to find its own
bindings. Detail as the revisor wrote it:
`/data/.hive/tasks/T-011/revisor-round-1.md` *Proposed found debt* — working
notes, outside the repo, not read once this task is done, so the paragraphs above
are the record.
