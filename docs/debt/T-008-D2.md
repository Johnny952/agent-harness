# T-008-D2 — A card that will not parse is skipped with a warning, and nothing reports it

**Origin:** introduced by T-008. **Status:** resolved 2026-09-26 by T-009, by
the second branch of *Fix* and not the first — see *How it was resolved*.
**Ruling:** accepted by the revisor, rounds 1 and 2.

## What

`LocalBoardClient._read_path` logs a warning and returns `None` for a document
that will not parse, or that parses but carries no string `issue_id`;
`_card_path` does the same for an id that cannot name a file in the board
directory. Nothing quarantines such a document, repairs it, or tells a caller it
was skipped — `list_issues` simply returns a shorter list.

## Where it bites

Phase 1's read API, or anyone reconciling a `kanban_issue_id` in a task file
against a board that no longer lists the card. A board holding one foreign
document also warns on every `list_issues` call, so the noise arrives per read,
not once.

## Why it stays

Writes here are atomic, so a document this client cannot read came from outside
it, and repair policy was never given to Phase 0: the spec makes `get_issue` a
lookup and `list_issues` best-effort. Round 2 widened *which* cases warn, which
was the smaller thing the review asked for, and left quarantine alone by ruling.

## Cost of leaving it

A card can leave the board on a log line. A reader counting cards sees a smaller
board and no reason why, and `get_issue` on that id answers "no such issue",
which is indistinguishable from a card the board never had.

## Fix

Either rename an unreadable document aside (a `.corrupt` suffix) and surface it
in the Phase 1 read API's response, or have `list_issues` return a count of what
it skipped so a caller can say something. Which cases are silent and which warn
is settled: `docs/decisions.md` ADR 1, the `get_issue` bullet.

## How it was resolved

T-009 took the surfacing half. `LocalBoardClient.unreadable()` returns the card
files `list_issues` skipped, and `observability/api/app.py:_read_cards` turns
each into a warning naming that path, so every `/api/tasks` read says which
documents the board is short of rather than answering a quietly smaller list.
The method is the one public name the shared seam does not carry, which is why
`tests/dispatcher/test_vibe_kanban_client.py:LOCAL_BOARD_ONLY` names it and
`dispatcher/dispatcher.py` must never call it — `docs/decisions.md` ADR 4.

Not resolved: nothing quarantines or repairs the document, so a board holding
one foreign file still warns on every read rather than once. That is the first
branch of *Fix* above, and it stays available to whoever wants it — repair
policy still has no owner.
