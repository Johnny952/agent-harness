# T-013-D1 — `front/` has no test runner, no typecheck, no lint and no gate, so no TypeScript edit is ever executed in the loop

**Origin:** declared `found` by T-013's implementador while wiring `/api/phases`
into eight files under `front/src/`, and accepted by T-013's revisor round 1
with the reason that *finding 1 is the proof the declaration is honest rather
than a hedge*. The condition is older than this task — T-012's arquitecto
declared it first, and T-012's auditor never ran to file it (`T-012-D1`'s own
*What it already cost*), so it reaches this index two tasks after it was first
seen.
**Status:** resolved 2026-10-08, out of cycle — the last half of step 3
taken by hand on `main` (see *How it was resolved*). Steps 1 and 2 of the
*Fix* below landed by hand on 2026-10-04 — `front/` got `node_modules`, a
`typecheck`, a `lint` and a `test` script, a vitest config and its first two
test files — and so did the first half of step 3: `tests-in-diff` pairs a
changed file with a test in the same language (`docs/decisions.md` ADR 31).
The second half is a gate that runs the three scripts (ADR 39), so a phase
editing `front/src/**` is no longer reviewed by reading alone. Eleven defects
of the class this describes reached a commit or the tree before that; all
eleven are fixed.

## What

As declared — and the three events under *What it has already cost* all
happened under exactly these conditions. `front/` is a TanStack Start app in
TypeScript, in this repo whole under `docs/charter.md` C-9. It had no
`node_modules`, no `test` or `typecheck` script and no vitest config, and
nothing the dispatcher runs executed a line of it: `python3 -m pytest` is the
whole gate (`docs/learnings/the-pytest-suite-is-the-whole-gate.md`), and it
imports nothing under `front/`. A phase may not run `bun install` — it is out
of scope for every console task so far, and installing a dependency tree is an
operator's decision, not a phase's.

One clause of that declaration was wrong, and it is corrected here rather than
struck, because the correction is why step 3 came out smaller than it looked:
it was **not** true that `dispatcher/gates.py` did not look at `front/`. `.ts`
and `.tsx` have been in its `_CODE_SUFFIXES` since the gate was written, and
`*.test.tsx` has always matched its `is_test`. What the gate could not do was
notice that the test it had found was in another language — step 3 below.

So the only thing standing between a TypeScript edit and `main` is a human or
a revisor **reading** it. A type error, a bad import, a renamed export, a
fixture that no longer conforms to the type it is annotated with, a `.map` on
a value that is not an array — none of them is caught by anything this harness
runs. A green suite says nothing about this directory, and `docs/README.md`
already says so on `front/`'s row.

## Where it bites

Any task that edits a file under `front/src/`: its edits ship unexecuted, and
a type error, a bad import or an unguarded render reaches `main` with nobody
having run it. Also any task that *narrows* a type in
`front/src/lib/api/types.ts`, because the fixtures under
`front/src/lib/api/mock/` are typed against those interfaces and nothing
rechecks them —
`docs/learnings/narrowing-a-served-type-is-also-a-fixture-edit.md`.

Not a task that only edits `front/README.md`, `front/AGENTS.md` or the docs
that describe the console: there is nothing to execute there either, but there
is also nothing that could have been.

## What it has already cost

Three events on this branch, and the useful thing about them is that they fail
differently — which is why the entry names four missing things and not one:

- **A render that throws on data the api is pinned to serve.** T-013's
  implementador shipped `formatClock(phase.saved_at)` over a value
  `observability/api/app.py:_phase` passes through verbatim and does not
  validate, where `new Date(junk).toISOString()` is a `RangeError` and the only
  `errorComponent` in the tree is on the root route — one hand-edited handoff
  file for the whole console. Caught by the revisor **reading** the diff and
  fixed by hand in commit `aba17b2`. A typecheck would *not* have caught it:
  `Phase.saved_at` was typed `string` and the lie was in the annotation, which
  is the point of
  `docs/learnings/a-console-type-over-a-served-value-is-an-annotation.md`. A
  test over that render with a junk value would have, and there is no runner.
- **The same class, and it was nine more than anyone counted.**
  **Resolved 2026-10-04 by T-013, by hand on `main` after the merge** — the
  row stays because the gap this entry names is the missing runner, not these
  defects. `PhaseList` in `front/src/routes/tasks.$taskId.tsx` called
  `lines.map` on six payload keys guarded with `?? []` for *absent* and not for
  *wrong-typed*; a `handoff.changed` holding a string passes the length test and
  fails the map. Found by this task's auditor, after the branch had been fixed
  by hand and with no round left to take it — and the auditor's commit scope is
  `docs/` only (`dispatcher/project_docs.py:_COMMIT_SCOPES`), so it could not be
  fixed from there either. Closing it found **nine more render sites of the one
  class** across `tasks.$taskId.tsx` and `index.tsx`, including a board chip
  taking `.length` over a string and putting a confident wrong number on a card
  without throwing. All ten now guard at the render against a new `Malformed`
  primitive: `docs/decisions.md` ADR 29 and `docs/ui.md` *A value of the wrong
  shape is named, not rendered and not dropped*.

  That the auditor found one of ten is this entry's argument restated. Reading
  catches an instance; only something that runs catches a class.
- **A fixture that stopped conforming to its own type mid-edit.** Narrowing
  `Phase` from seventeen keys to six left
  `front/src/lib/api/mock/fixtures.ts:mockPhases` annotated `Phase[]` and
  returning seventeen-field rows. This one *is* a typecheck's job, and the
  implementador caught it in the same task — so it cost a hand-check rather than
  a defect, and it is here because the next narrowing is not guaranteed the same
  luck:
  `docs/learnings/narrowing-a-served-type-is-also-a-fixture-edit.md`.

## Why it stays

`bun install` is not a phase's call and the container half — a Node image with
`bun` in it, an install step, and a gate that runs the three scripts — is a
human's row on `docs/ROADMAP.md`, not a line in a console task. Declaring this
does not unblock it, and every other part of T-013's scope is finished:
the route, its fourteen tests, the reader, the timeline, the Board's banner and
the doc sweep all landed.

It is also not a one-line fix. The first half needs a dependency tree nothing
in this harness may install, and the second changes what a gate means for a
directory no gate has ever executed — a red `tsc --noEmit`, or a red
`eslint .`, on a tree Lovable keeps generating (C-9 keeps that round-trip
live) would stop a cycle over lines no role wrote. That trade was the
operator's to make, and it has been made: `docs/charter.md` C-10 blocks on the
typecheck and takes the lint as a note.

## Cost of leaving it

Console tasks are reviewed by reading, so the defects that survive are exactly
the ones reading does not catch: a shape assumption, a stale fixture, a helper
that throws on an input the api is pinned to serve. Reading caught two of the
three above and missed one for a whole round — and reading is a revisor's turn,
which is the most expensive gate this harness has, spent on what a second of
`tsc` would answer. The cost compounds with the console's reach: the wired reads
went from five to six in this task, and every one of them is a value the api
serves verbatim and the console renders with no runtime guard behind the type.

## Fix

Three steps; the third has two halves and one of them is still open:

1. **A human runs `bun install` in `front/`** and commits nothing new but what
   `bun.lock` already pins (C-9: no force-push, no rebase of a pushed commit).
   `node_modules` stays ignored. This step cannot be a phase's.
   **Done 2026-10-04 by T-013, by hand.** The install added the four test
   packages and re-pinned four top-level hoists (`lru-cache`, `ansi-styles`,
   `magic-string`, `@jridgewell/sourcemap-codec`); every prior consumer of the
   old majors kept a nested pin, so nothing lost a version.
2. **`front/package.json` gains `typecheck` (`tsc --noEmit`) and `lint`**, and a
   `test` script with a vitest config. Note which half does which: `tsc` catches
   the fixture case and nothing else this entry names, because the other two are
   renders whose *types* are correct and whose inputs the api does not validate.
   The first test worth writing is one render per api-served value with a junk
   value in it.
   **Done 2026-10-04 by T-013, by hand.** `typecheck`, `lint`, `test` and
   `test:watch` are scripts; `front/vitest.config.ts` is a file of its own
   rather than a `test` key in the Lovable-owned `vite.config.ts` (C-9), with
   `globals: false` — which means every test file registers its own
   `afterEach(cleanup)`, because `@testing-library/react` self-registers only
   when a global `afterEach` exists. The first tests are
   `front/src/components/console/payload.test.tsx` and
   `primitives.test.tsx`: the junk-value renders this step asks for, over the
   two renderers of a handoff payload and over `Malformed` itself. Getting
   there needed `PhasePill`/`PhaseList` out of the route file, which is
   `docs/decisions.md` ADR 30.

   **The next increment is the board.** `index.tsx`'s `TaskCard` holds the one
   defect of the class that does not throw — `.length` over a string — and it
   renders a `<Link>`, so a test over it needs a router harness
   (`createMemoryHistory` plus a `RouterProvider`, or a stub for the one
   component). Nothing of that is written yet.
3. **`dispatcher/gates.py` learns `front/`**, in two halves that are blocked
   on different things.

   **(a) `tests-in-diff` pairs a change with a test in its own language.
   Done 2026-10-04 by T-013, by hand.** The premise this step was declared on
   was wrong, and finding that out is most of what the step turned out to be:
   the gate already had `.ts` and `.tsx` in `_CODE_SUFFIXES` and already read
   `payload.test.tsx` as a test. What it could not do was keep looking after
   it had found one — the body was `if any(is_test(p) for p in changed):
   return []`, so a Python change arriving with its Python test cleared the
   `front/src/**` edit sitting beside it, which is the shape T-012 and T-013
   both shipped. It now groups code by the language a test for it would be
   written in and goes on asking about every group no test in the diff covers;
   `.sh` and `.sql` stay ungrouped and are cleared by any test at all.
   `docs/decisions.md` ADR 31 is the decision, and
   `test_a_test_in_one_language_does_not_cover_another` in
   `tests/dispatcher/test_gates.py` is the regression test for the shape.

   **(b) A gate runs the three scripts. Done 2026-10-08 by hand.** This half
   was blocked on an image rather than on a decision: the test gate ran the
   single `test:` command in `docs/README.md`'s frontmatter, neither agent
   container had `bun` on its PATH, and `front/node_modules` is ignored and so
   absent from a fresh worktree — so a Node image and an install step came
   first, and only then could a gate call `bun run typecheck`. What each
   script means when it comes back red was already settled and was not this
   half's to re-decide: `docs/charter.md` **C-10** blocks the phase on a red
   typecheck and takes a red lint as a note, because the tree carries
   pre-existing `prettier/prettier` errors — 125 when this was written, 124
   errors and 10 warnings measured on 2026-10-08 — and a gate that is red
   before the work starts is a gate the roles learn to route around. How it
   landed is *How it was resolved* below.

The sketch this was declared against is `/data/.hive/tasks/T-012/console-plan.md`
section 11, which is working notes outside the repo and may not outlive the
task; the three steps above are the entry's own copy, so nothing here depends
on that file still being there.

## How it was resolved

By the frontmatter, not by a new gate: the test gate already ran whatever
`docs/README.md` named, so it learned to read lists and two more keys, and
the index names the rest (`docs/decisions.md` ADR 39).

- `dispatcher/project_docs.py:COMMAND_KEYS` is `build`, `install`, `test`,
  `lint`, each a command or a list. A mapper is still asked for `build` and
  `test` only (`MAPPED_KEYS`); `install` and `lint` were added by hand.
- `gates._run_tests` runs install, then test, then lint. A failed install is
  a note, a red test entry blocks — the type check is one — and a red lint is
  a note under the new `lint` gate, which is C-10's split. After a clean
  install only exit 127 means the suite could not run, because `tsc` reports
  a broken import as "Cannot find module".
- `docker/agent/Dockerfile` ships `bun` 1.3.12, with its install cache on the
  projects mount so each worktree's `node_modules` is hardlinked out of it,
  and moves from `node:20-slim` to `node:24-bookworm-slim`: `front/`'s jsdom
  30 refuses any Node below 22.22.2, and on 20 every test file failed to load.

Measured in a recreated `agent-cuenta1` on a throwaway worktree: the install
takes 5.1 s cold and 0.6 s warm, the type check 4.4 s, the 23 vitest tests
1.7 s, the lint 3.2 s (red, 134 problems, all prettier), the Python suite
8.0 s. `node_modules` and the cache take 454M together, and each further
worktree about 13M. The gate was not run end to end on a real task: the
clone the agents work on predates the new frontmatter. Seven tests in
`tests/dispatcher/test_gates.py` and one in
`tests/dispatcher/test_project_docs.py` pin the order and the severities.

The lint stays red on `main` until someone formats `front/`, so every task
carries a `lint` note until then. That is the cost C-10 chose, not a new row.
