# T-133-S1-D1 — the worker's resolve copies the CLI's and reaches a private lock

**Origin:** introduced, by T-133-S1; found by the operator's review at merge.
**Status:** open.
**Ruling:** accepted by the operator at merge.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** risk.

## What

`dispatcher/worker.py` `_resolve_locked` calls `core._base_lock`, a private
name of `dispatcher/dispatcher.py`, and repeats the block of
`dispatcher/cli.py`'s `resolve-conflict` branch line for line: the cleanup
container, the base lock under the name `resolve-conflict`, `read_owner` and
`restore_owner` around `resolve_conflict`.

## Where it bites

A task that changes how a resolution takes the base lock or restores the
project's owner: the change has to land in both copies, and nothing fails when
only one gets it. A rename of `_base_lock` breaks the worker with no warning
from its name.

## Why it stayed

`dispatcher.py` and `cli.py` were outside T-133-S1's surface, so the shared
helper could not be lifted out of the CLI or made public.

## Cost of leaving it

Two copies of one base operation that can drift apart; the behavior is the
same today.

## Fix

Lift the block into one public function beside `resolve_conflict` in
`dispatcher/dispatcher.py` (lock, owner, resolve, owner back) and call it from
both the CLI branch and `_resolve_locked`.
