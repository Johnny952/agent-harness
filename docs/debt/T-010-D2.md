# T-010-D2 — `_unwrap_code` takes the outer pair off a cell that opens with one code span and closes with another

**Origin:** found by T-010's revisor, in `dispatcher/debt.py:_unwrap_code`,
which T-010 added.
**Status:** open. **Ruling:** accepted by the auditor. Proposed by the revisor
in round 1 as W1 — a non-blocking finding — and ruled on here rather than by the
revisor, because the revisor is the one who raised it.

## What

`dispatcher/debt.py:_unwrap_code` asks only whether the cell starts and ends
with a backtick, so it cannot tell "this whole cell is one code span" from
"this cell happens to begin with one code span and end with another". A cell
reading `` `cli.py` and `debt.py` `` comes back as ``cli.py` and `debt.py``:
the outer backtick of each of two distinct spans is eaten and the inner two
remain, which is the unbalanced rendering `T-009-D3` exists to prevent, in a
different shape.

Not a regression. The old `cell.strip("`")` did the same thing to this cell and
worse to several others; both sub-cases `T-009-D3` names — a cell that only
opens with inline code, and one that only closes with it — are fixed and
tested.

## Where it bites

A row in `docs/debt/README.md` or any Markdown table `_rows` parses whose
**where** or **fix** cell both begins and ends with inline code — the shape of
this index's own newest rows — or a later task changing cell unwrapping in
`dispatcher/debt.py`. Visible only through `/api/debt` and the board's `/debt`,
which render those cells; `index_fingerprints` is unaffected, because
`fingerprint` substitutes punctuation with spaces before comparing.

## Why it stays

Widening the unwrap reopens the argument round 1 settled: the condition on the
`T-009-D3` fix was that no fingerprint move, and the test proving it
(`tests/dispatcher/test_debt.py:test_the_fingerprints_of_the_projects_own_index_did_not_move`)
compares this index under the new rule against the old `strip("`")`. A second
rule change in the same task means that test is asserting something different
from what it was written to assert. The defect it would close is also strictly
smaller than the one already closed.

## Cost of leaving it

One unbalanced cell on `/debt` for the row shape most likely to be filed next.
No dedupe, no filing and no fingerprint is affected.

## Fix

Require that `cell[1:-1]` contains no backtick before unwrapping — that is
exactly the test for "the whole cell is one code span" — and add the case to
`tests/dispatcher/test_debt.py:test_a_cell_keeps_the_backtick_it_only_opens_or_only_closes_with`,
which is where the sibling cases already live. Fixing this and `T-010-D1`
together is reasonable: both are one helper's reach, and neither touches
`index_fingerprints`.
