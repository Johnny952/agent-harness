# T-015-D1 — the nine `react-refresh/only-export-components` warnings are left as they are

**Origin:** found, declared by T-015's arquitecto and again by its implementador
as one entry, in `front/src/routes/index.tsx` — the one file that task edited,
and one of the nine, which is what makes it eligible for a `found` row.
**Status:** open. **Ruling:** accepted by the revisor in round 1, which
confirmed independently that `front/src/routes/index.tsx` is one of the nine.
**Card:** none — this harness has no board configured, the first reason given in
[`README.md`](README.md)'s closing paragraphs.

## What

`bun run lint` in `front/` exited zero on `main` with ten warnings
(`docs/decisions.md` **ADR 39**): one `react-hooks/exhaustive-deps` and nine
`react-refresh/only-export-components`. T-015 fixed the first one — ADR 40, the
board's `rows` — and left the nine untouched. The lint now exits zero with those
nine and nothing else.

Each of the nine is a module that exports a component beside something that is
not a component, so Vite's fast refresh cannot refresh that module in
development. The rule is configured `["warn", { allowConstantExport: true }]` in
`front/eslint.config.js`, so a plain constant export is already excused and what
remains is a function, a hook or a call expression sharing a module with a
component.

**Which nine, exactly, is the lint's to say and not this entry's** — and it has
now said. No phase of T-015 could run `eslint`, so this section was reasoning
rather than output; T-016's auditor ran `cd front && bun run lint` in a phase on
2026-10-09, at `617c7f3`, and got `9 problems (0 errors, 9 warnings)` in **eight
files**:

```
front/src/components/console/payload.tsx       116:17
front/src/components/console/primitives.tsx    140:14, 146:17
front/src/components/ui/badge.tsx               32:17
front/src/components/ui/button.tsx              49:18
front/src/components/ui/form.tsx               163:3
front/src/components/ui/navigation-menu.tsx    111:3
front/src/components/ui/sidebar.tsx            743:3
front/src/components/ui/toggle.tsx              42:18
```

Two of the three shapes this entry predicted are there and the proportions were
right: six vendored shadcn modules, and the console's two helpers — with
`primitives.tsx` carrying two warnings, which is the ninth and the reason eight
files hold nine findings.

The third shape is **not** there, and this entry had it as its one confirmed
fact. `front/src/routes/index.tsx` exports `TaskCard` beside
`export const Route = createFileRoute("/")({…})` and the lint does not warn on
it. The mechanism is the rule's and not this project's: a PascalCase `const`
whose initialiser is a call expression reads to
`eslint-plugin-react-refresh` 0.4.20 as a component, so TanStack's own
file-route export is excused without any configuration. Treat that as observed
behaviour of this version rather than as a documented guarantee.

## Where it bites

A task that wants `bun run lint` promoted from a note to a blocking gate, or one
splitting a route module's or a vendored component's non-component export out of
it. Also any task reading `docs/charter.md` **C-10** to find out why the lint is
still only a note.

Not a task that merely edits a file under `front/src/` — the nine are green-exit
warnings, they block nothing, and a new edit inherits no obligation from them.

## Why it stays

The task text put them out of scope, and they are not one decision.

They are not a lint fix. Each one asks what a module's surface should be, and
the three groups above want three different answers. `front/src/routes/index.tsx`
exports `Route` beside a component *because that is TanStack's own convention*,
so the rule is complaining about the framework; the right answer there is
plausibly a scoped disable with a reason, not surgery. The console's own two are
a genuine question about where a helper lives. And the shadcn modules under
`front/src/components/ui/` are vendored — editing them is a decision about
whether this project maintains its copy of that library, which is far larger
than a lint warning and belongs nowhere near a one-line fix.

C-10's own split is the other half: a style finding is the revisor's to weigh
rather than the dispatcher's to enforce, so nine warnings that exit zero are
exactly the state the charter tolerates.

## Cost of leaving it

`docs/charter.md` **C-10**'s condition for promoting the `front/` lint from a
note to a blocking gate is a clean tree, and nine warnings is not clean. So the
condition stays unmet, the lint stays a note every phase may ignore, and the one
thing that would catch the *next* `react-hooks/exhaustive-deps` regression — a
blocking lint — stays unavailable. The sentence that used to close this
paragraph — that no phase of this project can run the lint itself — was
falsified on 2026-10-09 by T-016, whose task description granted the four
`front/` commands and whose phases ran them
(`/data/.hive/learnings/inbox/T-016-bun-runs-in-a-phase-when-the-task-grants-it.md`,
harness scope and still unconfirmed, refuting
`T-015-bun-is-refused-in-a-phase.md`). It changes what this costs rather than
whether it costs: a phase can now observe the count when its own task grants the
command, the dispatcher's gate observes it on every round either way, and a note
is still an observer nobody has to read.

Fast refresh not working in the eight modules costs a developer a full reload
during local work. Nobody has reported it.

## Fix

Decide per module, not in one sweep, and in this order: the two console modules
(move the helper out — `front/src/lib/` is where `asPathLine`'s kind of function
already lives), then the six vendored ones (a scoped disable carrying the
reason, since that export shape is the library's rather than this project's).
Two modules and six, not three groups: the route module needs nothing, the lint
having excused it.

Then raise C-10's promotion as a human's charter entry. That part is explicitly
**not a judgement a phase makes**: C-10 is a charter entry, and what a red gate
costs a round was settled there rather than in any task — ADR 39 and ADR 40's
closing paragraph both say the promotion waits on a clean tree and on a human.

Run the lint first all the same, and work from its own output. The eight file
names in *What* above are a real run, at `617c7f3`, but they are a measurement
with a date on them, and the first item of this fix is to move two of them.
