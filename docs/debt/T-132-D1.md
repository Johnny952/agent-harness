# T-132-D1 — the actions token still counts two routes

**Origin:** found, by the operator's review of T-132.
**Status:** open.
**Ruling:** accepted by the operator at merge.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cosmetic.

## What

`front/src/lib/api/server-env.ts` still counts the routes
`BOARD_ACTIONS_TOKEN` guards as two:

- the module comment's ADR 157 paragraph: "the bearer of the board-service's
  two action routes (ADR 151)", and "those two routes answer a 503";
- `BOARD_ACTIONS_TOKEN`'s doc comment: "the board-service's start and cancel
  routes", and "answers those two routes with a JSON 503".

The board-service's action routes have grown since ADR 157 (approve and
request changes among them), and `forward.ts`'s header names the nine that
carry the token.

## Where it bites

A task that edits `server-env.ts`'s comments on the actions token, or that
greps `front/` for which routes carry the token.

## Why it stayed

T-132 was scoped to `T-131-D1`, the backlog writes' count.

## Cost of leaving it

A reader gets a stale count; the code is unaffected.

## Fix

Reword both to name the token's routes by where `forward.ts` decides them
rather than count them, as T-132 did for `BOARD_SERVICE_URL`. See the learning
[the-forwarded-route-count-is-prose-and-derived-from-nothing](../learnings/the-forwarded-route-count-is-prose-and-derived-from-nothing.md).
