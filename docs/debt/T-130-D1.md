# T-130-D1 — `forwardBoard`'s doc comment still carries stale route counts

**Origin:** found, declared by T-130's arquitecto and implementador.
**Status:** open.
**Ruling:** accepted by the revisor in round 1.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cosmetic.

## What

The doc comment on `forwardBoard` in `front/src/lib/api/forward.ts` still
opens two paragraphs with counts that `boardTarget` no longer bears out:
*The four backlog writes* (the verdict write makes five) and *The three action
routes* (approve, request-changes and the epic actions came after it was
written; the same comment then describes them in later sentences). T-130 fixed
the file's header comment the same way but its Goal named only the header.

## Where it bites

A task that edits `forwardBoard`'s doc comment in
`front/src/lib/api/forward.ts`, adds or removes a pair in `boardTarget`, or
relies on that comment's counts to know which routes carry the bearer.

## Why it stayed

T-130's Goal names only the header comment; the fix was kept to that scope.

## Cost of leaving it

A reader of `forwardBoard`'s comment gets wrong counts; the code is unaffected.

## Fix

Recount from `boardTarget` and reword those two sentences, as T-130 did for the
header comment (name the routes rather than count them, so the next added
route cannot make the number lie — see the learning
[the-forwarded-route-count-is-prose-and-derived-from-nothing](../learnings/the-forwarded-route-count-is-prose-and-derived-from-nothing.md)).
