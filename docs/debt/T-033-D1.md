# T-033-D1 — `Task.description` is typed `string` and served `null`

**Resolved 2026-10-12 by T-034.** See *How it was resolved*; the sections
before it describe the tree as it was.

**Origin:** found, declared by T-033's arquitecto and by the implementador in
round 1.
**Ruling:** accepted by the revisor: real and verified in `_task`'s
docstring, but outside the fields `docs/decisions.md` ADR 59 removed, and
the fix touches every render of `description`, a screen edit T-033's card
excluded.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).

## What

`Task` in `front/src/lib/api/types.ts` declares `description: string`.
`_task` in `observability/api/app.py` serves the text of the task's
`description.md` as `read_description` in `dispatcher/tasks.py` returned it,
"served verbatim and `null` when there is none". So the console's type says
a value is always a string that the api answers `null` for on any task filed
without a description. The nine rows of `mockTasks` in
`front/src/lib/api/mock/fixtures.ts` and the `TASK` constant of
`front/src/routes/-index.test.tsx` all carry a string, so no fixture or test
shows the `null`.

Nothing throws on it today. The three reads of the field, as the auditor
found them on T-033's branch:

- `front/src/routes/index.tsx`, the Board's filter: a template literal,
  `${t.task_id} ${t.description}`, which turns `null` into the text `null`.
  A task with no description therefore matches the search `null`.
- The same file's task tile renders `{task.description}` as a JSX child,
  which React prints as nothing.
- `front/src/routes/tasks.$taskId.tsx` passes it as `PageHeader`'s
  `subtitle`, which `front/src/components/console/primitives.tsx` renders
  only when truthy.

## Where it bites

A task rendering a task's `description` in `front/`, or calling a string
method on it (`.toLowerCase()`, `.split`, `.length`), or editing `Task` in
`front/src/lib/api/types.ts` or a `Task` literal. Not a task that reads no
field of `/api/tasks`.

## Why it stays

T-033's card kept it to the fields ADR 59 removed. Typing the field
`string | null` makes `tsc` object at every read, and answering each one is a
decision about what a screen shows for a task with no description, which is
a screen edit.

## Cost of leaving it

`tsc` will not object when a screen calls a string method on `null`, and a
throw in a render reaches the root `errorComponent`, which takes the whole
page. Until then the cost is the Board's search matching `null`, and two
places that show nothing where `docs/ui.md` asks for an absent value to be
said.

## Fix

Type it `string | null`, conform one `mockTasks` row to `null` so the edge
has a fixture
(`docs/learnings/narrowing-a-served-type-is-also-a-fixture-edit.md`), and
guard each of the three reads per the absent-value rule of `docs/ui.md`.
The rule that the guard goes at the render and not in the route is
`docs/learnings/a-console-type-over-a-served-value-is-an-annotation.md`.

## How it was resolved

**Resolved 2026-10-12 by T-034** (`docs/implementations/T-034.md`, *The
edits*).

`Task` in `front/src/lib/api/types.ts` declares `description: string | null`,
with a docblock saying `null` is a task with no `description.md`. The `T-007`
row of `mockTasks` in `front/src/lib/api/mock/fixtures.ts` carries `null`;
the other eight rows and the `TASK` constant keep their strings.

Each of the three reads is guarded at the render:

- the Board's filter, the `filtered` memo of `BoardPage` in
  `front/src/routes/index.tsx`, adds the empty string for a `null`, so the
  search `null` no longer matches the task and its id still does;
- `TaskCard` in the same file renders `Absent` labelled *no description*
  where the description goes;
- `TaskDetailPage` in `front/src/routes/tasks.$taskId.tsx` passes the same
  `Absent` as `PageHeader`'s `subtitle` for a task that was read, and no
  subtitle while none has been.

`PageHeader`'s `subtitle` prop in
`front/src/components/console/primitives.tsx` was `string` and is now a
node, the one edit to that file: the header could not render `Absent`
without it.

`front/src/routes/-index.test.tsx` covers the tile (*a task the api served
with no description*) and the search through the mounted route (*the Board's
search over a task with no description*). The header's arm has no test: no
test file exists for the task page and T-034's card ruled out a new harness
for it. T-034 declared that as debt.
