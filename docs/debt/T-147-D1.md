# T-147-D1 — Backup once before each merge, and nightly scheduling, are not wired

**Origin:** introduced, by T-147; declared by its arquitecto and implementador.
**Status:** open.
**Ruling:** accepted by T-147's revisor.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** risk.

## What

`docs/plans/server-deployment.md` *Decisions*, 8 asks for a copy nightly and
once before each merge. T-147 built the `backup` verb and `scripts/backup.sh`
(`docs/decisions.md` ADR 327) but nothing calls them on a schedule: the
nightly copy is only a host crontab line the root `README.md` *Backups and
restore* section documents, and no backup runs before a merge.

## Where it bites

A task that changes the worker's approve/merge handler, adds a mount to the
`worker` service in either compose file, or wires backups into any schedule.

## Why it stayed

The worker has no `BACKUP_DIR` mount. Adding one is a compose change in both
compose files, which T-147 could not make without approval.

## Cost of leaving it

A merge runs with no fresh copy behind it; only an operator-installed crontab
line protects the records, and a night refused with exit 75 (a cycle running)
is not retried until the next night.

## Fix

After approval, mount `BACKUP_DIR` into the `worker` service in both compose
files and call `dispatcher/backup.py` `backup` before the approve merge, as
`docs/decisions.md` ADR 327 *Consequences* lays out.
