# T-028-D2 — the root `README.md` still offers a board, and the agent image still installs `mcp`

**Origin:** introduced, declared by T-028's arquitecto and by the
implementador in rounds 1 and 2.
**Ruling:** accepted by the revisor in both rounds: a large README rewrite and
an image change no phase can prove, and the startup error names the ADR.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).

## What

Two leftovers of the board seam T-028 removed, outside the files its card
named:

- The root `README.md` still describes the optional board in the present
  tense: the architecture sketch, the *Vibe Kanban* component bullet, the
  `vibe-kanban` compose service and its `kanban` profile, the passage *The
  board, if you want one* with both config blocks and `--kanban-issue-id`,
  the debt-card passages, and the known-limits entries about the client.
- `pyproject.toml` and `docker/agent/Dockerfile` still install `mcp`, which
  only the deleted client module imported, and the Dockerfile's comment
  names that module.

Widened by T-030's auditor, on a proposal of that task's revisor. The same
`README.md` is stale a second way since T-030, whose card kept it out of
that file:

- The exit-code table under "`run-task`'s exit code says how the cycle
  ended" gives exit 1 as a phase that failed or blocked, the rounds running
  out, a held lock or a diverged branch. `open_cycle` now also refuses a
  task with a dependency that is not merged and a child of a malformed
  epic, with one log line, `task <id> cannot start: <reasons>`.
- The `merge-task` passage does not say a merge is recorded on the task
  file (the `merged` block a dependency waits for), that the last merged
  child closes its epic, or that `merge-task` prints a `recorded as merged
  into` line.
- Nothing there says a blocked cycle writes `status: blocked` to the task
  file. Its remaining "the card goes `blocked`" sentences are the board
  prose above.

Widened again by T-031, whose card kept it out of `README.md` and sent the
gap here (`docs/decisions.md` ADR 60):

- The exit-code table has no row for exit 3, `EXIT_SPLIT`: the arquitecto
  split the task, it is now an epic, and `run-task` printed `task <id> is now
  an epic: <ids>; run them in that order`. The exit-1 row does not say that a
  task whose file says `status: epic` is refused, or that a split that could
  not be filed blocks the task.
- The verbs it lists do not include `dispatch file-split --task-id <id>
  --project <slug>`, which files the split of a saved arquitecto handoff
  without running a model, and exits 1 when it refuses.
- The `run-phase` passage does not say that an arquitecto phase prints a
  split it proposes and files nothing.

## Where it bites

An operator following `README.md` to configure a board, or reading it after
`run-task` exits 1 on a task with `depends_on`; a task editing that file's
exit-code table or `merge-task` section; or a task editing
the agent image's pip list or `pyproject.toml`'s dependencies. Also any task
removing a config key that reads
`docs/learnings/a-config-key-has-three-homes.md`: the README is the third
home, and here it is the one left behind.

## Why it stays

The card keeps T-028 to named files. The README's board prose runs through
more than a dozen passages, and an image change cannot be proved inside a
phase (`docker` is refused there).

## Cost of leaving it

An operator who follows the README adds a `vibe_kanban` or `local_board`
block and gets a startup error naming the key and ADR 59, or passes a flag
that is now a usage error. The agent image carries one unused package.

## Fix

One docs task rewrites the README's board passages against ADR 59 and drops
`mcp` from `pyproject.toml` and `docker/agent/Dockerfile`, with its comment.
Grep `README.md` for `kanban`, `local_board` and "the board" to find them
all. The image half needs a build by a human or a task whose card grants it.
The same task adds the dependency and epic gate to the exit-1 row and a
sentence each on the merged record and the `blocked` status; what to say is
in `docs/implementations/T-030.md`, *What a later task should know* and
*Merge: one function both paths call*. Until then an operator refused for
an unmet dependency has only the log line to explain the exit. It also adds
the exit-3 row, the `file-split` verb and the `run-phase` sentence; what to
say is in `docs/implementations/T-031.md`, *What a later task should know*.
Until then an operator whose `run-task` exits 3 has the printed line and
ADR 60.
