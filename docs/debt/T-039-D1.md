# T-039-D1 — The docs index calls the project's own spec vendored

**Resolved 2026-10-14 by T-039**, in its auditor phase: `docs/README.md` now
says `docs/superpowers/` holds this project's founding spec and first plans,
kept as records and edited only where a task names one, and that the pointers
gate reads none of them (`docs/decisions.md` ADR 38).

**Origin:** found, declared by T-039's arquitecto and again by its
implementador in round 1.
**Ruling:** accepted by the revisor in round 1: the sentence is in
`docs/README.md`, outside the card's surface, and the card itself named the
spec for editing.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).

## What

`docs/README.md` said all of `docs/superpowers/` was vendored upstream material
and was not to be edited. The git history of all three files under it shows
they were written in this repository, and T-039's card told it to edit the
design spec's section 8. The same sentence said the pointers gate greps all of
`docs/`, which ADR 38 had already ruled out for that directory.

## Where it bites

A task that edits a file under `docs/superpowers/`, or a phase that applies the
`docs/README.md` rule about that directory to judge another phase's diff.

## Why it stayed

The card kept the implementing phases to the six docs it named and the
implementation note. The docs index is the auditor's to keep.

## Cost of leaving it

A later phase could refuse to fix the project's own spec, or flag T-039's edits
to it as a breach of the docs index.

## Fix

Narrow the sentence in `docs/README.md` to say the files are the project's own
records. Taken as declared, by the auditor that filed it.
