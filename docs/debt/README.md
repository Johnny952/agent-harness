# Debt

Work a task decided not to do, declared by the implementador, ruled on by the
revisor, filed here by the auditor. This index is the source of truth and
nothing mirrors a row anywhere else: the board seam that once opened a card
per entry was removed by T-028 (`docs/decisions.md` ADR 59).

Read the whole table and open only the entries whose **where** matches the task
in front of you: the trigger is a condition to check against your own work, not
a topic.

The table only grows, at its end, and it is the last block of this file
(`docs/decisions.md` ADR 297). A row is never edited once written and never
deleted, because a fix can be reverted and the row should outlive that. An
entry that gets resolved is not rewritten: a *resolution row* is appended with
the same id, `**Resolved <date> by <task>.**` as **what**, an empty **where**,
how it was taken as **fix**, and `none` as **card** and **impact**. Read an
entry's open row together with any resolution row further down: the dispatcher
folds the two into one resolved entry. Rows resolved in place before ADR 297
stay as they are. A repeated id that is not a resolution row stops the merge.

The per-task notes that used to follow the table are in `docs/debt/log.md`:
append one paragraph for your task there, never edit an earlier one. This file
and that one merge by union (`.gitattributes`), so two tasks that each append
to them merge without a conflict.

Declare `found` debt only for files your task touched, and only if it is not
already a row here.

`card` is `none` on every row because no card exists to point at. That was
first an accident of configuration — this harness never had a board set, so
no auditor from T-008 on was handed a card id — and since T-028 it is the
rule: the board seam is removed and nothing opens a card
(`docs/decisions.md` ADR 59). The column stays, unchanged, because
`dispatcher/debt.py`'s `COLUMNS` and the api's debt route read it; write
`none` in it, as the filing note says. Step 5 of
`docs/plans/board-service.md` *How it would be built* was once going to put a
backlog item's id there; T-086 links the other way instead (`docs/decisions.md`
ADR 131): the backlog item carries the entry's id as its `debt_id`, so `card`
stays `none` and old rows need no rewrite. "The first reason above" in the
paragraphs below means this one: no card exists.

`impact` says what leaving the entry as it is costs, and the auditor writes it:
`risk` (left as it is, it can break or lose something), `cost` (it slows or
costs work) or `cosmetic` (wording or polish). The dispatcher files every open
entry as a proposed backlog item tagged `debt`, and the impact sets its
priority: `risk` is `high`, `cost` is `normal`, `cosmetic` is `low`. A row with
no impact, or one outside those three, reads as `none` and files at `normal`.
Resolved rows say `none`: they are never filed. The column is last so a row
written before it existed still parses.
