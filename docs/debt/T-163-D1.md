# T-163-D1 — The console does not show `proposed_by`

**Origin:** introduced, by T-163; declared by its arquitecto and implementador.
**Status:** open.
**Ruling:** accepted by T-163's revisor.
**Card:** none — nothing mirrors a row (`docs/decisions.md` ADR 59).
**Impact:** cosmetic.

## What

T-163 made a console proposal record the signed-in person in a task file's
`proposed_by`, and both `board_service/app.py` `board_list` and
`observability/api/app.py` `_task` serve it on every row
(`docs/decisions.md` ADR 390). The front end does not: `front/src/lib/api/types.ts`
`TaskRow` has no `proposed_by` and the backlog screen does not print it.

## Where it bites

A task that changes the backlog screen's card detail or the front `TaskRow`
type.

## Why it stayed

The Done-when asked only for the write and the api read-through; a screen
change is another surface.

## Cost of leaving it

Who proposed a card is on the file and in the api but not visible in the
console.

## Fix

Add `proposed_by: string | null` to `TaskRow`, `null` to every fixture
literal, and print it beside `source` on the backlog card (ADR 390,
*Consequences*).
